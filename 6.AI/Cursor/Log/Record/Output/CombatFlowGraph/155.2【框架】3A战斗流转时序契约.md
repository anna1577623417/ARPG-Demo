## 〇、一句话结论

154.2 的 Fix（延迟游标、Late 锚点、解析绑 Stage Action）方向正确，但它是**症状级补丁**。
真正的病根在 155.1 已经点破：**系统里同时存在多个「当前」，而它们各自被独立推进**。
本项目代码已经在 **Combo 段位** 上做对了这件事（Resolve 纯函数、只在 Enter 提交），却在 **Graph 游标** 上漏了——`_currentNodeId` 有两个写入点。
框架级修复 = 把「谁是真相、谁能推进、谁能消费」写成**单点契约**，让 Graph 游标退化为 `CurrentStage` 的**派生量**。

## 二、根因归纳

> **病根不是「Late 窗 0.5s 太长」，也不是「NormalRoute 没 CD」。**
> 病根是：**Graph 游标被允许在 Resolve 阶段写入，从而脱离了唯一时间源（在播 Stage）。**

154.2 的三条 Fix 本质都是在「**手动把这 5 个当前重新对齐**」：

- 延迟游标 = 让 #1 不在 Resolve 写；
- Late 锚点 = 让 #2 不继承 #1 误差；
- 解析绑 Stage Action = 让 #3 改从 #4 推导。

方向对，但只要 `_currentNodeId` 仍是「可被多处独立写入的一等状态」，下一个功能（取消技、派生技、空地衔接、Boss 阶段）就会再制造第 6、第 7 个「当前」。**必须从契约上消灭「多个当前」这件事本身。**

## 三、3A 战斗流转契约（七条铁律 → 本项目落点）

> 改编自 155.1 七原则，逐条绑定到本仓库的真实类型 / 方法。

### 铁律 1 — 唯一时间锚点：`CurrentStage`

- **唯一真相** = 当前正在执行的 `SkillRouteRuntime.Stage`（`ActiveRoute.Stage`）。
- 其余全部**派生**，不得独立存储为「可被外部写」的状态：

```
CurrentStage (唯一真相, Action 生命周期驱动)
   └─► CurrentAction = CurrentStage.Definition.Action
          └─► CurrentNode  = Data.TryFindNodeIdByAction(CurrentAction)
                 ├─► ResolveNode    = CurrentNode（+Late 缓冲，见铁律 4）
                 └─► LateWindowNode = CurrentNode
```

- **禁止** `Node → Action → Stage` 的反向推导（155.1 第七原则）。

### 铁律 2 — Graph 只描述，不驱动时间

- `CombatGraph.Resolve(node, intent)` 是**纯查询**：返回 `TargetRoute` / `Pending`，**绝不写 `_currentNodeId`**。
- 删除 `ApplyEdgeCursorAfterPick` 对 `_currentNodeId` 的写入；该方法降级为「产生 PendingTransition + 打 Flow/Interrupt Log」。

### 铁律 3 — 唯一推进点：`BindEntryAction`（Enter 时刻）

- `_currentNodeId` **有且只有一个写入者**：`BindEntryAction`（由 `NotifyRouteEntered` 调用）。
- 与本项目 Combo `CommitAdvance` 的位置**完全一致**——把 Graph 游标拉到和段位提交同一时刻。
- Interrupt 边的 `_skipNextBindEntryActionCursor` 语义保留（Interrupt 进 End，不前移连招游标）。

### 铁律 4 — Late Window 只缓存 Intent，不解析、不前移

- Late 窗口期内：缓存的是 `GameplayIntent`（Attack / Dodge…），**不是** ComboB/ComboC。
- 解析仍在 `Resolve` 时按 `CurrentStage` 决定目标（155.1 第四原则）。
- `_lateWindowNodeId` 必须 = 段结束那一刻的 `CurrentNode`（即在播 Stage 的节点），不是 pick 后的游标。

### 铁律 5 — Intent 队列存意图，不存 Action / Node

- 缓冲层永远存 `Attack / Dodge / Jump` 等**物理意图**（本项目 `GameplayIntent.Kind` + `Semantic`）。
- **禁止**把 `ComboB`、`ActionC` 这种「未来 Route/Node」入队（155.1 第三原则）。这正是连点 A→C 的来源。

### 铁律 6 — 三条时间线显式分离

| 时间线 | 含义 | 本项目锚点 | 禁止混淆 |
|---|---|---|---|
| **Input Time** | 玩家按键 | `InputSnapshot` / Semantic 入队 | ≠ Enter |
| **Resolve Time** | 消费输入、查 Graph | `TryResolveForIntent` / `TryResolveContextual` | 此处**只**产生 Pending |
| **Enter Time** | 真正切段 | `NotifyRouteEntered` → `BindEntryAction` | **唯一**可写 CurrentStage/Node |

### 铁律 7 — Graph Edge 无状态

- `CombatFlowCompiledEdge` 保持纯静态数据（已是 struct，无 `Pending/LateConsumed` 字段，✅ 现状达标）。
- 所有运行时状态只存在 `CombatGraphRunner`，且按铁律 1 尽量派生而非独立存储。

## 四、目标运行链（统一后）

```
Input ─►Intent Queue ─►Resolve ─►PendingTransition ─►Enter ─►CurrentStage 更新
  │          │            │              │               │            │
玩家按键   存 Attack    查 Graph      记录"下一段是谁"  BindEntryAction  派生 CurrentNode/
          (不存Node)   (纯查询)       (不改任何 Current) (唯一推进点)     ResolveNode/LateNode
```

- **A→C 跳段**：不可能再发生——第二次 Attack 时 `CurrentStage` 仍是 ComboA（B 还没 Enter），Graph 永远 `Resolve(ComboA, Attack)=ComboB`。
- **AAAA / 整段重开**：Idle 才 Fallback Entry；连点期间 `CurrentStage` 非空 → 只能走 chain，不会反复起手。
- **环 / 双 Combo / 取消技**：见第六节，全部只是 `Resolve(CurrentNode, Intent)` 返回不同目标，时间仍由 Stage 推进。

## 五、落位计划（遵循 09，分 N 次通电；先设施后握手）

> 同一迭代只开 1 个切片；每个 Landing 只通 1–2 站，留可观测 Log 对照 154.1。

### Landing 1/4 — 消灭 Graph 游标的「第二写入者」（核心，治 A→C）

**设施表**

- `CombatGraphRunner` 新增 `PendingTransition`（`{ string ToNodeId; CombatFlowEdgeKind Kind; SkillRouteDefinition Route; }`）。
- 保留 `_currentNodeId`，但**收敛为只读派生 + 单写**。

**握手表**

| 通电点 | 上游 | 下游 | 状态 | 验收 Log |
|---|---|---|---|---|
| 取消 Resolve 写游标 | `ApplyEdgeCursorAfterPick` | `_currentNodeId` | WIRE | 不再出现 `FLOW advance cursor` 早于 `BindEntryAction` |
| 唯一推进 | `NotifyRouteEntered` | `BindEntryAction`→`_currentNodeId` | WIRE | `BindEntryAction Combo_B node ComboA→ComboB` |

**改动**：`ApplyEdgeCursorAfterPick` 删除 `_currentNodeId = e.ToNodeId`，改为记录 `PendingTransition`；游标只在 `BindEntryAction` 落地。

### Landing 2/4 — 解析锚点改为「在播 Stage.Action 推导」（治游标超前残留）

**握手表**

| 通电点 | 上游 | 下游 | 状态 | 验收 Log |
|---|---|---|---|---|
| ResolveNode 派生 | `ActiveRoute.Stage.Definition.Action` | `GetResolutionNodeId` | WIRE | `RESOLVE node=<在播Action节点>`；若与 `_currentNodeId` 不符打 `CURSOR_LAG` |

**改动**：`GetResolutionNodeId` 在 `ActiveRoute != null` 时优先 `Data.TryFindNodeIdByAction(ActiveRoute.Stage.Definition.Action)`，与 `_currentNodeId` 不一致仅作诊断 Log，不再以游标为准。

### Landing 3/4 — Late Window 锚点 = 段结束节点 + 只缓存 Intent

**握手表**

| 通电点 | 上游 | 下游 | 状态 | 验收 Log |
|---|---|---|---|---|
| Late 锚点 | 段结束时 `CurrentNode` | `_lateWindowNodeId` | WIRE | 不再出现 `LATE open node=ComboB` while stage=ComboA |

**改动**：`TryOpenLateWindow` 用「在播 Stage 的节点」开窗，而非 pick 后游标；窗口期仅缓存 `GameplayIntent`，解析时再按 `CurrentStage` 决定 Route。

### Landing 4/4 — Validator 环检测（自动边环 = Error，输入边环 = Allowed）

**握手表**

| 通电点 | 上游 | 下游 | 状态 | 验收 |

## 六、环 / 双 Combo / 取消技 / 空地衔接（统一解释）

按契约，这些**不是特例**，只是 `Resolve(CurrentNode, Intent)` 返回不同目标 + 不同推进事件：

| 场景 | Graph（可能性） | 推进事件（时间） |
|---|---|---|
| 连招环 A→B→C→A | `OnInput` 边构成环（**合法**） | 每段 Attack Intent + Stage Exit |
| 双 Combo（地/空） | 地链 + 空链 + JumpCancel/Land 边 | `Jump Intent` / `Land Event` |
| 取消技 | A 上挂 `Dodge→Dodge` Interrupt 边 | Dodge Intent（窗口内）+ BindEntryAction |
| 派生技 | `CurrentNode + Skill Intent → Derivative` | Skill Intent + Enter |
| Boss 阶段 | 阶段节点 + 条件边 | 阶段事件（HP 阈值）驱动，**非**游标自走 |

**唯一禁止**：纯 `OnSegmentComplete` 自动边构成环（无 Intent）→ 死循环 → Validator 必须拦（Landing 4）。

## 七、验收 Log 对照（修后必须 / 必不出现）

**必须出现（健康连招）**

```text
RESOLVE node=ComboA in=LM → edge→Route_B          # Resolve 不改 Current
BindEntryAction Combo_B node ComboA→ComboB         # 唯一推进点
RESOLVE node=ComboB in=LM → edge→Route_C           # 锚点来自在播 ComboB
BindEntryAction Combo_C node ComboB→ActionC
```

**必不出现（时间线分裂的特征）**

```text
FLOW advance cursor ComboA→ComboB ...   （出现在 BindEntryAction 之前）
LATE open ... node=ComboB                （而 stage 仍 = Combo_A）
RESOLVE ComboA→B 紧接 RESOLVE ComboB→C    （中间无 ComboB 的 BindEntryAction）
DUAL_GATE block node=ActionC ... stage=Stage_Combo_A action=Combo_A
```

> 若仍出现 `CURSOR_LAG`（Landing 2 新增诊断），说明还有第三处在写游标，按铁律 3 收敛。
