# 170.4【精讲总结】Graph 连段最后一招无法退出到 Idle —— 根因 / 误诊临时方案 / 当前代码正解

> 现象：`Route_Normal_Combo_C` 末招 `General_Armature_Sword_Attack_Combo_C_ActionData` 播完后角色卡在 Combo_C 末帧姿态，不回 Idle；继续按 LM 表现为"卡住 / 又从头起手 Combo A"。
>
> 关联资料：[170.1 BUG 描述]、[170.2 Log 一轮]、[170.2 v2 改进 Log]、[170.3 第二轮 Output]、[169.1 系统性修复蓝图]

---

## §1 现象时序还原

```
玩家 LM → A → 等命中 → LM → B → 等命中 → LM → C （末招）
                                                     ↓
                                       动画播完 nt=1.0
                                                     ↓
                                       ❌ 角色保持 Combo_C 末帧
                                       ❌ 不回 Idle / 不回 Locomotion
                                                     ↓
                                          再按 LM → 表现"卡住" / "再从 A 起手"
```

**症状链特征**：
1. 末招动画看似播完，但 FSM 仍在 `PlayerActionState`
2. Console 在 [Action][Exit] 上**每帧刷屏**（frame 5138 → 5143 连续 6 帧重复）
3. 后续按 LM 必走 `MISS node=End` → `ENTRY_FALLBACK` → 重新从 Combo A 起手

---

## §2 根因（H8 —— 最终确认）

### §2.1 触发四要素

末招进入凝滞需要**同时**满足：

| 要素 | 描述 |
|---|---|
| ① 走 **CombatGraph** 路由（不是 MultiStage） | Graph 三连每段是独立 `NormalRoute`，Stage 在 0.5s 已 `IsActive=false`，但 Clip 要到 nt=1.0 才结束 |
| ② **空中起手**（`m_startedWhileAirborne = true`） | 触发末段 `ExitToBaseline` 走的是 **JumpLand 分支** |
| ③ JumpLand 分支用 `Change<PlayerActionState>()` | **FSM 同状态切换被直接忽略**（见 `StateMachine.Change` 注释） |
| ④ 没有 `m_exitDispatched` 单次保护 | 每帧 `gatePass=true` 都会再调一次 `ExitToBaseline` |

### §2.2 死循环成因

```
PlayerActionState.OnLogicUpdate (frame N)
    ├─ Route 已 IsActive=false（半秒前就结束了）
    ├─ Action nt = 1.0 ✓
    ├─ gatePass = true
    └─ ExitToBaseline(player)
            └─ takeJumpLandBranch = true（旧逻辑）
                    └─ player.States.Change<PlayerActionState>()
                            └─ StateMachine: 同状态忽略 ❌
                            └─ ArmPendingAction(JumpLand) 永远进不了 OnEnter
                            
─── 下一帧 ───
PlayerActionState.OnLogicUpdate (frame N+1)
    └─ gatePass 仍 = true   ↑
    └─ ExitToBaseline 再触发 ↑
        ... 无限循环，每帧刷 [Action][Exit]
```

### §2.3 为什么 MultiStage 同动作能正常退出

**不是路由系统差异，是退出分支不同**：

| 起手地点 | `m_startedWhileAirborne` | 走的分支 | 切换 |
|---|---|---|---|
| 地面起 LM 三连（MultiStage 或 Graph） | false | `Change<PlayerLocomotionState>()` | ✓ 状态不同 → 切换成功 |
| **空中起 LM 三连（Graph）** | **true** | `Change<PlayerActionState>()` JumpLand 自插 | ❌ 同状态被忽略 |

## §3 误诊轨迹（重要 —— 避免下次再上当）

### §3.1 第一轮误诊（170.2 v1）：H1 — graph-only 未 NaturalExit

**初始判断**：观察到 `ActionC_Action → End` 是 `OnSegmentComplete` 且 `TargetRoute=null` 的 graph-only 边；推进游标到 `End` 但**未调 `NotifyRouteNaturalExit`** → 怀疑缺 Idle 握手。

**临时方案**：在 `SkillEntryService.TryAdvanceCombatFlowOnSegmentComplete` 的 graph-only 分支补一行：

```csharp
case CombatFlowResult.GraphOnly:
    _combatGraph?.NotifyRouteNaturalExit(exitingAction);   // ← 临时方案
```

同时收紧三处诊断噪声：
- `STALL-SUSPECT` 仅在 `!gatePass` 时打
- `EXIT-GATE` dedup 去掉 nt（同动作只一条）
- `STAGE-DONE` 仅 Route 刚变 inactive 打一次

**为什么 H1 不是主因（170.3 揭穿）**：
资产里 `Route_Normal_Combo_C.IdleNodeId = End`，**`End` 本身就是 Idle 节点**。补的 `NotifyRouteNaturalExit` 本质只是把游标从 `End` "推进"到 `End`（自环 no-op），**行为未变**。

> ⚠️ **误诊教训**：上 Log 看到 "GRAPH-ONLY 后无 NATURAL-EXIT"，**直接假设 = "缺 NaturalExit"**。但没核对资产 IdleNodeId 配置。真正应做的是先 dump `route.Definition.IdleNodeId` 比对 graph-only 终点。

### §3.2 误诊为何"看起来生效"

第一轮修复后**地面三连**完全正常 —— 但**地面起手本来就走 Locomotion 分支**（§2.3 表），跟 H1 修不修都无关。当时只测了地面，没复现空中起手 → 误以为问题解决。

### §3.3 第二轮诊断（170.2 v2）：H8 真相浮出

加 `[CombatGraph][Finisher]` 独立通道 + `BASELINE-EXIT branch=JumpLand|Locomotion forceReenter=…` 新探针后，**专测空中起手末招**，立刻看到：

```
EXIT-GATE pass=True
EXIT-FIRED                              ← gatePass 通过
（无 BASELINE-EXIT）                    ← Action 退出"成功"了
[Action][Exit] frame=5138               ← 但下一帧又触发
[Action][Exit] frame=5139               ← 每帧重刷
[Action][Exit] frame=5140
[Action][Exit] frame=5141
...
```

`EXIT-FIRED` 打了但 `BASELINE-EXIT` 没出 → 说明 `ExitToBaseline` 内部的 `Change<PlayerActionState>()` 被 FSM 吞了。

## §4 当前代码正解（已落地，**两层修复**）

### §4.1 第一层（170.3）：症状级补丁

**`PlayerActionState`** 增加 `m_exitDispatched` 单次退出闸门：

```csharp
// PlayerActionState.cs:22
bool m_exitDispatched;

// OnEnter 复位
protected override void OnEnter(Player player) {
    m_exitDispatched = false;
    ...
}

// OnLogicUpdate:305 — 关键守卫
if (gatePass && !m_exitDispatched)
{
    m_exitDispatched = true;
    var exitReason = routeEnded ? "RouteEnded" : "LastStageComplete";
    CombatGraphFinisherDiagnostics.LogActionExitFired(player, m_action, exitReason);
    ...
    ExitToBaseline(player);
}
```

> 这步保证**即使 `Change` 被吞，下一帧也不会再触发**第二次 `ExitToBaseline`；同时为下一层正解准备结构。

### §4.2 第二层（169.1 系统性正解）：删除 takeJumpLandBranch

**核心契约**（资料 169.1）：

> **"Graph 的游标到 End 就是回到 Idle 的意思"** —— Action 退出层不允许隐式注入 JumpLand 打断。

**`ExitToBaseline`** 现行实现（[PlayerActionState.cs:592-626](3_Gameplay/Characters/Player/States/PlayerActionState.cs:592)）：

```csharp
void ExitToBaseline(Player player)
{
    // 169.1 系统性修复：Action 退出层一律回 Locomotion。
    //   后续接地判定 → Idle / Airborne / JumpLand 全部由 FSM 标准链处理：
    //     · Locomotion.OnLogicUpdate 见 !IsGrounded → Change<PlayerAirborneState>
    //     · PlayerAirborneState.TryExitToLandOrLocomotion 是 JumpLand 唯一合法触发点
    //   "Graph 游标到 End = 回 Idle" 的语义不再在 Action 退出层被隐式注入打断。
    //   旧 takeJumpLandBranch 强插 JumpLand 已删除（详见 169.1 蓝图）；
    //   LocomotionGraphContext.JumpLand 字段仅保留作 Combat Graph 编辑期合法上下文池（165.1 §14 契约）。
    
    if (player.DebugLocomotion) { /* 诊断日志 */ }
    
    // 迁移提示
    if (m_startedWhileAirborne && player.IsGrounded
        && m_action.IntentCategory == ActionIntentCategory.Combat
        && player.DebugSkillRoute)
    {
        Debug.Log($"[CombatGraph][Finisher] 169.1-NOTE Combat 空中→落地结束 action={m_action.name} —— " +
                  $"如需软着陆请在 Combat Graph 加显式 Flow 边到 JumpLand Action，不再依赖 ExitToBaseline 隐式插入。");
    }
    
    CombatGraphFinisherDiagnostics.LogActionBaselineExit(player, m_action, jumpLandBranch: false, forceReenter: false);
    player.States.Change<PlayerLocomotionState>();    // ★ 唯一出口
}
```

### §4.3 修复后的退出链（**单一路径**）

```
PlayerActionState 末段播完
    ↓ gatePass=true 且 m_exitDispatched=false
m_exitDispatched = true
ExitToBaseline(player)
    └─ Change<PlayerLocomotionState>()           ← 一律走 Locomotion
            ↓
PlayerLocomotionState.OnEnter
    ├─ IsGrounded=true  → 选 Idle / Walk / Run（按 WantsRun + 输入）
    └─ IsGrounded=false → Change<PlayerAirborneState>()
                                ↓
                    PlayerAirborneState.TryExitToLandOrLocomotion
                                ↓
                    地面 → JumpLand Action（唯一合法触发点）
                    空中 → 保持 Airborne
```

**关键改善**：
- ✅ 同状态切换问题**结构性消失** —— ExitToBaseline 永远切到不同状态
- ✅ JumpLand 只有一个合法触发点（PlayerAirborneState）—— 不再有"动作退出层悄悄插一脚"
- ✅ Action 退出语义**单一**：游标到 End = 回 Locomotion，后续由 FSM 标准链分流

### §4.4 配套诊断系统（保留作监控）

| 文件 | 作用 |
|---|---|
| `CombatGraphFinisherDiagnostics.cs` | 独立 `[CombatGraph][Finisher]` 通道，trace 会话 + dedup |
| `SkillRouteDebug.LogFinisher` | 新 API |
| `PlayerLocomotionState.OnEnter` | `TRACE-END outcome=Locomotion` 收尾事件 |

诊断标签（精简后）：

| 标签 | 含义 |
|---|---|
| `TRACE-BEGIN` / `TRACE-END` | 末段 Trace 会话起止（含 outcome） |
| `STAGE-DONE` | Route IsActive 翻转一次性事件 |
| `SEGMENT-END` | `GRAPH→ENTER` vs `GRAPH-ONLY` 分叉 |
| `NATURAL-EXIT` | `IDLE` / `LATE-OPEN` |
| `EXIT-GATE` | `pass=True/False`（同动作 dedup） |
| `EXIT-FIRED` | 真正切 Locomotion |
| `BASELINE-EXIT` | `branch=Locomotion forceReenter=false`（169.1 后恒为此值） |
| `STALL-SUSPECT` | 仅 `!gatePass` 时报；已修后不应出现 |

## §5 三句话沉淀

> 1. **死循环的真正成因不是"缺一步"，而是"两个看起来无关的弱点叠加"** —— Change 同状态被吞 × 缺 m_exitDispatched 单次闸 = 每帧重触发
> 2. **症状级修复（170.3）** 让 bug 不再表征，**系统性修复（169.1）** 才让它结构上不可能重现 —— 两层都重要
> 3. **任何 "Action 退出层悄悄插一个状态"的设计都是反模式** —— FSM 状态切换必须由该状态本身负责，跨层注入 = 同状态切换风险

## §6 防再犯检查清单

| 检查项 | 检查方法 |
|---|---|
| **任何 `Change<T>()` 是否可能 T == 当前状态？** | 必须用 `ForceChange<T>()` 或上层加 dispatched 闸 |
| **退出函数是否每帧可能重复触发？** | 加 `m_xxxDispatched` 单次标志 + `OnEnter` 复位 |
| **Action 退出后的 FSM 后续状态有"分支决策"吗？** | 决策必须在**下一个 State 的 OnEnter** 内做，不在退出函数里隐式插入 |
| **Route IdleNodeId 是否就是 End？** | 修 graph-only 相关 bug 前**必须 dump 一次**比对，否则等于自环 no-op |
| **测试覆盖空中起手末招？** | 地面起手不能完全代理空中起手，FSM 退出分支不一样 |
| **JumpLand 是否仅有 PlayerAirborneState 一个触发点？** | grep `Change<PlayerActionState>.*JumpLand` 应仅返回 1 处 |

## §8 验收方式

**地面三连 LM**：
```
[CombatGraph][Finisher] TRACE-BEGIN action=Combo_C
[CombatGraph][Finisher] EXIT-GATE pass=True
[CombatGraph][Finisher] EXIT-FIRED reason=RouteEnded
[CombatGraph][Finisher] BASELINE-EXIT branch=Locomotion forceReenter=false
[CombatGraph][Finisher] TRACE-END outcome=Locomotion
```
应 ≤ 12 行；角色干净回 Idle / Walk / Run。

**空中起手、落地打完 C**：
```
（同上前 4 行）
[CombatGraph][Finisher] BASELINE-EXIT branch=Locomotion forceReenter=false
                                              ↑ 169.1 后恒为 Locomotion
[CombatGraph][Finisher] 169.1-NOTE Combat 空中→落地结束 …
[CombatGraph][Finisher] TRACE-END outcome=Locomotion
```
然后由 `PlayerAirborneState.TryExitToLandOrLocomotion` 接管，**若需软着陆**请在 Combat Graph 加显式 Flow 边到 JumpLand Action（不再依赖隐式注入）。

**再按 LM**：不应再出现 `MISS node=End` + `ENTRY_FALLBACK`；从 Idle 干净走 Combo A 起手。
