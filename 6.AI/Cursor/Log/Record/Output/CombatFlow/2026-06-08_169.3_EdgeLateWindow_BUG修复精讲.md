# 169.3 Edge Inspector · LateWindow 切边残留 — BUG 修复精讲

## 一、现象（用户语言）

| 操作 | 期望 | 实际（修复前） |
|---|---|---|
| Edge A 改 LateWindow，**不按 Enter**，点 Edge B | B 显示自身 `metaLate` | B 仍显示 A 正在编辑的文本 |
| 按 Enter 再切边 | 正常 | 正常 |
| 关闭 Graph 重开 | — | 才看到真实值（meta 其实一直是对的） |

用户诉求：**与 Unity 原生 Inspector 一致 — 失焦/切选即提交，不要求 Enter。**

---

## 二、一句话根因

> **不是 meta 没写对，而是 IMGUI 在切边后仍持有上一条 Edge 的 TextField 编辑态；Layout 又提前更新了 `s_lastEdgeGuid`，导致同帧 Repaint 不再清焦点。**

Log 铁证（169.3 第一次 Log）：

```
SWITCH 95c24e7e→9322f49a metaLate=2.000 focusCleared=False editingTF=True
STALE-FOCUS drawing=9322f49a stillFocused=CombatFlow.LateWindow.95c24e7e…
```

- `metaLate=2.000` 正确 → **数据层无 bug**
- `stillFocused=…95c24e7e…` → **UI 层仍绑旧控件**

---

## 三、误诊链（为什么修了三次）

### 168.2 — 部分正确，不够

- `GUI.FocusControl(null)` + `SetNextControlName(GUID)` 防控件 ID 冲突
- **缺陷**：在 `EventType.Layout` 跳过清焦点；且 **Layout 就把 `s_lastEdgeGuid` 更新为新边** → 同帧 Repaint 认为「没切边」，焦点永不释放

### 169.3 方案 A — flush 重绘旧控件

- 切边前先画一次旧边 LateWindow，Repaint 时 `FocusControl` 触发提交
- **缺陷**：Layout 只登记 1 个控件、Repaint 又跑完整 `Draw()` →  
  `ArgumentException: Getting control 1's position in a group with only 1 controls`

### 169.3 方案 B — 仅文本缓存

- `Dictionary<guid, string>` + 切边时 `CommitLateWindowIfDirty`
- **缺陷**：能写 meta，但 **未在同帧 Repaint 清 IMGUI 编辑态** → 报错没了，**显示又回去了**

### 169.3 终态 — 数据 + 显示双轨

| 轨 | 职责 | 关键 API |
|---|---|---|
| **数据轨** | 切走前把缓存文本写入 `meta.Authoring` | `CommitLateWindowIfDirty` |
| **显示轨** | Repaint 清焦点 + 新边显示文本强制对齐 meta | `ClearImguiEditFocus` / `SyncLateWindowDisplayText` |
| **时序轨** | `s_lastEdgeGuid` **仅 Repaint 更新** | 禁止 Layout 提前写入 |

## 四、IMGUI 机制精要（本 bug 为何难）

```
同一帧 Inspector Draw：
  Layout  → 登记控件数量 N
  Repaint → 必须再画 N 个控件，顺序一致

切边时若 Layout 画 flush(1 个) 而 Repaint 画 full Inspector(M 个) → 必崩。

切边时若 Layout 更新 s_lastEdgeGuid=B，Repaint 认为 guid 未变 → 不清焦点 → STALE-FOCUS。
```

Unity 原生 Inspector 用 **SerializedObject + PropertyField**：失焦由序列化系统提交，不依赖「同控件再画一次」。

本 Graph Edge Inspector 用 **`meta.Authoring` struct + 手写 IMGUI** → 必须自己管：**焦点生命周期 + 切选提交 + Layout/Repaint 对称**。

## 五、终态实现要点

### 5.1 文件落点

| 文件 | 改动 |
|---|---|
| `Editor/CombatFlow/CombatFlowGraphEdgeInspector.cs` | LateWindow 字段、文本缓存、焦点清、Draw 时序 |
| `Editor/CombatFlow/CombatFlowGraphWindow.cs` | 切边/切节点/选区变化时 `Commit` + `ClearImguiEditFocusForSelectionChange` |
| `Editor/CombatFlow/CombatFlowGraphInspectorDiagnostics.cs` | 事件-only 诊断（可选） |

### 5.2 控件约定

```csharp
// 每条边独立 controlName，防 ID 冲突
GUI.SetNextControlName("CombatFlow.LateWindow." + edgeGuid);
EditorGUILayout.TextField(...);  // 非 DelayedFloatField：每帧回写缓存字符串
```

### 5.3 切边时序（正确顺序）

```
GraphView 点 Edge B
  → CommitLateWindowIfDirty(A)     // 数据：缓存 → meta
  → ClearImguiEditFocusForSelectionChange()  // 标记下帧 Repaint 清焦点
  → CommitEdge(B)

Inspector Draw (Edge B)
  → Repaint: ClearImguiEditFocus()
  → CommitLateWindowIfDirty(A)     // 兜底（Draw 内 prevGuid）
  → Repaint: s_lastEdgeGuid = B; SyncLateWindowDisplayText(B, metaLate)
  → 绘制 B 的 TextField（显示 meta，无 STALE 缓存）
```

### 5.4 三条硬规则（以后同类 Editor bug 对照）

1. **Layout 阶段不要改 `s_lastEdgeGuid` / 不要 `FocusControl`（除非整帧控件对称）**
2. **切选对象前：先提交旧对象编辑态（数据），再在 Repaint 清焦点（显示）**
3. **Log 只打事件（SELECT / SWITCH / SAVE-LATE），禁止 Draw 每帧刷屏**（169.3 教训）

## 七、面试口述版（30 秒）

Combat Flow Graph 的 Edge Inspector 用 IMGUI 编辑 struct 字段。用户不切 Enter 就点另一条边时，Unity 仍保持上一条 TextField 的 **editingTextField 内部缓存**，而 Inspector 已经开始画新边；加上我们在 Layout 提前更新了 last GUID，Repaint 不会释放焦点，造成 **meta 正确、UI 显示错**。修复是 **切边前文本缓存写 meta + Repaint 才更新 last GUID 并清焦点 + 新边强制 sync 显示文本**，并避免 flush 重绘导致的 Layout/Repaint 控件数不一致。
