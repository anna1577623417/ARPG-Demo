# 为什么不绑 Entry

例如：

```text
Space
 ├─ Attack
 ├─ Roll
 ├─ Skill
```

如果 Ability 挂 Entry：

```text
Attack
 ├─ ComboAbility
 ├─ CancelAbility
```

问题来了：

---

轻攻击A

```text
Attack_A
```

有 Combo

---

重攻击

```text
Attack_Heavy
```

没有 Combo

---

蓄力攻击

```text
Attack_Charge
```

有霸体

---

升龙

```text
Attack_Shoryuken
```

有浮空

---

结果：

```text
Attack
```

这个入口下面的 Ability 已经无法描述了。

因为：

```text
同一个入口
不同Route
能力完全不同
```

---

所以：

```text
Entry
```

太粗。

能力天差地别。

## 136.3 验收结论（代码修复后）

### 四向闪避 — 选路层（Slice 已跑通）

| 验收项 | Log 证据 | 结论 |
|--------|----------|------|
| F/B/L/R 各命中对应 Route | `PICK … chord=Forward/Backward/Left/Right` + `RESOLVED … Standing Dodge *` | **通过** |

### Bug1 — A/D 体感像前后（根因：Motion 参考系，非选错 Route）

- Log 中 Left/Right 的 `deltaLocal` 以 **X 为主、Z≈0**，与资产曲线一致（Left 为负 X）。
- `MotionExecutor` 将局部 `(x,y,z)` 映射为：`right*x + forward*z`，其中 `forward` 来自 `PlayerActionState` 的 `GetMovementDirectionOrForward()`。
- 按 A 时移动意图为 **左**，`forward≈左`，此时局部 **X 轴等价于角色「前后」**（Cross(up,左)=前），故左右闪避在体感上像前后位移。
- **修复（136.3+）**：`MotionProfileSO.MotionSpace`（去掉 MovementIntent）— 四向闪避默认 **`CameraForward`**：局部 Z 沿镜头水平前向，S+Space 后撤时 **角色面朝可不变**；与 `MovementIntent`/Locomotion 转身解耦。菜单：`Tools/Motion/136.3 Wire C1 Dodge MotionSpace = CameraForward`。

### Bug2 — 空中仍可空格闪避（根因：准入未挂在 Tap 选路 + Context 回落 PrimaryGroup）

| 问题 | 原因 |
|------|------|
| `AbilityMap` 仅对 `semantic=Directional` 校验 | 实际多为 `semantic=Tap` + chord |
| ContextGroup `requireDirectional` | Tap 不匹配 → 回落 `PrimaryGroup`，地面 Context 失效 |
| Loadout 槽位绑定 | 与「按 Route 描述能力」不一致 |

- **修复（136.3）**：
  1. `SkillRouteDefinition.abilityGateRules[]` — 准入挂在 **Route**；`TryPickGroupRoute` / `PrimaryRoute` 在 `CanCast` 前调用 `AbilityGateService.CanActivateRoute`。
  2. `SkillContextGroupDefinition` — `requireDirectional` 时同时接受 **Tap/None**（和弦选路）。
  3. Loadout 存在匹配 slot 的 ContextGroup 候选但 **无一命中** 时，**禁止** 回落 `PrimaryGroup`（`ContextGroup DENY no match`）。
  4. C1：`AbilityMap`  bindings 清空；`AbilityGateRule_MobilityGrounded` 绑到四条 Dodge Route。
