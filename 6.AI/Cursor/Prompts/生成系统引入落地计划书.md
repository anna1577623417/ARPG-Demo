## 必读约束（违反则计划无效）

在生成计划前，内化以下项目规则与经验（若用户 @ 了文件，以用户资料为准并与之对齐）：

1. **单轨**（`.cursor/rules/07-single-track-migration.mdc`）  
   - 运行时只有一条权威路径；禁止 `if (legacy)`、`UseXxxRuntime`、长期 `allowFallback`。  
   - 旧 API / 旧 SO 仅出现在 Editor 迁移工具，不进 `Update` / 主状态机。  
   - 回滚靠 **git tag**，不靠 Feature Flag。

2. **两层 Done**（`.cursor/rules/09-refactor-delivery-protocol.mdc`）  
   - **Landing Done（单次落位）**：设施已就位 + 本落位握手表 WIRE 行已接 + 边界可观测 Log；**允许玩法未正确**。  
   - **Slice Done（切片闭环）**：经 N 次 Landing 后，Play Mode 最小验收通过；剩余仅限参数/资产/时序微调。  
   - 核心隐喻：**设施搭好，差握手通电** — 禁止用 fallback 假装通电。

3. **禁兜底修 Bug**  
   - 禁止无契约的 `block fallback`、`COERCE` 与另一层 `REJECT` 打架、在错误生命周期判结算/末段。  
   - 每个可配置时机枚举 → **唯一 public 入口**；状态 **单点写入、他层只读**。

4. **经验总结**（`6.AI/Cursor/Output/Refactor/2026-05-17_SkillRoute重构经验教训.md`）  
   - 连带面：SO Inspector、Editor 枚举、HUD/Presenter、EditMode 测试须纳入切片或明确 OPEN。  
   - WIP：同一迭代最多 **1 主切片 + 1 附属切片**。  
   - 一次落位只动 **一层握手面**；PR 类型不混（契约 / 接线 / 资产Editor / 修bug 分开）。

5. **Unity 工程卫生**  
   - `[Tooltip]` 不用内嵌英文双引号，用【】或「」。  
   - 改签名全仓 grep；子类钩子用 `protected`；避免作用域重复声明。

## 你的输出：落地计划书

用**中文**输出一份 Markdown《落地计划书》，结构**必须**包含以下章节（不可省略、不可合并为散文）。

### 0. 元信息

| 项 | 内容 |
|----|------|
| 计划名 | |
| 切片名 | |
| 总 Landing 数 N | |
| 最早 Play Mode 验证 | 第几次 Landing |
| 关联 Rule | 07 / 09 / 域内 Rule |
| 建议 git tag | |

### 1. 目标与诚实边界

- **架构目标**（3 条以内）  
- **本计划不解决什么**（明确列出，防止范围蔓延）  
- **与资料/蓝图的差异**（若资料过大，说明本计划裁剪了哪些 Phase）

### 2. 垂直切片策略

- **主切片** + **附属切片**（若有）  
- **推荐落地顺序**（编号列表；说明为何此顺序能最快验证）  
- **依赖关系简图**（ASCII 或 Mermaid，展示数据/调用主链）

### 3. 设施表（Slice 结束前必须存在）

表格列：**设施项 | 类型/路径 | 所属层级(1_Core~5_Presentation) | 由哪次 Landing 创建 | 备注**

### 4. 握手表（全切片通电清单）

表格列：**通电点 | 上游 | 下游 | Landing k/N | 状态 WIRE/OPEN | 通电成功验收 Log | 断点未通时预期 Log**

要求：

- 每一行对应一个可观测握手点；  
- OPEN 行须写「故意延后」原因；  
- Log 前缀与项目管线一致（例 `[Semantic]` `[Resolve]`），禁止模糊 `Debug.Log("here")`。

### 5. 契约表（仅当涉及时间/状态/结算/优先级时）

表格列：**契约项 | 唯一真相 API/字段 | 谁写入 | 谁只读 | Inspector/配置对应（若有）**

若存在「配置面 → 运行时锚点」：单独子表列出，并注明是否与某次 Landing 同 PR 修改 Editor。

### 6. Landing 明细（核心：Landing 1 … N）

对每个 Landing 重复以下子结构（**每个 Landing 独立一小节**）：

#### Landing k/N：{短标题}

- **本落位目标**（Landing Done 判定句）  
- **WIRE 行**（引用握手表行号或点名）  
- **OPEN 行**（本落位不接，留待后续）  
- **设施增量**（本落位新建/修改的类型与文件，含**删除**的旧文件）  
- **禁止在本落位做**（防伤筋动骨）  
- **改动文件清单**（路径 + 一句话职责）  
- **可观测**（新增/复用的 Log 类别或 Debug 开关）  
- **验证步骤**（≤5 步：如何进 Play Mode、按什么键、看到什么 Log；允许断在哪一站）  
- **通过标准**（Landing Done checklist，勾选项）  
- **常见失败与通路修复**（按 09 规则：先握手表定位，再上下游接线，禁止 fallback）  
- **风险与回滚**（本落位若失败，tag 回滚点）

### 7. Slice 闭环验收（仅 Slice Done 使用）

- Play Mode **60 秒**操作脚本（步骤化）  
- **必须出现**的 Log / 行为（3～5 条）  
- **不得出现**的 Log / 行为（3～5 条）  
- EditMode 测试项（若有，与运行时 Log 对齐）

### 8. 单轨与删除清单

- **主循环将删除的旧调用点**（文件/方法级）  
- **grep 验收关键词**（旧类型名应为 0 命中）  
- **Editor/HUD 同步项**（枚举、Tooltip、Presenter）

### 9. PR / 提交切分建议

表格：**PR 序号 | 对应 Landing | 类型(契约/接线/资产Editor/修bug) | 预估范围 | 禁止混入**

### 10. 禁止模式自检

对照经验总结，列出本计划**已规避**与**需人工盯防**的项（双轨、兜底 fallback、Enter 判 last、Resolver/Service 双写状态等）。

### 11. 未决问题（需用户确认）

编号列出；**不得**用「实现时再定」搪塞架构分叉项。
