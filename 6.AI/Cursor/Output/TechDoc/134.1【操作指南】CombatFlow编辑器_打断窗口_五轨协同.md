# 134.1 操作指南：Combat Flow 编辑器 · 打断窗口 · 五轨协同

> 整合来源：`137.1`（StateTag / 打断 / 流转分层）+ `147.1`（Combat Flow Authoring 终态）  
> 读者：策划配表、程序验收 Play Mode 日志

---

## 0. 先读这三句话

| 系统 | 只回答什么 | 配置在哪 |
|------|-----------|---------|
| **打断（Interrupt）** | 当前 Action 播放中，**此刻**能否被新意图切断 | `ActionDataSO` → `Windows` → `InterruptibleByCategories` |
| **流转（Flow）** | 当前图节点上，**允许提前切到哪条 Route** | `CombatGraphAsset` → 边 `Transition` + `TargetRoute` + `Conditions` |
| **入口（Entry）** | 空闲时按哪个键走哪条 Route | `SkillLoadout` → `Entry_*` → `NormalRoute` / `MultiStageRoute` |

**禁止混用**：在 ActionWindow 里勾 `AllowInterruptBySwordDash` **不会**自动产生 Flow 边；在 Flow 边里写条件 **不会**替代打断窗口。

---

## 1. 整体工作流（从零到 Play Mode）

```
1. 创建/选中 CombatGraphAsset（.asset 已 Save）
2. Loadout_Skill_*.combatFlow 绑定该资产
3. Inspector → Open Graph Editor
4. 填 resource pools + 画布节点 + 连线 + 选边配 Transition
5. Sync && Compile（Graph 窗口或 Inspector）
6. Inspector 显示 compileValid=true + Compiled Flow Preview
7. Play Mode 开 DebugSkillRoute → 看 [Flow] / [Interrupt] 日志
```

**当前 C1 注意**：`Loadout_Skill_C1.combatFlow` 仍为 `{fileID: 0}`，Runner 不会 Attach，Flow 全 OPEN。配完图务必绑 Loadout。

## 2. CombatGraphAsset Inspector（Project 选中 .asset）

### 2.1 顶部操作

| UI | 含义 |
|----|------|
| **Open Graph Editor (GraphProcessor)** | 创建/打开 `*_View` 子资产并弹出 Graph 窗口。**唯一正确入口**（见 §3.2 按钮问题）。 |
| HelpBox「147.1 Combat Flow Authoring」 | 系统摘要：三池 + 编译后 Runner 只读 `CompiledData`。 |
| **compileValid 状态条** | `true` = Play Mode 可流转；`false` = 仅可编辑，运行时不推进。 |

### 2.2 Resource Pools（Default Inspector）

| 字段 | 含义 | 规则 |
|------|------|------|
| **actionPool** | FlowAction 节点可引用的 Action 白名单 | 节点 `Action` 应在此列表；不在则 Validator **Warning** |
| **routePool** | `TargetRoute` / RouteSwitch 可引用的 Route 白名单 | 不在池内 → 编译 **Error** |
| **conditionPool** | 边 `ConditionRefs` 可引用的条件资产池 | 引用不在池 → Graph 边面板 **Warning** |

### 2.3 Flow Graph (Authoring)（序列化镜像，一般由 Sync 写入）

| 字段 | 含义 |
|------|------|
| **nodes[]** | 图节点：`NodeId` / `Kind` / `Action` / `Route` / 位置 |
| **flowEdges[]** | 有向边：from/to、Transition、TargetRoute、Conditions、Priority |

> 手工改 YAML 可以，但推荐在 Graph 窗口编辑后 **Sync && Compile**。

### 2.4 Compiled Runtime

| 字段 | 含义 |
|------|------|
| **compiledData** | 运行时 `CombatGraphRunner` **唯一**读取的数据 |
| **compileValid** | 上次编译是否通过 Validator |
| **lastCompileReport** | 错误/警告全文 |

### 2.5 Inspector 底部按钮

| 按钮 | 行为 |
|------|------|
| **Validate** | 只校验，不写 compiledData |
| **Validate && Compile** | Push 画布 → Validator → 写 compiledData |
| **Compiled Flow Preview** | 编译成功后列出每条边 `pri / from→to / Transition / TargetRoute` |

## 3. Combat Flow Graph 窗口（GraphProcessor 画布）

窗口标题：`Combat Flow — {资产名}`

### 3.1 左上角两个按钮（你截图里红框）

| 按钮 | 作用 |
|------|------|
| **Sync && Compile** | ① 画布 → `CombatGraphAsset.nodes/flowEdges`（PushToAuthoring）② Validator ③ 写 `compiledData` ④ 弹窗报告 |
| **Validate** | 先静默 Sync，再只弹 Validator 报告（不改 compile 结果时仍可能更新 authoring） |

**为何「看起来是按钮但点了没反应」**

| 原因 | 现象 | 处理 |
|------|------|------|
| 从 **Window → Combat Flow Graph** 打开 | `_ownerAsset == null`，旧代码静默 return | **已修复**：现弹 Dialog 说明必须从 Inspector 打开 |
| 未绑定 Loadout / 未 Compile | 按钮有反应但 Play 仍无 Flow | 绑 Loadout + Compile |
| Graph 未 Save | 首次 Open 前资产非 persistent | Ctrl+S 保存 .asset 后再 Open |

**正确打开方式**：Project 选中 `CombatFlow_Player` → Inspector → **Open Graph Editor**。

### 3.2 Flow Edge 面板（画布上方 ~320px）

未选中边时显示：「选中画布上的一条边以编辑 Transition / TargetRoute。」

选中**一条连线**后：

| 字段 | 含义 |
|------|------|
| **Transition** | `OnSegmentComplete` 段自然结束触发；`OnInput` 动作中按键；`Immediate` 编译期占位（慎用） |
| **Edge Kind** | `Flow` 正常流转；`Interrupt` 语义标记（与 Action 打断分层，运行日志区分） |
| **Label** | 调试标签，进 `[Flow]` 日志 |
| **Priority** | 同一 `from` 节点多条出边时 **升序** 求值，先匹配先用 |
| **Target Route** | 命中此边时要 **施放** 的 Route；空 = 只移动图指针不切换 Route |
| **Input Slot** | 仅 `OnInput`：过滤物理槽位（`Shift`/`RM`/…），`Any` 不过滤 |
| **Input Semantic** | 仅 `OnInput`：过滤 Tap/Hold/Charge 等语义 |
| **Conditions (AND)** | 内联 `SkillTransitionCondition` 数组，全部满足才走边 |
| **Condition Assets (AND)** | 引用 `CombatFlowConditionDefinition` 资产，与内联 AND 合并 |
| **Compile preview** | 合并后叶子条件数量 |
| **Edge GUID / Connect** | 调试：边 id 与节点名 |

**Combo 提示**：`OnSegmentComplete` + 指定 `TargetRoute` 若落在某 `ComboRouteDefinition` 子 Route 上，面板会提示该 Combo 的 `AllowFlowSegmentAdvance` 必须为 `true`，否则运行时会 BLOCK。

### 3.3 图节点类型（右键 Add Node → Combat Flow/…）

| 节点 | 颜色 | 端口 | 字段 | 运行时含义 |
|------|------|------|------|-------------|
| **Start** | 绿 | Out | `nodeId`（默认 Start） | 图入口；编译为 `StartNodeId` |
| **Flow Action** | 蓝 | In, Out | `nodeId`, **Action** | 绑定一个 Action；Route 进入时 `BindEntryAction` 按 Action 名对齐到节点 |
| **Route Switch** | 金 | In, Out | `nodeId`, **Route** | 图内标记 Route 切换点（须有 Route 且在 routePool） |
| **End** | 灰 | In | `nodeId`（常用 Idle） | 段结束无匹配边时回到 `IdleNodeId` |

**Node Id 规则**：图内唯一；编译进 `CombatFlowData`；Runner `_currentNodeId` 跟踪位置。

### 3.4 GraphProcessor 自带 UI（非 Combat Flow 语义）

| 元素 | 含义 |
|------|------|
| **Create Note**（黄便签） | 仅注释，不参与编译 |
| **Create Group**（分组框） | 仅视觉分组 |
| 画布缩放/平移 | GraphProcessor 默认操作 |
| 节点折叠箭头 | 折叠节点标题栏 |

### 3.5 节点内字段（选中节点 Inspector）

- **Flow Action**：务必从 **actionPool** 选 `General_Armature_Slide_Exit_ActionData` 等；留空 `None` → Validate **Error**。
- **Route Switch**：选 routePool 内 Route。

## 4. SlideExit → SwordDash 完整配置（C1 默认键位）

### 4.1 键位与资产对应（易错）

| 键 | Entry | Route | 动作 |
|----|-------|-------|------|
| **Shift** | `Entry_Shift` | `Route_MultiStage_Slide_Shift` | Slide Start → Loop → **Exit** |
| **RM（右键）** | `Entry_RM` | `Route_Normal_Sword_Dash_RM` | **SwordDash** |

Slide 后半段按 **RM** 接剑冲，不是 Shift。

### 4.2 路径 A — 打断（推荐，SlideExit 已配窗口时）

**适用**：仍在 `PlayerActionState` 播放 `General_Armature_Slide_Exit_ActionData`，在窗口内按 RM。

**配置 — ActionData**（`General_Armature_Slide_Exit_ActionData`）

在 **Action 时间轴 / Windows** 中确认有一段：

| 项 | 建议值 | 说明 |
|----|--------|------|
| NormalizedStart ~ End | 例如 `0.80 ~ 1.00` | 出滑铲收招窗口 |
| **Interruptible By Categories** | 勾选 **Offense** | SwordDash 的 `Category = Offense`；Resolver 按 **类别** 判定 |
| Min Incoming Priority | `0` 或 ≤ SwordDash.InterruptPriority(10) | 来袭优先级门槛 |
| Allow Self Interrupt | 按需 | 一般 false |

**不要依赖**：旧 `WindowSlotMask` 里单独勾 `AllowInterruptBySwordDash` — **137 终态**下 `ActionInterruptResolver` 只看 `InterruptibleByCategories` + 优先级，不看 Allow* 位掩码。

**运行时链**（7 层管线节选）：

```
Intent(RM) → TryResolveForIntent（通常失败：仍在 Slide MultiStage）
→ TryAdvanceCombatFlowOnInput（若配了 Flow 边，见路径 B）
→ PlayerActionState.TryConsumeGameplayIntent
→ ActionInterruptResolver.CanInterrupt(SlideExit, t, intent, SwordDashAction)
→ 通过则 NotifyRouteExited(interrupted) + 切 SwordDash Action
```

**验收日志**（Player 开 `DebugInterruptFlow`）：

```
[Interrupt] allow=true cat=Offense pri=10 reason=window+category
```

### 4.3 路径 B — Combat Flow 边（OnInput + TargetRoute）

**适用**：Entry 解析失败但 `ActiveRoute` 仍在时，由 `CombatGraphRunner` 施放 `Route_Normal_Sword_Dash_RM`。

**前置**

1. `Loadout_Skill_C1.combatFlow` → `CombatFlow_Player`
2. `CombatFlow_Player` 编译 valid

**Step 1 — 填 Pools**

```
actionPool:
  - General_Armature_Slide_Start_ActionData
  - General_Armature_Slide_Loop_ActionData
  - General_Armature_Slide_Exit_ActionData
  - General_Armature_Sword_Dash_RM_ActionData   （可选，便于预览）

routePool:
  - Route_MultiStage_Slide_Shift
  - Route_Normal_Sword_Dash_RM
```

**Step 2 — 画布拓扑（MultiStage 需段间 OnSegmentComplete）**

```
Start → SlideStart → SlideLoop → SlideExit ──OnInput(RM)──→ SwordDashActionNode → End(Idle)
         │              │            │
         └─OnSegmentComplete─────────┘（段间链，Transition=OnSegmentComplete，TargetRoute 空）
```

- 每个 **Flow Action** 的 `nodeId` 唯一，`Action` 绑定对应 ActionData。
- **SlideExit → SwordDash** 边：
  - **Transition** = `OnInput`
  - **Input Slot** = `RM`
  - **Target Route** = `Route_Normal_Sword_Dash_RM`
  - **Edge Kind** = `Flow`（或 `Interrupt` 仅影响日志语义）
  - **Priority** = `0`
  - **Conditions**：默认空；需要地面则加 `Grounded()`

**Step 3 — Sync && Compile**

Inspector 应显示类似：

```
#0 pri=0 SlideExit→SwordDashNode [OnInput] route=Route_Normal_Sword_Dash_RM
```

**Step 4 — Play 验收**

`DebugSkillRoute` 开启后：

```
[Flow] BindEntryAction General_Armature_Slide_Start... node Start→SlideStart
[Flow] SegmentComplete graph-only ...（段间推进）
[Flow] flow-pick→SwordDashNode route=Route_Normal_Sword_Dash_RM ...（按 RM 时）
[Flow] SegmentComplete→Enter route=Route_Normal_Sword_Dash_RM
```

**MultiStage 限制（现状）**：`BindEntryAction` 仅在 `NotifyRouteEntered` 时调用，**段内切换不会自动改 Flow 节点**。因此必须用 **Start→Loop→Exit 的 OnSegmentComplete 链**把图指针推到 `SlideExit` 节点，OnInput 边才会从 Exit 出发。若只有 Start→Exit 一条边，指针会停在 Start，Flow 不生效。

### 4.4 路径 A + B 同时存在时

| 阶段 | 谁先决定 |
|------|---------|
| Action 播放中按 RM | **Interrupt**（ActionState 闸门）与 **Flow OnInput**（Resolve 失败后）并行候选；Interrupt 在 `TryConsumeGameplayIntent` 阶段 |
| 段已结束 | **OnSegmentComplete** Flow 边，不走 Interrupt |

两者配置 **不互相替代**：窗口管「能不能断」，边管「断/切之后进哪条 Route」。

### 4.5 Ability / Route 闸门（常被忽略）

Flow 施放 TargetRoute 前还会过：

- `AbilityGateService.CanActivateRoute`（Route 上 `abilityGateRules`）
- `runtime.CanCast`（CD / Cost）

SwordDash Route 若被 AbilityMap 或 Gate 拒掉，日志：

```
[Flow] SKIP flow→Route_Normal_Sword_Dash_RM gate=...
```

检查 `Loadout.abilityMap` 与 Route 的 `abilityGateRules`。

## 5. 五轨标签与技能流转协同（137.1 契约）

### 5.1 五轨一览

| 轨 | 枚举 | 谁写 | 谁读 | 与 Flow/Interrupt 关系 |
|----|------|------|------|------------------------|
| **State** | `StateTag` | FSM、ActionWindow 时间片段 | Flow `OnTag` 条件、TransitionResolver | Phase/物理/Invulnerable；**不**再写 Can* |
| **Status** | `StatusTag` | Buff/Debuff | Condition、Gate | 眩晕等禁止输入 |
| **Ability** | `EntityCapabilityTag` | `EntityAbilitySystem` | TransitionResolver、AbilityGate | CanSwordDash / CanDodge 等 **资格** |
| **Mechanic** | `MechanicTag` | 玩法系统 | Flow `OnMechanicTag` | 锚点、特殊机制 |
| **Faction** | 阵营位 | 关系系统 | 目标过滤 | 与 Flow 边较少直接相关 |

### 5.2 分工表（唯一真相 — 禁止兜底混配）

| 语义 | 唯一权威 | 读取方 | 禁止 |
|------|---------|--------|------|
| 物理/阶段（Grounded、PhaseRecovery） | State 机 + ActionWindow Phase 位 | ConditionEvaluator | 在 Flow 边重复写「打断许可」 |
| **打断许可** | `ActionWindow.InterruptibleByCategories` | `ActionInterruptResolver` | 用 Flow 边代替窗口 |
| **提前流转** | CombatFlow 边 + Conditions | `CombatGraphRunner` | 用 AllowInterrupt* 位代替边 |
| **能不能按 RM/Shift** | Ability 轨 + Entry Resolve | TransitionResolver、EntryService | 在 State 轨写 CanSwordDash |

### 5.3 ActionWindow 里两类掩码（Inspector 易混）

| 字段 | 写入 State 轨？ | 用途 |
|------|----------------|------|
| **WindowSlotMask**（Phase、Invulnerable、ComboInput_Window…） | 是 | 时间轴语义、UI 显示、部分缓冲逻辑 |
| **InterruptibleByCategories** | 否（不进 Tag 容器） | **唯一**打断判定 |

`AllowInterruptBySwordDash` 等位在 **WindowSlotMask 的 Allow 槽**里属于遗留展示；137 终态打断以 **Categories** 为准。

### 5.4 Flow 条件可用的标签类

`SkillTransitionCondition` 在边上：

| Kind | 含义 |
|------|------|
| `OnTag` | `requiredStateTags` / `forbiddenStateTags` / Mechanic 同理 |
| `OnGrounded` / `OnAirborne` | 物理态快捷 |
| `OnTime` | Stage 经过秒数 |
| `WithMoveDirection` | 八向移动 |
| `RouteCdReady` | 目标 Route CD 就绪 |
| `OnInput` | 与边 Transition 叠加的二次输入条件 |

评估失败时（Debug 开）：`ConditionEvaluator` → `[Flow] cond fail ...`

### 5.5 运行时帧序（与标签的关系）

```
PreLogicUpdate:
  TransitionResolver（读 State/Status/Ability）→ 意图是否 offer
  SkillEntryService.TryResolveForIntent（Entry/Route/CD/Combo）
  失败且有 ActiveRoute → TryAdvanceCombatFlowOnInput（读 CombatContext + Conditions）
PlayerActionState:
  ActionInterruptResolver（读 ActionWindow，不读 Flow 边）
NotifyRouteEntered → BindEntryAction（Flow 图指针）
TickActive 段结束 → TryAdvanceOnSegmentComplete
```

## 6. 常见问题

| 现象 | 原因 | 处理 |
|------|------|------|
| Graph 按钮无反应 | 空窗口未绑 asset | Inspector → Open Graph Editor |
| `AddObjectToAsset not persistent` | .asset 未 Save | Ctrl+S 后再 Open |
| Compile INVALID FlowAction 缺 Action | 节点未绑 Action | 选 actionPool 内 Action |
| Play 无 `[Flow] Attach` | Loadout 未绑 combatFlow 或未 Compile | 绑引用 + Validate && Compile |
| 窗口内按 RM 不断 | Categories 未含 Offense | 改 InterruptibleByCategories |
| Flow 边不配但 Interrupt 能断 | 正常；Interrupt 不读 Graph | 若要指定 Route，加 TargetRoute 边 |
| OnInput 边不触发 | 图指针不在 SlideExit | 补全 MultiStage 段间 OnSegmentComplete 链 |

## 8. 面试口述版

Combat Flow 是 **Loadout 级编排图**：Entry 管「起手进哪条 Route」，Graph 管「Route/Action 播放过程中何时切到下一条 Route」；**打断**由 ActionWindow 类别掩码单点判定，**流转**由编译后的边 + ConditionEvaluator 判定；五轨里 **Ability 管资格、State 管阶段与 Flow 条件、Window Categories 管能不能断**，三者不混表。
