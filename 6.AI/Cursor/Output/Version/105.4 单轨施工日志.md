## §1 落地（2026-05-16）— W8 HUD 单轨收口

### 1.1 改动文件

| 文件 | 改动类型 | 摘要 |
|------|---------|------|
| `2_Framework/Skill/Routes/Runtime/IRouteRuntimeHandle.cs` | 增字段 | 新增 `SkillEntrySlot EntrySlot { get; }`：HUD 分组用，单轨契约下 HUD 不需要再知道 PresentationKind。 |
| `2_Framework/Skill/Routes/Runtime/RouteRuntimeHandle.cs` | 实现 | 新增 `EntrySlot => _slot;`（构造函数内已有 `_slot` 成员）。 |
| `3_Gameplay/UI/Presenters/SkillBarRoutePresenter.cs` | **重写** | 从读 `Player.SkillLoadout / loadout.Entries / unit.PresentationKind` 改为唯一数据源 `player.SkillEntries.HudHandles`，按 `IRouteRuntimeHandle.EntrySlot` 自动分组。 |

### 1.2 关键设计决策

1. **HUD 看不见 PresentationKind**：契约 C4 = HUD 只通过 `IRouteRuntimeHandle` 读运行时面。原 Presenter 反向去 Loadout 取 `SkillRoutePresentationKind` 再回查 handle，等于把 Route 多态泄漏到 HUD。重构后 HUD 直接拿 `HudHandles` 列表（service 在 `Rebuild` 时已按 `ShowOnHud` 筛过），不再反查。
2. **同槽多 Widget 自然支持**：`HudHandles` 内同一 `SkillEntrySlot` 可能出现 N 个 handle（普攻 + 蓄力 + 派生），Presenter 用 `Dictionary<SkillEntrySlot, Transform>` 在 root 下生成横向 `HorizontalLayoutGroup` 容器，N 个 Widget 进同一个组。
3. **零事件订阅 / 零 GC**：Presenter 只在 `Bind` 时实例化；`RouteWidget.LateUpdate` 直接拉值。

### 1.3 验证

- 编译：`SkillBarRoutePresenter.cs / IRouteRuntimeHandle.cs / RouteRuntimeHandle.cs` 无 Lint 错误。
- 静态契约：grep `SkillSlotType` / `SkillDataSO` 在 Presenter 中为 0。
- Runtime 行为预期（待 PlayMode 验证）：Q 槽配 Normal + Charge → HUD 渲两 Widget；CD/Charge 进度互不干扰。
