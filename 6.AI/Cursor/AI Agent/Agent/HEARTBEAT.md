# HEARTBEAT

## Purpose

HEARTBEAT is the operating rhythm for LeonOS: a long-term learning and interview training system for computer programming, Unity game development, gameplay architecture, and technical interview preparation.

The goal is not to collect more notes. The goal is to repeatedly transform raw input into structured knowledge, project evidence, interview expression, code drills, review tasks, and long-term memory.

## Core Loop

Every Agent session should run this loop:

1. Intake: identify the source material, task type, and expected output.
2. Extract: compress the source into stable concepts, not scattered summaries.
3. Structure: place the result into the correct LeonOS layer.
4. Map: connect knowledge to real Unity/gameplay/computer science use cases.
5. Express: convert knowledge into interview-ready language.
6. Drill: create code, quiz, or oral practice when useful.
7. Remember: update weakness, progress, open questions, and next actions.

## Session Checklist

At the start of each session:

- Confirm what layer the request belongs to: Raw, Knowledge, Project, Interview, CodeDrill, ComputerScience, Review, Agent, Career, or Thinking.
- Preserve original evidence when processing source material.
- Do not produce loose notes if the user expects a reusable system file.
- Prefer templates and stable contracts over one-off explanations.
- If generating interview content, include safe answer, project answer, architecture answer, likely follow-ups, and what not to mention.
- If generating programming or algorithm content, include problem pattern, reasoning path, complexity, mistakes, Unity/game-dev mapping, and final code template.

At the end of each session:

- Record progress.
- Record unresolved gaps.
- Recommend the next step.
- State where new files or outputs were placed.

## Output Discipline

Every output should be one of these:

- Knowledge Unit
- Interview Question Card
- Code Drill Card
- Project Reflection
- Architecture Evolution Note
- Review Plan
- Agent Memory Update
- Prompt Pipeline
- Directory/Contract Spec

Avoid:

- Long unstructured summaries.
- Pure collection without processing.
- Standard answers without project mapping.
- Overly broad "learn everything" plans.

## Daily Minimum Loop

If the user asks for a learning routine, default to:

- 1 hour project development.
- 1 hour knowledge extraction, only 1-2 knowledge points.
- 30 minutes interview speaking practice with recording.
- 30 minutes code drill or handwritten programming practice.

## Quality Bar

A file is useful only if it can be reused later by a human or Agent.

The highest value outputs are:

- Project-to-interview mappings.
- Cognitive error history.
- Architecture evolution records.
- Reusable prompt pipelines.
- Code drill templates that can be handwritten.
