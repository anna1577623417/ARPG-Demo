## 1. 终态架构（最终一张图）

```
Physical Input
   │
   ▼
InputReader (Slot 双写表 + 持续按住时间)
   │
   ▼
InputInteractionResolver  (Tap / Hold / DoubleTap / Sequence)
   │
   ▼
InputChordResolver        (WASD modifier + Trigger → Direction)
   │
   ▼
GameplayIntent { Kind = Skill_Entry_NN, Slot, HoldDuration, MoveBuffered }
   │
   ▼
SkillEntryService    (按 Slot 取 SkillEntryDefinition 对应 RouteRuntime 集合)
   │
   ▼
RouteResolver        (优先级：Charge > Combo > Directional > Derivative > MultiStage > Normal)
   │
   ▼
SkillRouteRuntime  ──► SkillStageRuntime ──► Transition (RequireHit / TargetRule / OpenTime / Conditions)
   │                                     │
   │                                     ▼
   │                            Next Stage / Next Route / Recovery / Exit
   │
   └──► MotionExecutor  ◄── MotionPlaybackContext (LoopWindow / Pause / SpeedMul)
                       ◄── ActionDataSO + MotionProfileSO
```

握手点只有一个：`SkillStageDefinition.Action`。

## 2. 施工 Wave（替代旧 Phase 编号；保持单轨节奏）

> 当前进度（依据 105.2）：W1 数据层、W2 Runtime 骨架、W3 Resolver+RouteRuntime、W4 SkillEntryService 接 PlayerStateManager、W5 输入边沿/单一事实源 大部分已落地。下文按**剩余**工作量排，每 Wave 内零并行新旧路径。

### W6 — Charge 多 Clip & 后摇 Stage 化 ⭐ 配置语义补齐 1
- **新增/落地**
  - `ChargeRouteRuntime` 内部状态机：`Idle → Startup(Stage0) → HoldLoop(Stage1, LoopWindow) → Release(Stage2) | Cancel(Stage3)`。
  - `MotionPlaybackContext`：`LoopWindow [t0,t1]` / `Pause` / `RuntimeSpeedMultiplier`，`MotionExecutor.Tick` 内对 `_clipTime` 做 `mod` 循环；松手切 Release 时 `_startPos` 回写避免位移跳变。
  - `SkillStageDefinition.Transitions[]`：当一个 Stage 之后没有显式 `RequireInput`/`Conditions` 的 Transition 时，自动把 `(OpenTime=1, CloseTime=1, AutoAdvance=true)` 视为后摇衔接，下一个 Stage 即 **Recovery Stage**。
- **删除**
  - `SkillChargeCommit.*`、`SkillData.chargeLevels[]`、`PlayerActionState.ChargeMicroPhase`、`ChargeCastHandler` 主帧路径（保留旧 .cs 仅供 Editor 迁移读）。
- **验收**：四 Clip Demo（前摇/HoldLoop/释放/取消）资产 + EditMode 测试 `Charge_TapBelowThreshold_FallbackNormal`、`Charge_HoldOverFull_AutoRelease`、`Charge_Cancel_PlaysCancelStage`。

### W7 — Stage 条件门 & 多阶段范式 ⭐ 配置语义补齐 2
- **新增**
  - `SkillTransitionCondition` 叶子：`OnHit` / `OnTargetTagAny` / `OnTimer` / `OnInputEdge` / `OnTagAll` / `Combined(All|Any|Not)`。
  - `ConditionEvaluator.Evaluate(in TransitionEvaluationContext)`：纯函数，0-GC。
  - `MultiStageRouteRuntime`：基于 Stage 游标 + Transition Window；与 `ComboRouteRuntime` 物理分离（前者跨 Stage，后者跨 Route）。
- **删除**
  - `SkillRuntime.SecondStageAvailable / OpenSecondStageWindow` 旧二段窗硬编码。
- **验收**：盲僧 Q 范式资产：Q1 命中后 5s 内允许 Q2，未命中只能等 CD；EditMode 三测试覆盖（命中开门 / 未命中关门 / 超时关门）。

### W8 — HUD 解耦 ⭐ 配置语义补齐 3
- **新增**
  - `IRouteRuntimeHandle { RouteId; Icon; CooldownProgress01; ChargeProgress01; IsCharging; ComboIndex; StageIndex; ShowOnHud; }`
  - `RouteWidget`：单 Widget 绑定一个 `IRouteRuntimeHandle`。
  - `SkillBarRoutePresenter`：从 `SkillEntryService` 拉所有 `ShowOnHud=true` 的 RouteHandle，**多 Widget per Slot 自然支持**。
- **删除**
  - `SkillBarPresenter` 旧分支（直接读 `SkillDataSO/SlotType` 的 path）。`SkillSlotView` 中 SkillData 字段。
- **验收**：Q 槽同时挂 Normal + Charge，HUD 渲两个 Widget，分别独立 CD/进度。

### W9 — Chord & Direction
- **新增**：`InputModifierBuffer`（方向键 0.15s 缓冲）、`InputChordResolver`（modifier+trigger → `Skill_Entry_X_Forward` 等 Directional 派生），`DirectionalRouteSet : SkillRouteDefinition`。
- **关键**：方向**不进 IntentKind**，只挂在 `InputContext.MoveModifierBuffer` 给 RouteResolver 读。
- **验收**：Shift+W → DashForward Route；Shift 单按 → Dodge Normal Route。

### W10 — Editor 工具：配方 → 资产
- **目录强制**：`Assets/GameMain/Data/_Skills/<EntryId>/{Routes,Stages,Recipes}/`。
- **`SkillAuthoringRecipeSO`**：策划唯一入口，5 子描述（Normal / Combo / Charge{Single|Multi} / MultiStage / Derivative）。
- **`SkillRecipeCompiler`** 幂等：读配方 → 复用/生成 `ActionDataSO + MotionProfileSO`（Motion 走预设库，禁 inline）→ 生成 `SkillStageDefinition` → 生成 `SkillRouteDefinition` → 写 `SkillEntryDefinition` → 写 `_authoringFingerprint`。
- **`SkillLegacyMigrationTool`**：一次性把现存旧 `SkillDataSO + SkillLoadoutSO.bindings` 转配方 → 跑 Compiler。完成即在 git 中删除旧资产、删除旧 .cs 主路径文件。
- **`Verify All Recipes`**：CI 钩子，校验 fingerprint。

### W11 — 旧主循环代码物理删除 + 测试矩阵
- **删除**：`SkillRuntime.cs / SkillSystem.cs / SkillChargeCommit.cs / SkillCastHandlers.cs（仅 Charge 部分）/ SkillSegmentResolver`，从 `PlayerActionState`、`PlayerController`、`PlayerStateManager` 中清掉所有 `SkillData / SkillSlotType` 引用。
- **保留**（仅 Editor 命名空间）：旧 `SkillDataSO` 类定义，给 Migration 工具 deserialize 用，并加 `[Obsolete(error:true)]` + `#if UNITY_EDITOR` 包裹。运行时 asmdef 拒之门外。
- **测试矩阵**（EditMode + PlayMode）：
  1. LM 单按 Normal；LM 三连点 Combo；LM 长按 Charge（Single/Multi）。
  2. RM 派生：Normal 命中后窗口内 RM 触发派生 Route。
  3. Q1 命中开 Q2、未命中无 Q2。
  4. 后摇 Stage 自动衔接退出 ActionState。
  5. Shift+W Dash、Shift 单按 Dodge。
  6. HUD 单槽双 Widget CD/Charge 独立刷新。
  7. Profiler：完整连招 60s GC = 0。

## 4. 风险 & 单轨理由（写给质疑者）

| 顾虑 | 单轨回答 |
|------|---------|
| "万一新路径有 bug，旧路径回不去？" | 打 git tag `pre-route-W{N}`，回滚 = `git reset --hard`。比维护两套 if 分支便宜一个数量级。 |
| "美术/策划资产没迁完怎么办？" | `SkillLegacyMigrationTool` 一次性跑批；未迁完的资产**禁止进运行时主循环**，编辑器报 LegacyAsset 错误。 |
| "HUD 旧 Presenter 不能渐进切？" | `SkillBarPresenter` 一次性替换为 `SkillBarRoutePresenter`，删除旧组件 GameObject 引用。Bug 周期短、定位快。 |
| "Charge 多 Clip 没人配过怎么验？" | W10 工具在 Recipe 层提供 `mode = Multi` 默认模板；W6 Demo 资产即验收资产。 |
