根据 `154.1` Log，可以比较确定地把三类异常归因到 **同一套机制问题**，而不是 NormalRoute 无 CD 本身。

---

## 一、Log 结论（按现象）

### 1. AAAA（连点重复首段 / 整段重来）

典型循环（L28–30、L61–63…）：

```text
MISS node=Start → Fallback→Entry node=End
BindEntryAction Combo_A  End→ComboA
… ABC …
ActionC→End → SegmentComplete
（回到 Idle/End，再 Fallback Entry ComboA）
```

说明：**每次整段结束都会走 `Entry.NormalRoute → ComboA` 重新起手**，连点会把多段输入堆进 Late/Resolve，加速「整段结束 → 再 A」的循环。  
你的猜测（无 CD + 无打断窗 + 预输入）会**放大**这个问题，但**直接触发点**是：段结束后 `Fallback→Entry` 合法、且 Graph 游标/Late 与「实际在播段」不同步。

---

### 2. A→C 跳过 B（最典型：L16–20、L286–291）

```text
L16  FLOW advance ComboA → ComboB        ← 按键解析时游标已跳到 B
L17  RESOLVE node=ComboA → Route_B       ← 解析节点仍是 A（当帧）
L18  LATE open 0.50s node=ComboB_Action   ← Late 开在 B，但 B 还没播
L19  FLOW advance ComboB → ActionC
L20  LATE consume node=ComboB → Route_C   ← 下一段输入从 B 节点解析，B 被跳过
```

更严重的连点（L286–291）：

```text
RESOLVE ComboA→B
RESOLVE ComboB→C          ← 同一轮连点，中间没有 ComboB 的 BindEntryAction
MISS node=ActionC
DUAL_GATE block stage=Stage_Combo_A action=Combo_A  ← 还在播 A，游标已在 ActionC
```

**根因已坐实**：`TryPickFromScratch` 里 **`ApplyEdgeCursorAfterPick` 在 Route 真正 Enter 之前就把游标推到 To 节点**（Landing 3 为 Flow 连招加的「显式推进」）。  
后果：

| 机制 | 后果 |
|---|---|
| 游标提前到 ComboB | 下一发 LM 从 **ComboB** 解析 → 直接走 B→C |
| `TryOpenLateWindow` 读 `_currentNodeId` | Late 开在 **未来段**（ComboB），`LATE consume` 继续跳段 |
| `GetResolutionNodeId` 在 ActiveRoute 时用 `_currentNodeId` | 解析节点与 **Stage 在播 Action** 脱节 |

所以：**不是 NormalRoute 又把 ComboA 解析了一遍**，而是 **游标/Late 比动画快一整段**。

---

### 3. 正常 ABC（L286–287 后半、或 L403–412 带完整 BindEntryAction）

正常时应看到：

```text
RESOLVE node=ComboA → B
BindEntryAction Combo_B  …→ComboB
RESOLVE node=ComboB → C
BindEntryAction Combo_C  …→ActionC
```

Log 里 healthy 段是 **每次 RESOLVE 后都有对应 BindEntryAction**，且没有「A 还在播但 node=ActionC」的 DUAL_GATE。

---

## 二、与当前设计的冲突点

153.2 契约里写的是：

> Flow 游标应在 **Route 成功进入后** 与 `BindEntryAction` 对齐  

但 Landing 3 实现在 **`TryPickFromScratch` 命中边时立刻 `_currentNodeId = e.ToNodeId`**，早于 `NotifyRouteEntered` / `BindEntryAction`。  
154.1 Log 证明这在 **OnInput 单链 Combo** 下会破坏：

- 解析锚点（应从「在播 Action 对应节点」解析）
- Late Window 锚点（应从「刚结束的段」开 Late，而不是下一段）

---

## 三、修复方案（建议分 2 个 Landing）

### Landing A — 运行时（必做，治 A→C / 连点）

**契约调整（单点真相）**

| 概念 | 规则 |
|---|---|
| **解析节点**（ActiveRoute 中） | `TryFindNodeIdByAction(当前 Stage.Action)`，**不要**用 pick 后的 `_currentNodeId` |
| **Flow + OnInput 游标推进** | **禁止**在 `TryPickFromScratch` 里立刻 `ToNodeId`；改为 `NotifyRouteEntered` → `BindEntryAction` 成功后再落到 To |
| **Late Window 开启** | 用「段结束时的 Action 节点」(`_lateWindowNodeId`)，**不要**用 pick 后已前进的游标 |
| **SegComplete 无 Route** | 仍可立即推进游标（Slide 链），与 Combo OnInput 分开 |

**建议实现要点**

1. `ApplyEdgeCursorAfterPick`：若 `EdgeKind==Flow && Transition==OnInput` → 只记 `_pendingFlowCursorNodeId`，不改 `_currentNodeId`。
2. `GetResolutionNodeId`：ActiveRoute 非空时，优先 Stage.Action 对应节点；与 `_currentNodeId` 不一致时打 `[ComboChain] CURSOR_LAG`。
3. `TryOpenLateWindow`：在 `NotifyRouteNaturalExit` 前用 **当前 Stage 的 Action 节点** 开 Late，而不是 `_currentNodeId`。
4. （可选）Flow OnInput 命中后若 `TargetRoute` 入口 Action == 当前 Stage Action → 丢弃并打 `REPEAT_SUSPECT`（防同段连点）。

**验收 Log（修后）**

```text
RESOLVE node=ComboA → Route_B
BindEntryAction Combo_B  ComboA→ComboB     ← FLOW advance 应出现在 Bind 之后
RESOLVE node=ComboB → Route_C              ← 不应在 A 还在播时出现
不应出现：LATE open node=ComboB  while stage=Combo_A
```

---

### Landing B — 数据 / Graph 配置（配合，治连点体感）

| 项 | 建议 |
|---|---|
| **Start→ComboA** | 仅 `OnSegmentComplete`、**无 Route**；起手只靠 `Entry.NormalRoute=ComboA`（你已在做） |
| **ComboA→B、B→C** | `OnInput` + Flow + 各 NormalRoute；**LateWindowSeconds = 0**（154.1 里 0.5s Late 是跳段帮凶） |
| **ActionC→End** | `OnSegmentComplete` 无 Route 即可 |
| **ComboA Route** | 单 Stage；Action 上配 **Combo 衔接窗**（Early Window / 可打断类别），与 Graph 解析窗对齐 |
| **Entry NormalRoute** | 可保留无 CD；若仍易「整段重开」，给 **Group CD** 或仅对「Fallback 起手」加极短防抖（可选，非首选） |

---

## 四、三类现象 ↔ 修复对照

| 现象 | 主因 | Landing A | Landing B |
|---|---|---|---|
| A→C 跳过 B | pick 时游标提前 + Late 从下一段解析 | 延迟游标 + 解析绑 Stage Action | Late=0 on A→B/B→C |
| AAAA / 频繁重 A | 整段结束 Fallback Entry + 连点堆 Late | 同上 + Late 锚点修正 | Late=0；Entry 仅 Idle 生效 |
| DUAL_GATE @ ActionC 但 stage=Combo_A | 游标到 C、动画还在 A | GetResolutionNodeId 绑 Stage | — |
| `Fallback node=End` | Idle 游标在 End（正常） | 可改 Log 文案区分 Start/End | — |

---

## 五、推荐 Graph 形态（与你目标一致）

```text
Idle(End/Start) ──LM Entry NormalRoute──► ComboA
ComboA ──OnInput LM/Tap [Flow]──► ComboB
ComboB ──OnInput LM/Tap [Flow]──► ActionC
ActionC ──OnSegmentComplete──► End
（不要 Start──OnInput──► ComboA）
（A→B、B→C 边 LateWindow = 0）
```

## 六、小结

154.1 Log **已经能定因**：主要是 **Flow OnInput 在边命中时过早推进游标 + Late Window 跟错节点**，不是 Entry NormalRoute 单独背锅。  
你的 NormalRoute 无 CD + 无打断窗会让连点更容易堆输入，但**跳过 B / 游标超前**必须用 **Landing A 运行时契约**修。
