# 153.2 Combat Graph — Flow / Interrupt 双类型落地计划书

> 来源讨论：`153.1【迭代】Graph 节点的Flow与Interrupt类型.md`
> 配套规则：`07-single-track-migration.mdc`（单轨）、`09-refactor-delivery-protocol.mdc`（设施+握手分 Landing）、`06-skill-route-single-track.mdc`（技能域）
> 核心目标：**把 Combat Graph 做成一份可读的「上下文技能链路图」** —— Flow 显式画出「动作 → 动作」连招，Interrupt 把 Route 藏进「IN→END」边表达取消/派生。

---

## 一、设计结论（一句话）

把现在「纯标识、无逻辑」的 `EdgeKind`（Flow / Interrupt）升级为 **两种合法性模式 + 两种可视语义**：

| EdgeKind | 连接形态 | Route 显隐 | 表达的关系 | 典型用途 |
|---|---|---|---|---|
| **Flow** | `ActionNode → ActionNode`（含 `Start→ActionNode`） | Route 在边里，但**编辑器自动显示其入口 Action**，图上看得到「切到谁」 | **连招关系**（AttackA→AttackB、JumpLanding→ChopDown） | 显式连招表 |
| **Interrupt** | `ActionNode → End`（IN→END，强制） | Route **完全藏在边里**，图上只表达「此处允许打断」 | **打断/派生关系**（SlideExit 时 RM 取消成剑冲、闪避取消、跳跃取消） | 取消窗、派生招、多阶段技能入口 |

> 这正好解决讨论里那句：**「图表达了『什么时候能切』，但没表达『切到谁』」**。
> Flow 把目标 Action 显式化；Interrupt 保留现有「Route 藏在边里」的取消机制（**当前已跑通的双闸门不推翻**）。

## 二、现状分析（已读代码事实）

### 2.1 节点（`4_Data/1.Skills/Routes/CombatFlow/CombatFlowGraphNodes.cs`）

- `CombatFlowStartNode` / `CombatFlowActionNode(action)` / `CombatFlowRouteSwitchNode(route)` / `CombatFlowEndNode`。
- `CombatFlowActionNode.action : ActionDataSO` —— 已具备「显式动作节点」的容器。

### 2.2 边（`4_Data/1.Skills/Routes/CombatFlowAuthoring.cs` 的 `CombatFlowEdgeAuthoring`）

字段齐全：`EdgeKind`、`Transition`、`InputSlot`、`InputSemantic`、`Conditions`、`ConditionRefs`、`Priority`、`TargetRoute`、`LateWindowSeconds`。

### 2.3 运行时（`2_Framework/Skill/Routes/Runtime/CombatGraphRunner.cs`）

- **`EdgeKind` 在运行时完全没有被读取**（grep 确认）：只读 `Transition` / `InputSlot` / `InputSemantic` / `Conditions` / `LateWindowSeconds`。→ 这是「纯标识」的根因。
- `TryPickFromScratch`：边命中后，**仅当 `route == null`** 才 `_currentNodeId = e.ToNodeId` 推进游标；route 非空时游标推进依赖 `BindEntryAction(action)` 按 Action 名回匹配 → 这是「Flow 连招游标不显式落到目标节点」的根因。

### 2.4 校验器（`Editor/Authoring/CombatFlowGraphValidator.cs`）

- 现有：NodeId 唯一、Start 恰好 1 个、FlowAction 须有 Action、RouteSwitch 须在 routePool、边 from/to 合法、OnInput 须配 slot/semantic、Combo 段进阶。
- **缺**：EdgeKind 合法性规则、Route 类型 / 单 Stage 规则、Flow 边「To.Action == Route 入口 Action」规则、MultiStage「必须接 End」规则、Derivative「解析唯一入口」规则。

### 2.5 Route 类型（`4_Data/1.Skills/Routes/*`）

- `SkillRouteDefinition`（抽象）→ `Normal` / `MultiStage` / `Derivative` / `Combo` / `Charge`，靠 `RouteKind Kind`（已存在）区分；`Stages[]` 私有 + `FirstStage()`。
- 讨论要求：**只有 Normal / MultiStage / Derivative 三类进图**；Combo（容器）、Charge 不进图。

## 三、类型系统与契约（单一真相）

### 3.1 新增 `RouteGraphType`（图配置资格）

```csharp
// 4_Data/1.Skills/Routes/RouteGraphType.cs（新增）
public enum RouteGraphType : byte
{
    Unsupported = 0, // Combo / Charge：不可进图
    SingleAction = 1, // NormalRoute（单 Stage）→ 可做 Flow 目标
    MultiStage   = 2, // MultiStageRoute → 只能 Interrupt(IN→End)
    Derived      = 3, // DerivativeRoute → 解析唯一入口 Action，可做 Flow 目标
}
```

`SkillRouteDefinition` 加 **虚属性**（默认 Unsupported），子类 override：

| 子类 | `GraphType` | 入口 Action 解析 |
|---|---|---|
| `NormalRouteDefinition` | `SingleAction` | `FirstStage().Action`（须单 Stage） |
| `MultiStageRouteDefinition` | `MultiStage` | `FirstStage().Action`（仅用于 Flow 禁用判断，不参与 To 匹配） |
| `DerivativeRouteDefinition` | `Derived` | `FirstStage().Action`（解析后唯一） |
| `Combo` / `Charge` | `Unsupported` | — |

### 3.2 单一真相 API（基类）

```csharp
// SkillRouteDefinition 内新增
public virtual RouteGraphType GraphType => RouteGraphType.Unsupported;

/// <summary>图入口 Action（Flow 边 To 节点须与之匹配）；返回 false 时 error 给出原因。</summary>
public bool TryResolveGraphEntryAction(out ActionDataSO entryAction, out string error)
{
    entryAction = null; error = null;
    var first = FirstStage();
    if (first == null || first.Action == null)
    {
        error = $"{name} 无有效 Stage[0].Action";
        return false;
    }
    entryAction = first.Action;
    return true;
}
```

### 3.3 NormalRoute「单 Stage」契约（用户补充 = 最高优先级）

- `NormalRouteDefinition` 增 `[SerializeField] bool singleAction = true`（默认开）。
- 自定义 Inspector：`singleAction == true` 时 **Stage 数组锁定为长度 1、只读显示 `Stages.Length = 1`**；运行时只用 `Stage[0]`。
- `singleAction == false`（遗留多段普攻）→ `GraphType` 仍 `SingleAction` 但 **Validator 在被 Flow 边引用时报 ERROR**（`NormalRoute contains multiple stages`）。
- > 这条直接采纳讨论补充：「在 NormalRoute Stage 配置加开关，只应用 Stage[0]，数组长度只读为 1」，并覆盖「绝不自动取 Stage0」的旧倾向。

### Landing 3/4 — 运行时读 EdgeKind + Flow 游标显式落到目标 ActionNode（运行时单轨）

**设施表**

| 设施 | 文件 | 说明 |

| Flow 游标显式推进 | `CombatGraphRunner.TryPickFromScratch` | 命中 Flow 边且 route 进入成功后 `_currentNodeId = e.ToNodeId` |

**握手表**

| 通电点 | 上游 | 下游 | 本落位 | 验收 Log |
|---|---|---|---|---|
| Flow 推进游标 | 边命中+Route 进入 | `_currentNodeId=ToNodeId` | WIRE | `[Flow] FLOW advance cursor JumpLanding→ChopDown route=...` |
| Interrupt 取消 | 边命中+Route 进入 | To=End → Late/Idle | WIRE | `[Flow] INTERRUPT via edge route=Sword_Dash → End` |
| 双闸门保留 | `ActionInterruptResolver`+Graph | `PlayerActionState` | 保持 | `DUAL_GATE pass`（不回退既有逻辑） |

**契约（单点真相，禁止兜底）**
- Flow 边：`To` 必为 FlowAction，游标推进到 `ToNodeId`，与 `BindEntryAction(action)` 结果一致（双保险但不冲突：以边 `ToNodeId` 为准）。
- Interrupt 边：`To` 必为 End，进入 Route 后沿用现有 Late Window / `NotifyRouteNaturalExit` 回 Idle。
- MultiStage：只能走 Interrupt（接 End），段内流转由 Route 自身控制权负责，**图不接管段内**。

**本落位不做**：不动 HUD / Presenter；不改 Combo 容器 CD 结算。
**验收**：`Start→JumpLanding→ChopDown→End`（Flow）+ `Start→Slide(MultiStage)→End`（Interrupt）两条链均按预期跑通，日志出现 `FLOW advance` 与 `INTERRUPT via edge`。

## 五、Validator 规则表（Landing 2 落地）

| # | 触发 | 规则 | 失败信息 |
|---|---|---|---|
| R1 | 任意配 Route 的边 | `TargetRoute != null` 且 `GraphType != Unsupported` | `E: 边 Route 为空 / 该 Route 类型不可进图（Combo/Charge）` |
| R2 | EdgeKind=Flow | `TargetRoute.GraphType ∈ {SingleAction, Derived}` | `E: Flow 边不接受 MultiStageRoute（请用 Interrupt→End）` |
| R3 | EdgeKind=Flow | `To` 为 FlowAction 且 `To.Action == Route.TryResolveGraphEntryAction()` | `E: Flow 边 To 动作与 Route 入口 Action 不一致` |
| R4 | EdgeKind=Flow + Normal | `singleAction==true` 或 `Stages.Length==1` | `E: NormalRoute contains multiple stages` |
| R5 | EdgeKind=Interrupt | `To.Kind == End` | `E: Interrupt 边必须连接 End 节点` |
| R6 | TargetRoute=MultiStage | `To.Kind == End`（等价 EdgeKind 应为 Interrupt） | `E: MultiStageRoute must terminate at EndNode` |
| R7 | TargetRoute=Derived | `TryResolveGraphEntryAction` 成功且唯一 | `E: DerivativeRoute resolves to multiple/zero entry actions` |

> R3/R4 让「连招表味道」成立：Flow 边一旦配错目标动作，编辑期即报错，运行时不再靠运气对齐游标。

## 六、编辑器可读性改造（贯穿 Landing 2 / 4）

- **Edge 面板按 EdgeKind 分流**：
  - Flow：显示 `Target Route`、自动只读行 `入口 Action = {To.Action}`、Input/Condition/Priority；若 To 非 ActionNode 即时红字。
  - Interrupt：显示 `Target Route`（可为 Multi/Normal/Derived）、Late Window、Input/Condition；强调「此边须接 End」。
- **边标签**：图上边中点显示 `[Flow] LM→ChopDown` / `[Interrupt] RM→(hidden)`，实现「链路图」直读。
- **双重表达提示**：`AttackA` 节点 + Flow 边 Route(入口=AttackA) 时，面板提示「Route 入口与 To 节点同动作，符合预期」；不一致才报错。

## 七、运行时单轨改动点（Landing 3，最小面）

仅在 `CombatGraphRunner.TryPickFromScratch` / 边消费处加 EdgeKind 分支，**不新增第二套解析路径**：

```text
命中边 e：
  route = ResolveTargetRoute(e)
  进入 route 成功后：
    if e.EdgeKind == Flow:
        _currentNodeId = e.ToNodeId          // 显式连招推进（To 必为 ActionNode）
        Log [Flow] FLOW advance cursor {from}→{to}
    else (Interrupt):
        // To==End：沿用现有 Late/NotifyRouteNaturalExit 回 Idle
        Log [Flow] INTERRUPT via edge route={route} → End
```

- `EdgeKind` 此前运行时未读 → 不存在双轨，属「通电」而非「并行」。
- 既有双闸门（`PlayerActionState` + `ActionInterruptResolver`）**不动**。

## 八、风险与回滚

| 风险 | 缓解 |
|---|---|
| NormalRoute 改单 Stage 影响存量「普攻+后摇」资产 | `singleAction` 默认开但 **不强制改存量**；仅当被 Flow 边引用才报错，存量非图用法不受影响 |
| Flow 游标显式推进与 `BindEntryAction` 冲突 | 以边 `ToNodeId` 为准；`BindEntryAction` 仍保留作 MultiStage 段内游标 |
| EdgeKind 旧资产默认值 | 现有边默认 `Flow`；Landing 2 Validator 会把「接 End 的旧打断边」标成应改 Interrupt，按提示一键改 |
| 回滚 | 每个 Landing 前打 `git tag combatgraph-153.2-L{k}`；运行时分支仅 Landing 3，回滚单 commit |

## 十、最终形态（落地后）

```text
            ┌────────── Flow（连招，显式可读）──────────┐
Start ──▶ JumpLanding ──[Flow: LM → ChopDown]──▶ ChopDown ──▶ End
              │
              └──[Interrupt: RM → (Route 藏边)]──▶ End      （取消/派生）

Start ──▶ Slide(MultiStageRoute) ──[Interrupt → End]──▶ End （多阶段，图不接管段内）
```

- **Flow**：图上看得到「切到谁」——连招表味道。
- **Interrupt**：Route 藏在 IN→END 边里——保留现有取消/派生/多阶段机制。
- 执行链仍是 `Input → SkillEntry → Route → Action`，**不推翻现有技能系统**。
