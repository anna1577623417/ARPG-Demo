【1】【锚点】
本项目是一个长期演进的 3A ACT 战斗系统架构设计项目，目标是建立一套职责清晰、时序一致、可验证、可扩展的统一运行时框架。系统以 Input → SkillEntry → Route → Graph → Action → Timeline 为主链路，其中 Graph 用于显式描述 Action 之间的合法流转关系，Route 负责入口解析与合法性校验，Stage/Action 生命周期是唯一时间驱动源。项目重点解决输入缓冲、预输入、Graph游标推进、动作窗口、打断规则、多阶段技能、派生技能、双Combo链、空地衔接、环状流转等复杂问题，确保图上定义与运行时行为严格一致，避免游标超前、跳段、重复首段、状态分裂等问题。

同时要求 CombatGraph 不成为万能状态机，不接管 Locomotion、受击、交互等基础系统，但允许非战斗 Action 以“上下文节点”形式参与 Graph 可视化表达。例如 JumpLoop、JumpLand、WallRun、AirDash 等 Locomotion Action 可以作为 Graph 来源节点参与派生关系定义，但不强制进入 CombatGraph 的二次校验体系。Graph 负责表达 Action 关系，而非审核所有 Action。系统最终应形成“Graph定义可能性、Intent表达玩家意图、Route解析入口、Stage推动时间、Action执行表现”的统一契约。具体表现为可验收JumpLand可被WASD对应的走/跑动作打断

额外验收要求：新系统落地后必须能够立即验证空中战斗与移动系统兼容性，至少完成 JumpStart → JumpLoop → DownSlash → JumpLand 的完整 Graph 配置与运行时验证，确保空中状态能够作为合法上下文参与战斗派生，同时落地后能够无缝回归 Locomotion 流程，而无需为基础移动动作配置大量无意义的 CombatGraph 流转边。
