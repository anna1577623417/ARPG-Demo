# 159.3【诊断+修复】Walk 状态链路对称化

> 触发：Enabled States 有 WalkStart/WalkEnd 但无 **Walk**；Run 已有 Run/RunStart/RunEnd 对称组。  
> 前置：159.1 起停四态、160.2 Profile Sync、Sprint→Run 改名。

---

## 一、诊断结论（Executive Summary）

**Walk 并未「丢失能力」，而是被 `Move`（Id=2）隐式承载**——158.2 原设计用单一 `Move` + `WantsRun` 在表现层二选一 Clip。  
159.1 拆出 WalkStart/WalkEnd 离散态，Sprint→Run 后又独立出 **Run 连续态**，但 **未同步把 Move 升格为 Walk**，导致：

| 层级 | Run 链路 | Walk 链路（修复前） | 问题 |
|---|---|---|---|
| Enabled States | Run ✓ | **无 Walk**；有 Move | Inspector 语义不对称 |
| Detect 持续段 | 仍返回 **Move** | WantsRun 只在 Anim 层分流 | Resolver 无法按 Walk Binding 查表 |
| Profile Binding | Run 行可配 | Move 行承担 Walk_Loop | 策划以为缺 Walk |
| AnimController | Locomotion_Run | Locomotion_Walk（AnimLibrary） | Profile Walk 行不生效 |
| 速度 | `WantsRun→RunSpeed` | `!WantsRun→WalkSpeed` | ✓ 正常 |

**四支柱状态机**：仍只有 `PlayerLocomotionState` 一个子类承载 Idle/Walk/Run——**没有**单独的 `PlayerWalkState`；Walk 是 Locomotion 支柱内的 **LocomotionStateId**，不是 SM 子类名。

---

## 二、全链路对照（修复前）

```text
Input WASD + !Shift
  → Player.WantsRun=false, WantsWalk=true
  → PlayerLocomotionState.DetectRequestedState
       press  → WalkStart (17)
       hold   → Move (2)          ← 应为 Walk (2)
       release→ WalkEnd (15)
  → LocomotionResolver → GetBinding(Move)
  → PublishLocomotionPresentation (Move 行 Clip，常为空)
  → PlayerAnimController.ResolveLocomotionSub
       → LocomotionSub.Walk（靠 WantsRun，非 ResolvedState）
       → AnimLibrary "Locomotion_Walk"（Profile 未接通）
  → Player.MoveByLocomotionIntent(wantsRun:false) → WalkSpeed ✓
```

Run 链路（Sprint→Run 后）：

```text
Input WASD + Shift
  → Detect: RunStart / Run / RunEnd
  → Profile Run 行可配 ContinuousClip
  → Anim 可走 Profile 或 Library
```

## 四、修复策略（159.3 — 已落代码）

### 4.1 契约（单轨）

| 概念 | 权威 | 数值 |
|---|---|---|
| 走循环 Continuous | `LocomotionStateId.Walk` | Id=**2**（原 Move，资产不改） |
| 跑循环 Continuous | `LocomotionStateId.Run` | Id=14 |
| 走起 / 走停 | WalkStart / WalkEnd | 17 / 15 |
| 跑起 / 跑停 | RunStart / RunEnd | 18 / 16 |
| Obsolete | `Move` = `Walk` 别名 | 编译期迁移 |

### 4.2 Detect v3（PlayerLocomotionState）

```text
5. hasInput && !WantsRun → Walk
6. hasInput &&  WantsRun → Run
7. !hasInput             → Idle
```

（优先级 1–4 不变：Turn / release / press / Strafe）

### 4.3 Profile / Sync

- Enabled States 菜单：**Walk** 替代 Move（同 bit）
- Sync 校验 Missing Simple 含 **Walk**（不再报 Move）
- WalkStart Fallback → **Walk**；RunStart Fallback → **Run**

### 4.4 表现桥接（159.3 WIRE）

- `LocomotionAnimProfileBridge.TryGetLoopContinuousClip` — Idle/Walk/Run
- `PlayerAnimController.TryPlayProfileLoopClip` — Profile 优先，回落 AnimLibrary
