# 137.1 落地计划书：StateTag / 打断窗口 / 技能流转

## 目标与边界
- 目标：在现有框架内，把 `StateTag`、`ActionWindow` 打断闸门、`CombatFlow` 技能流转做成一套可配置、可观测、可验证的单轨系统。
- 边界：不推翻五轨标签体系（`State/Status/Ability/Mechanic/Faction`），仅做最小必要调整。
- 约束：技能流转（Flow）与打断（Interrupt）分层，禁止混在一张表里做二义性配置。

---

## 一、终态定义（单轨）

### 1) StateTag 只负责“状态与时间语义”
- `StateTag` 保留：
  - Physical：`Grounded/Airborne/...`
  - Phase：`PhaseStartup/PhaseActive/PhaseRecovery`
  - 时间行为：`Invulnerable/ComboInput_Window/HitboxActive_Window/RootMotion_Window`
  - 打断位：`AllowInterruptBy*`（40~45）
- 移除运行时依赖：`CanJump/CanDodge/CanLightAttack/...`（旧 Can* 只保留兼容，不再参与新逻辑）

### 2) 打断窗口只回答“此刻能否被某类能力打断”
- 来源：`ActionWindow`
- 核心字段：
  - `InterruptibleByCategories`
  - `MinIncomingPriority`
  - `AllowSelfInterrupt`
  - （新增）`AllowedAbilityTags`（能力白名单，最小集合）
- 执行点：`ActionInterruptResolver` 统一判定

### 3) 技能流转只回答“允许从A提前流向B”
- 来源：`CombatFlow` + `SkillTransitionCondition[]`
- 不再复用打断窗口字段表达流转边
- 执行点：`CombatGraphRuntime/ConditionEvaluator`

---

## 二、契约表（唯一真相）

| 语义 | 唯一写入点 | 读取方 | 禁止做法 |
|---|---|---|---|
| 当前状态（Grounded/Airborne/Phase） | Player/State machine | Interrupt/Flow/Resolver | 在 Flow 边里重复写状态 |
| 打断许可 | `ActionWindow` | `ActionInterruptResolver` | Flow 边直接决定打断 |
| 技能流转许可 | `CombatFlowEdge + Conditions` | `CombatGraphRuntime` | 用窗口位模拟“可流转到某技能” |
| 能力可释放 | `AbilityService` | Interrupt/Resolver | 继续硬编码 Jump/Dash/Roll 名字 |

---

## 三、设施表（先建后通电）

| 设施 | 文件域 | 说明 |
|---|---|---|
| `AbilityTag` 最小集合 + `AbilityService` | 2_Framework / 4_Data | 负责“当前可释放什么” |
| `ActionWindow` 能力白名单字段 | 4_Data/2.Actions | 打断能力闸门 |
| `ActionInterruptResolver` 三段式判定 | 3_Gameplay | `窗口开` + `能力许可` + `优先级` |
| `CombatFlow` 边条件编辑器 | Editor | 与运行时字段一一对应 |
| `StateTag` 检查器规则 | Editor | 仅暴露本切片允许配置的位 |

---

## 四、握手表（WIRE / OPEN）

| 通电点 | 上游 | 下游 | 状态 | 验收日志 |
|---|---|---|---|---|
| Window → Interrupt | `ActionWindow` | `ActionInterruptResolver` | WIRE | `[Interrupt] window=open ...` |
| Ability → Interrupt | `AbilityService` | `ActionInterruptResolver` | WIRE | `[Interrupt] deny by ability ...` |
| StateTag → Flow 条件 | `Player.BuildCombatContext` | `ConditionEvaluator` | WIRE | `[Flow] cond fail need=... have=...` |
| Flow Edge → Route 切换 | `CombatGraphRuntime` | `SkillEntryService` | WIRE | `[Flow] edge picked ...` |
| 旧 Can* 位清退 | 旧调用点 | 新判定链 | OPEN→WIRE | 构建期无新引用 |

## 五、Landing 计划（7 次）

### Landing 1/7：StateTag 使用边界固化
**做**
- 梳理 `StateTag` 的运行时可写位白名单（Physical/Phase/Window 时间行为/AllowInterrupt*）。
- 在 Inspector 与合并策略中明确禁用旧 `Can*` 新写入。

**不做**
- 不重做标签枚举。

**验收**
- 日志：`[Tag] write mask=...` 仅出现白名单位。

---

### Landing 2/7：ActionWindow 能力化字段
**做**
- `ActionWindow` 新增 `AllowedAbilityTags`（或能力类别位掩码）。
- Inspector 可视化：打断窗口一屏内可配置“类别+能力+优先级”。

**不做**
- 不改事件轨（`RuntimeEvents`）。

**验收**
- 保存资产后 YAML 可见新字段；运行时可读。

---

### Landing 3/7：ActionInterruptResolver 单点判定升级
**做**
- 判定链统一：
  1. 窗口是否打开
  2. Incoming Category 命中
  3. Incoming Priority >= MinIncomingPriority
  4. Incoming Ability 命中 `AllowedAbilityTags`
  5. SelfInterrupt 规则

**不做**
- 不把 CombatFlow 条件并入此处。

**验收**
- `Ability` 不允许时固定拒绝；日志清晰可解释。

---

### Landing 4/7：CombatFlow 与打断彻底分层
**做**
- CombatFlow 编辑器文案与字段区分：
  - “流转边条件” vs “打断窗口条件”
- Runtime 日志前缀分离：
  - `[Interrupt] ...`
  - `[Flow] ...`

**不做**
- 不新增复杂图算法。

**验收**
- 同一次输入可看见先过 Interrupt，再过 Flow（或反之失败原因明确）。

---

### Landing 5/7：技能流转条件最小闭环
**做**
- `SkillTransitionCondition` 重点支持并验收：
  - `OnInput`
  - `OnTime`
  - `OnAirborne/OnGrounded`
  - `WithMoveDirection`
  - `RouteCdReady`
- 对 `ConditionEvaluator` 输出结构化失败原因。

**不做**
- 不扩展新条件类型。

**验收**
- 四向与空地分支的条件拒绝/命中可稳定复现。

---

### Landing 6/7：编辑器语义清晰化（重点）
**做**
- ActionWindow Inspector：突出“打断许可”
- CombatFlow Inspector：突出“提前流转许可”
- 加互斥提示：当用户在错误区域配置对方语义时给 warning

**不做**
- 不改策划数据模型版本号。

**验收**
- 设计师可在 2 个面板独立完成配置，不再混淆。

---

### Landing 7/7：回归与清债
**做**
- 旧硬编码映射（Jump/Dash/Roll）迁移到 Ability 映射表。
- 增加最小回归集：
  1. 无窗口不可打断
  2. 有窗口但能力不允许不可打断
  3. 有窗口且能力允许可打断
  4. 非流转窗口不可提前流转
  5. 流转窗口条件满足可提前流转

**验收**
- 5 条全部通过，且日志归因唯一。

## 六、最小日志规范（本切片）
- 打断：
  - `[Interrupt] open={bool} cat={...} pri={...} ability={...} allow={bool} reason=...`
- 流转：
  - `[Flow] node={...} edge={...} cond={...} pass={bool}`
- 标签：
  - `[Tag] stateMask={...} phase={...}`

---

## 七、风险与规避
- 风险：Flow 与 Interrupt 仍有字段重叠导致“看起来可配，实际不生效”
  - 规避：编辑器分区 + 互斥警告 + 运行时前缀分离
- 风险：旧 Can* 位在某些路径仍被读取
  - 规避：逐步替换读取点为 AbilityService，并加 grep 守卫
- 风险：配置迁移导致旧资产行为变化
  - 规避：Landing 粒度迁移 + 每 Landing 验收脚本 + git tag 回滚

---

## 八、本蓝图对应诉求映射
- `StateTag`：保留体系、收敛职责、最小改动。
- `打断窗口`：能力化与优先级化，摆脱动作名硬编码。
- `技能流转`：从打断逻辑中解耦，成为独立“提前到达后继行为节点”的机制。
- `编辑器`：打断与流转双面板语义分离，避免“配了但跑不通”。
