# 182.3【技术文档】InheritPhysics 脆弱性根治 —— 多源 Duration 收口 / 单一权威模式

> **关联**：182.1 Stop Authoring Framework（架构蓝图）
> **触发**：182.1 P0 落地后 BUG 反复 —— "动画播完再位移"现象在几次修复中再次复发
> **本质定论**：**InheritPhysics 之所以脆，是因为它把"运行时算 Duration"引入；只要把 Duration 收口成 OnEnter 一次性算 + 全链路只读，脆弱性立即消失。**
> **本文档目标**：可执行的 BUG 修复技术规约 —— 6 处必修代码点 / 一对一探针 / 4 条单测 / 5 律脆弱性沉淀 / 方法论给未来 AI 协作者

---

| **现象** | InheritPhysics 模式 RunEnd："动画先播完，角色还在滑"现象复发 |
| **根因** | 多源 Duration（5 个口径并存），任一组件读错就脱钩 |

## §1 现象与历史回顾

### §1.1 用户视角现象

| 时间点 | 现象 | 当时假设的修法 |
|---|---|---|
| 166.3 落地 | DynamicBrake 播两遍 RunEnd | 重构成"Action 内部位移策略" |
| 166.4 修订 | Snap 偷偷不播动画 | 解耦 Strategy 与动画播放 |
| **182.1 P0 落地** | InheritPhysics + 高速：**动画先完成，位移还在滑** | 本文档处理 |
| **182.1 P0 + N 次修复后** | **同样现象再次复发** | 暴露根因 |

### §1.2 为什么屡修屡复发

每次单点修复只覆盖**多源 Duration 中的一个**。其他源仍按旧路径计算 → 任一组件再次读错就 BUG 重现。这是典型的**多源真相**反模式。

> **教训**：当一个 BUG 修了 3 次又复发，**不是修不对，是边界没收紧**。

## §2 根因分析：多源 Duration 5 口径

### §2.1 当前并存的 Duration 来源

```
┌─────────────────────────────────────────────────────────┐
│  Duration 口径全景                                       │
├─────────────────────────────────────────────────────────┤
│  A. ActionDataSO.Duration                                │
│     ↑ 配置值，"作者期望时长"，编辑期填写                  │
│                                                          │
│  B. ActionData.ResolveLogicalDurationSeconds()           │
│     ↑ 历史封装，可能套了 Stat 缩放                       │
│                                                          │
│  C. MotionProfile 自带 Duration                          │
│     ↑ MP 内部可能再算一次                                │
│                                                          │
│  D. StopRuntimeContext.RuntimeDuration                   │
│     ↑ ★ 应是 InheritPhysics 模式下的唯一权威             │
│                                                          │
│  E. AnimationClip.length / Segment.SegmentSeconds        │
│     ↑ 表现层时长（动画素材物理长度）                     │
└─────────────────────────────────────────────────────────┘
```

### §2.2 典型 BUG 链（多组件读错）

```
ActionState  → 用 A 算 nt
              → elapsed / Action.Duration = 0.5（早退）

MotionExecutor → 用 D 算位移
              → elapsed / RuntimeDuration = 0.3（晚完）

AnimController → 用 A.AnimSpeed × Curve
              → animator.speed = 1.0（不动态匹配）

★ 三轨脱钩 → 动画 t=1.0 播完了，位移还在 0.6 进度，视觉"动画先完再位移"
```

### §2.3 为什么"修对一处"不够

| 修法 | 覆盖范围 | 漏点 |
|---|---|---|
| 仅改 ActionState 用 D | nt 对了 | MotionExecutor / AnimController 还用 A |
| 仅改 MotionExecutor 用 D | 位移对了 | nt / AnimSpeed 还用 A |
| 仅改 AnimController | AnimSpeed 对了 | nt / 位移还用 A |
| **三处一起改 + 收口到 OnEnter 一次性 cache** | 全链路一致 | 无漏点 |

## §3 6 处必修代码点（可执行清单）

> **施工规约**：每处修完打 commit；运行单测；探针抓 drift%；再下一处。

| # | 文件 | 错路径 | 收口正解 | 行级修改 |
|---|---|---|---|---|
| **1** | `PlayerActionState.OnEnter` | 不算 stopCtx，仅记 startTime | 先调 `StopMotionRuntime.Build` → 缓存 `m_stopCtx` + `m_stopActive` | +8 行 |
| **2** | `PlayerActionState.OnLogicUpdate` 计 nt | `nt = elapsed / m_action.Duration` | `nt = elapsed / ResolveDurationSeconds()` | -1/+1 |
| **3** | `PlayerActionState` 退出闸门 | 同 #2 错（自动跟着 #2 修） | 同 #2 正 | 0 |
| **4** | `MotionExecutor.Begin` 时长入参 | `motionDuration = action.Duration` | `motionDuration = m_stopCtx.RuntimeDuration` | -1/+1 |
| **5** | `MotionExecutor.SampleLocalDelta` / `Tick` | 自己缓存 dur 并算 nt | **nt 由 ActionState 推送**，内部不再算 | -10/+4 |
| **6** | `PlayerAnimController.SetActionSpeed` | `speed = action.AnimSpeed × Curve(nt)` | **`speed = (RefDur / RuntimeDur) × Curve(nt)`**（InheritPhysics 时） | -2/+6 |

## §4 单一闸门模式（PlayerActionState 实现）

### §4.1 字段 + OnEnter

```csharp
public sealed class PlayerActionState : EntityState<Player>
{
    StopRuntimeContext m_stopCtx;
    bool  m_stopActive;          // EnableStopFeature && Mode != Disabled
    float m_startTime;

    protected override void OnEnter(Player p)
    {
        m_startTime = Time.time;

        // ★ Step 1：OnEnter 一次性 Build（运行期不再重算）
        var entrySpeed = p.PlanarVelocity.magnitude;
        m_stopCtx = StopMotionRuntime.Build(m_action, entrySpeed);
        m_stopActive = m_action.EnableStopFeature
                       && m_stopCtx.Mode != StopMode.Disabled;

        // ★ Step 2：把同一 ctx 推送给所有下游
        m_motionExecutor.Begin(
            m_action.MotionProfile,
            m_stopCtx.RuntimeDuration,    // ← 不传 action.Duration
            m_stopCtx);                    // ← ctx 透传
        p.AnimController.PlayAction(m_action, m_stopCtx);

        // ★ Step 3：探针 — 详见 §7
        StopProbe.LogBuild(m_action, in m_stopCtx, entrySpeed);
    }
}
```

### §4.2 单一对外口径

```csharp
/// <summary>★ 唯一对外 Duration 口径；任何组件读 Action 时长都走这里。</summary>
public float ResolveDurationSeconds()
    => m_stopActive
       ? m_stopCtx.RuntimeDuration
       : m_action.Duration;
```

**铁律**：`ResolveDurationSeconds()` 是**整个 Action 系统唯一**的时长访问点。grep `m_action\.Duration` 之外的旧调用必须为 0（探针 / 测试代码除外）。

### §4.3 Tick 推送

```csharp
protected override void OnLogicUpdate(Player p)
{
    var dur = ResolveDurationSeconds();
    var elapsed = Time.time - m_startTime;
    var nt = dur > 0.001f ? Mathf.Clamp01(elapsed / dur) : 1f;

    // ★ 子系统不再自己算 nt；由这里单点推送
    m_motionExecutor.Tick(nt);
    p.AnimController.UpdateActionSpeed(nt);

    if (nt >= 1f)
    {
        StopProbe.LogExit(m_action, in m_stopCtx,
            actualElapsed: elapsed,
            actualDistance: p.PlanarTraveledSinceActionStart);
        ExitToBaseline(p);
    }
}
```

## §5 PlayerAnimController 单一公式

### §5.1 收口前（旧路径，多写入点）

```csharp
// 旧 A：CrossFade 时一次性写
m_animator.CrossFade(clip.name, t);
m_animator.speed = m_currentAction.AnimSpeed;

// 旧 B：每帧 ActionState 改写
m_animator.speed = m_currentAction.AnimSpeed * curve.Evaluate(nt);

// 旧 C：其它子系统也可能改 speed
// ...
```

**问题**：3 处都能写 `animator.speed` → 任一处错就 BUG。

### §5.2 收口后（**唯一写入点**）

```csharp
public sealed class PlayerAnimController
{
    StopRuntimeContext m_stopCtx;
    ActionDataSO m_currentAction;

    public void PlayAction(ActionDataSO action, in StopRuntimeContext stopCtx)
    {
        m_currentAction = action;
        m_stopCtx = stopCtx;
        m_animator.CrossFade(action.MainClip.name, transitionDur);
        // ★ 不写 m_animator.speed；由 UpdateActionSpeed 接管
    }

    /// <summary>★ 整个项目内唯一允许写 m_animator.speed 的方法。</summary>
    public void UpdateActionSpeed(float normalizedT)
    {
        if (m_currentAction == null) return;

        var baseSpeed = m_stopCtx.Mode == StopMode.InheritPhysics
            ? m_currentAction.ReferenceDuration / Mathf.Max(0.001f, m_stopCtx.RuntimeDuration)
            : m_currentAction.AnimSpeed;

        var curve = m_currentAction.AnimSpeedCurve;
        var multiplier = curve != null ? curve.Evaluate(normalizedT) : 1f;

        m_animator.speed = baseSpeed * multiplier;       // ★ 唯一写入点
    }
}
```

### §5.3 防再犯：grep 锁

CI / 单测中加一条：
```
grep -rn "m_animator\.speed\s*=" Assets/GameMain/Scripts \
   | grep -v "ActionTimelineEditor"            # 编辑期预览除外
   | grep -v "PlayerAnimController\.cs"        # 唯一允许处
   | exit code 1 if non-empty
```

**任何新增 `animator.speed = ...` 调用都会让 CI 红灯**。

## §6 MotionExecutor 取消自治时间

### §6.1 收口前（旧自治）

```csharp
public void Begin(MotionProfileSO mp, float duration)
{
    m_profile = mp;
    m_duration = duration;
    m_startTime = Time.time;
}

public Vector3 Tick()                              // ← 自己算时间
{
    var elapsed = Time.time - m_startTime;
    var nt = elapsed / m_duration;                  // ← 自治 nt
    ...
}
```

**问题**：`m_duration` 与 ActionState 的 ResolveDurationSeconds 可能不一致；`m_startTime` 与 ActionState 的 m_startTime 可能漂移 1 帧。

### §6.2 收口后（**外部推送 nt**）

```csharp
public void Begin(MotionProfileSO mp, float motionDuration, in StopRuntimeContext stopCtx)
{
    m_profile = mp;
    m_duration = motionDuration;       // ★ 由 ActionState 注入，不自算
    m_stopCtx = stopCtx;
    m_prevNt = 0f;
}

public Vector3 Tick(float currentNt)   // ★ nt 由外部喂入
{
    Vector3 delta;
    switch (m_stopCtx.Mode)
    {
        case StopMode.Snap:
            delta = Vector3.zero;
            break;

        case StopMode.InheritPhysics:
            // 节奏曲线归一化采样 → 乘 runtimeDistance
            var p0 = m_profile.AxisCurves.SampleLocalPosition(m_prevNt);
            var p1 = m_profile.AxisCurves.SampleLocalPosition(currentNt);
            var normalizedDelta = p1 - p0;
            delta = Vector3.Scale(normalizedDelta * m_stopCtx.RuntimeDistance,
                                  m_stopCtx.ApplyMask);
            break;

        case StopMode.MotionProfile:
        default:
            delta = m_profile.AxisCurves.SampleLocalDelta(m_prevNt, currentNt);
            break;
    }
    m_prevNt = currentNt;
    return delta;
}
```

## §7 一对一探针 `[Stop]`（防再犯核心）

### §7.1 三档输出（OnEnter / 关键 nt / OnExit）

```csharp
internal static class StopProbe
{
    public static void LogBuild(ActionDataSO action,
        in StopRuntimeContext ctx, float entrySpeed)
    {
        if (!Player.DebugStop) return;
        var baseAnim = ctx.Mode == StopMode.InheritPhysics
            ? action.ReferenceDuration / Mathf.Max(0.001f, ctx.RuntimeDuration)
            : action.AnimSpeed;
        Debug.Log(
            $"[Stop] action={action.name} mode={ctx.Mode} entrySpeed={entrySpeed:F2}\n" +
            $"       runtimeDuration={ctx.RuntimeDuration:F3} " +
            $"runtimeDistance={ctx.RuntimeDistance:F2}m " +
            $"ref={action.ReferenceDuration:F3} → baseAnim={baseAnim:F3}");
    }

    public static void LogExit(ActionDataSO action,
        in StopRuntimeContext ctx, float actualElapsed, float actualDistance)
    {
        if (!Player.DebugStop) return;
        var expectedDur = ctx.RuntimeDuration;
        var expectedDist = ctx.RuntimeDistance;
        var durDrift = Mathf.Abs(actualElapsed - expectedDur) / Mathf.Max(0.001f, expectedDur);
        var distDrift = Mathf.Abs(actualDistance - expectedDist) / Mathf.Max(0.001f, expectedDist);
        var maxDrift = Mathf.Max(durDrift, distDrift);
        var prefix = maxDrift > 0.05f ? "[Stop][WARN]" : "[Stop]";

        Debug.Log(
            $"{prefix} EXIT action={action.name}\n" +
            $"       actualElapsed={actualElapsed:F3}  expectedDur={expectedDur:F3}\n" +
            $"       actualDistance={actualDistance:F2}m  expectedDistance={expectedDist:F2}m\n" +
            $"       drift={maxDrift * 100f:F1}%");
    }
}
```

### §7.2 期望输出（正常）

```
[Stop] action=RunEnd mode=InheritPhysics entrySpeed=5.20
       runtimeDuration=0.330 runtimeDistance=1.62m ref=0.250 → baseAnim=0.758
[Stop] EXIT action=RunEnd
       actualElapsed=0.331  expectedDur=0.330
       actualDistance=1.61m  expectedDistance=1.62m
       drift=0.6%
```

### §7.3 异常输出（漏改点自动浮现）

```
[Stop][WARN] EXIT action=RunEnd
       actualElapsed=0.500  expectedDur=0.330        ← Action 退出晚于预期 = #2/#3 没收口
       actualDistance=1.62m  expectedDistance=1.62m
       drift=51.5%                                     ← 自动告警
```

> **drift 含义**：duration 漂移 = ActionState 端漏改；distance 漂移 = MotionExecutor 端漏改。**一行日志直接定位文件**。

### §7.4 实例化建议（最小开销）

- `Player.DebugStop` 总开关默认关闭
- 探针仅在状态翻转（OnEnter / OnExit）触发，**不每帧打**
- 一次完整 RunEnd 仅 2 行输出，无刷屏

## §9 5 律脆弱性沉淀（**方法论**）

| # | 脆弱点 | 防御机制 | 落点 |
|---|---|---|---|
| **1** | 多源 Duration | `ResolveDurationSeconds()` 唯一口径 | §4.2 |
| **2** | 子系统自治时间 | nt 由 ActionState **单点推送** | §6.2 |
| **3** | 动画速率多写入点 | `UpdateActionSpeed` 唯一写入 + CI grep 锁 | §5.2/§5.3 |
| **4** | runtimeDuration 重算 | OnEnter 算一次，运行期只读 | §4.1 |
| **5** | InheritPhysics / MP 旧路径切换遗漏 | 显式 `m_stopActive` 标志位 + 探针每次 Build 记录 | §4.1/§7.1 |

### §9.1 通用方法论 —— "**单一权威 + 一次性算 + 全链路只读**"

> 当一个 BUG 修了 3 次仍复发，说明**问题不在算错，在边界没收紧**。
>
> 解法 = **缩成单源 + 一次性 cache + 让其它组件只读**。

适用面：
- 时间 / 时长（本案例）
- Tag mask / 状态位（168.3 Air Interrupt）
- 配置覆盖（177.1 Stance Loadout）
- 任何"运行时动态计算 + 多组件消费"的场景

### §9.2 反模式速查

| 反模式 | 表现 | 后果 |
|---|---|---|
| **多源真相** | 5 个组件各算 Duration | BUG 修不完 |
| **自治时间** | 子系统读自己缓存的时间 | 帧间漂移 |
| **多写入点** | N 处都能写 `animator.speed` | 任一漏改就 BUG |
| **每帧重算** | OnLogicUpdate 重算 stopCtx | 入场速度变化导致动画跳变 |
| **隐式默认值** | StopMode 默认 Disabled 但代码假设 InheritPhysics | 旧资产不勾开关时 BUG |

## §12 方法论沉淀（**给未来 AI 协作者**）

### §12.1 三句话沉淀

> 1. **修了 3 次还复发的 BUG，问题不在算错，在边界没收紧** —— 缩成单源
> 2. **OnEnter 一次性 cache + 全链路只读** —— 避免运行期漂移
> 3. **唯一写入点 + CI grep 锁** —— 让"漏改"在代码评审前就红灯

### §12.2 AI 协作时的 "收口三步法"

| 步骤 | 行动 |
|---|---|
| ① **找权威** | 当前系统中"该是单源真相"的字段是什么？给它一个明确的 Owner |
| ② **加入口** | 提供 `Resolve***()` 唯一对外口径；其它组件只能读这个 |
| ③ **断后路** | CI 加 grep 锁；单测兜底；探针 drift 监控 |

### §12.3 实施时的"先探针后修复"原则

**反例**：拿到 BUG 直接改代码 → 改完跑一次测试 → 仍有 BUG → 再改 → 死循环。

**正例**：
1. 先加一对一探针让 BUG 自己"自我描述"（drift%、来源、字段值）
2. 探针定位到具体文件 / 组件 / 字段
3. 一次性 6 处全改（按收口清单）
4. 再跑探针验证 drift% 全部 < 5%
5. 加单测锁死

### §12.4 反模式清单（给 AI 协作时避免）

| 反模式 | 防御 |
|---|---|
| 直接 `m_animator.speed = X` 写多处 | 单一写入点 |
| 子系统自己读 `Time.time` 算时间 | nt 由 State 推送 |
| 配置默认值与代码假设不一致 | 显式 `m_stopActive` bool 标志位 |
| 修了 3 次还复发 | 不是修不对，是边界没收紧 |
| 验收靠"跑一次看视觉" | drift% + 单测 + 静态 grep |
