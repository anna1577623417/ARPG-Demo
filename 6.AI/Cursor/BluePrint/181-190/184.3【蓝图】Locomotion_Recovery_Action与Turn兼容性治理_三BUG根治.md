# 184.3【蓝图】Locomotion Recovery Action 与 Turn 兼容性治理 —— 三 BUG 根治

> **基线**：184.1 Facing/Turn 解耦已落位
> **触发**：184.1 落位后实测发现 3 个 Locomotion ↔ Recovery Action ↔ Tap Turn 三方协作问题

## §0 三 BUG 现象与根因

### §0.1 BUG 1：松开 W → 快速 D+Space 不能向右翻滚

**现象**：
```
玩家 Hold W → 松开 W → 0.1s 内按 D+Space
期望：向右翻滚（Dodge Right）
实际：无反应（Dodge Intent 被吃掉）
```

**根因链**（代码定位）：

| 阶段 | 文件 | 行为 |
|---|---|---|
| 1 | `PlayerLocomotionState.cs:296-301` | `wasHadInput && !hasInput` → 触发 `LocomotionStateId.WalkEnd` |
| 2 | `PlayerLocomotionState.cs:334` | `States.Change<PlayerActionState>()` 进 ActionState |
| 3 | `PlayerActionState.TryConsumeGameplayIntent` | 查 `ActionWindow.InterruptibleByCategories` |
| 4 | WalkEnd 资产 | **InterruptibleByCategories 未含 Defensive/Skill** → 拒收 Dodge Intent |

→ **WalkEnd 作为 Recovery 表现 Action，却被当作普通 Action 用闸门拦截**。

### §0.2 BUG 2：角色面朝左但逻辑位移向前（概率复现）

**现象**：
```
连续切换方向输入 → 偶发：模型朝左，但 Transform.forward 朝前
玩家视觉：角色侧向滑步前进（八字身形不对）
```

**根因链**：

| 阶段 | 文件 | 行为 |
|---|---|---|
| 1 | `Player.SetLogicForward` (line 487-519) | `transform.rotation = LookRotation(m_logicForward)` ★ 同帧 |
| 2 | 同上 | `visualRoot.rotation = visualWorldRot` ★ Visual 保留旧朝向 |
| 3 | `VisualFacingDriver.LateUpdate` | `RotateTowards(target, 720°/s × dt)` ★ 缓追 |
| 4 | KCC 移动方向 | 用 `Player.LogicForward`（即新朝向） |
| 5 | **角差 180° / 720°/s = 0.25s 缓追期间** | Visual 朝旧方向 + KCC 按新方向 → **视觉错位 0.25s** |
| 6 | 若期间 Hold 持续触发 SetLogicForward | Visual 永远追不上（每帧 Logic 又动了一点）|

→ **VisualFacingDriver 角速度恒定 720°/s，大角差时缓追时间过长**，且 Hold 期间 Turn 动画无机制触发。

### §0.3 BUG 3：Tap 转向与 WalkEnd/RunEnd 不兼容

**现象**：
```
玩家跑步 → 松开 W → RunEnd 播放中 → Tap D 想转身
期望：立刻转向东并进 Turn 动画
实际：Tap D 无反应；RunEnd 播完后才能转向
```

**根因链**：

| 阶段 | 现象 |
|---|---|
| 1 | RunEnd 进入 PlayerActionState |
| 2 | Tap Turn 的处理逻辑在 `PlayerController` + `PlayerLocomotionState` 内 |
| 3 | ActionState 期间 Tap Intent **没有被 PlayerActionState 路径消费** |
| 4 | LogicForward 也不会被改写（无 Tap Turn 入口） |
| 5 | 玩家被锁在 RunEnd 整段播放时长内 |

→ **与 BUG 1 同源**：Tap Turn 也需要打断 Recovery Action 的能力。

### §0.4 同源结论

**三 BUG 同根**：WalkEnd / RunEnd / 类似的 Recovery 表现 Action 当前**没有"我是 Recovery，所有主动输入都该打断我"**的元信息；通用 ActionWindow 闸门按"战斗 Action"标准控制打断，**过严**。

## §1 设计原则

> **Recovery 表现 Action（WalkEnd / RunEnd / WalkStart / RunStart）≠ 战斗 Action**
>
> - 战斗 Action：通过 ActionWindow.InterruptibleByCategories 精确控制打断窗口
> - Recovery 表现 Action：**任何主动 Intent 都该立刻打断**（手感优先）

### §1.1 三条铁律

| 铁律 | 含义 |
|---|---|
| **Recovery 是表现而非战斗** | 标记位区分；闸门策略不同 |
| **Tap Turn 跨状态生效** | 不论当前在 Locomotion / ActionState(Recovery)，Tap 都能改 LogicForward + 打断 Recovery |
| **Visual 缓追要对大角差敏感** | 角速度动态：小角差柔顺、大角差快速；避免视觉错位 |

```csharp
// PlayerActionState.TryConsumeGameplayIntent
public override bool TryConsumeGameplayIntent(Player player, in FrameContext ctx, in GameplayIntent intent)
{
    if (intent.Kind == GameplayIntentKind.Move) return true;
    if (!IntentRouter.IsRoutable(in intent)) return false;

    // 184.3 — Recovery 表现 Action：跳过 ActionWindow 闸门，主动 Intent 直接打断
    if (m_action != null && m_action.IsLocomotionRecovery)
    {
        var incomingAction = IntentRouter.PeekActionDataForRouting(player, in intent);
        var incomingCategory = ActionInterruptResolver.ResolveIncomingCategory(in intent, incomingAction);
        // 仍尊重 IdleFallback 兜底（168.3 契约）
        if (incomingCategory == ActionCategory.IdleFallback) return false;

        TurnProbe.LogRecoveryInterrupt(player, m_action, intent.Kind, incomingCategory);
        return IntentRouter.Route(player, in intent, forceActionReentry: false);
    }

    // 旧路径：通过 ActionWindow 闸门
    return base.TryConsumeGameplayIntent(player, in ctx, in intent);
}
```

### §2.4 Visual 缓追的动态角速度

```csharp
// VisualFacingDriver 改造
[SerializeField] float m_baseAngularSpeedDeg = 540f;
[SerializeField] float m_fastAngularSpeedDeg = 1440f;
[SerializeField] float m_fastTriggerAngleDeg = 60f;        // 角差 ≥ 60° 用 fast 速度
[SerializeField] AnimationCurve m_speedCurve;              // 可选：角差→倍率曲线

void LateUpdate()
{
    if (m_player == null) return;
    if (m_animController != null && m_animController.IsPlayingTurnPresentation) return;

    var logicForward = m_player.LogicForward;
    if (logicForward.sqrMagnitude < 0.0001f) return;

    var target = Quaternion.LookRotation(logicForward, Vector3.up);
    var deltaAngle = Quaternion.Angle(transform.rotation, target);

    // 184.3 — 大角差时用 fast 速度（避免视觉错位）
    var maxSpeed = deltaAngle >= m_fastTriggerAngleDeg
        ? m_fastAngularSpeedDeg
        : m_baseAngularSpeedDeg;

    transform.rotation = Quaternion.RotateTowards(
        transform.rotation, target, maxSpeed * Time.deltaTime);
}
```

**参数建议**：
- `baseAngularSpeedDeg = 540` —— 小角差柔顺
- `fastAngularSpeedDeg = 1440` —— 大角差快速（180° / 1440° = 0.125s）
- `fastTriggerAngleDeg = 60` —— 触发阈值与 LocomotionTuning.Turn90Threshold 同步

```csharp
        $"[Turn] VISUAL-LAG delta={deltaAngleDeg:F1}° speed={chosenSpeedDeg:F0}°/s " +

}
```

## §6 关键架构约束

1. **IsLocomotionRecovery 仅标记 Locomotion 表现 Action** —— 战斗 Action（Attack/Skill/Dodge）严禁勾选
2. **Recovery 旁路也尊重 168.3 IdleFallback** —— 自动 Idle 仍不打断
3. **Tap Turn 在 Recovery 期间走"改 Forward + ExitToBaseline"模式** —— 不在 Action 内直接播 Turn 动画
4. **Visual 大角差用 fast 速度** —— 阈值与 Turn90Threshold 同步
5. **Stop Feature 优先级高于 Recovery** —— RequiresLogicForwardLock 时 IsLocomotionRecovery 标记失效

## §7 反模式清单（本次暴露）

| 反模式 | 防御 |
|---|---|
| **所有 Action 用同一闸门** | Recovery 表现 Action 独立旁路 |
| **Tap Turn 仅在 Locomotion 状态机内生效** | 跨 State 路径（Recovery 期间也能 Tap） |
| **Visual 缓追角速度恒定** | 动态：base 柔顺 / fast 抢救 |
| **未区分"表现 Action" vs "战斗 Action"** | 明确字段标识 + Inspector Tooltip 警示 |

## §8 三句话沉淀

> 1. **Recovery 表现 Action ≠ 战斗 Action** —— 闸门策略必须不同
> 2. **Tap Turn 是全局 Intent** —— 不受当前 State 是否在 Locomotion 限制
> 3. **Visual 缓追要对大角差敏感** —— 540°/s 柔顺 + 1440°/s 抢救，避免视觉错位
