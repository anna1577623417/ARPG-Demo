## 二、ContinuousLocomotion 字段引入（解决 #1 + #2 双数据源）

### 2.1 目标契约

> **统一入口**：所有 Clip 都包成 `ActionDataSO`；Profile.Binding 只引用 ActionDataSO，不再裸 AnimationClip。
> **二态分支**：ActionDataSO 上新增 `IsContinuousLocomotion: bool`。
>   - `true` → Locomotion State **内** 直接播 Loop（不切 ActionState），等同于旧 ContinuousClip 路径
>   - `false` → 现行 Discrete 路径（ArmPendingAction + Change&lt;ActionState&gt;）
> **字段联动**：当 IsContinuousLocomotion=true 时，Action SO Inspector 屏蔽离散字段：
>   - 隐藏：`Duration` / `InterruptPriority` / `InterruptStability` / `AllowSelfInterrupt` / `Windows` / `TimelineMarkers` / `TeleportTriggers`
>   - 强制：`MainClip.isLooping = true`（通过 SerializedObject 改 Clip importer setting 或运行时 Loop 标志）
>   - 保留：`MainClip` / `CrossfadeTime` / `AnimSpeed` / `MotionProfile`（可空） / `IntentCategory=Locomotion`（强制） / `GraphParticipation=SourceOnly`（强制）

### 2.2 数据结构变更（Landing 1）

### 2.3 ActionDataSO Inspector 联动（Landing 2）

### 2.4 运行时分发（Landing 3）

`PlayerLocomotionState.TryRouteDiscreteLocomotionAction` 改造：

```csharp

if (actionSO == null) return false;
```

### 2.5 哪些状态需要 Action 配置位移（用户直问）

| 状态 | 类型 | MotionProfile 建议 | 原因 |
|---|---|---|---|
| **Idle** | Continuous | 无 | 站立无位移 |
| **Move (Walk/Run Loop)** | Continuous | 无（位移由 MoveByLocomotionIntent 程序计算） | 连续移动靠 KCC + Velocity，不靠 Clip RootMotion |
| **WalkStart / RunStart** | Discrete | **建议有**（Z 加速曲线 0→1）| 起步段需要平滑加速；Clip 自带 RootMotion 也行（二选一） |
| **WalkEnd / RunEnd** | Discrete | **建议有**（Z 制动曲线 1→0）| 急停段需要平滑减速 |
| **JumpStart** | Discrete | 可有可无 | 跳起初速由 `Player.Jump(force)` 给 vy；JumpStart Action 通常不动 Y |
| **JumpLand** | Discrete | **强烈建议有**（Y 制动 + Z 制动） | 解决"落地滑步" |
| **Pivot/TurnInPlaceDirected** | Discrete（推荐 Continuous） | 可有可无 | 转身主要靠 Clip RootMotion 旋转 |
| **Air (JumpLoop)** | Continuous | 无 | 滞空由重力 + AirMoveMultiplier 控制 |
| **Strafe*** | Continuous | 无 | 8 向移动由 KCC + Velocity 控制；Clip 只表现 |
| **Sprint** | Continuous | 无 | 同 Move |

> **总结口诀**：连续状态**不配** MotionProfile（用 KCC 速度）；离散状态**视情况配**（起步/急停/落地建议配，转身/起跳一般无需）。

## 三、跳跃落地循环 — Log 探针设计（解决 #3）

### 3.1 假设矩阵

```
H1：JumpStart Action 走 ExitToBaseline → IntentCategory=Locomotion → 跳过 JumpLand 分支 → Change<Locomotion>
H2：Locomotion 见 !IsGrounded → Change<Airborne>
H3：Airborne.OnEnter ConsumeJumpFromIntent=false → mid-air 分支；JumpStart 不重新 arm
H4：Airborne 直到 IsGrounded → TryExitToLandOrLocomotion → 若 ctx.JumpLand==null → Change<Locomotion>
H5：Locomotion 检测如 hasInput → 进 Move Loop
```

**疑点**：
- H4 中 ctx.JumpLand 是从 **SkillEntryLoadoutSO.LocomotionGraphContext** 读，**不是** LocomotionProfile.JumpLand。两者不一致 → 用户配了 LocomotionProfile.JumpLand 但没配 SkillEntryLoadoutSO.LocomotionGraphContext.JumpLand → JumpLand 永不触发
- H2 + H3 之间如果 `m_pendingJumpStartArmed=true`（OnEnter reset 后被 159.1 改逻辑重置）— 不会，确认 OnEnter 重置 `_pendingJumpStartArmed=false`
- 如果用户 LocomotionProfile.Bindings 配了 JumpStart Action 但触发逻辑回 Locomotion 后又被 Detect 误判为 press 边沿（163.1 已 fix）

## 四、转向延迟根因（解决 #4）

### 4.1 现状

`PlayerLocomotionState.OnLogicUpdate` 序：
```
1. TryRouteDiscreteLocomotionAction (Detect → 大角度 → TurnInPlaceDirected 切 ActionState)
2. 若上面没切，TurnResolver.Tick → TurnInfo
3. MoveByLocomotionIntent → LookAtDirection（平滑旋转）
4. ApplyMotor
```

转向有 3 条路径：
- **路径 A**：Profile 注册 TurnInPlaceDirected + DiscreteAction → 切 ActionState 播 Turn Action。**期间 LookAtDirection 不跑，旋转完全依赖 Turn Clip 的 RootMotion**。若 Clip 无 RootMotion 或不旋转 → 角色站着 Clip 转
- **路径 B**：Profile 未注册 TurnInPlaceDirected → 走 MoveByLocomotionIntent → 每帧 LookAtDirection MoveTowards 平滑旋转。**RotationSpeed** 控制速率
- **路径 C**：刚切回 Locomotion 但 m_pivotCooldownRemaining 还在 → 走 path B

### 4.2 假设 + 验证

| 假设 | 验证方式 |
|---|---|
| Turn Clip 无 RootMotion → 角色不转 | Inspect Turn Clip 的 Animation Type / RootMotion Curves；Animator.applyRootMotion 必须 = true |
| RotationSpeed 太慢（Locomotion 路径 B） | Tuning.RotationSpeedDegPerSec 当前 540°/s；改成 720°/s 试 |
| m_pivotCooldownRemaining=0.4 阻挡新 Turn | 看 [LocoResolver] 是否 `m_pivotCooldownRemaining` 在转身期间持续 > 0 |
| Turn 切 ActionState 后位移被锁定 | 看 Action 期间 ControlOwner=Action；MoveByLocomotionIntent 不跑（已知） |

### 4.3 短期改善建议

- **Turn 走 ContinuousLocomotion 模式**：把 Turn Action 标 `IsContinuousLocomotion=true`，不切 ActionState；让 `LookAtDirection` 继续每帧旋转角色 forward，**Turn Clip 只做表现**。这样 Pivot 不再"卡住位移仲裁"
- **Tuning.RotationSpeed 提高**：540°/s → 720°/s（180° 转身 0.25s）
- **Pivot 冷却降低**：PivotReentrySeconds=0.4 → 0.2 或动态等于 Action 时长

## 五、Motion 位移播完才动（解决 #5）

### 5.1 假设

KB-09 §10 明确控制权矩阵 [待验证]，最可能的冲突源：

```
Animator.applyRootMotion = true
  → Clip 自带 RootMotion 每帧推 transform
  → PlayerKCCMotor 接受 desiredVelocity 但被 Animator 直接位移覆盖
```

或者反过来：
```
MotionExecutor.SetDesiredVelocity 每帧调用
  → KCC.Move(velocity * dt)
  → 但 Animator.applyRootMotion 也尝试 transform.Translate
  → 二者顺序冲突；Animator 在 LateUpdate，KCC 在 FixedUpdate / Update
  → 最终 transform 由后写入者决定，可能看似"播完才动"
```

### 5.2 诊断 Log

在 `MotionExecutor.TickAxisCurves` 已有 `[Motion] sample motionT=... deltaLocal=...`。再加：

```csharp
// PlayerKCCMotor.MoveByDesiredVelocity 之类入口
DebugLog($"[KCC][In] desiredVel={desiredVelocity} animRootMotion={animator.applyRootMotion} " +
        $"transformBeforeMove={transform.position} frame={Time.frameCount}");

// PlayerKCCMotor 移动完成后
DebugLog($"[KCC][Out] transformAfterMove={transform.position} delta={delta} " +
        $"plannedDelta={desiredVelocity * Time.deltaTime} frame={Time.frameCount}");
```

若 `delta != plannedDelta`，RootMotion 在干预；若延迟 N 帧才看到 delta，Animator 与 KCC 时序错位。

### 5.3 短期治理

- **关闭 Animator.applyRootMotion** for ActionData 含 MotionProfile 的情形：让 MotionExecutor 全权
- **或者**：Action SO 加字段 `MotionDriver { ClipRootMotion, ProgrammaticCurves }`，二选一不可同时
- 默认推荐：起步 / 急停 / 落地 → Programmatic Curves；转身 → Clip RootMotion（旋转走骨骼）

### 13.3 转向行为最终契约（点按式）

#### A. 触发规则

| 输入序列 | 角色当前 | 期望行为 |
|---|---|---|
| 站立 Idle，**点按** A | forward=(0,0,1) | 原地左转 90°（Turn90L Action） → 回 Idle |
| 站立 Idle，**点按** D | forward=(0,0,1) | 原地右转 90° → 回 Idle |
| 站立 Idle，**点按** S | forward=(0,0,1) | **180° 转身**（带左右判断：按 S 默认右转；可配） → 回 Idle |
| 站立 Idle，**持续按** D | forward=(0,0,1) | Turn90R → 转完后接 WalkStart Action → Run/Walk Loop |
| **跑动中**按 S | forward=(0,0,1) | 急停 (RunEnd) + Turn180 + Run Loop 朝后（顺序由设计师决定）|
| **交替狂按** A→D→A→D | 任何 | **绝对时间冷却**：第一次 Turn 触发后 0.4s 内不再触发新 Turn；之间的输入按 priority 5 走 Move Loop |

#### B. Detect 优先级（v2 修订）

```
1. 大角度 ≥ Pivot180Threshold (135°) + 非冷却 → TurnInPlaceDirected + L180/R180
2. 大角度 ≥ Pivot90Threshold (70°) + 非冷却 → TurnInPlaceDirected + L90/R90
3. release 边沿 → WalkEnd / RunEnd（按 m_lastWantsRun）
4. press 边沿 → WalkStart / RunStart（按当帧 WantsRun）  
   ★ press 边沿仅当角度 < Pivot90Threshold 时触发；否则归 Turn 优先级
5. LockedOn + hasInput → StrafeLocomotion + dir（暂不通电）
6. 持续 hasInput → Move
7. !hasInput → Idle
```

> 优先级 4 内嵌"角度小才走 Start"，**自动协作奥德赛模式**：站立按 D（90°差）→ 先 Turn90，转完角度归 0 → 续按 D 走 WalkStart Loop。

#### C. AD 防抖（绝对时间冷却）

**当前 bug**：`m_pivotCooldownRemaining` 在 LocomotionState.OnLogicUpdate 中按 Time.deltaTime 衰减；但 ActionState 期间 OnLogicUpdate 不跑，且 OnEnter 又把它清零 → **冷却失效，AD 抽搐**。

**修复**：用绝对时间戳替代帧累减。

```csharp
// 字段
private float m_lastTurnFireTime = -10f;
private const float TurnReentryCooldownSeconds = 0.4f;

// 触发 Turn 后
m_lastTurnFireTime = Time.time;

// 检查冷却
bool TurnCooldownReady() => Time.time - m_lastTurnFireTime >= TurnReentryCooldownSeconds;

// 在 Detect 优先级 1 / 2 加判定：
if (hasInput && TurnCooldownReady())
{
    // ... 大角度判定 ...
}
```

`OnEnter` **不再**清零（绝对时间天然跨状态有效），把 `m_pivotCooldownRemaining` 字段连同清零逻辑全删。

### 13.4 奥德赛启动手感（新增 §5b）

#### 目标

- **短按移动键**：缓慢移动一小段，反复 Start ↔ Idle 切换（"嗒、嗒、嗒"小步走）
- **长按移动键**：经过 Start 段过渡到 Run/Walk Loop
- **启动过程可配**："别太满"——既不是僵直瞬移到全速，也不是磨蹭 1 秒才动

#### 实现要点

1. **WalkStart Action 必须有 Z 位移**（不能是原地踏步动画）；Z 曲线建议 0→0.5（不到 1，留给 Move Loop 继续加速）。
2. **WalkStart Action Duration 可配**：通过 ActionDataSO.Duration（Continuous=false 时启用）。Tuning 加 `Tuning.StartActionDurationScale`（默认 1.0；可全局缩放所有 Start 类 Action）。
3. **短按反复触发条件**：WalkStart Action 后摇 Window `[0.7, 1.0]` 配 `InterruptibleByCategories = Locomotion` → 玩家在 Start 末段松手 → WalkEnd 立刻接 → 再按又触发 WalkStart。**自然达成 Start ↔ Idle 切换**。
4. **奥德赛"小步走"位移量**：由 WalkStart Action 内 MotionProfile.Z 曲线 + Tuning.StartActionDurationScale 决定。短期内若用户觉得"太慢"，**调大 Z 曲线尾值**或**缩短 Duration**；觉得"太冲"则反之。

#### 设施

| 字段 | 位置 | 默认 | 用途 |
|---|---|---|---|
| `LocomotionTuningSO.StartActionDurationScale` | Tuning | 1.0 | 全局缩放 WalkStart/RunStart Duration |
| `ActionDataSO.Duration` | Action SO | 0.25-0.45 (设计师定) | WalkStart/RunStart 一次性段时长 |
| `ActionDataSO.MotionProfile.Z` | Action SO 嵌套 | 0→0.5 曲线 | 启动段位移量 |

#### 验收

| 操作 | 期望 |
|---|---|
| Idle，点按 W 一下（< 0.2s）| 角色播 WalkStart Action 一次，移动一小段 ≈ 0.5m，松手后 WalkEnd 收回 Idle |
| Idle，连续点按 W 3 次 | Start ↔ Idle 切换 3 次（"嗒、嗒、嗒"）|
| Idle，长按 W（> 0.5s）| WalkStart → 进入 Walk/Run Loop 持续移动 |
| Idle，点按 D 一下 | Turn90R → Idle（**不进 WalkStart**，因为 priority 1 抢先；松手后角度归 0）|
| Idle，长按 D | Turn90R → 转完 → 续按 → 进入 WalkStart → Loop |
| Idle，点按 S 一下 | Turn180R → Idle |

### 13.9 3A 级 AD 抽搐治理 — "启动时间天然吸收"（语义修正）

#### 用户修正

> **绝对时间冷却生效，但不应让转向失效**。
> 由于启动时间（WalkStart Action）的存在，交替狂按 AD 会让角色一直处于"启动状态"——不真正移动、也不抽搐。**对标 3A**。

#### 重新理解机制（v2.1）

之前 §13.3 把抽搐治理建在"冷却屏蔽 Turn"上。**这是错的**。3A 级思路是：
- **不屏蔽 Turn**——每次按键都"响应"输入意图
- 但 Turn 触发后接 WalkStart Action 段（即"启动时间"）
- 在 WalkStart Action 期间再按反向键 → 触发新 Turn → 又接 WalkStart
- 玩家陷入 `Turn → Start → Turn → Start ...` 循环，**真正的 Move Loop 永远进不去** → 角色仅原地碎步 + 转向，**不真移动也不抽搐**
- 一旦玩家停手 ≥ Start Action 时长，WalkStart 自然走完 → 进入 Move Loop → 正常移动

这其实是"输入响应优先、加速度低、Start 段足够长"三要素的自然结果。

#### 实现要点对 §13.3 C 的修订

| 维度 | §13.3 C（旧）| §13.9（正确）|
|---|---|---|
| 冷却用途 | 屏蔽新 Turn 触发 | **不屏蔽 Turn**；冷却保留作为"日志去重 + Stagger 防御性兜底" |
| 抽搐吸收 | 靠冷却阻止 | 靠 **WalkStart Action 的 Duration 与 MotionProfile.Z 曲线** 吃掉"冲速" |
| 关键参数 | `TurnReentryCooldownSeconds` | `WalkStart.Duration`（0.25-0.45）+ `WalkStart.MotionProfile.Z` 顶值（0.3-0.5）+ `Tuning.StartActionDurationScale` |
| 视觉表现 | 转身后等冷却 → 才能下次转 | **每次按键都看到 Turn / Start 响应**，角色像在原地小步颠 / 转 |

#### 关键代码差异（相对 §13.3 C）

- `m_lastTurnFireTime` + `TurnReentryCooldownSeconds` **仍然加**，但**仅作 Log 节流和防御性兜底**（如某帧逻辑异常重复入 Detect 时去重）
- DetectRequestedState 优先级 1/2 **不**因冷却 SKIP Turn；保留 `[Turn][SKIP] reason=...` Log 仅在防御性兜底命中时打
- "抽搐"的真实预防剂在 **资产层**：WalkStart 的 Duration / MotionProfile.Z 顶值 / Loop 进入阈值

#### 调参指南（3A 手感）

| 字段 | 推荐值 | 影响 |
|---|---|---|
| `WalkStart.Duration` | 0.30s | 太短 → 抽搐回来；太长 → 启动迟钝 |
| `WalkStart.MotionProfile.Z 顶值` | 0.35 | 一次 Start 移动量；太小角色"原地颠"；太大冲出去 |
| `Tuning.StartActionDurationScale` | 1.0 | 全局拉伸；游戏后期可加 ScaleUp Buff |
| `WalkStart 后摇 Window 放行 Locomotion` | 0.7-1.0 | 后摇期可立即 cancel；保证短按 Start↔Idle 切换 |
| `Tuning.GroundAcceleration` | 18 (legacy) → 12 推荐 | Move Loop 内加速度；3A 手感建议低一些 |

#### 3A 验收

| 测试 | 期望 | 失败征兆 |
|---|---|---|
| 站立连点 W 5 次（每次 0.1s） | 角色原地颠 5 次小步，每次约 0.1m 位移 | 若直接冲速 → Duration 太短；若不动 → Z 顶值太低 |
| 站立交替 ADAD 持续 1s | 角色不停转向但**几乎不位移**，看起来像"被定住" | 若位移大 → Start Duration 太短或 Z 顶值太大 |
| 长按 W 持续 2s | 0.3s 后进入 Move Loop，加速到全速 | 若加速过快 → GroundAcceleration 太高 |

### 13.10 左右脚相位急停（设施就位 / 暂不通电）

#### 设计意图

3A 手感的关键细节：脚步停止时根据**当前支撑脚**选播对应相位的急停 Clip，避免"右脚抬起时强制播左脚收脚版本"导致的腿部动画闪现。

#### 数据契约

`ActionDataSO` 加可选**相位变体**字段（仅离散 Action，且 Continuous=false）：

```csharp
[Header("Phase Variants (159.1 L10 — 设施就位，运行时未通电)")]
[Tooltip("可选：左脚支撑相位的变体 Clip（适用于 WalkEnd/RunEnd 等）。空 = 用 MainClip。")]
public AnimationClip LeftFootSupportClip;

[Tooltip("可选：右脚支撑相位的变体 Clip。空 = 用 MainClip。")]

```

#### 支撑脚检测算法

```csharp
public enum FootSupport { Auto, Left, Right }

static class FootSupportDetector
{
    /// <summary>采样左右脚骨骼世界 Y 高度，更低者为支撑脚（贴地）。</summary>
    public static FootSupport Detect(Animator anim, Transform leftFootBone, Transform rightFootBone)
    {
        if (leftFootBone == null || rightFootBone == null) return FootSupport.Auto;
        var dy = leftFootBone.position.y - rightFootBone.position.y;
        // 0.03m 容差，避免轻微抖动反复切
        if (dy < -0.03f) return FootSupport.Left;
        if (dy >  0.03f) return FootSupport.Right;
        return FootSupport.Auto;
    }
}
```

挂点：`PlayerKCCMotor` 或 `Player` 上加 `Transform leftFootBone / rightFootBone` 字段（在 prefab 上手工拖入）。

```csharp
{
```

### 13.11 多级降落检测（设施就位 / 暂不通电）

#### 设计意图

3A 落地反馈：
- 低空（< 2m）跌落 → 普通双脚缓冲（沿用 JumpLand Action）
- 中空（2-5m）跌落 → 重落地动作（多一段震幅）
- 高空（> 5m）跌落 → 翻滚缓冲（Roll Land）防硬直 + 防伤害

#### 数据契约

`SkillEntryLoadoutSO.LocomotionGraphContext` 加 2 个 Action 槽（与现有 JumpLand 并列）：

```csharp
[Header("159.1 L11 — 多级降落（设施就位，未通电）")]
public ActionDataSO JumpLandLight;   // 低空：默认即旧 JumpLand
public ActionDataSO JumpLandHeavy;   // 中空：稍长缓冲
public ActionDataSO JumpLandRoll;    // 高空：翻滚
```

#### 高度采样

`PlayerAirborneState` 在起跳瞬间记录 Y 坐标 → 落地瞬间算差：

```csharp
// PlayerAirborneState 字段
private float m_airbornePeakOrStartY;
private float m_landFallHeight;

// OnEnter 起跳分支
m_airbornePeakOrStartY = player.transform.position.y;

// OnLogicUpdate 上升期：更新 peak（持续追踪 Y 最大值）
if (player.VerticalSpeed > 0f)
    m_airbornePeakOrStartY = Mathf.Max(m_airbornePeakOrStartY, player.transform.position.y);

// 落地瞬间（TryExitToLandOrLocomotion 开头）
m_landFallHeight = m_airbornePeakOrStartY - player.transform.position.y;
```

#### 通电开关 + 选 Action

```csharp

[Min(0f)] public float LandingHeavyThreshold  = 5f;
```

通电时（暂关闭）：`TryExitToLandOrLocomotion` 选 Action 前查 fallHeight：

```csharp
ActionDataSO pickLand(float h, LocomotionGraphContextBinding ctx)
{
    if (!tuning.EnableTieredLanding) return ctx.JumpLand;  // 不通电走旧路径
    if (h >= tuning.LandingHeavyThreshold)  return ctx.JumpLandRoll  ?? ctx.JumpLand;
    if (h >= tuning.LandingMediumThreshold) return ctx.JumpLandHeavy ?? ctx.JumpLand;
    return ctx.JumpLandLight ?? ctx.JumpLand;
}
```

- ✅ 数据字段就位（3 个 Land Action 槽）
- ✅ 高度采样算法就位（Peak Y 追踪 + 落地差）
- ❌ **通电开关默认 false**；运行时仍 `ctx.JumpLand` 单 Action
- ❌ 没填 Light/Heavy/Roll Action 资产时也无害（pickLand 走兜底返回 ctx.JumpLand）

### 13.12 v2 Landing 顺序最终调整（v2.1）

| Landing | 内容 | 默认通电 | 优先级 |
|---|---|---|---|
| **L0** Jump + Turn + Loco 探针 Log | 已落 | ✅ | 立刻 |
| **L1** ActionDataSO.IsContinuousLocomotion + Editor 联动 | — | ✅ | 优先 |
| **L2** Profile.Binding 精简（单 Action 字段） | — | ✅ | 中 |
| **L3** 运行时 dispatch Continuous vs Discrete | — | ✅ | 中 |
| **L4** Turn 触发**不再屏蔽**（仅日志去重 + 防御兜底）+ 绝对时间戳 | 修复点按转向 | ✅ | 优先 |
| **L5** Detect 优先级 4 内嵌"小角度才走 Start" | 奥德赛模式协作 | ✅ | 优先 |
| **L6** Animator.applyRootMotion Per-Action 治理 | 修位移播完才动 | ✅ | 中 |
| **L7** Tuning.StartActionDurationScale + WalkStart 资产时长/Z 曲线调优 | 启动手感（13.9 调参指南） | ✅ | 后 |
| **L8** 资产批量包 Action SO + 清旧字段 | 收尾 | ✅ | 后 |
| **L10** 左右脚相位急停（FootSupportDetector + 变体字段） | **暂不启用**（Tuning.EnableFootPhasedStopVariants=false） | ❌ | 设施就位 |
| **L11** 多级降落（fallHeight 采样 + 3 槽 Action） | **暂不启用**（Tuning.EnableTieredLanding=false） | ❌ | 设施就位 |

**推荐施工**：L0 探针 → L4（Turn 不屏蔽 + 时间戳） + L5（press 边沿协同）→ L1+L2+L3（数据源统一）→ L7 启动手感调参 → L10+L11 设施落位（不通电）→ L6+L8 收尾。
