# Bug 修复完成 — 168.2 Edge Inspector 焦点残留

## 根因

经典 Unity Editor IMGUI 陷阱：

|用户操作|Unity 内部|视觉结果|
|---|---|---|
|点 Edge A|FloatField 控件 ID = X，从 `edge.LateWindowSeconds` 读 0.5|显示 0.5|
|鼠标点入字段编辑 "1"|控件 X 获得**键盘焦点**，文本缓冲区 = "1"|字段显示 "1"（**未提交**）|
|不按 Enter，直接点 Edge B|选择切到 B；但**控件 X 仍持焦**，文本缓冲区 = "1" 未清|**新 Edge B 的 FloatField 继续显示 "1"**（卡住）|
|重启编辑器|焦点状态重置 → 用 B 的真实值重绘|正常|

## 修复（3 处改动）

### 1. 静态字段跟踪 GUID

```csharp
// 168.2 Fix：跟踪上一次绘制的 Edge GUID。
static string s_lastEdgeGuid;
```

### 2. Draw 入口检测 GUID 变化 → 清焦点

```csharp
if (serialEdge.GUID != s_lastEdgeGuid)
{
    if (Event.current != null && Event.current.type != EventType.Layout)
    {
        GUI.FocusControl(null);                      // 释放任何控件焦点
        EditorGUIUtility.editingTextField = false;   // 清掉 IMGUI 文本编辑标志
    }
    s_lastEdgeGuid = serialEdge.GUID;
}
```

> **为什么挡 Layout 事件**：IMGUI 每帧分 Layout / Repaint 两次调用同一段代码；在 Layout 阶段改 GUI 状态会破坏布局对称（Unity 会报 `ArgumentException: GetControlRect 调用次数不一致`）。只在 Repaint 阶段处理。

### 3. LateWindow 字段加 GUID 作控件名

```csharp
GUI.SetNextControlName("CombatFlow.LateWindow." + serialEdge.GUID);
edge.LateWindowSeconds = EditorGUILayout.FloatField(...);
```

> **双保险**：即便焦点没清干净，Unity 也会把不同 Edge 的 LateWindow **视作不同控件**（控件名不同 → 内部 ID 不同），上一条边的编辑文本不会跨边继承。

## 验证

|操作|修复前|修复后|
|---|---|---|
|Edge A LateWindow 设 1.0（不 Enter）→ 点 Edge B（真实值 0.5）|显示 1.0（缓存）|**显示 0.5（真实值）✓**|
|Edge A LateWindow 设 1.0 + Enter → 点 Edge B|显示 0.5（已经正常）|显示 0.5 ✓|
|反复切 A→B→A→C|每次都需重启编辑器|**每次都实时刷新** ✓|

## 副作用

- ✅ 零回归：FocusControl(null) 只清焦点，不动数据
- ✅ Layout 事件守卫：避免 IMGUI 布局异常
- ✅ 控件名隔离：即便其他字段未来加同类问题也不会蔓延
