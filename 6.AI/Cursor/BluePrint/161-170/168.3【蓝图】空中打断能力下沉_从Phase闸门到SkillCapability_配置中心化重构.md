# 168.3【蓝图】空中打断能力下沉 —— 从 Phase 闸门到 Skill Capability / 配置中心化重构

> **基线**：168.1 误诊 H1（Buffer 太短）/ 168.2 临时探针 / 169.1+170.4 退出层系统化 / **本次发现真因 H4-变体：Airborne Phase 闸门 mask 错位**
> **重构核心**：**"角色能不能在空中打断 / 接技能"是一项 *Skill Capability*，不是 *Player State 配置***。把决定权从 `PlayerStateManager` 全局 mask 下沉到 `SkillEntryDefinition` 自身声明。
> **目标**：消灭"配置失误一处，整条 Air-Combat 链路死掉"的脆弱性；同时让升龙 / 空袭 / 空中冲刺等技能的"空中可用"特性**自带声明**，不依赖角色身上的全局 mask。

---

## §0 现状摸底（BUG 谱系还原）

### §0.1 现象时序

```
A1 升龙（IntentCategory=Combat，IsLauncher=true）
        ↓
PlayerActionState 执行 A1，把角色推到空中
        ↓
A1 Action 结束 → ExitToBaseline（169.1 后一律回 Locomotion）
        ↓
PlayerLocomotionState.OnEnter → !IsGrounded → Change<PlayerAirborneState>
        ↓
玩家此时按 LM 想接 A2（升龙第二段或空袭）
        ↓
PlayerAirborneState.TryConsumeGameplayIntent
   ├ allowed = airborneAscendingAllowedCategories = 0（None，Inspector 默认）
   ├ incomingCategory = Offense
   └ (0 & Offense) == 0 → ❌ REJECT
        ↓
Intent 在到达 SkillEntryService.TryResolveContextual 之前被掐死
        ↓
LateWindow / Edge / ComboSession / airComboRoute 全部旁路 —— 配多久都没用
```

### §0.2 关键洞察

| 视角 | 误诊 / 真相 |
|---|---|
| **168.1 H1**（Buffer 过短） | ❌ Intent 还没进 Buffer 就被驳回 |
| **168.1 H4**（Recovery Window 拒收 Offense） | 🟡 **方向对，归属错** —— 不在 Recovery 层，在 Airborne Phase 层 |
| **真相** | Airborne 的 Phase mask 充当**全局粗粒度闸门**，Inspector 默认值 = `None` 时整段 Ascending 阶段拒收所有 Combat |
| **更深层问题** | "空中能否接技能"被表达为**角色身上的固定全局 mask**，而不是**技能自身的能力声明** |

### §0.3 症状级修复（已落地）的退路

168.3 起步阶段我们已经做了：
1. `airborneAscendingAllowedCategories` 默认改为 `AllPillarCategories`
2. `BuildStateList` 运行时兜底（Inspector=0 → fallback AllPillar）
3. 一对一探针 `[ComboAirGate]`

**问题**：这只是**把"默认值错"换成"默认值全开"**。
- 全开 = 任何 Movement/Defensive/Utility 都能空中触发（包括平砍、翻滚）
- 这并非游戏设计想要的（很多 ARPG 仅升龙 / 空袭可空中发，平砍不可空中发）
- 决定权仍在 Player Inspector，**与技能本身解耦** = 策划改技能时还得跑去改 Player

**168.3 系统级正解**：**把决定权下沉到每个技能 Entry 自己**，Player Inspector 只保留"硬性下限"（Death / Stun 类绝对禁止）。

### §0.4 已有可复用基础

| 资产 | 现状 | 复用为 |
|---|---|---|
| `SkillEntryDefinition` | 已有 `airComboRoute`（空中连段路由） | 强提示："空中可用"是 Skill 本身属性 |
| `SkillEntryLoadoutSO` | 槽位绑定聚合 | 提供 Loadout 级 Air Capability 聚合 |
| `ActionDataSO.IntentCategory` | Locomotion / Combat / Reaction / Interaction | 不动 |
| `AbilityGateService` | 已有的能力闸门服务 | 接入 AirCapability 查询 |
| `PlayerAirborneState` | 现 Phase mask 驱动 | 改为 Capability 优先 + Phase 兜底 |

## §1 设计原则（不可越界）

### §1.1 三层职责切分（**核心契约**）

```
[A] 系统硬性下限              ←  PlayerStateManager.airborneXxxAllowedCategories
    Death / Stun / Cinematic 等绝对禁止              （默认仅 None 之外的"绝对开"）

[B] 技能能力声明               ←  SkillEntryDefinition.AirborneActivation
    "升龙天生空中可发" / "平砍天生地面专属"          （核心改动）

[C] 上下文连段许可             ←  CombatGraph Edge / Route LateWindow
    "A1→A2 在 0.5s 内空中可触发"                    （已有 Edge 系统）

判定顺序（自下而上）：
    if [A] 硬下限拒绝 → BLOCK（无视任何 Capability）
    if [B] Skill 自带 AirCapability 包含当前 Phase → ALLOW
    if [C] Edge LateWindow 显式打开 → ALLOW
    else  → BLOCK
```

### §1.2 三句锁死

> 1. **Phase mask 不再是"允许什么"，而是"绝对禁止什么"** —— 默认全开（None 等同 AllPillar，写出反语义意图必须 explicit）
> 2. **"空中可发"是技能自带属性** —— `SkillEntryDefinition` 一份资产决定升龙/空袭/空中冲刺的 Air 能力
> 3. **Graph Edge 是上下文级许可** —— Edge 只决定"在 A1 之后 0.5s 内能接什么"，不决定"这个技能本质上是不是空中可用"

### §2.1 `AirborneActivationPolicy` enum + struct

```csharp
// 4_Data/1.Skills/Capability/AirborneActivationPolicy.cs（新增）
[Flags]
public enum AirbornePhaseMask : byte
{
    None        = 0,
    Ascending   = 1 << 0,    // VerticalSpeed > 0
    ApexHold    = 1 << 1,    // 顶点附近（|Vy| < 阈值）
    Descending  = 1 << 2,    // VerticalSpeed < 0
    All         = Ascending | ApexHold | Descending,
}

[Serializable]
public struct AirborneActivationPolicy
{
    [Tooltip("地面是否可发（绝大多数技能 = true）")]
    public bool Grounded;

    [Tooltip("空中可发的 Phase 子集（None = 完全不可空中发；All = 全部空中段可发）")]
    public AirbornePhaseMask Air;

    [Tooltip("空中触发时是否走 airComboRoute（true）还是 normalRoute（false）；与 SkillEntryDefinition.airComboRoute 字段联动")]
    public bool PreferAirComboRoute;

    [Tooltip("Coyote 宽限：刚离地 N 秒内仍当作地面判定（与 Jump 系统的 CoyoteTime 独立）")]
    [Range(0f, 0.3f)] public float GroundCoyoteSeconds;

    public static readonly AirborneActivationPolicy GroundOnly =
        new() { Grounded = true, Air = AirbornePhaseMask.None, GroundCoyoteSeconds = 0.08f };

    public static readonly AirborneActivationPolicy AirOnly =
        new() { Grounded = false, Air = AirbornePhaseMask.All, PreferAirComboRoute = true };

    public static readonly AirborneActivationPolicy Universal =
        new() { Grounded = true, Air = AirbornePhaseMask.All, PreferAirComboRoute = true };
}
```

## §3 运行时层重构

### §3.1 `AirCapabilityResolver`（新单例 / 静态类）

```csharp
// 2_Framework/Skill/AirCapability/AirCapabilityResolver.cs（新增）
public static class AirCapabilityResolver
{
    public enum Verdict : byte { Allow, HardFloorBlock, NoCapability, GroundOnlyEntry }

    public struct Result
    {
        public Verdict Code;
        public string Reason;          // 仅在 BLOCK 时填，便于探针
        public AirbornePhaseMask Phase;
    }

    public static Result Evaluate(
        Player player,
        in GameplayIntent intent,
        ActionCategory incomingCategory,
        bool ascending,
        ActionCategory hardFloorBlockMask)
    {
        var phase = ascending ? AirbornePhaseMask.Ascending : AirbornePhaseMask.Descending;
        // ① 硬下限
        if ((hardFloorBlockMask & incomingCategory) != 0)
            return new Result { Code = Verdict.HardFloorBlock, Phase = phase, Reason = "HardFloor" };

        // ② Skill 自身能力
        var slot = ResolveSlot(in intent);
        var entry = player.SkillEntryLoadout?.GetEntryBySlot(slot);
        if (entry == null)
            return new Result { Code = Verdict.NoCapability, Phase = phase, Reason = "EntryMissing" };

        if ((entry.AirborneActivation.Air & phase) != 0)
            return new Result { Code = Verdict.Allow, Phase = phase };

        // ③ 地面专属（默认）
        return new Result { Code = Verdict.GroundOnlyEntry, Phase = phase, Reason = $"entry={entry.name}.Air={entry.AirborneActivation.Air}" };
    }

    static SkillEntrySlot ResolveSlot(in GameplayIntent intent) { /* 从 intent 反解 */ }
}
```

### §3.2 `PlayerAirborneState.TryConsumeGameplayIntent` 改造

```csharp
public override bool TryConsumeGameplayIntent(Player player, in FrameContext ctx, in GameplayIntent intent)
{
    if (intent.Kind == GameplayIntentKind.Move) return true;
    if (!IntentRouter.IsRoutable(in intent)) return false;

    var incomingAction = IntentRouter.PeekActionDataForRouting(player, in intent);
    var incomingCategory = ActionInterruptResolver.ResolveIncomingCategory(in intent, incomingAction);
    var ascending = player.VerticalSpeed > 0f;
    var hardFloor = ascending ? m_ascendingHardFloorBlock : m_descendingHardFloorBlock;

    // 168.3 核心：Capability 优先
    var r = AirCapabilityResolver.Evaluate(player, in intent, incomingCategory, ascending, hardFloor);
    LogAirCapabilityIfFlipped(player, in r, intent.Kind, incomingCategory);

    if (r.Code != AirCapabilityResolver.Verdict.Allow)
        return false;

    return IntentRouter.Route(player, in intent, forceActionReentry: false);
}
```

### §3.3 `SkillEntryService.TryResolveContextual` 接 airComboRoute 选择

`PreferAirComboRoute=true` 的 Entry 在空中触发时 → 走 `airComboRoute` 资产；落地时回 `comboRoute`。已存在的 `airComboRoute` 字段终于有"何时启用"的明确语义。

### §3.4 与 Graph Edge / LateWindow 的咬合

Edge 的 LateWindow 仍由 `CombatGraphRunner` 管理；本蓝图**不动 Edge**。流程如下：

```
玩家在空中按 LM
    ↓
PlayerAirborneState.TryConsumeGameplayIntent
    ↓ Capability=Allow（升龙 entry 声明 Air=All）
IntentRouter.Route → SkillEntryService.TryResolveContextual
    ↓
查 ActiveRoute 是否有 LateWindow 开启 → 是 → 命中 Edge → 切下一段 ✓
否 → 走 Skill Entry 主链（airComboRoute 优先）
```

> Edge 仍按现有逻辑生效；本重构**让 Edge 真正能被空中触发到**。168.1 误诊的"LateWindow 失灵"在 §3.2 解决后**结构性消失**。

## §8 关键架构约束

1. **Phase mask 默认 0 = 不禁止**（语义反转）—— 旧"None=全拒"陷阱结构性消失
2. **每个 SkillEntryDefinition 必填 AirborneActivation** —— 默认 `GroundOnly` 是安全起点
3. **Capability 优先，HardFloor 在外** —— Resolver 先查能力，再查硬下限；不能颠倒
4. **airComboRoute 由 Capability + Phase 联动选择** —— 不允许"空中触发但走 normalRoute"的混乱
5. **Edge LateWindow 不动** —— 本蓝图只解决"Intent 能不能到 Resolver"，不动 Resolver 内部
6. **探针一开关一前缀** —— `[AirCap]` 独占，dedup by `phase|kind|cat|verdict`

## §9 不做项（明确 P3+）

- ❌ Phase 内部细分（Ascending 上升早期 / 上升末期 等）—— 用 ApexHold 一槽顶替即可
- ❌ AI / Boss 复用同一 Resolver —— 本切片仅 Player；AI 独立切片
- ❌ 联机同步（单机阶段）
- ❌ "动态 Capability"（运行时改 Entry.Air）—— SO 始终 readonly
- ❌ Capability UI 提示玩家 —— 留给 UI 切片

## §10 反模式清单（本次 BUG 暴露的）

| 反模式 | 表现 | 防御 |
|---|---|---|
| **能力配置错位** | 技能能力放在 Character 全局 mask | 下沉到 Skill 自身 SO |
| **mask 默认值 = None 等价于全拒** | Inspector 序列化为 0 时整段死链 | 语义反转：默认 0 = 不禁止 |
| **多层闸门职责重叠** | Phase mask + Edge LateWindow + AbilityGate 三处都管"能不能"，互相打架 | 三层职责切线清晰：硬下限 / 能力 / 上下文 |
| **配置中心散落** | 改一个技能要跑 Player Inspector + Edge Inspector + Loadout 三处 | 中心化到 SkillEntryDefinition |
| **症状级 fallback 当正解** | None→AllPillar 兜底 = 默认全开 | 退路移除（W7） |

---

## §11 三句话沉淀

> 1. **"能不能空中接技能"是 Skill Capability，不是 Player State 配置** —— 这是本次 BUG 揭示的最深层架构原则
> 2. **mask 默认 None 不应等于"全拒"** —— 语义反转为"硬下限"，从此 Inspector 漏配=零影响
> 3. **三层职责切线**：HardFloor / Capability / Edge —— 任一系统失效不再连带瘫痪整条链路
