### 1.1 已确认（grep + 读码）

| **H6** | ComboSessionResetTime 偏短 | **⚠️ 部分** | 默认资产 `Route_Combo_LM` 为 **1.2s**（足够）；问题不在 Session 总长，而在 **窗开启前输入已被丢弃** |

### 1.2 关键代码路径（当前行为）

```
OnReleaseEdge(LM)
  gap = GetGapSinceLastSegmentEnd()   // 段未结束 → -1
  linkWindowOpen = IsLinkWindowOpen() // 需 NotifySubRouteSegmentEnded 后才 true
  if (gap < 0 && sessionActive && !linkWindowOpen)
      → Suppress → TryApplyComboOutcome  return false  ★ 意图从未 Enqueue
  else
      → EnqueueSemantic → IntentBuffer(ExpireTime = now + 0.18s)

PlayerStateManager.OnPreLogicUpdate
  FlushExpired(now)                   ★ 0.18s 后丢弃
  TransitionResolver.CanOfferIntent   ★ expired 再拒一次
  SkillEntryService.TryResolveForIntent
      if (comboIdx>0 && gap<0) REJECT "link window not open"  ★ 即使 somehow 入队也拒
  PlayerActionState.TryConsumeGameplayIntent
      CanInterrupt + DualGate
```

**重构前能接、重构后不能接** 的最合理解释：

> 116.1 把 Combo 窗锚点改为 **SubRoute 自然结束**（正确契约），但 **`AllowEarlyBufferInput` 配套设施从未接入 Resolver/Service**，导致「段中预输入」从「可能靠长缓冲碰运气」变成「语义层直接 Suppress」。

## 四、Landing 1 — Early Buffer 通电（RC0 修复）

### 4.1 设计原则

- **单轨**：不恢复「松手锚点」；段中输入写入 **Pending Combo Slot**，段结束时 **单点 Flush**。
- **与 06 规则一致**：`NotifySubRouteSegmentEnded` 仍是 link window 起点；Early Buffer 只是 **把按键时刻提前到段结束前的合法预存**，不是改窗口计时。
- **配置驱动**：`ComboRouteDefinition.AllowEarlyBufferInput == false` 时行为与现网相同（Suppress）。

### 4.2 设施表

| 类型 | 位置 | 职责 |
|---|---|---|
| `PendingComboIntent` struct | `SkillEntryService` 或 `InputSemanticResolver` | slot / semantic / comboIdx / hold / timestamp |
| `PerSlotConfig.AllowEarlyBufferInput` | `InputSemanticResolver` | 从 ComboRoute 注入 |
| `PerSlotConfig.EdgeAllowInputBuffer[]` | 同上 | 从 `comboTransitions[i].allowInputBuffer` 注入 |
| `ArmPendingComboInput(...)` | `SkillEntryService` | 段中写入 |
| `TryFlushPendingComboInput(slot, now)` | `SkillEntryService` | 在 `NotifySubRouteSegmentEnded` **同一帧**调用 |
| `EvaluateComboTapOrAdvance` 分支 | `InputSemanticResolver` | gap&lt;0 + allowEarly → **EnqueueAdvance + ArmPending**（非 Suppress） |

### 4.3 握手表

| 通电点 | 上游 | 下游 | 验收 Log |
|---|---|---|---|
| 段中按键 | `OnReleaseEdge` | `ArmPendingComboInput` | `[Combo][EarlyBuf] ARM slot=LM idx=1 gap=-1` |
| 段自然结束 | `NotifySubRouteSegmentEnded` | `TryFlushPendingComboInput` | `[Combo][EarlyBuf] FLUSH idx=1 gap=0.00` |
| Flush 后解析 | `TryResolveForIntent` | 命中 chain[1] | `[Combo][Resolve] resolved=true routeType=NormalRoute` |
| 消费打断 | `TryConsumeGameplayIntent` | `IntentRouter.Route` | `[Combo][Pass]` |

### 4.4 Resolver 伪代码（替换 Suppress 分支）

```csharp
if (gapSinceSegmentEnd < 0f)
{
    if (comboSessionActive && !comboLinkWindowOpen)
    {
        var edgeIndex = currentComboIndex; // next = current+1 → edgeIndex
        var edgeAllows = cfg.EdgeAllowInputBuffer != null
            && edgeIndex >= 0 && edgeIndex < cfg.EdgeAllowInputBuffer.Length
            && cfg.EdgeAllowInputBuffer[edgeIndex];
        if (cfg.AllowEarlyBufferInput && edgeAllows)
        {
            semantic = InputSemanticType.Combo;
            newComboIndex = currentComboIndex + 1;
            detail = "early buffer armed (segment still playing)";
            return ComboAdvanceOutcome.EnqueueEarlyBuffer; // 新 enum 值
        }
        detail = "previous segment still playing";
        return ComboAdvanceOutcome.Suppress;
    }
    return ComboAdvanceOutcome.EnqueueFirstTap;
}
```

`TryApplyComboOutcome` 对 `EnqueueEarlyBuffer`：**不入 IntentBuffer**，改调 `SkillEntryService.ArmPendingComboInput`。

### 4.5 Service 侧配合

1. **`TryResolveForIntent`**：若 `HasPendingComboInput(slot)` 且 `gap >= 0`（段已结束），**优先消费 pending**，跳过 gap&lt;0 REJECT。
2. **`NotifySubRouteSegmentEnded` 末尾**：`TryFlushPendingComboInput` → 合成 `GameplayIntent` 入队（带 L2 动态 TTL）或直接内部 Resolve+NotifyRouteEntered（二选一，**推荐入队**以保持帧序一致）。

## 五、Landing 2 — 动态 Intent ExpireTime（RC1 / H1 修复）

### 5.1 契约

```csharp
// SkillEntryIntentFactory — 唯一 TTL 入口
public static float ResolveBufferSeconds(Player player, SkillEntrySlot slot)
{
    const float baseDefault = 0.18f;
    const float shiftSpace = 0.28f;
    var baseSec = slot is Shift or Space ? shiftSpace : baseDefault;

    if (player?.SkillEntries?.TryGetActiveComboSession(slot, out var session) == true)
    {
        var def = session.Definition as ComboRouteDefinition;
        var reset = def != null ? def.ComboSessionResetTime : 1.2f;
        // Session 内：至少覆盖到 Session 断档 + 余量（段结束→消费延迟）
        return Mathf.Max(baseSec, reset + 0.15f);
    }

    return baseSec;
}
```

- **LM/RM 默认** 可保留 0.18s **仅 Session 外**；Session 内自动 ≥ `ComboSessionResetTime + 0.15`。
- **可选增强**：Pending Early Buffer 的 Flush 意图 TTL = `ComboSessionResetTime + 0.1`（与 pending 语义一致）。

### 5.2 验收

| 操作 | 期望 Log |
|---|---|
| Session 外点 LM | `[Combo][Enq] validFor=0.18s` |
| A1 Session 中/后点 LM | `[Combo][Enq] validFor≥1.35s`（reset=1.2） |
| 段结束 0.4s 后按 LM | 无 `[Combo][Drop] EXPIRED` |

## 六、Landing 3–5 — 次要根因

### 6.1 L3 — DualGate（H5）

**症状**：`[Combo][DualGateBlock] participation=Full resolvedViaGraph=false`

**检查清单**：

- [ ] Combat Graph 存在 A1 Action 节点 → A2 Action 的 **Input 边**（slot=LM, semantic=Combo）
- [ ] `CombatGraphRunner.TryResolve` 命中边时写 `_lastIntentResolvedViaGraph = true`
- [ ] 若链走 **纯 ComboRoute 不经 Graph**，Incoming Action 的 `GraphParticipation` 应为 **SourceOnly** 或 **None**（避免 Full 双闸误杀）

**修复选项（单轨，二选一）**：

| 选项 | 做法 | 适用 |
|---|---|---|
| A（推荐） | Graph 补边 + Resolve 写 flag | Graph 启用的 LM 链 |
| B | Combo 子 Route Entry Action 设 `GraphParticipation.SourceOnly` | 地面连段不走 Graph 边 |

### 6.2 L4 — ActionWindow（H4）

**症状**：`[Combo][Reject] CanInterrupt=false incomingCat=Offense windowAllowed=…`

**修复**：A1 Action 时间轴 Recovery（或 Active 末段）窗口：

- `InterruptibleByCategories |= Offense`
- 可选：加 `ComboInput_Window` 标签窗（与 StateTag 一致，供 HUD/调试）

**不改** `ActionInterruptResolver` 规则 — 仅资产。

### 6.3 L5 — 状态切换叠加（H7）

**症状**：A1 末段 `[Combo][StateSwap] Action→Locomotion→Airborne`，IntentBuffer Count>0 但未消费

**修复方向**（169.1 已修 JumpLand 强插，本 Landing 可选）：

- Session 活跃 + `HasPendingComboInput || IntentBuffer 含 Combo semantic` 时，`PlayerActionState.ExitToBaseline` **延迟一帧** 或 **ForceChange 续 Action**（仅 Session 内，禁止永久 fallback）。

**优先级低**：L1+L2 通后若仍失败再开。

## 八、风险与缓解

| 风险 | 缓解 |
|---|---|
| Early Buffer 导致「段中按键 → 段末自动出招」不可取消 | 仅 `allowInputBuffer=true` 的边 + 容器 `AllowEarlyBufferInput` 开启；Flush 前若 Session 被 Interrupt 则 ClearPending |

| 探针刷屏 | `DebugComboWindow` 独立开关；Session Log 5 帧限频 |

## 十一、面试口述总结

> 连招窗口失灵的根因不是 Session 时间太短，而是 **116.1 把窗口锚点改到段自然结束之后，段中预输入设施（AllowEarlyBufferInput）没有接入运行时**，语义层直接 Suppress，再叠加 **0.18s Intent TTL**，玩家必须「段结束后 + 缓冲未过期 + 窗口内 + 打断窗 + Graph 双闸」五重对齐才能接招。168.2 用 **Pending Early Buffer 单点 Flush + Session 内动态 TTL** 恢复 ACT 手感，探针按 168.1 矩阵验收，不改单轨契约。
