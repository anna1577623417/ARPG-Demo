## 一、设计目标

### 1.1 用户原话提炼

> · Run_End / Walk_End MotionProfile 加制动曲线（End 动画期间渐进减速）
> · ExitVelocityPolicy 枚举化；可配置；多种策略；**不一定按 166.1 §三 的 4 种**
> · 减速位移可遵循旧 ZXY 轴【**默认**策略】
> · 推荐制动曲线默认值
> · 外加绝区零点按模式
> · 不包括 Segment 裁剪，但预留兼容

### 1.2 设计原则

| # | 原则 |
|---|---|
| ① | **默认策略 = MotionCurveDriven** —— 沿用 ZXY 轴，**MotionProfile.Z 曲线末段斜率自然定义减速**，无需额外代码路径，**零回归** |
| ② | **策略矩阵 ≥ 10 种** —— 覆盖 3A 主流（如绝区零、原神、鸣潮、星铁、永劫无间） |
| ③ | **资产侧单选 + 运行时分发** —— ActionDataSO 选一种 policy + 参数，运行时按策略路由到不同实现 |
| ④ | **Segment 兼容** —— TapJumpToEndTail（绝区零方案 A）的 `normalizedStart` 字段就是"未来 Segment 的归一化起点"；Segment 系统落地后直接复用 |
| ⑤ | **资产侧推荐预设** —— 给每个 Locomotion 状态推荐最佳 policy + 默认参数；用户立刻可用 |

## 二、ExitVelocityPolicy 完整矩阵（10 种策略）

### 2.1 总表

| # | Policy | 用一句话描述 | 关键参数 | 推荐场景 |
|---|---|---|---|---|
| 0 | **`MotionCurveDriven`** ⭐ 默认 | **MotionProfile.Z 曲线末段 = 减速曲线**（零额外代码） | 无 | WalkEnd/RunEnd 默认；Action 自带 MotionProfile 时 |
| 1 | `Snap` | 立即清零，硬刹车 | 无 | JumpLand；StunStop |
| 2 | `LinearDecay` | 线性匀速减速到 0 | `LinearDecayDuration` | 旧手感兼容；Stop（通用）|
| 3 | `ExpDecay` | 指数衰减（半衰期可配） | `ExpDecayHalfLife` | RunEnd 偏柔 |
| 4 | `FixedDuration` | **固定时长**内归零（无视初速度）| `FixedDecelDuration` | 节奏稳定（节拍游戏）|
| 5 | `FixedDistance` | **固定距离**内归零（用初速度反推时长） | `FixedDecelDistance` | 招式打击距离严格控制 |
| 6 | `SpeedProportional` | 减速时长与初速度成正比（速度越大滑得越远）| `DurationPerUnitSpeed` | 跑步惯性手感 |
| 7 | `StepDecay` | 多档阶梯衰减（100% → 60% → 30% → 0%）| `StepValues[]` + `StepIntervalSec` | 演出感（黑魂打击感）|
| 8 | `PreservedSlide` | 残余完整保留（绝区零滑步）| `SlideMaxResidualSpeed` | 滑步 / 战斗位移 |
| 9 | **`TapJumpToEndTail`** ⭐ 绝区零 | **短按时跳到 End Clip 后半段播**（normalizedStart 起播）| `TapWindowSec` + `EndTailNormalizedStart` | RunStart 短按 = 轻巧迈步收回 |

### 2.2 详细契约

#### 0 — `MotionCurveDriven`（默认 ⭐）

**核心思路**：**不写任何减速代码**。Action.MotionProfile.AxisCurves.Z 曲线本身就是位移随时间的归一化函数；末段斜率 → 末段速度。设计师只要把 Z 曲线"末段拉到 0"或"末段斜率减小"，自然实现渐进减速。

**与 166.1 §1.1 H1 的关系**：H1 假设的根因 = "Z 曲线末段斜率非 0 → 末帧速度高 → KCC 残余"。MotionCurveDriven 策略**强制要求 Action 的 Z 曲线末段斜率为 0 或单调递减**，并在 Action.OnExit 时根据"曲线末段 N 帧的斜率"决定是否需要 `ClearPlanarVelocity`：

```csharp
// OnExit 内
if (action.ExitVelocityPolicy == MotionCurveDriven)
{
    // 推断：MotionProfile.Z 在末 0.05 归一化区间斜率 < 0.5 m/s → 视作已平滑减速 → 清残余
    var tailSlope = action.MotionProfile.AxisCurves.SampleTailSlope(0.95f, 1.0f, axis: Z);
    if (Mathf.Abs(tailSlope) < 0.5f)
    {
        player.ClearPlanarVelocity();  // 自然汇聚 → 直接清零（无视觉断裂）
    }
    // else 不动，由 LocomotionState.MoveByLocomotionIntent 自然衰减
}
```

**用户立刻可享受的好处**：
- 不动代码就有"渐进减速"
- 末段速度小 → ClearPlanarVelocity 不可感知
- 末段速度大 → 由 LinearDecay 路径自然衰减

#### 1 — `Snap`

```csharp
case Snap:
    player.ClearPlanarVelocity();
    break;
```

适用：JumpLand 落地、Stun 强制硬刹。

#### 2 — `LinearDecay`

```csharp
public float LinearDecayDuration = 0.15f;  // 秒

case LinearDecay:
    player.BeginVelocityDecay(VelocityDecayKind.Linear, LinearDecayDuration);
    break;
```

PlayerLocomotionState.OnLogicUpdate 优先执行：
```csharp
if (player.TryTickVelocityDecay(dt)) { player.ApplyMotor(); return; }
```

Linear 实现：`v_t = v_0 * (1 - t/T)`

适用：通用 Stop；与旧 MoveByLocomotionIntent.MoveTowards 行为兼容。

#### 3 — `ExpDecay`

`v_t = v_0 * exp(-t * ln(2) / halfLife)`

```csharp
public float ExpDecayHalfLife = 0.25f;
```

适用：RunEnd 偏柔；视觉上"角色自然慢下来"。

#### 4 — `FixedDuration`

```csharp
public float FixedDecelDuration = 0.30f;  // 不论初速多少，都在 0.3s 内归零
```

实现 = LinearDecay 但 `T = FixedDecelDuration`（无视 v_0）→ 减速度 = v_0 / T，**初速度越大减速度越大**。

适用：节奏游戏；保证总时长稳定。

#### 5 — `FixedDistance`

```csharp
public float FixedDecelDistance = 0.6f;  // 米；不论初速，总滑行距离=0.6m
```

实现：用 `v_0` 反推 `T = 2 * d / v_0`（线性减速），然后走 LinearDecay 路径。

适用：招式打击距离严格控制（如剑姬 Q 突进后固定 1m 滑行）。

#### 6 — `SpeedProportional`

```csharp
public float DurationPerUnitSpeed = 0.05f;  // 每 m/s 滑 0.05s
```

`T = v_0 * DurationPerUnitSpeed`，线性减速。

适用：跑步惯性手感（跑得越快滑得越远，物理直觉）。

#### 7 — `StepDecay`

```csharp
public float[] StepValues = { 1.0f, 0.6f, 0.3f, 0f };  // 速度倍率台阶
public float StepIntervalSec = 0.08f;                   // 每档持续时长
```

实现：每 `StepIntervalSec` 把速度 = v_0 * StepValues[i]，无插值。

适用：演出感（黑魂"咚咚咚"打击感停顿）。

#### 8 — `PreservedSlide`

```csharp
public float SlideMaxResidualSpeed = 0f;  // 0 = 不限
```

Action OnExit 不动残余 PlanarVelocity；可选 cap：
```csharp
case PreservedSlide:
    if (SlideMaxResidualSpeed > 0.01f)
    {
        var v = player.PlanarVelocity;
        if (v.magnitude > SlideMaxResidualSpeed)
            player.SetPlanarVelocity(v.normalized * SlideMaxResidualSpeed);
    }
    break;
```

适用：绝区零滑步、战斗位移、Dodge 收尾。

#### 9 — `TapJumpToEndTail`（绝区零方案 A）⭐

**触发条件**（在 *Start Action 期间检测）：玩家按住时长 < `TapWindowSec` 即松手 → 视为"短按"。

**实现**：在 PlayerActionState 检测到 Move release 边沿时：
```csharp
case TapJumpToEndTail:
    // 当前不是 End Action 本身的策略；这是 *Start Action 期间的"短按检测"
    if (m_action.IsStartAction && elapsedSec < action.TapWindowSec)
    {
        // 跳到 End Action 的归一化 EndTailNormalizedStart 开始播
        var endAction = ResolveCorrespondingEndAction(m_action);  // WalkStart → WalkEnd
        if (endAction != null)
        {
            player.ArmPendingAction(GameplayIntentKind.Move, endAction);
            // ★ 关键：归一化起播
            player.SetPendingActionNormalizedStart(action.EndTailNormalizedStart);
            player.States.Change<PlayerActionState>();  // 不退 Locomotion，直接续 End
        }
    }
    break;
```

参数：
```csharp
public float TapWindowSec = 0.15f;                  // 资料 B 推荐
public float EndTailNormalizedStart = 0.6f;          // 资料 B 推荐
public ActionDataSO TapPairedEndAction;             // 可选：显式配对的 End Action
```

**用户体验**：W 轻点 50ms → RunStart 播 20% → 检测到短按 → 跳到 RunEnd 0.6 起播 → 角色"轻巧迈一步收回站稳"。

### 2.3 PlayerActionState.OnExit 分发骨架

```csharp
void ApplyExitVelocityPolicy(Player player, ActionDataSO action)
{
    switch (action.ExitVelocityPolicy)
    {
        case MotionCurveDriven:  // 默认
            var slope = action.SampleMotionTailSlope();
            if (Mathf.Abs(slope) < 0.5f) player.ClearPlanarVelocity();
            // else 让 LocomotionState.MoveByLocomotionIntent 自然 MoveTowards 衰减
            break;
        case Snap:
            player.ClearPlanarVelocity();
            break;
        case LinearDecay:
            player.BeginVelocityDecay(VelocityDecayKind.Linear, action.LinearDecayDuration);
            break;
        case ExpDecay:
            player.BeginVelocityDecay(VelocityDecayKind.Exp, action.ExpDecayHalfLife);
            break;
        case FixedDuration:
            player.BeginVelocityDecay(VelocityDecayKind.Linear, action.FixedDecelDuration);
            break;
        case FixedDistance:
        {
            var v0 = player.PlanarVelocity.magnitude;
            var T = v0 > 0.01f ? 2f * action.FixedDecelDistance / v0 : 0f;
            player.BeginVelocityDecay(VelocityDecayKind.Linear, T);
            break;
        }
        case SpeedProportional:
        {
            var v0 = player.PlanarVelocity.magnitude;
            var T = v0 * action.DurationPerUnitSpeed;
            player.BeginVelocityDecay(VelocityDecayKind.Linear, T);
            break;
        }
        case StepDecay:
            player.BeginVelocityDecayStep(action.StepValues, action.StepIntervalSec);
            break;
        case PreservedSlide:
            CapResidualSpeed(player, action.SlideMaxResidualSpeed);
            break;
        case TapJumpToEndTail:
            // 仅在 *Start Action 期间检测；OnExit 阶段已晚——见 §2.4
            break;
    }
}
```

### 2.4 TapJumpToEndTail 特殊处理（不在 OnExit 阶段）

`TapJumpToEndTail` 的触发**不是** Action 自然结束时，而是 **Action 进行中** 检测到 release 边沿 → 主动切到对应 End Action 的归一化起点。

落地点：
1. **PlayerActionState.TryConsumeGameplayIntent**：拦截 `IntentKind.Move` 的 release 边沿
2. 若当前 Action `ExitVelocityPolicy == TapJumpToEndTail` 且 `elapsedSec < TapWindowSec`
3. 立即 ArmPendingAction(End Action) + 显式归一化起播

## 三、推荐制动曲线默认值（MotionProfile.Z）

### 3.1 WalkEnd / RunEnd 推荐 Z 曲线

| 时间归一化 | Z 位移（m）| 斜率（m/s）| 备注 |
|---|---|---|---|
| 0.00 | 0.00 | v_initial（来自 Loop 的速度）| 入场对接 Loop 速度 |
| 0.20 | 0.7 × v_initial × 0.2 | 0.7 × v_initial | 平滑减速段开始 |
| 0.50 | 渐进 | 0.3 × v_initial | 主要减速完成 |
| 0.80 | 接近最终 | 0.1 × v_initial | 末段微调（绝区零方案 A 的"轻挪入口"= 0.6） |
| 1.00 | 总位移 = 0.8m（Walk）/ 1.4m（Run） | **0** | **末段斜率为 0 → MotionCurveDriven 自动 ClearPlanarVelocity 无视觉断裂** |

### 3.2 Z 曲线形状推荐

```
        Z
        ▲
   1.4m │             ╭───
        │           ╱
   1.0m │         ╱
        │       ╱
   0.5m │    ╱
        │  ╱
   0.0m └─────────────────► normalized
        0   0.2  0.5  0.8  1.0
```

**关键特征**：
- 0.0 — 0.5 区间：陡峭（继承 Loop 速度，快速减速）
- 0.5 — 0.8 区间：平缓（自然收尾）
- 0.8 — 1.0 区间：**几乎水平**（末段斜率 → 0，避免抖动）
- 0.6 起播（绝区零方案 A）：开始位于 0.5 → 1.0 的"平缓收尾段"，无突兀感

## 四、Segment 系统预留兼容点（不实现）

### 4.1 现状

资料 A 提案：未来 ActionDataSO 加 `SegmentStart / SegmentEnd ∈ [0,1]`，**一个 Clip 可拆多个 Action**（如 GreatSwordCombo 的 0.0-0.3 / 0.3-0.6 / 0.6-1.0）。

**167.1 不实现** Segment 字段也不实现 Clip 内部映射，但 `TapJumpToEndTail` 的 `EndTailNormalizedStart` 字段**就是 Segment 系统的小型先驱**。

### 4.2 三处预留接口（关键）

#### A — Player.SetPendingActionNormalizedStart（新 API）

```csharp
float m_pendingActionNormalizedStart;  // 0 = 正常起播

public void ArmPendingAction(GameplayIntentKind kind, ActionDataSO action, float normalizedStart = 0f)
{
    m_pendingActionKind = kind;
    m_pendingAction = action;
    m_pendingActionNormalizedStart = Mathf.Clamp01(normalizedStart);
    m_pendingActionArmed = true;
}
```

#### B — PlayerActionState.OnEnter 接受 normalizedStart

```csharp
// OnEnter 内
m_elapsed = m_baseDuration * m_pendingActionNormalizedStart;
m_prevNormalizedTime = m_pendingActionNormalizedStart;

// MotionExecutor.Begin 也需要接受起播点
m_motionExecutor.Begin(profile, duration, dir, pos,
    baseAnimSpeed: animSpeed,
    startNormalizedTime: m_pendingActionNormalizedStart);
```

#### C — MotionExecutor.AxisCurves.SampleLocalDelta 已天然支持

`SampleLocalDelta(prevT, currT)` 用归一化时间采样 → 直接传 0.6~1.0 即可正确计算"从 60% 起的位移增量"。**无需改动 MotionExecutor**。

### 4.3 Animator CrossFade 也支持 normalizedStart

```csharp
// PlayerAnimController 内
animator.CrossFade(stateName, transitionDuration, layer:0, normalizedTime: 0.6f);
```

→ **Clip 也能从 60% 起播**。

### 4.4 与 Segment 系统未来落地的关系

| 167.1 现在 | Segment 系统落地后 |
|---|---|
| `EndTailNormalizedStart=0.6` 只能"动态选起播点" | Action 可静态绑定 `SegmentStart=0.6, SegmentEnd=1.0` → 等价"一个独立 Action" |
| 起播点固定运行时计算 | Inspector 直接配 Segment 范围 |
| `Player.SetPendingActionNormalizedStart` API | 升级为 ActionDataSO.SegmentStart 字段读取 |
| Anim 层 CrossFade normalizedStart | 复用 |
| MotionExecutor 起播点 | 复用 |

> **结论**：167.1 落地的 `EndTailNormalizedStart` + `normalizedStart` API + 三处接口预留**完整覆盖了**未来 Segment 系统的运行时能力。Segment 系统落地后**只需要把字段从"运行时计算"改为"资产静态配"**，零运行时改动。

## 五、与 166.1 §三 的差异

| 166.1 §三（4 种） | 167.1（10 种） |
|---|---|
| Snap | 保留 |
| LinearDecay（默认）| 降级为通用兼容；**新默认 = MotionCurveDriven**（更接近"零回归" + 沿用 ZXY 轴）|
| ExpDecay | 保留 |
| PreservedSlide | 保留 |
| — | 新增 MotionCurveDriven（默认）|
| — | 新增 FixedDuration / FixedDistance / SpeedProportional / StepDecay |
| — | 新增 TapJumpToEndTail（绝区零方案 A）|

### 5.1 默认改动说明

166.1 的默认 `LinearDecay` 改为 167.1 的 `MotionCurveDriven`：
- **理由**：MotionCurveDriven 让"减速"成为资产的本质属性（曲线决定），不需要写 Decay 代码
- **零回归**：当前 WalkEnd/RunEnd 若 MotionProfile 末段斜率 > 0.5 m/s → 自动 fallback 到 LinearDecay（由 LocomotionState.MoveByLocomotionIntent 接管）
- **资产侧改造门槛低**：设计师只需把 Z 曲线末段拉到 0 → 自动平滑

## 九、验收

### 9.1 默认策略 MotionCurveDriven（L0–L4 后）

| 操作 | 期望 |
|---|---|
| WalkEnd MotionProfile.Z 末段拉 0 → 跑停 | 无"忽然抖一下"；角色自然减速到 0 |
| WalkEnd MotionProfile.Z 末段不拉 0（斜率 > 0.5）| 自动 fallback：进 Locomotion 后 MoveByLocomotionIntent 衰减接管 |

### 9.2 Tap 模式 TapJumpToEndTail（L7–L9 后）

| 操作 | 期望 |
|---|---|
| W 轻点（< 0.15s） | RunStart 播 20% → 立刻跳到 RunEnd 60% 起播 → 角色"轻挪一步收回" |
| W 长按（> 0.5s） | RunStart 完整播完 → Loop |

### 9.3 StepDecay 演出感

| 操作 | 期望 |
|---|---|
| 蓄力释放 + StepDecay [1, 0.5, 0] @ 0.08s | 视觉：角色每 0.08s 速度断档跳变（咚咚咚）|

### 9.4 Segment 兼容验证（Segment 系统落地后）

| 操作 | 期望 |
|---|---|
| WalkStart Action 改用 Segment（Start=0.0, End=0.5）+ 静态绑定到 0.5-1.0 的 WalkEnd Tail | 行为与 TapJumpToEndTail 完全一致；运行时代码不变 |

## 十、风险

| 风险 | 缓解 |
|---|---|
| MotionCurveDriven 末段斜率检测错误 → ClearPlanarVelocity 不该清却清了 | Tail Slope 阈值可配；OnValidate 警告"Z 曲线末段 > 0.5"；用户可强制改 LinearDecay |
| 用户不知道选哪个 Policy | Editor 加 Tooltip + 状态级推荐预设按钮（一键应用 §六 推荐）|
| TapJumpToEndTail 需要"配对的 End Action" 配置麻烦 | ActionDataSO.TapPairedEndAction 字段；为空时自动按命名匹配（WalkStart → WalkEnd）|
| Animator CrossFade normalizedTime 在某些 Animator 模式下失效 | L8 加 fallback：CrossFade 后 SetTime |
| 10 种 Policy Inspector 字段太多 | L5 Editor 联动按 Policy 隐藏不相关字段（仅显示当前 Policy 用到的参数）|

## 十二、设计理念汇总

> **三句话钉死**：
>   1. **MotionCurveDriven** = 默认策略，沿用旧 ZXY 轴 —— "减速是资产的属性，不是代码的"
>   2. **10 种 Policy 矩阵** = 覆盖 3A 主流手感（绝区零、原神、鸣潮、星铁、永劫无间、黑魂）
>   3. **`normalizedStart` API 预留接口** = Segment 系统落地的零成本桥梁（绝区零方案 A → 方案 C 无缝升级）

---

> 落地协议：L0–L4 + L6 立刻做（核心策略矩阵 + 默认 MotionCurveDriven）→ L7–L9 紧随（绝区零点按）→ L5 收尾（Editor 联动）→ Segment 系统未来独立切片自动复用本蓝图的 normalizedStart 接口。
