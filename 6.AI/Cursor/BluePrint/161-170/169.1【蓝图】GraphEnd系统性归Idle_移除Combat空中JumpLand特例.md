## 一、临时方案代码事实

### 1.1 原文（`PlayerActionState.cs:487-521`）

```csharp
void ExitToBaseline(Player player)
{
    var ctx = player.LocomotionGraphContext;
    var takeJumpLandBranch = m_startedWhileAirborne   // ← 起手在空中（如 Combo C）
        && player.IsGrounded                          // ← 现在已落地
        && ctx.JumpLand != null                       // ← LocomotionGraphContext 配了 JumpLand
        && m_action != null
        && m_action.IntentCategory == ActionIntentCategory.Combat;  // ← Combat 车道

    // ... 日志 ...

    if (takeJumpLandBranch)
    {
        // ★★ 临时方案：强插 JumpLand Action 重新进 ActionState ★★
        player.SetGraphContextAction(ctx.JumpLand, "jump-land-after-air-combat");
        player.ArmPendingAction(GameplayIntentKind.Jump, ctx.JumpLand);
        player.States.ForceChange<PlayerActionState>();  // 同状态须 ForceChange
        return;
    }

    player.States.Change<PlayerLocomotionState>();
}
```

### 1.2 用户为什么说"破坏系统性"

| 维度 | 临时方案逻辑 | 用户原则 |
|---|---|---|
| 触发条件 | 空中起手 + **已落地** + Combat → 强插 JumpLand | **Combo C 本就是空中落地终结技；落地动作已含在 Combo C 自身的 Clip/MotionProfile 里** |
| 视觉表现 | Combo C 挥刀落地 → 又播一段 JumpLand → Idle | 应该：Combo C 挥刀落地 → Idle |
| 系统性 | 在 Action 退出层引入"Combat 车道特例"，破坏 FSM 标准链 | **Graph 游标到 End 节点 = 回 Locomotion (Idle)**，无中间隐式插入 |

### 1.3 错误的根本

**`takeJumpLandBranch` 条件实际上在做相反的事**：
- `player.IsGrounded == true` 说明角色**已经安全落地**
- 此时**最不需要** JumpLand 软着陆
- 但条件偏偏在这一刻触发 JumpLand

真正需要 JumpLand 的场景是 "Action 结束时 `!player.IsGrounded`"（如战斗中拔剑挥空，角色还在下落），那才需要空中→地面的过渡动画。但这个场景**本来就有标准链兜底**（见 §三）。

## 二、FSM 标准链（系统性应该的样子）

### 2.1 4 支柱接地判定流（已存在，无需新增）

```
PlayerActionState.OnLogicUpdate
   · actionEnded && routeEnded → ExitToBaseline
   ↓
PlayerActionState.ExitToBaseline
   · 全部走 Change<PlayerLocomotionState>      ★ 删 takeJumpLandBranch
   ↓
PlayerLocomotionState.OnLogicUpdate
   · IsGrounded=true → 留 Locomotion（Detect→Idle/Move）
   · IsGrounded=false → Change<PlayerAirborneState>
   ↓
PlayerAirborneState.OnLogicUpdate
   · 落地（IsGrounded=true）→ TryExitToLandOrLocomotion
       → ctx.JumpLand 非空 → ArmPendingAction → ActionState 播 JumpLand
       → ctx.JumpLand 为空 → Change<Locomotion>
```

### 2.2 这条标准链已经覆盖所有合理场景

| 场景 | 标准链行为（删除临时方案后） |
|---|---|
| **Combo C 空中下劈落地结束（Combo C 含落地姿势）** | ExitToBaseline → Locomotion → IsGrounded=true → Idle ✅ |
| Mid-air Combat 挥空（结束时仍在空中）| ExitToBaseline → Locomotion → !IsGrounded → Airborne → 自然下落 → 触地 → JumpLand → Idle ✅ |
| 普通地面 Combat | ExitToBaseline → Locomotion → IsGrounded=true → Idle ✅ |
| 跳跃 → Air → 落地 | Airborne.TryExitToLandOrLocomotion → JumpLand → Idle ✅ |

→ **删除临时方案，行为完全正确，且更系统**。

### 2.3 Graph 已有 IdleNodeId 概念，无需新增

`SkillEntryService.cs:873`：
```csharp
var idleNodeId = _combatGraph?.IdleNodeId;
```

Graph 游标在末招完成（NaturalExit）时已经会推进到 `IdleNodeId` —— 这正是用户说的"游标到 End 就是回 Idle"。Graph 自身的语义层早就对了，**只是被 PlayerActionState 的临时方案在 Action 退出层强行截胡**。

## 三、系统性修复（核心改动）

### 3.1 改动一：删除 `takeJumpLandBranch` 整段

`PlayerActionState.ExitToBaseline` 简化到：

```csharp
void ExitToBaseline(Player player)
{
    if (player.DebugLocomotion)
    {
        Debug.Log(
            $"[Jump][ActionExit] action={(m_action != null ? m_action.name : \"NULL\")} " +
            $"intentCategory={(m_action != null ? m_action.IntentCategory.ToString() : \"NULL\")} " +
            $"startedWhileAirborne={m_startedWhileAirborne} grounded={player.IsGrounded} " +
            $"branch=Locomotion frame={Time.frameCount}",
            player);
    }

    CombatGraphFinisherDiagnostics.LogActionBaselineExit(player, m_action, jumpLandBranch: false, forceReenter: false);

    // 169.1 系统性修复：Action 结束 → 一律回 Locomotion。
    //   后续判定接地 → Idle / Airborne / JumpLand 全部由 FSM 标准链处理。
    //   Graph 游标到 End 节点 = 回 Idle（与 IdleNodeId 语义一致），不在 Action 退出层做隐式 Action 注入。
    player.States.Change<PlayerLocomotionState>();
}
```

**删除内容**：
- `var ctx = player.LocomotionGraphContext;`（不再需要）
- `var takeJumpLandBranch = ...` 整个判定
- `if (takeJumpLandBranch) { SetGraphContextAction + ArmPendingAction + ForceChange<PlayerActionState>; return; }` 整块
- 不再需要 `CombatGraphFinisherDiagnostics.EndTrace(player, "JumpLand-reenter")` 这条分支

**保留**：
- `LogActionBaselineExit(... jumpLandBranch: false ...)` 探针（用于观测）
- `Change<PlayerLocomotionState>` —— 唯一出口

### 3.2 改动二：`m_startedWhileAirborne` 字段可保留（语义有别）

字段本身记录"Action 起手时是否在空中"——是合理的诊断字段（FrozenAction 期间地面状态可能切换）。**不删**，仅删基于它做 JumpLand 决策的逻辑。后续如有别的诊断 / 表现层联动，仍可用。

### 3.3 改动三（兼容期，可选）：保留兜底警告

若有合法场景**真**需要"Action 退出后强制走 JumpLand"，应该由 **Combat Graph 边**显式表达（如配一条 `Combo C → JumpLand_Action` 的 Flow 边），而**不是在代码里隐式插**。

可以在 ExitToBaseline 加一条诊断：

```csharp
if (m_startedWhileAirborne
    && player.IsGrounded
    && m_action != null
    && m_action.IntentCategory == ActionIntentCategory.Combat
    && player.DebugSkillRoute)
{
    Debug.Log(
        $"[CombatGraph][Finisher] 169.1-NOTE Combat 空中→落地结束 action={m_action.name} —— " +
        $"如需软着陆请在 Combat Graph 加显式 Flow 边到 JumpLand Action，不再依赖 ExitToBaseline 隐式插入。",
        player);
}
```

这是**非阻塞**的迁移提示，方便发现历史资产是否有依赖。

## 十、设计理念汇总

> **三句话钉死**：
>   1. **Graph 游标到 End 节点 = 回 Idle**（用户原则）—— Action 退出层不得隐式插入新 Action
>   2. **JumpLand 唯一合法触发点 = `PlayerAirborneState.TryExitToLandOrLocomotion`**（标准 FSM 链）
>   3. **空中落地的 Combat Action（如 Combo C）= 自身完整收尾**（落地姿势在 Clip / MotionProfile 内表达），不需要也不应该追加 JumpLand
