## 一、Strafe Left/Right 与 Strafe Locomotion —— 代码结论

### 1.1 定义层（数据）

| 项 | Id | Flag 位 | 引入 | 绑定模型 |
|---|---|---|---|---|
| `StrafeLeft` | 11 | `1<<10` | 158.2 | Simple：1 State → 1 Binding |
| `StrafeRight` | 12 | `1<<11` | 158.2 | Simple |
| `BackWalk` | 13 | `1<<12` | 158.2 | Simple |
| `StrafeLocomotion` | 19 | `1<<18` | 159.1 L1+ | Composite：1 Flag → **16 Binding**（8 向 × WalkOnly/RunOnly） |

159.1 蓝图 §2.1 原映射：`Strafe[Walk|Run]_L/R/B` → **粗粒度 3 向**（Left/Right/BackWalk）；L3 验收改为 **8 向 × 走跑** → `StrafeLocomotion`。

### 1.2 运行时谁被 Detect 产出？

`PlayerLocomotionState.DetectRequestedState`（159.1 §5.2 优先级 4）：

```
LockedOn + hasInput → StrafeLocomotion + StrafeDirection8
```

**全项目 grep 结论**：除枚举定义与 `IsContinuous()` 分类外，**无任何** Detect / Resolver / Anim 分支读取 `StrafeLeft` / `StrafeRight` / `BackWalk`。

| 状态 | Detect 产出 | Resolver 查表 | Anim 表现 |
|---|---|---|---|
| StrafeLeft / Right / BackWalk | **永不** | 若强行 Request 则 Simple `GetBinding(id)` | 无专用分支 |
| StrafeLocomotion | LockOn 持续输入 | `GetBinding(state, strafeDir, turnDir, wantsRun)` | `PlayerAnimController` Profile 优先 |

### 1.3 结论（架构决议）

| 问题 | 答案 |
|---|---|
| 功能是否重复？ | **是（运行时语义重复）**。启用 `StrafeLocomotion` 后，旧三态 **不会被 Detect 走到**，配了 Binding 也不生效。 |
| 能否同时勾选？ | **技术上可以**，但属于 **无效双配表** —— 仅 StrafeLocomotion 16 行有玩法意义。 |
| 159.1 权威方案 | **StrafeLocomotion**；Left/Right/BackWalk 为 **158.2 迁移残留**，应标 Obsolete 并在 AutoFix 中 **互斥**。 |
| TurnInPlace 同理 | Detect 产出 **TurnInPlaceDirected**（4 向 Composite），`TurnInPlace`（Simple）同为 **158.2 残留**；与 160.3 同一套互斥规则。 |

如果功能重复，那么请你进行语义重复清除

### 1.4 Editor 互斥契约（160.3 新增）

| 规则 | 行为 |
|---|---|
| **M1** | `EnabledStates` 含 `StrafeLocomotion` → Authority **忽略** `StrafeLeft/StrafeRight/BackWalk`（不生成 Binding；Validate 报 **Info**：「已由 StrafeLocomotion 取代」） |
| **M2** | 同上，`TurnInPlaceDirected` 启用 → Authority **忽略** `TurnInPlace` |
| **M3** | 若 **未** 启用 StrafeLocomotion 但启用 Left/Right/BackWalk → 保留 Simple 三行（仅 Legacy Profile 迁移期；新 Profile 默认不开） |
| **M4** | AutoFix **删除** Target 中所有不在 Authority Key 集合内的行（**无需** Remove Unused 二次确认 —— 见 §2.2 R6） |

## 二、AutoFix 2.0 ——「Reconcile」契约

### 2.1 从 Append-Sync 升级为 Reconcile

160.2 铁律 S2「Sync 只追加」适用于 **Sync Bindings** 按钮；**Auto Fix** 升级为 **ReconcileBindings**：

```
AuthorityKeys = ExpandEnabledStates(enabledStates)   // 含 Composite 展开
TargetKeys    = MapBindingsToKeys(bindings)

Reconcile:
  1. REMOVE  TargetKeys \ AuthorityKeys          // 含 Unused、Legacy Strafe 三行
  2. DEDUPE  同 Key 保留首条（Clip/Action 合并策略见 §2.3）
  3. ADD     AuthorityKeys \ TargetKeys          // 默认行工厂
  4. NORMALIZE 每条合法行的结构字段（§2.4）      // 不默认覆盖 Clip/Action，除非类型非法
  5. REBUILD ORDER 按 LocomotionStateFlag 菜单序（已有 RebuildBindingsInAuthorityOrder）
  6. ASSERT   bindings.Length == AuthorityKeys.Count
```

**幂等性**：步骤 1–6 对同一 `enabledStates` 重复执行，`Added=Removed=0`，`Length` 不变。

### 2.2 新铁律（相对 160.2 的修订）

| # | 规则 | 适用范围 |
|---|---|---|
| R1 | Authority 仍为唯一真相 | Sync + AutoFix |
| R2 | **Sync Bindings** 仍只追加 Simple + 重排（160.2 S2 不变） | Sync 按钮 |
| R3 | **Auto Fix = Reconcile**：删 Unused、补 Missing、去重、规范化、排序 **一步完成** | Auto Fix 按钮 |
| R4 | Auto Fix **不要求** Remove Unused Dialog | 用户已书面允许删除对齐 |
| R5 | Auto Fix **允许**清空「类型非法」资源（Continuous 态上的 DiscreteAction / 反之） | 见 §2.4 |
| R6 | Auto Fix **不覆盖**「类型合法且 Key 正确」的 Clip/Action（策划劳动保护） | 默认 |
| R7 | 可选：**Shift+Auto Fix** 或二级菜单「Reset Assets」清空全部 Clip/Action（本切片 OPEN，非必须） | 后续 |
| R8 | 每次写 SO：`Undo.RecordObject` + `WriteBindingsToSerializedObject` | 已实现 |

### 2.3 Authority Key 展开与期望行数

**算法**（`LocomotionProfileSyncAdapter.BuildAuthorityBindingKeys`）：

```
foreach flag in BuildAuthorityFlagOrder():   // 与 Inspector 菜单序一致
  if !flag.IsEnabledIn(enabled): continue
  if IsSupersededLegacy(flag, enabled): continue   // M1/M2

  id = flag.ToId()
  if id is StrafeLocomotion:
     for dir in StrafeDirections[8]:
       for run in {WalkOnly, RunOnly}:
         yield Key(StrafeLocomotion, dir, None, run)
  else if id is TurnInPlaceDirected:
     for turn in TurnDirections[4]:
         yield Key(TurnInPlaceDirected, None, turn, Any)
  else if !IsCompositeAuthority(id):
     yield Key(id, None, None, Any)
```

**用户截图勾选集（Run 未勾、TurnInPlace 未勾、Legacy Strafe 未勾）期望行数**：

| 分组 | 勾选项 | 行数 |
|---|---|---|
| 基础 | Idle, Dead | 2 |
| 走 | Walk, WalkStart, WalkEnd | 3 |
| 跑 | RunStart, RunEnd（**无 Run 循环**） | 2 |
| 跳 | AirJumpLoop, JumpStart, JumpLand | 3 |
| 转身 | Pivot | 1 |
| Turn Composite | TurnInPlaceDirected | 4 |
| Strafe Composite | StrafeLocomotion | 16 |
| **合计** | | **31** |

勾选 **Run** 时 +1 → **32**。与当前「32 行」资产差 1 的原因即为 **Run 未启用却残留 Run Binding** 或 **Legacy 行未删**。

### 2.4 规范化（Normalize）字段清单

对 **Authority 内**每一行执行（Clip/Action 除外，除非非法）：

| 字段 | 规则 |
|---|---|
| `State` / `StrafeDirection` / `TurnDirection` / `RunRequirement` | 与 Key 一致；Simple 行强制 `Strafe=None, Turn=None, Run=Any` |
| `FallbackState` | `GetDefaultFallback(State)`（扩展现有 switch，见 §2.5） |
| `Speed` | `< 0.001` → `1` |
| `TransitionDuration` | `< 0.0001` → `0.08` |
| `UseRootMotion` / `CanRotateDuring` / `CanMoveDuring` | 不强制改（OPEN：后续按 State 模板） |
| `DiscreteAction` | 若 `State.IsDiscrete()` 且 Action 为空 → 保持空；若 **Continuous 态** 非空 → **清空** + 计数 `ClearedIllegalAssets` |
| `ContinuousClip` | 若 `State.IsContinuous()` 且 Clip 为空 → 保持空；若 **Discrete 态** 非空 → **清空** |

### 2.5 Fallback 默认表（AutoFix 强制写回）

| State | FallbackState | 说明 |
|---|---|---|
| Idle, Dead, Walk, Run, AirJumpLoop | Idle | 循环态自身未注册时回 Idle |
| WalkStart | Walk | 跑起链 |
| RunStart | Run | |
| WalkEnd, RunEnd, JumpLand, Pivot, TurnInPlace | Idle | 离散结束/转身 |
| JumpStart | AirJumpLoop | 起跳 → 滞空 |
| TurnInPlaceDirected（4 行） | Idle | |
| StrafeLocomotion（16 行） | Walk | LockOn 降级到走 |
| StrafeLeft/Right/BackWalk（Legacy） | Walk | 仅 M3 路径 |

**环检测**：Fallback 目标须在 `EnabledStates` 内或链至 Idle；否则 Validate 报 Error（AutoFix 不静默改 Detect）。

## 八、面试口述总结

Locomotion 的 Strafe 经历了 **158.2 三态 Simple** → **159.1 八向×走跑 Composite** 的演进；运行时 Detect **只认 StrafeLocomotion**，旧三态是配表僵尸。160.2 的 Sync 适合「只补不删」；160.3 把 **Auto Fix** 升级为 **Reconcile**：以 Enabled States 展开 Authority Key 集合，一步删 Unused、补 Missing、去重、规范化 Fallback，并保证与 Inspector 菜单 **同序同数**，让策划只剩挂 Clip/Action。
