# 166.4【蓝图】Action 退出减速重构 —— DynamicBrake 智能急停 / 压缩十策略到四正交

> **基线**：166.1 配置化（3 策略起步）/ 167.1 矩阵化（扩展为 10 策略，但**与 MotionProfile 重叠 + 缺差异化**）
> **触发点**：用户实测 `SpeedProportional` 与 MotionProfile Z 曲线重叠 → 退出瞬间动画追位移、效果模糊
> **目标**：把十策略压回 **4 个正交策略**；用一个**真正智能**的 `DynamicBrake` 替代 5 个换汤不换药的衰减曲线；复刻绝区零"速度越大→减速越久 + 动画自匹配"的拖尾重感

## §0 167.1 矩阵的反思（必须先看清）

### §0.1 167.1 十策略实测的三个问题

| 问题 | 表现 |
|---|---|
| **① 与 MotionProfile 重叠** | `MotionCurveDriven` / `SpeedProportional` 都在读 Action 内 Motion Z 曲线 → MotionProfile 本就驱动位移，二者首尾拼接时**重叠采样** → 退出瞬间出现"动画追位移"卡顿 |
| **② 策略大同小异** | LinearDecay / ExpDecay / TapJumpToEndTail / SpeedProportional / VelocitySmoothing 五种本质都是"衰减公式选 1"；配置时策划无法判断"用哪种区别在哪" |
| **③ 缺真正物理感** | 十策略全部**先把速度归零再播 Idle**；高速急停时角色"瞬切站定"，没有绝区零式"高速冲入急停 → 残影滑动 → 动画与位移协同收尾"的重感 |

### §0.2 167.1 与 MotionProfile 的职责重叠

```
Action 期 (t = 0..1)
─────────────────────────────────────────
MotionProfile.AxisCurves.SampleLocalDelta → 位移
（动作期的所有位移都来自这里）

Action 退出瞬间 (t = 1)
─────────────────────────────────────────
167.1 SpeedProportional：
  ↘ 读 motion 末段斜率 → 继续叠加位移
  ↘ 动画速率匹配位移
  ⚠ 与 MotionProfile 内的 Z 曲线尾段语义重叠
  ⚠ 等于"退出瞬间又算了一次位移"

Action 退出后 (t > 1)
─────────────────────────────────────────
LocomotionState 自然回 Idle
```

**根因**：167.1 把"退出处理"和"运动数据源"混在一起。MotionProfile 已经是动作期位移的唯一数据源，**退出期不应再去读它的曲线**。

## §1 设计原则（166.3 核心契约）

> 1. **MotionProfile 只管"动作期"** —— Action 内 t ∈ [0,1] 的位移完全由 AxisCurves 决定；不向后延伸
> 2. **Brake 只管"退出期"** —— Action 完结后的速度处理由 ExitBrakePolicy 接管；**不读 MotionProfile**
> 3. **速度是退出期的唯一输入** —— `currentSpeed` 是切线之前已确定的物理量，Brake 只根据它推演结束态
> 4. **动画速率服从 Brake duration** —— 动态计算的 brakeDuration → playbackSpeed 自匹配，避免"动画播完了但还在滑"

### §1.1 三层切线

```
[A] 动作内位移
    └ MotionProfile.AxisCurves（不变）

[B] 退出期速度处理
    └ ExitBrakePolicy（166.3 重构核心）

[C] Locomotion 接管
    └ PlayerLocomotionState（不变）
```

A → B 切换点：Action 退出瞬间，**速度由 MotionProfile 末段切线导出一次**（边界条件）；后续 B 接管。

## §3 `DynamicBrake` 详细设计（核心）

### §3.1 输入 / 输出

| 输入 | 含义 |
|---|---|
| `entrySpeed` | Action 退出瞬间的 `Player.PlanarVelocity.magnitude` |
| `referenceSpeed` | Action 内"代表速度"（建议取 MotionProfile Z 轴末段斜率 m/s，或策划填基线） |
| `BrakeProfile`（SO 内嵌） | 速度→duration 映射 + 衰减曲线 + 动画匹配选项 |

| 输出 | 含义 |
|---|---|
| `brakeDuration` | 动态算出的减速持续时间 |
| 每帧 `targetSpeed(t)` | 衰减曲线决定 [0, brakeDuration] 内速度变化 |
| `playbackSpeed` | 动画速率，使 Clip 剩余尾段在 brakeDuration 内播完 |

### §3.2 公式（**核心物理**）

```csharp
// 1. 动态计算 brakeDuration（速度越大，减速越久）
float speedRatio = entrySpeed / referenceSpeed;                 // 0.5 表示半速，1.0 标准，2.0 加速 Buff
float brakeDuration = Mathf.Clamp(
    profile.BaseDuration * Mathf.Pow(speedRatio, profile.SpeedExponent),  // exponent=1 线性；0.5 平方根；2 平方
    profile.MinDuration,                                          // 不低于（如 0.08s）
    profile.MaxDuration);                                         // 不超过（如 0.6s）

// 2. 衰减曲线：speed(t) = entrySpeed × DecayCurve(t / brakeDuration)
//    DecayCurve 从 1 → 0；策划可填 EaseOutCubic / EaseOutExpo / 自定义

// 3. 动画速率：让 Segment 内剩余尾段在 brakeDuration 内播完
//    ★ Segment + Duration 是动画的唯一输入（不是裸 Clip）
float segRemainingSecs = (action.SegmentEnd - currentSegT) * clip.length;   // Segment 余量秒数
float playbackSpeed = segRemainingSecs > 0.01f
    ? Mathf.Clamp(segRemainingSecs / brakeDuration, 0.3f, 3f)
    : 1f;
```

#### §3.3.A 双重上限计算流程（**166.3 修订**）

```csharp
public DynamicBrakeContext Build(float rawEntrySpeed)
{
    // Step 1：钳速度上限（A 类）
    var entrySpeed = Mathf.Min(rawEntrySpeed, profile.MaxEntrySpeed);

    // Step 2：按指数公式算 brakeDuration
    var ratio = entrySpeed / profile.ReferenceSpeed;
    var duration = Mathf.Clamp(
        profile.BaseDuration * Mathf.Pow(ratio, profile.SpeedExponent),
        profile.MinDuration, profile.MaxDuration);

    // Step 3：估算滑行距离 = entrySpeed × AvgDecayFactor × duration
    //         AvgDecayFactor = ∫ DecayCurve(τ)dτ from 0 to 1（曲线下方面积，离线烘焙）
    var avgFactor = profile.AvgDecayFactorCached;   // 曲线变化时 OnValidate 重算
    var estDistance = entrySpeed * avgFactor * duration;

    // Step 4：若超距离上限，反推 duration（B 类硬钳）
    if (estDistance > profile.MaxBrakeDistance)
    {
        duration = profile.MaxBrakeDistance / (entrySpeed * avgFactor);
        // 注意：这里可能让 duration < MinDuration，但物理优先（防滑出）
    }

    return new DynamicBrakeContext { EntrySpeed = entrySpeed, Duration = duration };
}
```

**两阶段钳制语义**：
- `MaxEntrySpeed`：先把"输入速度"压一次（防 brakeDuration 公式爆炸）
- `MaxBrakeDistance`：再把"实际位移"硬钳一次（无论 duration 多长，物理上不超）
- 任一触发即生效，取更紧的那个

### §3.4.A **澄清：Brake 与 RunEnd 是"并联同步"，不是"串联"**（用户问题）

**关键不变量**：DynamicBrake 的动画输入是 **RunEnd Action 配置的 Segment + Duration**（不是裸 Clip）。
- **Segment**（归一化区间 [SegStart, SegEnd]）决定播放**哪段画面**
- **Duration**（秒）决定播放**多长时间**
- DynamicBrake 沿用这两者作素材，把 Duration 换成动态 `brakeDuration`，Segment 范围不变；动画速率 = `(Segment内剩余归一化长度 × ClipSegmentSeconds) / brakeDuration`

```
旧 167.1 SpeedProportional（串联，错）：
[Run Loop 高速] → [RunEnd Action 播 (Segment + 固定 Duration)] → [SpeedProportional 再滑] → 停
                  ↑ Segment 播完                                 ↑ 还在滑 = "画面定格再跑位移" ❌

新 166.3 DynamicBrake（并联同步，对）：
[Run Loop 高速] → [DynamicBrake 时间窗 = brakeDuration（动态算）]
                    │
                    ├─ 动画轨：以 RunEnd 的 Segment [SegStart, SegEnd] 为素材窗
                    │  playbackSpeed = SegmentSeconds(剩余) / brakeDuration
                    │  → brakeDuration 末 ⇋ Segment End 帧 ✓
                    │
                    └─ 位移轨：speed(t) = entrySpeed × DecayCurve(t / brakeDuration)
                       → brakeDuration 末 ⇋ 速度=0 ✓
                    
                    ★ 两轨同一时长，同帧到位
```

| 维度 | 167.1 串联 | 166.3 并联 |
|---|---|---|
| 时长来源 | **RunEnd.Duration 固定** + Brake 衰减各自有时长 | **brakeDuration 单源**（覆盖 RunEnd.Duration） |
| 动画速率 | 1.0（写死） | `SegmentSeconds(剩余) / brakeDuration` 自匹配 |
| 动画范围 | Segment 决定（不变） | **Segment 决定（不变）** |
| 位移规律 | RunEnd MotionProfile + Brake 衰减叠加（可能突变） | 单一 DecayCurve（连续平滑） |
| 收尾同步 | ❌ Segment 播完→然后才滑 | ✅ 同帧到位 |

> ⚠️ 副作用 1：策划在 RunEnd 上配的 **Duration 字段在 DynamicBrake 模式下被 brakeDuration 覆盖**。Inspector 灰显 + 提示。
>
> ⚠️ 副作用 2：**Segment 配置 (SegStart/SegEnd) 仍生效** —— 这是动画"播哪段"的唯一来源；策划想缩短画面用 SegEnd 0.75 即可，DynamicBrake 不会越界采样。

#### §3.4.A.1 关键公式（**Segment-aware**）

```csharp
// SegmentSecondsTotal = (SegEnd - SegStart) × clip.length
// SegmentRemainingNormalized = SegEnd - currentSegNormalized
// SegmentRemainingSeconds = SegmentRemainingNormalized × clip.length

var segRemainSecs = (SegEnd - currentSegT) * clip.length;
var playbackSpeed = Mathf.Clamp(
    segRemainSecs / brakeDuration,
    profile.PlaybackSpeedClamp.x,
    profile.PlaybackSpeedClamp.y);
```

入 Brake 时 `currentSegT = SegStart`，因此 `segRemainSecs = SegmentSecondsTotal`。中途切换的极端场景下，公式自动按当前位置算余量，不丢逻辑。

### §3.4.B 【BUG 修复】DynamicBrake 是 Action **内部位移策略**，不是后置阶段（实施严重错误）

#### §3.4.B.1 实施期两个症状同源

| 症状 | 根因 |
|---|---|
| "Dynamic Brake / 三个 BrakeProfile 都播两遍 RunEnd" | RunEnd Action 已经正常播了一次（含 MotionProfile 位移），ExitToBaseline 后 Brake 阶段**又用 RunEnd Clip 作素材再播一次** → 双重播放 |
| "InheritPhysics 仍突然动一下" | RunEnd MotionProfile 末段斜率不为 0 → Action 结束瞬间未把"末速度"作为 Locomotion 入态速度；或 Locomotion.OnEnter 强制清零 → 跳变 |

#### §3.4.B.2 正解：Brake 嵌入 Action 内部

```
错误实施（双重播放）：
[ActionState 播 RunEnd: 动画 + MotionProfile 位移]   ← 第一遍
       ↓ ExitToBaseline
[Locomotion + Brake 阶段: 用 RunEnd Clip 再播]       ← 第二遍 ❌

正解（Brake 嵌入 Action）：
[ActionState 播 RunEnd 一次]
   ├─ 动画：Segment + Duration（Duration 被 brakeDuration 覆盖）
   │   playbackSpeed = SegRemainSecs / brakeDuration
   └─ 位移：★ MotionProfile 禁用 ★ 由 DynamicBrake 公式驱动
       speed(t) = entrySpeed × DecayCurve(t / brakeDuration)
   ↓ Action.nt >= 1.0
[ExitToBaseline → Locomotion → Idle]    ← 不再二次 Brake ✓
```

#### §3.4.B.3 关键代码契约（**必须落实**）

```csharp
// PlayerActionState.OnEnter：

// PlayerActionState.OnLogicUpdate：

}
```

#### §3.4.B.4 InheritPhysics 突然动一下的独立修复

| 阶段 | 当前 BUG | 正解 |
|---|---|---|
| RunEnd Action 内 | MotionProfile 末段 Z 斜率 > 0 → 末帧速度=X | 保留 |
| Action.nt = 1.0 退出瞬间 | `PlanarVelocity` 仍 = X | 保留 |
| `PlayerLocomotionState.OnEnter` | **错误**：强制清零或不接管 | **正解**：**什么都不做** —— 让 `PlanarVelocity` 自然带过来 |
| Locomotion 第一帧 | 速度跳变 → 视觉"突然动一下" | 物理从 X 自然衰减到 0 → 视觉连续 |

```csharp
// PlayerLocomotionState.OnEnter（修复版）
protected override void OnEnter(Player player)
{
    // ★ 关键：不清零 PlanarVelocity；它已经包含上一个 Action 末段的速度
    //   后续 OnLogicUpdate 内 hasInput=false 时由 GroundDeceleration 自然衰减
    base.OnEnter(player);
    // 其它初始化（不动 PlanarVelocity）...
}

// PlayerLocomotionState.OnLogicUpdate（确保物理衰减 work）
if (!player.HasMovementIntent)
{
    var planar = player.PlanarVelocity;
    var dec = tuning.GroundDeceleration;
    var newMag = Mathf.MoveTowards(planar.magnitude, 0f, dec * Time.deltaTime);
    var dir = planar.sqrMagnitude > 0.0001f ? planar.normalized : Vector3.zero;
    player.SetPlanarVelocity(dir * newMag);
}
```

#### §3.4.B.5 三大不变量（**实施时必须满足**）

1. **Brake 不跨 State 边界** —— 整个 Brake 周期在 PlayerActionState 内完成；Action.nt 0→1 = brakeDuration 0→full
2. **DynamicBrake 启用 ⇒ MotionProfile 禁用** —— 同一 Action 内**只有一套位移源**生效；不允许 MotionProfile 和 DecayCurve 同时叠加
3. **Locomotion.OnEnter 不清 PlanarVelocity** —— 让前一 State 末速度自然传递；物理衰减负责后续

### §3.5 与 PlayerLocomotionState 的接管握手

```csharp
// Action 退出瞬间：
ExitToBaseline(player):
    var entrySpeed = player.PlanarVelocity.magnitude;
    var brakeCtx = DynamicBrakeContext.Begin(action, entrySpeed);
    player.BrakeRuntime.Begin(brakeCtx);          // 写入 Player 持有的 Runtime
    player.States.Change<PlayerLocomotionState>(); // 169.1 一律走 Locomotion

// PlayerLocomotionState.OnLogicUpdate（最前面，在 Idle 兜底之前）：
if (player.BrakeRuntime.IsActive && player.BrakeRuntime.TryTick(Time.deltaTime, out var speed))
{
    player.SetPlanarVelocityMagnitude(speed);
    player.AnimController.SetPlaybackSpeed(brakeRuntime.CurrentPlaybackSpeed);
    return;   // ★ Brake 期间不接管 Locomotion 输入；不进入 Idle 兜底
}
// brake 结束 → 正常 Locomotion 流程
```

### §3.6 与 MotionProfile 的边界（**结构性消除重叠**）

| 阶段 | 数据源 |
|---|---|
| Action 期 (t ∈ [0,1]) | **MotionProfile.AxisCurves 唯一驱动**（166.3 加锁，明令 Brake 不读它） |
| 退出瞬间 (t=1) | 取 `Player.PlanarVelocity.magnitude` 作为 entrySpeed（**已经包含 MotionProfile 末段贡献**，不需要再读曲线） |
| Brake 期 [0, brakeDuration] | DynamicBrake 公式驱动；**与 MotionProfile 完全脱钩** |

> 关键不变量：DynamicBrake 实现内**不允许出现** `motionProfile.AxisCurves` / `SampleLocalDelta` 调用 —— 一处不许有。

## §4 绝区零机制复刻要点

### §4.1 三个签名手感

| 手感 | 实现 |
|---|---|
| **速度越大 → 减速越久** | `BrakeDuration = BaseDuration × ratio^Exponent`，Exponent=1.8 时 2× 速度 → 3.5× 时长 |
| **拖尾感（动画与位移协同收尾）** | `MatchAnimationSpeed = true`，playbackSpeed = clipRemaining / brakeDuration |
| **重感（高速急停有明显残影）** | `DecayCurve = EaseOutCubic`，前 30% 时间衰减 70% 速度 → 视觉先猛刹再轻柔收尾 |

### §4.2 Buff 加速时的连带行为

| 场景 | 行为 |
|---|---|
| 加速 Buff +50%，Player 当前速度 = 1.5 × 标准 | entrySpeed = 1.5 × refSpeed → ratio=1.5 → BrakeDuration = 0.25 × 1.5^1.8 = 0.53s → playbackSpeed = clipRemain / 0.53s（动画自慢 → 视觉拖更远） |
| 减速 Debuff，Player 当前速度 = 0.6 × 标准 | ratio=0.6 → BrakeDuration = 0.25 × 0.6^1.8 = 0.10s → 瞬切感 |

**对照 167.1**：旧 SpeedProportional 只是按 ratio 缩 timer，时长固定 → 无法表达"速度越大需要越长时间"的物理感。166.3 通过 Exponent>1 真正做出差异。

## §7 关键架构约束

1. **DynamicBrake 不读 MotionProfile** —— grep `motionProfile.*Brake|Brake.*motionProfile` 必须返回 0
2. **MotionCurveTail 是唯一例外** —— 仅它允许读 Motion 末段；明令注释标"绝区零式智能急停请用 DynamicBrake"
3. **entrySpeed 是 Brake 唯一输入** —— 不允许再回头采样 Clip / Action 中段
4. **playbackSpeed 钳制 [0.3, 3]** —— 防止极端速度比导致动画过快/过慢失真
5. **资产迁移幂等** —— 旧 ExitVelocityPolicy 字段 [Obsolete] 保留一个版本；新 ExitBrakePolicy + BrakeProfile 字段并存兼容期

## §8 反模式（167.1 暴露 + 本次教训）

| 反模式 | 防御 |
|---|---|
| **策略数量 = 复杂度** | 4 个正交 > 10 个微调 |
| **退出期读动作期数据源** | DynamicBrake 不读 MotionProfile；entrySpeed 单一输入 |
| **衰减公式当差异化** | 公式只是"How"，真正的差异化是"When / How long" —— 由 BrakeDuration 决定 |
| **缺动画速率联动** | 动画播完了但位移还在 → 视觉假；playbackSpeed 自匹配 brakeDuration |
| **配置无可视化** | Editor 推演图让策划"看见" Brake 形状 |

## §9 三句话沉淀

> 1. **MotionProfile 管动作期，Brake 管退出期** —— 二者不交叉，结构性消除 167.1 重叠
> 2. **速度→duration→playbackSpeed 是因果链** —— 高速急停的物理感来自 duration 拉长 + 动画自匹配，不是衰减公式
> 3. **4 个正交 > 10 个微调** —— 策划决策树越浅，配置质量越高
