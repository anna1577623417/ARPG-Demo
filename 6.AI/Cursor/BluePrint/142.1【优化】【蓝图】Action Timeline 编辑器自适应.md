# Action Timeline 编辑器 UI/UX 整改计划书 V1.0

---

# 一、问题分析（35%）

当前 Timeline 编辑器核心功能已经具备：

```text
ActionData
↓
Timeline
↓
Track编辑
↓
属性编辑
```

已经进入可用阶段。

但随着：

```text
HitBox
HurtBox
Invincible
Motion
FX
Audio
Camera
```

持续增加，编辑器开始暴露出布局问题。

目前问题不属于功能缺失，而属于：

```text
编辑效率
配置体验
内容生产效率
```

问题。

---

## 问题1：左右区域不可调整

当前布局：

```text
┌────────────────────┬──────────┐
│                    │ Property │
│ Timeline           │          │
│                    │          │
└────────────────────┴──────────┘
```

左右区域比例固定。

用户无法：

```text
扩大Timeline
扩大Property
```

只能接受默认布局。

---

### 风险

随着属性增加：

```text
字段变长
Track变多
配置复杂度增加
```

会越来越拥挤。

---

## 问题2：Property出现水平滚动条

当前：

```text
属性过宽
↓
出现横向滚动
```

需要：

```text
左右拖动
+
上下滚动
```

同时操作。

---

### 风险

用户视线不断移动。

配置效率下降。

尤其：

```text
HitBox
FX
Camera
```

配置项较多时体验极差。

---

## 问题3：属性面板无法自适应

当前很多字段：

```text
Label
Input
Dropdown
```

采用固定宽度。

导致：

```text
窗口变窄
↓
字段拥挤
```

---

### 风险

未来：

```text
Interrupt Semantics
Runtime Event
Gameplay Tags
```

名称更长。

问题会持续扩大。

---

## 问题4：缺少标准编辑器布局

目前更像：

```text
功能窗口
```

而不是：

```text
专业编辑器
```

缺少：

```text
Splitter
StatusBar
Dock布局
```

等基础设施。

---

# 三、落地计划（55%）

---

# P0：可拖拽分割线（最高优先级）

## 目标

支持：

```text
Timeline ←→ Property
```

自由调整宽度。

---

## 实现

新增：

```csharp
float propertyWidth;
```

维护：

```csharp
Rect splitterRect;
```

支持：

```text
鼠标悬停
↓
显示Resize光标
↓
拖动改变宽度
```

---

## 约束

Timeline最小宽度：

```csharp
600
```

Property最小宽度：

```csharp
320
```

---

## 验收

能够：

```text
拖动中间分隔线
```

实时调整区域大小。

---

# P0：移除水平滚动条

---

## 目标

Property区域：

```text
仅允许纵向滚动
```

禁止：

```text
横向滚动
```

---

## 实现

修改：

```csharp
BeginScrollView
```

参数。

统一：

```text
Horizontal = false
Vertical = true
```

---

## 验收

默认状态：

```text
无横向滚动条
```

---

# P0：属性布局自适应

---

## 目标

字段宽度自动适应窗口。

---

## 实现

统一管理：

```csharp
EditorGUIUtility.labelWidth
```

动态比例：

```csharp
40%
Label

60%
Control
```

---

## 验收

无论窗口宽窄：

```text
Label
Input
Dropdown
```

均保持可读。
