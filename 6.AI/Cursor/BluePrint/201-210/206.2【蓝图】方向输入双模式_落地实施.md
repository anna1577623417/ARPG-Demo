## 关键设计 highlights

1. **双阈值配置化**：`ChordWindow` / `MotionWindow` 两个滑条，策划可调；灰色地带默认归 Chord（响应更跟手）
2. **签名升级**：`ResolveDirectionalChord(buf, out isMotionMode)`，保留无 out 的 overload 不破坏调用
3. **Group 可选 MotionForwardRoute**：默认 null → 复用 Forward 槽（零破坏既有资产）；想做"前冲翻滚"独立动作时才填
4. **二态性 SOP**：`ChordWindow=99` → 永远 Chord；`MotionWindow=0` → 永远 Motion；勾选 vs 不勾选有可观察差异
5. **验收锚定 # 3 vs # 5**：同样按 D + Space，**只 hold 时长不同**，走两条 Route — 这就是 206.1 的核心契约

## §1 W2 — LocomotionTuningSO 双阈值

### §1.1 文件改动

**`4_Data/Locomotion/LocomotionTuningSO.cs`** —— 在 `AbilityContextWindowSec` / `DirectionGraceSec` 旁边加：

```csharp
[Header("206.1 方向输入双模式 (Chord vs Motion)")]
[Tooltip("方向键按下到 Space 按下的间隔 ≤ 此时间 → Chord 态（8 向 camera-relative）。\n" +
         "推荐 0.10–0.15s。低于此值 = 玩家把方向键当 Space 的修饰符。")]
```

### §1.2 二态性验收

| 配置 | 行为 |
|---|---|
| `ChordWindow=0, MotionWindow=0` | 任何 hold → Motion 态（F-Dodge）|
| `ChordWindow=99, MotionWindow=99` | 任何 hold → Chord 态（8 向）|
| 默认 | 短按 Chord、长按 Motion |

## §3 W4 — Player.ResolveDirectionalChord 双模式分支

### §3.1 签名升级

**`3_Gameplay/Characters/Player/Core/Player.cs`** —— `ResolveDirectionalChord` 改：

```csharp
public DirectionalRouteType ResolveDirectionalChord(
    Vector2 moveBuffered,
    out bool isMotionMode)
{
    var tuning = m_locomotionTuning;
    var chordWin  = tuning != null ? tuning.ChordWindowSec  : 0.12f;
    var motionWin = tuning != null ? tuning.MotionWindowSec : 0.20f;

    var now = Time.time;
    var holdDur = m_inputContext.MoveHoldDurationSec(now);

    isMotionMode = holdDur >= motionWin;

    var mode = holdDur < 0f         ? "Neutral"
             : isMotionMode         ? "Motion"
             : holdDur <= chordWin  ? "Chord"
             : "Grey→Chord";
    DodgeChord8Probe.LogAbilityDown(now, m_inputContext.MoveActiveSince,
        moveBuffered, chordWin, motionWin, mode);

    if (isMotionMode)
    {
        DodgeChord8Probe.LogMotionResolve(LogicForward, holdDur);
        return DirectionalRouteType.Forward;  // Motion 态强制 Forward 槽
    }

    var result = InputChordResolver.Resolve(moveBuffered);
    DodgeChord8Probe.LogChordResolve(moveBuffered, result);
    return result;
}

// 兼容 overload — 206.1 诊断阶段调用方
public DirectionalRouteType ResolveDirectionalChord(Vector2 moveBuffered)
    => ResolveDirectionalChord(moveBuffered, out _);
```

### §3.2 关键设计

- **isMotionMode out**：让 SkillEntryService 知道当前是 Motion 态，可走 `MotionForwardRoute` 替代 `Forward` 槽（W6 可选）
- **灰色地带归 Chord**：与 173.1 ContextWindow 默契 — 玩家短促组合输入优先视为 chord，响应更跟手
- **Time.time**：用 unscaled wall time，与 Locomotion 转向计算一致

## §8 验收路径

### §8.1 二态性矩阵（与 206.1 §5 对齐）

| # | 操作 | 预期 |
|---|---|---|
| 1 | 站立不动 + Space | Fallback (Step Back) |
| 2 | D + Space (30ms 内) | R-Dodge ✓ |
| 3 | D + Space (100ms) | R-Dodge ✓ |
| 4 | D + Space (150ms, 灰色) | R-Dodge ✓ (默认 Chord) |
| 5 | **D 长按 0.3s + Space** | **F-Dodge ✓** (Motion 态，沿 LogicForward) |
| 6 | D 长按 1s 跑步 + Space | F-Dodge ✓ |
| 7 | W + Space (50ms) | F-Dodge ✓ |
| 8 | W 长按 1s + Space | F-Dodge ✓ |
| 9 | W → 松 W → S+Space (173.3 grace) | B-Dodge ✓ (Chord) |
| 10 | 跑步中按 Space 不松 | F-Dodge ✓ (Motion) |

**关键**：# 3 vs # 5 — 同一方向键，**hold 时长决定模式**，这是 206.1 的核心契约。

### §8.2 [DodgeChord8] Log 验收

启用诊断后，操作 # 2 应见：

```
[DodgeChord8] MoveDown t=1.234 moveBuf=(1.00,0.00) ...
[DodgeChord8] AbilityDown t=1.264 holdDur=0.030s ... → mode=Chord
[DodgeChord8] Chord moveBuf=(1.00,0.00) → Right (camera-relative)
[DodgeChord8] PICK mode=Chord dir=Right route=Route_RightDodge
```

操作 # 5 应见：

```
[DodgeChord8] MoveDown t=10.000 moveBuf=(1.00,0.00) ...
[DodgeChord8] AbilityDown t=10.300 holdDur=0.300s ... → mode=Motion
[DodgeChord8] Motion holdDur=0.300s logicFwd=(0.95,0.31) → Forward (沿 LogicForward 持续移动方向)
[DodgeChord8] PICK mode=Motion dir=Forward route=Route_ForwardDodge
```

→ **同样按下 D + Space，holdDur 差 0.27s，走两条不同 Route**，肉眼可见的 mode 分流。
