3.引入输入语义解析层

---

你现在已经开始接近一个真正 ARPG / ACT 战斗系统里的核心问题了：

“蓄力”本质上不是动画，而是一个输入语义驱动的技能路由状态机。

你之前的问题，本质是：

> 你把“进入凝滞”放到了 Release 之后。 但真正合理的设计是：

进入 ChargeRoute 后，就应该在动画时间线上进入“蓄力维持区”。



也就是说：

一、重新定义：单 Clip 蓄力的本质

单 Clip 蓄力不是：

按住 → 等待 → 松手 → 播放动画

而是：

按住
→ 进入 ChargeRoute
→ 播放同一个动画
→ 到达时间锚点后冻结/慢放
→ 持续积累 ChargeValue
→ Release 后继续播放后半段
→ 命中

真正的重点：

单 Clip 蓄力 = “一段动画上的时间控制”

不是多状态切换。

Input Semantic Resolver 引入约束（AI/架构实施规范）

适用于：

Unity ACT / ARPG

技能路由系统

输入语义层

Charge / Combo / Directional / Chord 输入

---

一、核心目标

Input Semantic Resolver（输入语义解析层）的职责：

将“原始输入事件”解析为“稳定、可路由、可预测的 Gameplay Intent”。

它：

不执行技能

不直接播放动画

不处理伤害

不决定技能效果


它只负责：

“玩家想做什么”


---

二、绝对禁止事项（核心约束）

1. 禁止技能系统解析输入时间

禁止：

if (holdTime > 0.2f)
{
    EnterCharge();
}

出现在：

SkillRuntime

AbilityRuntime

StageRuntime

AnimationEvent

StateMachine


原因：

输入语义属于 InputSemanticResolver。


---

2. 禁止技能直接读取 InputAction

禁止：

InputAction.IsPressed()
Input.GetKey()

出现在：

技能

Stage

Hit

Buff

Runtime


技能层只能消费：

GameplayIntent


---

3. 禁止技能决定输入分支

禁止：

技能内部：
Tap?
Hold?
DoubleTap?

输入语义必须在：

路由前完成解析


---

4. 禁止动画状态决定输入语义

错误：

动画播到某帧后
认为进入蓄力

正确：

输入语义先确定：
ChargeIntent

之后：
动画只是表现

六、Gameplay Intent 的定义约束

GameplayIntent 必须：

1. 稳定

Intent 一旦发出：

不可在技能运行中反复变化

例如：

错误：

边运行边重新判断Tap/Hold


---

2. 原子化

Intent 是：

“玩家意图最小单位”

例如：

LM_Charge

而不是：

Charge + Animation + Damage


---

3. 与技能解耦

Intent：

不直接绑定具体技能

错误：

GreatSwordChargeAttackIntent

正确：

LM_Charge


---

它负责：

“Intent → Route”

例如：

LM_Tap
→ NormalAttackRoute

LM_Charge
→ ChargeRoute

它：

不解析输入

不计算按住时间
