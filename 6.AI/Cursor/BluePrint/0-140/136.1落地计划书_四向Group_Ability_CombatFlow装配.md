# 136.1 落地计划书：四向 Group + Ability + CombatFlow 装配

## 切片信息
- 切片名：SkillRoute 四向位移与 Ability 仲裁单轨化
- 目标：在现有框架上，跑通「带上下文语义输入的 Group 选四向 Route」，移除 DirectionalRoute 旧链路；CombatFlow 改为 Loadout 装配；补齐 Ability 职责与编辑器。
- Landing 规划：`1/8` ~ `8/8`
- 回滚策略：每个 Landing 前打 tag（示例：`skill-v136.1-L1`）

## 一、约束与终态定义（单轨）

### 1) 单轨终态
- 运行时不再读取 `SkillEntryDefinition.directionalRoute` 与 `DirectionalRouteSet`。
- 四向选择只允许一条主链：`InputSemantic(Directional) -> ContextGroup/Ability -> Group选路 -> RouteRuntime`。
- `CombatFlow` 不再由 `Player` 单独字段挂载，统一挂在 `SkillEntryLoadoutSO`。
- `NormalRoute` 不再承担四向回退职责（仅保留“非四向输入”语义下的普通回退）。

### 2) 最小改动标签原则
- 保留既有 `State/Status/Ability/Mechanic/Faction` 五轨。
- 本次仅新增/整理 **Ability 轨最小集合**，不重做全标签体系。
- 打断窗口从“动作名硬编码”迁到“Ability 许可 + 最小优先级”。

### 3) Done 判定
- Landing Done：设施到位 + 指定握手通电 + 固定日志可观测。
- Slice Done：四向前后左右均可稳定命中对应 Route；不存在 DirectionalRoute/NormalRoute 误导性回退；Ability 与打断窗口配置可在编辑器直观操作。

---

## 二、当前基线（按现有代码）
- `SkillEntryLoadoutSO` 目前仅含 `bindings`，尚未统一承载 `CombatFlow` 与 `AbilityMap`。
- `Player` 仍含 `combatFlowGraph` 字段并在 `Init()` 中 `AttachGraph(combatFlowGraph)`。
- `SkillEntryService.TryResolveForIntent()` 仍存在 `entry.DirectionalRoute` 分支，且优先级会与 Group/Graph 互相干扰。
- `ActionWindow` 已有 `InterruptibleByCategories/MinIncomingPriority`，但尚未形成“Ability 放行”统一能力闸门。

## 七、关键实现要点（避免重演问题）

### 1) 彻底避免“看似四向，实际 NormalRoute 干扰”
- Directional 语义路径下，禁止直接回退 `Entry.NormalRoute`。
- 若四向配置缺失，显式 `NO_ROUTE (Directional)`，并输出结构化日志。

### 2) Graph 边求值策略
- 当命中候选边但 `CanCast=false` 时继续尝试下一候选边，不应早退。
- 禁止 `Always` 边抢占四向边（编辑器给出警告）。

### 3) Group 与 ContextGroup 分责
- `ContextGroup`：解决“当前是什么语义上下文”。
- `RouteGroup`：解决“该上下文下选哪条 Route + 共享CD/Cost”。

## 八、编辑器改造范围（本切片）
- `SkillEntryLoadout` Inspector：
  - 展示 `CombatFlow`、`AbilityMap`、`ContextGroups`。
- `ActionWindow` Inspector：
  - 暴露 `AllowedAbilityTags`（或能力类别位掩码）与最小优先级。
- `CombatFlow` Inspector：
  - 边条件（MoveDirection/Ability/OnTag）与命中顺序可视化。
- `ContextGroup` Inspector：
  - 条件到 Group 的映射表，支持一键校验“未命中路径”。

## 九、风险与回避
- 风险：旧资产大量依赖 DirectionalRouteSet。
  - 回避：先做迁移工具与校验报告，再执行 Landing 7 切断。
- 风险：Ability 与旧标签语义重叠导致双重拒绝。
  - 回避：Ability 只作为“可施放闸门”，不重做 State/Mechanic。
- 风险：CombatFlow 与 Group 双重选路冲突。
  - 回避：Directional 统一走 `ContextGroup -> Group`，CombatFlow 负责“跨阶段流转”，非同层选路。
