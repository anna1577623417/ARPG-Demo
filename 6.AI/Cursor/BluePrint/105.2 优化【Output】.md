# 〇、AI 代码生成约束（贯穿全程的硬契约）

> 这是给 AI（含本对话所有后续 turn）落地此重构时**必须满足的红线**。任何违反即视为不合格代码，必须回滚重写。

### A. 命名与边界

- **A1** 新代码**禁止**出现 `SkillDataSO / SkillStageSO / SkillLoadoutSO / SkillSlotType / SkillRuntime / SkillChargeCommit / SkillSegmentResolver / GameplayIntentKind.LightAttack/ChargeAttack/ComboAttack` 等旧符号；现有这些文件原地保留（不删），但新管线**零引用**。
- **A2** 新管线一切冠以 `SkillEntry* / SkillRoute* / SkillStage*` 前缀（数据层）和 `*Runtime` 后缀（运行时层）。
- **A3** **入口语义**（按键 / Combo / Charge / Direction）与**动作语义**（Action / Motion / Clip）禁止互相 using；新 SkillStage 引用 `ActionDataSO` 是唯一握手点。

### B. 数据层（ScriptableObject）

- **B1** 所有可序列化字段**全部** `[SerializeField] private` + 公有只读属性；禁止 public 裸字段。
- **B2** 所有 SO 提供 `[CreateAssetMenu(menuName = "GameMain/SkillRoute/<分类>/<类名>")]`，**子菜单严格分层**（Entry / Route / Stage / Transition）。
- **B3** 每个 SO 头部 `Tooltip` 说明**它在两套语义中的位置**（"入口语义层" / "动作语义层"），杜绝策划误用。
- **B4** 0-GC：运行时**任何** `OnUpdate / Tick` 路径禁止 LINQ / `new List` / `foreach` over interface / 字符串拼接。

### C. 运行时层

- **C1** `SkillRouteRuntime` 为抽象基类；Normal / Combo / Charge / MultiStage / Derivative 五种子类，每种**单一职责**（不允许在 Normal 内出现 Combo 字段）。
- **C2** `MotionExecutor` 仅被注入 `MotionPlaybackContext`，**不引入** `using SkillRoute*`。
- **C3** Charge 状态机收口到 `ChargeRouteRuntime` 内部，`PlayerActionState` 删除一切微相位字段（Phase 3 验收点）。
- **C4** HUD 只通过 `IRouteRuntimeHandle` 读运行时状态，**禁止**反向写。

### D. 编辑器/工具

- **D1** 所有 Editor 代码放 `Assets/GameMain/Scripts/Editor/Skill/Routes/`，运行时 asmdef 不引用 Editor。
- **D2** `SkillRecipeCompiler` 幂等：同配方多次 Compile 不重建 GUID、不污染 dirty 状态（无变化时不 SetDirty）。
- **D3** 资产强制目录：`Assets/GameMain/Data/_Skills/<EntryId>/{Routes,Stages,Recipes}/`。

### E. 测试与验收

- **E1** 每个新 Runtime 类型对应 `EditMode` 测试（位于 `Tests/Editor/SkillRoutes/`）。
- **E2** Phase 完成必备：编译 0 warning（新代码）、关联测试全绿、文档化的回滚 tag。
