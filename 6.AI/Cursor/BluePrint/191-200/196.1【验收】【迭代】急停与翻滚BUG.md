## 诊断报告

### 你这个现象是 **设计而不是 bug**（但设计选择有问题）

**完整链路对账**

```
玩家按 WASD（或 Space 跳跃）
   ↓ 上游：PlayerController 把 MovementIntent / Jump 当连续输入塞进 Player.IntentBuffer
   ↓
PlayerStateManager.Tick 每帧消费 IntentBuffer：
   闸门 1: TransitionResolver.CanOfferIntent       （TransitionResolver 标签 + 过期）
   闸门 2: SkillEntryService（仅 Combat lane 走；Move/Jump 是 Locomotion lane → 跳过）
   闸门 3: Current.TryConsumeGameplayIntent       ← 当前是 PlayerActionState（Walk_End）
   闸门 4: Commit → IntentRouter.Route → 我植入的 ROUTE 日志
   
进入 PlayerActionState.TryConsumeGameplayIntent (line 530)：
   ↓ 检查 IsRoutable
   ↓ if (m_action.IsLocomotionRecovery)  ← Walk_End = Y，命中
        ↓ if (intent.Kind == Move || intent.Kind == Jump || category == Locomotion)
              return false;  ← **直接吞掉，没任何旁路**
```

Walk_End 自带 `IsLocomotionRecovery = Y` → 命中 Recovery 分支 → Move/Jump **被硬编码屏蔽**。

### 注释里的"由 Grammar 缓存 PendingFacing"是什么意思

设计意图：

- Walk_End 期间玩家按方向键 → **不立刻打断**，而是把方向缓存到 `PendingFacing`
- Walk_End 自然结束时，PlayerActionState.OnExit 里有这一段（你 log 里能看到对应日志）：
    
    ```csharp
    if (TransitionType == End/Pivot && TryConsumePendingFacing(out var pendingForward)){    player.SetLogicForward(pendingForward);}
    ```
    
- 这是 184.4 Motion Grammar 的 **Tap Facing 设计**：Walk_End 的 0.67s 内你按的方向，等动画播完一次性应用

### 为什么你的体感是"被锁死"

1. Walk_End duration = **0.67s**（一次按键周期）
2. 玩家在站立急停时往往会**反复点按**方向键（log 里帧 804 / 882 / 951 / 1019 四次连续重入证明了）
3. 每次按方向键 → 触发新的 Walk_End → 又 0.67s 不响应 → 又触发新的 Walk_End → **无限循环**
4. 视觉上没有任何"输入被缓存了"的反馈（PendingFacing 是默默存的，没有动画暗示）
5. **Jump 也被同一逻辑吞掉** → 急停期间没法跳

### 为什么"只有技能能用"

技能（Slide/Roll/Attack）是 **cat=Combat**：

- `incomingCategory = Combat`
- 不命中 line 549-554 的 Move/Jump/Locomotion 判定
- 落到 line 556-558：`IntentRouter.Route(player, in intent, forceActionReentry: false)` → **正常打断**

log 里帧 568 Walk_End 期间按 Shift → 同帧 ROUTE Skill_Entry_07 routed=Y → Slide 立刻接上 ← 这就是证据。
