## 二、为什么这是设计性失误（不只是 bug）

184.3 §9.2 + 184.4 的原始设计意图：

- 玩家在 End 期间点按方向键 → 不打断动画，缓存到 `PendingFacing`
- Action 自然结束（OnExit）时一次性应用方向（SetLogicForward + 切回 Locomotion）
- 视觉效果：动画播完整 + 转向一气呵成 —— "玩家的方向意图被尊重了，只是延迟了"

**这个设计的两个隐含假设全部不成立**：

|假设|现实|
|---|---|
|End duration 短到玩家感觉不到（≤ 0.2s）|Walk_End=0.67s, Run_End=**1.00s** —— 玩家以为游戏崩了|
|玩家只会"点按"方向键|玩家会**持续按住** WASD（一直想跑）|
|Jump 不需要被缓存|Jump 也被同一条规则吃掉 —— **跳是 ARPG 最高优先级响应**|

→ 这不是"配置写错了"可以补救的。**逻辑层需要时序化**。

# 系统性修复方案（4 层）

## 总览

```
┌─────────────────────────────────────────────────────────┐
│ Layer 1: 数据层 — ActionDataSO 加 RecoveryInterruptPolicy │
│ Layer 2: 逻辑层 — PlayerActionState.cs:549-554 改写         │
│ Layer 3: 配置层 — Walk_End / Run_End / Pivot 资产填值      │
│ Layer 4: 兜底层 — 异常转向独立子诊断（次要）               │
```

## Layer 1：数据层

新增结构体 `RecoveryInterruptPolicy`（放在 `4_Data/2.Actions/ActionDataSO.cs` 或同名 partial）：

```csharp
[System.Serializable]
public struct RecoveryInterruptPolicy
{
    [Tooltip("Move Intent 在 [0, MoveLockSeconds] 时间内仍走 PendingFacing 缓存（保留 184.4 Tap Facing）；\n" +
             "超过此时间则放行进入 ActionInterruptResolver 正常仲裁路径。\n" +
             "  0  = 立刻可中断（最激进，无 Tap Facing）\n" +
             "  >0 = 前 N 秒锁定保护动画过渡（推荐 0.10~0.20）\n" +
             "  <0 = 永不放行（保留 184.3 原行为；只在 OnExit 一次性应用 PendingFacing）")]
    [Range(-0.1f, 2f)] public float MoveLockSeconds;

    [Tooltip("Jump Intent 同上。Jump 推荐 0（立刻可中断，因为急停跳是 ARPG 核心手感）。")]
    [Range(-0.1f, 2f)] public float JumpLockSeconds;

    public static RecoveryInterruptPolicy LegacyHard
        => new RecoveryInterruptPolicy { MoveLockSeconds = -1f, JumpLockSeconds = -1f };

    public static RecoveryInterruptPolicy ResponsiveDefault
        => new RecoveryInterruptPolicy { MoveLockSeconds = 0.15f, JumpLockSeconds = 0.0f };
}
```

`ActionDataSO` 加字段：

```csharp
[Header("184.3 Recovery 旁路（仅 IsLocomotionRecovery=true 时生效）")]
public RecoveryInterruptPolicy RecoveryInterrupt = RecoveryInterruptPolicy.LegacyHard;
```

**关键**：默认值 = `LegacyHard`（永不放行）→ **对全部既有资产零回归**，必须显式配置才生效。

## Layer 2：逻辑层

[PlayerActionState.cs:549-557](https://claude.ai/epitaxy/Assets/GameMain/Scripts/3_Gameplay/Characters/Player/States/PlayerActionState.cs:549) 的 Recovery 旁路改写：

```csharp
// 184.3 §9.2 + 184.4：Move/Jump/Locomotion 默认不走 Recovery 旁路（由 Grammar 缓存 PendingFacing）
// 196.x：按 RecoveryInterruptPolicy 做"时序软屏蔽"——前 N 秒保护动画，之后走正常 ActionInterruptResolver 路径
if (intent.Kind == GameplayIntentKind.Move
    || intent.Kind == GameplayIntentKind.Jump
    || incomingCategory == ActionCategory.Locomotion)
{
    var policy = m_action.RecoveryInterrupt;
    var lockSec = intent.Kind == GameplayIntentKind.Jump
        ? policy.JumpLockSeconds
        : policy.MoveLockSeconds;

    // 仍在锁定窗口内 / 配置永不放行 → 保留 184.3 原行为（return false，落到 PendingFacing 缓存）
    if (lockSec < 0f || m_elapsed < lockSec)
    {
        InputActionProbe.LogIntentDropped(player, intent.Kind.ToString(), "PlayerActionState.Recovery-bypass",
            $"action={m_action.name} elapsed={m_elapsed:F3}s lock={lockSec:F3}s (still-in-lock)");
        return false;
    }

    // 超过锁定时间 → 放行到正常 ActionInterruptResolver 路径
    if (!ActionInterruptResolver.CanInterrupt(m_action, m_prevNormalizedTime, in intent, incomingAction, player))
    {
        InputActionProbe.LogIntentDropped(player, intent.Kind.ToString(), "ActionInterruptResolver",
            $"action={m_action.name} elapsed={m_elapsed:F3}s nt={m_prevNormalizedTime:F2} window-miss");
        return false;
    }

    player.ClearPendingFacing("recovery-time-window-pass");
    return IntentRouter.Route(player, in intent, forceActionReentry: false);
}
```

**为什么这样改是安全的**：

1. **默认 lockSec=-1 → 零回归**：所有未显式配置的 ActionData 行为完全不变
2. **lockSec=0 → 立即可中断**：等效于完全删除 549-554（最激进）
3. **lockSec=0.15 → 软屏蔽 150ms**：动画前 150ms 不可打断保护过渡，之后由 Window 仲裁
4. **不破坏 PendingFacing 缓存**：放行时调 `ClearPendingFacing` 避免缓存的方向二次应用造成抖动

## Layer 3：配置层

**只动两个资产**（Walk_End + Run_End），其它 Recovery Action 保持默认 LegacyHard：

|Asset|MoveLockSeconds|JumpLockSeconds|理由|
|---|---|---|---|
|`GhostSamurai_Common_Walk_End_ActionData`|**0.10**|**0.00**|站立急停短动画，前 100ms 保护后立刻响应|
|`GhostSamurai_Common_Run_End_ActionData`|**0.20**|**0.00**|跑步急停长动画，前 200ms 保护后响应（200ms 内玩家肉眼可接受）|
|`*_Pivot_*` 类|0.30|0.10|转身动画对方向锁需求更高|
|其它一般 Recovery|默认（永不）|默认（永不）|保留 184.3 行为|

**为什么 JumpLockSeconds = 0**：跳跃是高优先级响应，玩家按 Space 期望"任何时候都能跳"。现代 ARPG（黑神话、DMC、艾尔登）都允许 Recovery 期间立刻跳。

**为什么 MoveLockSeconds = 0.10 而不是 0**：完全 0 会让 End 动画第一帧就被打断 → 视觉上像"急停瞬间被取消" → 跑步惯性表现丢失。0.10s 是动画师能接受、玩家无感的最小值。
