## 一、战斗相机状态机（Camera State Machine）落地

### 1.1 不与 GameModeManager 平级，而是嵌在 Action Mode 内的子状态

现状 `GameModeManager` 是顶层 Mode（Action/FPS/MOBA），重切换会改 VCam Priority。资料里的"战斗相机状态机" **不应该** 顶替它——而是作为 **Action Mode 内部的细粒度状态机**。

```
GameModeManager (顶层；Action ↔ FPS ↔ MOBA — VCam Priority 切换)
   ↓
ActionCameraController (Action Mode 唯一控制器)
   ↓
ActionCombatCameraStateMachine (★ 新增 — Action Mode 内的子状态机)
   ├─ FreeLook    （地面自由跟随，默认）
   ├─ Combat      （战斗激活：3 秒内有命中/被击/技能 → 自动进入）
   ├─ LockOn      （右键锁定时进入）
   ├─ Skill       （Action.IntentCategory=Combat && CameraPreset!=null）
   ├─ Execution   （处决，留接口）
   └─ Cinematic   （大招/Boss演出，留接口）
```

### 1.2 子状态机职责（与 Mode 切换正交）

| 子状态 | 进入条件 | 退出条件 | 主要行为 |
|---|---|---|---|
| **FreeLook** | 默认 / Combat 计时器超时 | 命中事件 / LockOn 输入 / Skill 期 | 现有 ActionCameraController 不变 |
| **Combat** | `PlayerAttackStartedEvent` 或 `OnHitConfirm` 任一触发 | Combat 计时器 3s 超时 | 拉近 0.5m / FOV +5° / 平滑系数 ×1.3 |
| **LockOn** | 右键按下且有可锁目标 | 右键再按 / 目标死亡 / 距离超阈值 | Follow=target_center / 自动转 yaw / 锁定 pitch |
| **Skill** | `ActionDataSO.CameraPreset != null` 触发 | Action 结束 / 被打断 | 应用 Preset 内所有参数 |
| **Execution** | （留空，外部 API） | （留空） | 完全接管 Follow/LookAt |
| **Cinematic** | （留空，外部 API） | （留空） | Timeline 接管 |

### 1.3 状态机实现：复用 FSM 框架

```csharp
public abstract class CombatCameraState : State<ActionCameraController> { }

public sealed class CombatCameraStateMachine : StateMachine<ActionCameraController>
{
    // 子状态实例（4 + 2 占位）
    public CameraFreeLookState FreeLook { get; }
    public CameraCombatState Combat { get; }
    public CameraLockOnState LockOn { get; }
    public CameraSkillState Skill { get; }
    public CameraExecutionState Execution { get; }
    public CameraCinematicState Cinematic { get; }
}
```

挂到 `ActionCameraController` 上（仅 Action Mode 激活时跑）。状态切换由：
- 玩家输入（右键 → LockOn）
- Combat 事件（HitConfirm → Combat）
- Action 事件（OnEnter w/ Preset → Skill）

订阅，**不轮询**。

## 三、FOV Zoom 新增（P0 最后一块拼图）

### 3.1 ActionCameraController 新方法

```csharp
[Header("FOV State")]
[SerializeField] private float baseFov = 60f;
float _fovTarget;
float _fovTimer;
float _fovDuration;
float _fovStartValue;

public void RequestFovZoom(float targetFov, float duration)
{
    _fovStartValue = GetCurrentFov();
    _fovTarget = targetFov;
    _fovTimer = duration;
    _fovDuration = duration;
}

void UpdateFov()
{
    if (_fovTimer <= 0f) return;
    _fovTimer -= Time.unscaledDeltaTime;
    var t = _fovDuration > 0.0001f ? 1f - Mathf.Clamp01(_fovTimer / _fovDuration) : 1f;
    var fov = Mathf.Lerp(_fovStartValue, _fovTarget, t);
    SetVCamFov(fov);
    if (_fovTimer <= 0f && Mathf.Abs(fov - baseFov) > 0.01f)
    {
        // 退出阶段：恢复 baseFov
        _fovStartValue = fov;
        _fovTarget = baseFov;
        _fovTimer = _fovDuration;
    }
}
```

VCam 写 FOV 在 Cinemachine 2.x 是 `vcam.m_Lens.FieldOfView`。

## 八、与 Cinemachine 2.x 协作约定

- **不切 VCam Priority** — 子状态机内一律操作 **同一个 Cinemachine VirtualCamera**（ActionCameraController 持有的 `_vcam`）
- 切 VCam Priority 留给 **顶层 GameModeManager**（Action ↔ FPS ↔ MOBA 整 Mode 切换）
- Skill / Combat / LockOn 期间 **不创建新 VCam**，避免 Cinemachine Brain 切换闪烁
- Execution / Cinematic 才允许临时启用第二个 VCam（覆盖 Priority），结束回落

## 十二、设计理念三句话

> 1. **Combat 决定发生什么，Camera 决定如何表现** —— Action 触发事件，Camera 系统消费
> 2. **子状态机 ≠ Mode 切换** —— 战斗细粒度子状态嵌在 Action Mode 内，不重复 GameModeManager 职责
> 3. **资产驱动表现** —— 95% 的镜头表现由 `CameraPresetSO` + `TimelineMarker` 驱动，代码只提供 Request API
