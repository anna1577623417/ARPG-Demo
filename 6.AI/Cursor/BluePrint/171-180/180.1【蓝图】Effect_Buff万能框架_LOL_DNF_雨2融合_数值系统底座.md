## §1 数值管线（MathSystem 底座 / LOL-POE 公式）

### §1.1 Stage 5 层（**固化顺序，不可变**）

```
Final = Override
       ?? (Base + Σ Flat) × (1 + Σ PercentAdd) × Π (1 + PercentMul) × Σ Final
```

| Stage | 用途 | 例子 |
|---|---|---|
| **`Override`** | 强制覆盖（无视一切） | "强制 HP = 1"（黑魂诅咒 / DNF 觉醒锁血） |
| **`Flat`** | 平加（+50 攻击力） | 装备：+30 攻击力 |
| **`PercentAdd`** | 百分比加法叠加（线性堆叠） | 符文：+10% 攻击；3 件套 → +30% |
| **`PercentMul`** | 百分比乘法（独立乘区） | Buff：狂暴 ×1.5 攻击 |
| **`FinalAdd`** | 最终值加成（穿透防御） | 印记：最后再 +X |

> **铁律**：Stage 顺序在 `StatPipeline.Evaluate` 内**写死**。新 Stage 必须改 enum + 顺序，不能运行时混。

### §1.2 `ModifierStage` 升级

    Flat       = 1,
    PercentAdd = 2,

    FinalAdd   = 4,

### §1.3 `StatPipeline.Evaluate` 改造（保后兼）

```csharp
public static float Evaluate(float baseValue, IReadOnlyList<Modifier> mods)
{
    // 早退：Override 存在则直接返回（最大值优先 / 最后 wins 策略）
    float? overrideVal = null;
    float flat = 0, pctAdd = 0, finalAdd = 0;
    float pctMul = 1f;
    for (var i = 0; i < mods.Count; i++)
    {
        var m = mods[i];
        switch (m.Stage)
        {
            case ModifierStage.Override:   overrideVal = m.Value; break;
            case ModifierStage.Flat:       flat     += m.Value; break;
            case ModifierStage.PercentAdd: pctAdd   += m.Value; break;
            case ModifierStage.PercentMul: pctMul   *= (1f + m.Value); break;
            case ModifierStage.FinalAdd:   finalAdd += m.Value; break;
        }
    }
    if (overrideVal.HasValue) return overrideVal.Value;
    return (baseValue + flat) * (1f + pctAdd) * pctMul + finalAdd;
}
```

### §1.4 单元测试用例（确保公式锁死）

| Base | Flat | PctAdd | PctMul | FinalAdd | 期望 |
|---|---|---|---|---|---|
| 100 | +30 | +0.10 | ×1.5 | +20 | (100+30)(1.1)(1.5)+20 = **234.5** |
| 100 | 0 | +0.30 (三件×0.1) | — | — | 100×1.3 = **130** |
| 100 | 0 | — | ×1.2, ×1.2 | — | 100×1.2×1.2 = **144** |
| 100 | — | +0.5 | ×0.0 (沉默) | — | (100)(1.5)(1) but ×0 = **0** |
| 任意 | 任意 | 任意 | 任意 | Override=1 | **1** |

## §4 Stack 策略（**杜绝无限叠加**）

| StackPolicy | 行为 | 示例 |
|---|---|---|
| **Refresh** | 同 Def 二次 Apply → 仅刷新时长 | 神圣护盾再次施法 |
| **Independent** | 每次新实例，互不干扰，独立计时 | 多次中毒 DOT 同时跑 |
| **RefreshIndependent** | 实例数 ≤ MaxStack 时新建；满后刷新最早 | 出血最多 3 层独立 |
| **AddStack** | 同实例 + 1 层（最多 MaxStack）+ 刷新时长 | 雨2 蓝羽叠层 |
| **ReplaceLower** | 同 Tag 中只保留数值最高的 1 个 | 攻击 Buff 多档只取最强 |

### §4.1 `MaxStack` 强制约束

`EffectDefinitionSO.MaxStack` 默认 1，必填 ≥ 1。`BuffStack.Apply` 阶段查表：

```csharp
public BuffInstance Apply(EffectDefinitionSO def, EffectContext ctx)
{
    var existing = FindByDef(def);
    switch (def.StackPolicy)
    {
        case StackPolicy.Refresh:
            if (existing.IsValid) { RefreshDuration(existing); return existing; }
            break;
        case StackPolicy.AddStack:
            if (existing.IsValid)
            {
                if (existing.StackCount >= def.MaxStack) { /* 满了 → 刷时长 */ }
                else { IncreaseStack(existing); ReapplyModifiers(existing, def); }
                return existing;
            }
            break;
        case StackPolicy.Independent:
            // 不检查，直接 new
            break;
        case StackPolicy.RefreshIndependent:
            if (CountByDef(def) >= def.MaxStack) { RefreshOldest(def); return ... ; }
            break;
        case StackPolicy.ReplaceLower:
            var sameTag = FindBySelfTag(def.SelfTags);
            if (sameTag.IsValid && sameTag.Power >= def.Power) return sameTag;
            if (sameTag.IsValid) Remove(sameTag);
            break;
    }
    return CreateNewInstance(def, ctx);
}
```

### §4.2 StackMergeMode 公式

| Mode | Modifier 实际值 |
|---|---|
| Multiply | `Value × StackCount` |
| Linear | `Value × StackCount` (同 Multiply，命名歧义) |
| Logarithmic | `Value × log2(1 + StackCount)` |
| NoEffect | 仅刷新 / 计层数，不放大 Modifier |

## §7 防 Bug 七大铁律

### 七律对照表

| # | Bug | 触发场景 | 本框架防御 |
|---|---|---|---|
| 1 | **Buff 失效**（Modifier 残留但 Buff 已消失） | Remove 时只 Remove 部分 Modifier | **按 BuffInstance.RuntimeId 全量回收**：`stats.RemoveAllBySource(instance)` |
| 2 | **无限叠加** | 没有 MaxStack 检查 | EffectDefinitionSO.MaxStack **必填 ≥ 1**；Apply 阶段强制查 |
| 3 | **计时漂移** | Update 用 Time.deltaTime 但帧率波动 | 使用 **FixedTick 时钟源** + double 精度累积时间；不在 Update 内做计时 |
| 4 | **双重 Apply**（一次输入触发两次） | EventBus 重订阅 / 多帧重复触发 | `BuffInstance.RuntimeId` 唯一 + Apply 阶段去重；OnApply 事件**不允许同一 RuntimeId 触发两次** |
| 5 | **Source 漂移**（SO 引用变化导致回收失败） | 装备替换但 Modifier 还指旧 SO | Source 用 `BuffInstance` 实例而非 SO；卸装备先 `RemoveBySource(equipSO)` 再换 |
| 6 | **Modifier 残留**（场景切换 / 死亡复活） | 角色重置但 Modifier 未清 | `OnSceneUnload` / `OnRespawn` 自动 `stats.ClearAllModifiers()`；事件总线托管 |
| 7 | **Tick 漂移**（PeriodTimer 跨帧丢精度） | 一次 60fps，下一帧 30fps，timer 偏差累积 | Period 用 **while 循环消化超额** dt；防止单帧多次跳过周期 |

### §7.1 关键代码：FixedTick 消化超额 dt

```csharp
public void Tick(float dt)
{
    for (var i = _instances.Count - 1; i >= 0; i--)
    {
        var inst = _instances[i];

        // ① Period（while 循环消化所有应触发的 tick）
        if (inst.Definition.PeriodSeconds > 0f)
        {
            inst.PeriodTimer += dt;
            while (inst.PeriodTimer >= inst.Definition.PeriodSeconds)
            {
                inst.PeriodTimer -= inst.Definition.PeriodSeconds;
                FirePeriod(inst);             // 即使 dt = 1s 也补 3 个 0.3s 周期
            }
        }

        // ② Duration
        if (inst.Definition.Duration == DurationPolicy.Timed)
        {
            inst.RemainingSeconds -= dt;
            if (inst.RemainingSeconds <= 0f) { Remove(inst, RemoveReason.Expired); continue; }
        }

        _instances[i] = inst;
    }
}
```

### §7.2 RemoveBySource 一键回收

```csharp
public void RemoveAllBySource(object source)
{
    for (var i = _instances.Count - 1; i >= 0; i--)
    {
        if (ReferenceEquals(_instances[i].Source, source))
            Remove(_instances[i], RemoveReason.SourceRevoked);
    }
    _stats.RemoveModifiersBySource(source);   // StatSet 端清缴
}
```

## §12 关键架构约束

1. **Modifier.Source 必填** —— 任何 Modifier 必须可追溯到 `BuffInstance`（不允许"游魂 Modifier"）。
2. **Stage 顺序写死** —— Evaluate 内固化；新 Stage 必须 PR 改 enum。
3. **Buff Apply 必走 Stack 检查** —— 直接 `New BuffInstance` 是 bug；统一入口 `BuffStack.Apply`。
4. **Period 用 while 消化** —— 不允许 `if (timer >= period) timer=0`，必须 while 循环。
5. **Cleanse / Source 回收双闸** —— 任何 Buff 离场必须同时清 Modifier 和 Instance。
6. **Snapshot 是字段不是开关** —— 同一 SO 不能跨实例切换模式。
7. **Trigger 链深限制** —— ThreadStatic 计数 ≤ 4；无例外。
8. **Run / Equipment / Rune 分层** —— Run 数据走存档；Equipment 走装备槽；Rune 走永久 profile；不允许越界。

## §14 三句话设计哲学

> 1. **Source 是 Buff 的灵魂** —— 任何 Modifier 必须可追溯，任何 Buff 必须可精确回收
> 2. **Stack 不是计数，是策略** —— Refresh / Independent / AddStack / ReplaceLower 各司其职；MaxStack 必填
> 3. **Trigger 是 Buff 的生命周期接口** —— OnApply / OnPeriod / OnExpire / OnRemoved 替代散落的事件订阅
