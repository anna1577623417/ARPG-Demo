## §1 设计哲学：四层降级（资料 §362-385）

```
①  Override     ←  特殊 Action 显式标定         （覆盖率 ~5%，权重最高）
        ↓ miss
②  Clip DB      ←  离线 Pose 分析烘焙           （覆盖率 ~4%，O(1) 查询）
        ↓ miss
③  Tag Matrix   ←  10×10 类别矩阵               （覆盖率 ~90%，主力）
        ↓ miss
④  Default      ←  全局默认 fade (0.1s)         （兜底，永不为 null）
```

> **不允许运行时 PoseCost** —— 资料 §103-110。运行时只查表；所有计算移到编辑期烘焙。

### §2.4 `TransitionDatabaseSO` —— 离线烘焙 Clip 矩阵（资料 §285-358）

```csharp
[CreateAssetMenu(menuName="GameMain/Animation/Transition Database")]
public class TransitionDatabaseSO : ScriptableObject
{
    [SerializeField] List<Entry> _entries;            // Clip×Clip 稀疏存储（只存高 cost 项）
    Dictionary<(int, int), Entry> _lookup;            // 运行时构建（OnEnable）

    [Serializable]
    public struct Entry
    {
        public AnimationClip FromClip;
        public AnimationClip ToClip;
        public float PoseCost;          // 0=完美对齐 1=完全错位
        public float RecommendedBlend;  // 基于 PoseCost 推算
        public bool  PhaseMatchSafe;    // 节奏可对齐（Locomotion 间）
        public float FootPhase;         // From 结尾的足相位
    }

    public bool TryGet(AnimationClip from, AnimationClip to, out Entry e);
}
```

> **稀疏存储**：仅烘焙 cost > 阈值（默认 0.3）或人工标记的 Clip 对，避免 N×N 爆炸。100 Clip 实测烘焙后通常 200~500 条，体积 < 50KB。

### §2.5 推荐 Blend 公式（资料 §85）

```csharp
static float RecommendedBlend(float poseCost) =>
    Mathf.Lerp(0.03f, 0.20f, Mathf.SmoothStep(0f, 1f, poseCost));
// poseCost=0   → 0.03s （已对齐，瞬切几乎无视觉差）
// poseCost=0.3 → 0.07s
// poseCost=0.5 → 0.12s
// poseCost=1.0 → 0.20s
```

## §3 Runtime 层：`AnimationTransitionService`

```csharp
// 5_Presentation/Animation/Transition/AnimationTransitionService.cs
public sealed class AnimationTransitionService
{
    readonly TransitionTagMatrixSO _matrix;
    readonly TransitionDatabaseSO  _clipDb;
    readonly TransitionConfigSO    _config;   // DefaultBlend / DefaultMode

    public TransitionParams Resolve(ActionDataSO from, ActionDataSO to)
    {
        // ① Override（5%）
        if (to.OverrideIncomingTransition)
            return new TransitionParams(to.OverrideBlendDuration, to.OverrideMode, to.OverrideEaseCurve);

        // ② Clip DB（4%）—— 仅当存在烘焙条目
        var fromClip = from?.AnimationClip;
        var toClip   = to.AnimationClip;
        if (fromClip != null && toClip != null
            && _clipDb != null && _clipDb.TryGet(fromClip, toClip, out var e))
            return new TransitionParams(e.RecommendedBlend,
                e.PhaseMatchSafe ? TransitionMode.PhaseMatch : TransitionMode.CrossFade,
                null);

        // ③ Tag Matrix（90%）
        var entry = _matrix.Matrix[(int)from?.Tag ?? 0, (int)to.Tag];
        if (entry.BlendDuration > 0f || entry.Mode == TransitionMode.Snap)
            return new TransitionParams(entry.BlendDuration, entry.Mode, entry.EaseCurve);

        // ④ Default（兜底）
        return _config.Default;
    }
}

public readonly struct TransitionParams
{
    public readonly float BlendDuration;
    public readonly TransitionMode Mode;
    public readonly AnimationCurve EaseCurve;
}
```

`PlayerAnimController.PlayAction` 改造（唯一入口）：

```csharp
public void PlayAction(ActionDataSO to)
{
    var p = _transitionService.Resolve(_currentAction, to);

    switch (p.Mode)
    {
        case TransitionMode.Snap:
            _animator.Play(to.AnimationClip.name, 0, 0f); break;
        case TransitionMode.PhaseMatch:
            PlayWithPhaseMatch(to, p); break;
        default:
            _animator.CrossFadeInFixedTime(to.AnimationClip.name, p.BlendDuration); break;
    }
    _currentAction = to;
}
```

## §4 离线烘焙器 `TransitionBakerWindow`

### §4.1 操作流

```
[Window] GameMain → Animation → Transition Baker
   ↓
扫描：PlayerAnimLibrary + 所有 ActionDataSO.AnimationClip
   ↓
对每对 (ClipA, ClipB)：
   ① ClipPoseSampler.Sample(ClipA, t=ClipA.length)  → PoseA
   ② ClipPoseSampler.Sample(ClipB, t=0)             → PoseB
   ③ ComputePoseCost(PoseA, PoseB)
   ④ if cost > 阈值 → 写入 TransitionDatabaseSO
   ↓
保存：TransitionDatabase_Player.asset
```

### §4.2 PoseCost 算法（关节加权欧氏 + 速度差）

```csharp
public static float ComputePoseCost(in PoseSample a, in PoseSample b)
{
    float cost = 0f;
    foreach (var jw in s_JointWeights)   // Hip 3.0 / Spine 2.0 / Hand 1.5 / Foot 1.0 / Toe 0.5
    {
        var ra = a.LocalRot[jw.Index];
        var rb = b.LocalRot[jw.Index];
        cost += jw.Weight * Quaternion.Angle(ra, rb) / 180f;  // 归一到 [0,1]
    }
    // 速度匹配项：Hip 速度差
    cost += 0.5f * Mathf.Clamp01(Vector3.Distance(a.HipVel, b.HipVel) / 5f);
    return Mathf.Clamp01(cost / s_JointWeights.Sum(j => j.Weight));
}
```

### §4.3 PoseSample 数据结构

```csharp
public struct PoseSample
{
    public Quaternion[] LocalRot;   // 按 HumanBodyBones 索引
    public Vector3 HipPos;
    public Vector3 HipVel;          // 通过相邻帧差分
    public float FootPhase;         // 0=左脚支撑 0.5=右脚支撑 — 用于 PhaseMatch
}
```

复用 `ClipMotionExtractor` 既有的 SampleAnimation 流水线。

## §6 关键设计细节

### §6.1 `PhaseMatch` 模式（Locomotion 同节奏）

Walk → Run 切换时，必须在**相同足相位**起新 Clip 才不会出现"刹车感"：

```csharp
void PlayWithPhaseMatch(ActionDataSO to, TransitionParams p)
{
    var curPhase = ExtractFootPhase(_animator);   // 从当前 normalizedTime 推算
    var targetStart = AlignToFootPhase(to.AnimationClip, curPhase);
    _animator.CrossFadeInFixedTime(to.AnimationClip.name, p.BlendDuration, 0, targetStart);
}
```

不在烘焙数据库里的 Clip 退回 CrossFade，不报错。

### §6.2 Hit / Reaction = 全 Snap（资料 §211）

受击/死亡必须**立即切换**给玩家强反馈。矩阵 `Hit` 行全 0；`AnimationTransitionService` 检测 `Mode == Snap` 时调 `Animator.Play(0f)` 而不是 CrossFade。

### §6.3 Override 的特殊场景（资料 §259-282）

| 场景 | 为什么 Override |
|---|---|
| `ExecutionStart` | 处决动画需要长 Blend 0.25s 表达"凝重感" |
| `ParryCounter` | 必须 Snap 0s 表达"瞬间反应" |
| `Backstab` | 0.30s 高 Blend + 自定义 EaseOutCubic |
| `Fatality` | 同上 |

### §6.4 数据规模评估

| 项目 | 量级 | 存储 |
|---|---|---|
| Tag Matrix | 12 × 12 = 144 entry × ~30 bytes | < 5 KB |
| Clip DB（稀疏，cost > 0.3） | ~500 条 × ~40 bytes | < 25 KB |
| Override 字段 | 每个 ActionDataSO 增加 ~16 bytes | 87 Action × 16 ≈ 1.4 KB |
| **总计** | | **< 35 KB** |

### §6.5 烘焙性能

100 Clip × 100 Clip = 10000 对；每对采样 ~5ms（含 SampleAnimation + 骨骼遍历）= ~50s 全量烘焙。**仅在 Editor 内、手动触发**；运行时零开销。

| 既有 | 衔接 |
|---|---|

## §9 关键架构约束

1. **CrossFade 永远是关系属性** —— 不允许新代码在 ActionDataSO 上读 `crossFadeDuration`；唯一入口是 `AnimationTransitionService.Resolve`。
2. **运行时无 PoseCost 计算** —— 全部移到编辑期烘焙。Service 只查表。
3. **四层降级严格按顺序** —— Override > Clip DB > Tag Matrix > Default；中间任一命中即返回。
4. **稀疏 DB** —— 仅烘焙 cost > 阈值的对；100 Clip 不应产生 10000 条目。
5. **Tag 是单值** —— 同一 Action 只属于一个 Tag；不允许多 Tag 投票。
6. **PhaseMatch 必须 graceful fallback** —— 找不到节奏时退 CrossFade，不阻塞流程。

## §11 三句话设计哲学
