# 先看你现在的问题

目前你大概是：

```text
Route
 ├ Attack
 ├ Skill
 ├ Roll
 └ Jump
```

然后：

```csharp
if (Input.Jump)
{
    Jump();
}
```

或者：

```csharp
CanInterruptByJump()
```

这种逻辑。

于是出现：

```text
AttackA
 ├ 可被Roll打断
 ├ 可被Jump打断
 └ 不可被Skill打断
```

配置越来越多。

---

# 为什么你会一直纠结打断系统

因为：

你现在打断的是：

```text
动作类型
```

而不是：

```text
Ability
```

例如：

```text
Jump
Roll
Attack
Skill
```

这些是程序定义的。

但游戏设计根本不关心这些。

---

设计师想表达的是：

```text
升龙
可以打断普攻

闪避
可以打断升龙前摇

冲刺
不能打断翻滚

跳跃
不能打断受击
```

这里根本没有：

```text
Attack
Skill
Jump
```

概念。

只有：

```text
Ability
```

概念。

---

# LOL实际上就是这么干的

例如：

```text
Q
W
E
R
Move
Recall
Flash
```

本质全是：

```text
Ability
```

只是标签不同。

---

你未来应该逐渐变成：

```csharp
Ability
{
    AbilityTag[]
}
```

例如：

```text
Jump
 ├ Movement
 ├ Airborne

Roll
 ├ Movement
 ├ Dodge

AttackA
 ├ Attack
 ├ Combo

FireBall
 ├ Skill
 ├ Projectile
```

---

# 然后 Route

不要变成：

```text
Route_Attack
Route_Jump
Route_Roll
```

而是：

```text
Input
 ↓
Ability Request
 ↓
Route
 ↓
Ability
```

例如：

```text
Space
 ↓
JumpAbility
```

---

```text
Shift
 ↓
RollAbility
```

---

```text
LMB
 ↓
AttackAbility
```

# 打断系统会突然变简单

以前：

```csharp
CanInterruptByJump
CanInterruptByRoll
CanInterruptBySkill
```

爆炸。

---

未来：

```csharp
InterruptRule
{
    AllowedIncomingTags
}
```

例如：

```text
AttackA

允许：
Movement
Dodge

拒绝：
Attack
Skill
```

---

Jump：

```text
Movement
Airborne
```

因此：

```text
Jump
```

自然能打断。

---

Roll：

```text
Movement
Dodge
```

也自然能打断。

---

根本不需要：

```csharp
CanInterruptByJump()
```

这种代码。
