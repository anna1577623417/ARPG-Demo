# 171.7【蓝图】AnimSpeed 模式化 + Idle 兜底与主动打断分离

> **基线**：171.5 ActionTimeline 预览 v2 / 167.1 退出减速策略 / 169.1 GraphEnd 系统性归 Idle
> **范围**：两个互不相干但都触及"运行时 vs 编辑期不一致"的设计漏洞 ——
> - **A**：AnimSpeed 编辑期填什么，运行时就该是什么；要么显式声明"按 duration 自动匹配"
> - **B**：Idle 兜底切换不应被等同于"主动 Locomotion Intent 打断"；Recovery 内不该被自己回 Idle 静默打断

---

## §A：AnimSpeed 模式化（Free / AutoFitDuration）

### §A.0 现状（不一致根因）

| 时机 | 当前行为 |
|---|---|
| **编辑期** | Inspector 内 `AnimSpeed` 字段可手填（如 1.0）；按钮"按 Duration 匹配 Clip 速率"一次性写值 |
| **运行时** | `MotionProfile.SampleAnimSpeed(t)` 隐式按 `clip.length / duration` 重算 → **忽略 Inspector 的手填值** |
| **后果** | 策划设 Duration=1.0s + Clip=0.43s + 手填 AnimSpeed=1.0（期望 0.43s 处停止 + 0.57s 后摇空白）→ 运行时变成 `AnimSpeed=0.43` 把动画拉到 1.0s 整个播完，**没有空白后摇** |

### §A.1 设计：`AnimSpeedMode` 二态枚举

```csharp
public enum AnimSpeedMode : byte
{
    /// <summary>自由配置：运行时 = SO 内手填值；编辑器允许手编 + 按钮一次性写值</summary>
    Free = 0,

    /// <summary>自动跟随 Duration：运行时 = clip.length / duration（动态）；编辑器 AnimSpeed 灰色只读</summary>
    AutoFitDuration = 1,
}
```

### §A.2 数据层（MotionProfileSO 或 ActionDataSO，按现有归属）

```csharp
[Header("Anim Speed (171.7)")]
[Tooltip("Free = SO 内手填值；AutoFitDuration = 运行时按 clip.length / action.Duration 自动算（编辑器内 AnimSpeed 字段灰色只读）。")]
public AnimSpeedMode AnimSpeedMode = AnimSpeedMode.AutoFitDuration;   // 默认保持现行手感

[Range(0.05f, 4f)] public float AnimSpeed = 1f;   // 仅 Free 模式生效
```

### §A.3 运行时取值（**单一入口**）

```csharp
public float ResolveAnimSpeed(ActionDataSO action, float t)
{
    return AnimSpeedMode switch
    {
        AnimSpeedMode.Free            => Mathf.Max(0.01f, AnimSpeed),
        AnimSpeedMode.AutoFitDuration => ResolveAutoFit(action),
        _                             => 1f,
    };
}

static float ResolveAutoFit(ActionDataSO action)
{
    var clipLen = action?.MainClip != null ? action.MainClip.length : 0f;
    var dur = action != null ? action.ResolveLogicalDurationSeconds() : 0f;
    if (clipLen < 0.001f || dur < 0.001f) return 1f;
    return Mathf.Clamp(clipLen / dur, 0.05f, 4f);
}
```

**注意**：现行 `SampleAnimSpeed(t)` 若内部有 AnimSpeed 曲线（非常数），保留为 Free 模式下的可选行为；AutoFitDuration 时直接走上述公式忽略曲线。

### §A.4 编辑器 UI 联动（**关键**）


### §A.5 与 Duration Stat Scaling / Principal Axis 联动

| 已有字段 | 改造 |
|---|---|
| `Duration Stat Scaling` | 不动；Duration 已被 Stat 缩放后再传 ResolveAutoFit |
| `Principal Axis` | 不动；只影响主轴位移 |
| `Duration → SegmentEnd` 按钮 | 不动；改 Duration 后若 AutoFit 模式，AnimSpeed 自动跟变（无需手动点匹配按钮） |

### §A.6 关键不变量

1. **AutoFitDuration 模式**：编辑器 AnimSpeed 灰色只读；按钮灰色；Inspector 显示 "Live (auto) = ×0.43"
2. **Free 模式**：编辑器 AnimSpeed 可写；按钮可点（一次性写入但不切模式）；运行时严格 = SO 值
3. **改 Duration 立即可见**：AutoFitDuration 下编辑器实时显示新 Live 值（OnValidate 触发刷新）
4. **运行时无隐式重算**：`SampleAnimSpeed` 调用 `ResolveAnimSpeed` 唯一入口；旧 hardcoded `clipLen/dur` 路径全部下沉到此

### §A.7 **预览推演与运行时一致 + TimeWindow 双向编辑**（追加第三个不一致根源）

#### §A.7.1 现状（**预览看不到后摇**）

| 时机 | 行为 | 问题 |
|---|---|---|
| 运行时 (Free 模式) | Duration=1.0s / Clip=0.43s / AnimSpeed=1.0 → Clip 在 0.43s 播完 + 0.57s 空白后摇 | ✓ 已对 |
| **编辑器预览** | 拖时间轴 0→1 直接映射到 Clip 0→length；**忽略 AnimSpeed** → 预览始终看见"Clip 拉到全程"，根本看不到后摇 | ❌ 与运行时不一致 |

**根因**：`ActionTimelinePreviewController.ResolveSampleSeconds` 走 `action.MapActionTimeToClipSeconds(normalizedTime)`，纯线性 t→clipSecs（normalizedTime × clipLen），**没有把 AnimSpeed 纳入推演**。

#### §A.7.2 0-1 TimeLine vs Clip Time 的关系（核心契约）

```
0-1 Action Time Line（始终 0..1，表达"动作总时长进度"）
        │
        │  PreviewClipSeconds = t × duration × AnimSpeed   （AnimSpeed 常数时）
        │  PreviewClipSeconds = Σ AnimSpeed(τ) × Δτ × duration   （AnimSpeed 曲线时）
        ▼
Clip 播放进度（受 AnimSpeed 调制），到 clip.length 时定格 → 后摇可见
```

关键差异（**与"播放倍率 _playbackSpeed" 严格区分**）：

| 概念 | 角色 | 写入 SO？ |
|---|---|---|
| `_playbackSpeed`（预览工具栏） | 编辑器**人工调快/调慢**预览的倍率（1×/2×/4×） | ❌ 不写入 |
| `AnimSpeed`（SO 字段） | **运行时数据**，决定 Clip 在 Action 总时长内播多快 | ✅ SO |

> ⚠️ 二者**独立相乘**：编辑器一帧 t 推进 = `dt × _playbackSpeed / duration`（仅作用于 0..1 _previewTime），Clip 采样秒数 = `t × duration × AnimSpeed`。

#### §A.7.3 修正后预览采样

```csharp
// 旧（错）：
static float ResolveSampleSeconds(ActionDataSO action, float normalizedTime, AnimationClip clip)
    => action.MapActionTimeToClipSeconds(normalizedTime);   // 不读 AnimSpeed

// 新（对）：
static float ResolveSampleSeconds(ActionDataSO action, float normalizedTime, AnimationClip clip)
{
    var dur = action.ResolveLogicalDurationSeconds();
    var animSpeed = ResolveAnimSpeed(action, normalizedTime);   // §A.3 单一入口
    var clipSecs = normalizedTime * dur * animSpeed;            // 按 AnimSpeed 推演
    return Mathf.Min(clipSecs, clip.length);                    // 钳到 Clip 末帧 → 后摇定格
}
```

#### §A.7.4 后摇预览行为（对照表）

| t | Duration=1.0 / Clip=0.43 / AnimSpeed=1.0 (Free) | 视觉 |
|---|---|---|
| 0.00 | clipSecs = 0.000 | 起手帧 |
| 0.43 | clipSecs = 0.430 = clipLen | Clip 末帧 |
| 0.60 | clipSecs = clamp(0.600, 0.430) = 0.430 | **末帧定格**（后摇可见 0.17 长） |
| 1.00 | 同上 | 末帧定格（后摇总长 0.57） |

| t | AnimSpeed=2.0 (Free) | 视觉 |
|---|---|---|
| 0.00 | 0.000 | 起手 |
| 0.215 | 0.430 = clipLen | **0.215 处已播完**（动画拉到一半） |
| 0.50 | clamp 0.430 | 末帧定格 |
| 1.00 | 末帧定格 | 同上 |

| t | AutoFitDuration（AnimSpeed=0.43） | 视觉 |
|---|---|---|
| 0.00 | 0.000 | 起手 |
| 0.50 | 0.215 | Clip 中段 |
| 1.00 | 0.430 = clipLen | 末帧 **刚好播完，无后摇** ✓ |

#### §A.7.6 **TimeWindow 双向编辑（追加需求）**

**现状**：策划只能在 Inspector 改 Duration / Segment / AnimSpeed；TimeWindow（时间轴轨道上方 Authority 行）只能拖 Segment 进度条，无法直接编辑 Clip 关联字段。

**目标**：TimeWindow 把 TimeAuthority 的**核心字段**同步暴露 —— 任一处修改 → 所有处即时同步。

##### §A.7.6.1 双向同步字段表

| 字段 | Inspector | TimeWindow 内联 | 同步策略 |
|---|---|---|---|
| **Duration** | ✅ | ★ 新增 DelayedFloat | 同 SerializedProperty |
| **AnimSpeed** | ✅ | ★ 新增（Free 可写 / AutoFit 灰色只读） | 同上 |
| **AnimSpeedMode** | ✅ | ★ 新增 EnumPopup（迷你 56px） | 同上 |
| **Segment Start/End** | ✅ | ✅ 已有 → 改为同绑 | 已存在但需切到 SerializedProperty |
| **Principal Axis** | ✅ | ⛔ 不暴露（编辑频次低，留 Inspector） | — |
| **Duration Stat Scaling** | ✅ | ⛔ 不暴露 | — |

##### §A.7.6.2 实现策略：单一 SerializedObject 双绑

```csharp
// 关键：Inspector 与 TimeWindow 共享同一 SerializedObject 实例
//       → 任一处 ApplyModifiedProperties 后另一处 Update 自动同步

sealed class ActionTimeAuthorityBinding
{
    public SerializedObject SerializedAction;
    public SerializedProperty PropDuration;
    public SerializedProperty PropAnimSpeed;
    public SerializedProperty PropAnimSpeedMode;
    public SerializedProperty PropSegmentStart;
    public SerializedProperty PropSegmentEnd;

    public void Refresh() => SerializedAction.Update();
    public void Commit()
    {
        SerializedAction.ApplyModifiedProperties();
        EditorUtility.SetDirty(SerializedAction.targetObject);
        SceneView.RepaintAll();
        // Inspector 与 TimeWindow 各自下一帧 OnGUI 调 Refresh 自动同步
    }
}
```

每帧 GUI 前 `Refresh()`；任一字段被改后立即 `Commit()` → 另一面板下一帧 GUI Refresh 时拿到最新值。

##### §A.7.6.3 TimeWindow UI 形态（紧凑横排，**不拥挤**）

时间轴上方紧贴的 Authority 行（Layout.cs 已有）改造为：

```
─── Time Authority (Duration + AnimSpeed + Segment) ─────────────────────
Duration  [ 1.000 ]   AnimSpeed  [Free ▾] [ 1.00 ] x    Live ×1.00
Segment   [ 0.000 ] → [ 1.000 ]   Δ=0.430s   [Frame] [0~1]
```

## §B：Idle 兜底切换与"主动 Locomotion 打断"分离

### §B.0 现状（体感"Idle 自动打断后摇"的根因假设）

| 体感 | 可能根因 |
|---|---|
| 玩家不按键，Action.Recovery 段还没播完，角色就回 Idle Pose | ① Recovery 时间被 Duration < ClipLen 自动截断（接 §A 修复）<br>② ExitToBaseline → Locomotion.OnEnter → 无输入即播 Idle（覆盖 Recovery 视觉） |
| 玩家按 WASD，Recovery 内能被打断 | 这是设计意图（Allowed=Locomotion / Movement） |
| 玩家按 LM 连段，Recovery 内能被打断 | 同上（Allowed=Offense） |

**矛盾**：策划想要"主动 WASD 打断"（情景 2 留），但不想要"Idle 兜底也算打断"（情景 1 关）。两者目前都走同一 `ActionWindow.InterruptibleByCategories = Locomotion`。

### §B.1 设计原则

> **主动 Intent 打断** ≠ **FSM 兜底切换**
>
> - **主动 Intent**：`GameplayIntentBuffer` 内有具体 `IntentKind`（Move / Jump / Skill / Dodge）；玩家显式按键
> - **FSM 兜底**：`ExitToBaseline` 自然结束后切 Locomotion；进入 Locomotion 时无输入 → 播 Idle Binding
>
> 后者不该被 ActionWindow 闸门当作"打断"过滤。

### §B.2 方案对比

| 方案 | 实施 | 影响面 | 推荐 |
|---|---|---|---|
| **A 标记 Idle 资产** | Idle ActionData 加 `IsIdleFallback=true`；ActionInterruptResolver 跳过 IdleFallback 类 | 小 | ⭐ 候选 |
| **B 拆 ActionCategory** | 新位 `IdleFallback = 1 << 5`；Idle 类 Action.Category 改为 IdleFallback（不含 Locomotion）；策划要兜底打断必须显式勾 | 中 | ⭐⭐ **推荐** |
| **C Recovery 必须有 Intent** | ActionWindow 加 `RequiresPendingIntent=true`；Recovery 内打断必须 GameplayIntentBuffer 非空 | 中 | ⭐ 备选 |
| **D 隔离 ExitToBaseline 路径** | 169.1 已让 ExitToBaseline 一律回 Locomotion；进入 Locomotion 后**先检查 Recovery 是否还在播**，未播完则等待 | 大 | ❌ 复杂 |

### §B.3 **推荐方案 B**：拆 `IdleFallback` 类

#### §B.3.1 ActionCategory 扩展

```csharp
[Flags]
public enum ActionCategory : ushort
{
    None         = 0,
    Movement     = 1 << 0,    // WASD/Jump 战斗位移（主动）
    Offense      = 1 << 1,
    Defensive    = 1 << 2,
    Utility      = 1 << 3,
    Locomotion   = 1 << 4,    // WASD 全局移动 / Run / Walk Loop
    IdleFallback = 1 << 5,    // ★ 171.7：Idle 兜底 — 无输入时 FSM 自动接管
}
```

#### §B.3.2 Idle 类资产标记

| ActionData | 旧 Category | 新 Category |
|---|---|---|
| `Common_Idle` / `Armature_Idle_Loop` | Locomotion | **IdleFallback** |
| `Crouch_Loop` | Locomotion | **IdleFallback** |
| `Walk_Loop` / `Run_Loop` | Locomotion | Locomotion |
| `WalkStart` / `RunStart` | Locomotion | Locomotion（保留，主动起步） |

#### §B.3.3 默认 InterruptibleByCategories

- 现有 Recovery 段配 `Locomotion | Movement | Offense` —— **不含 IdleFallback** → Idle 兜底切换天然过滤
- 策划想"后摇结束自动接 Idle"那是 169.1 系统性正解（ExitToBaseline → Locomotion 状态自然进 Idle），**不再走打断路径**

#### §B.3.4 配套 Resolver 改动

```csharp
// ActionInterruptResolver.CanInterrupt
public static bool CanInterrupt(in GameplayIntent intent, ActionWindow window)
{
    var incomingCat = ResolveIncomingCategory(in intent, /*action*/ null);

    // 171.7 B：IdleFallback 永不计入打断（即使 mask 显式含它，也走兜底路径）
    if (incomingCat == ActionCategory.IdleFallback) return false;

    return (window.InterruptibleByCategories & incomingCat) != 0;
}
```

#### §B.3.5 与 169.1 / 170.4 咬合

- 169.1：`ExitToBaseline` 一律 `Change<PlayerLocomotionState>()` —— **不变**
- 170.4：`m_exitDispatched` 单次闸门 —— **不变**
- PlayerLocomotionState.OnEnter 选 Idle Binding 时不再触发"打断"（IdleFallback 永远被 Resolver 拒绝） —— **新约束**

### §B.4 ActionWindow Inspector 提示

在 `InterruptibleByCategories` 字段下加 Help：

```
ℹ️ IdleFallback 类不会被本字段消费（FSM 兜底切换不走打断路径）；
   想"自然回 Idle"无需勾选；想"WASD 移动打断"勾 Movement / Locomotion。
```

### §B.5 体感测试覆盖

| 场景 | 期望 |
|---|---|
| Recovery 段允许 `Movement | Locomotion`，玩家不按键 | Action 播完 → 自然 ExitToBaseline → Locomotion → Idle（**视觉完整后摇**） |
| 同上，Recovery 第 0.3s 玩家按 W | Movement Intent 入 Buffer → 打断 Recovery → 切 Walk |
| 同上，玩家按 Space | Jump Intent → 打断 → JumpStart |
| 同上，玩家按 LM | Offense Intent → 打断 → Combo 续段 |
| 旧资产 Idle.Category 仍为 Locomotion（未迁移） | Resolver 兜底排除（按 Action 名/SO 类型识别），不影响 |

## §E 关键架构约束

1. **AnimSpeed 单一入口** —— 运行时所有读 AnimSpeed 处都过 `ResolveAnimSpeed`；旧 hardcoded `clipLen/dur` 一处不剩
2. **AutoFit 默认值** —— 现有资产保持 `AutoFitDuration`（与现行手感一致），新资产策划显式选
3. **IdleFallback 永不打断** —— Resolver 提前拒绝，**无视** Allowed mask 是否勾选
4. **WASD/Jump/Skill 主动 Intent** —— 各自走自己的 Category（Movement/Locomotion/Offense），不被本蓝图影响
5. **资产迁移幂等** —— `*Idle*` / `*_Loop` 名字嗅探仅警告，不强改运行时
6. **Editor / 运行时数值同源** —— Inspector 显示 "Live (auto)" 与运行时 `ResolveAnimSpeed` 完全相同公式

## §F 反模式（本次暴露）

| 反模式 | 防御 |
|---|---|
| **运行时偷偷覆盖编辑期值** | 显式 enum 选择；任何"自动"必须 explicit mode |
| **多语义合并到同 mask** | Idle 兜底 vs Locomotion 主动 分离到独立 Category 位 |
| **Inspector 与运行时计算不一致** | 编辑器读同一 `ResolveAnimSpeed` 方法显示 Live 值 |
| **默认值与策划期望不符却"看起来工作"** | A.W3 显式标记默认 AutoFit，让策划知道现行手感是何机制 |

## §G 三句话沉淀

> 1. **运行时与编辑期必须一致** —— "AutoFit" 是显式声明，不是隐式覆盖
> 2. **主动 Intent ≠ FSM 兜底** —— Idle 接管不是打断，独立 Category 位才能切线
> 3. **mask 不应承载双语义** —— 同一个 Locomotion 位既管 WASD 又管 Idle 兜底就是反模式
