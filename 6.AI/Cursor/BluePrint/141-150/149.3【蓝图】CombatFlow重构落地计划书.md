# 149.3 CombatFlow 重构落地计划书（Move Graph 化）

> 认知基础：`149.1【资料】【重构】Graph与打断窗口.md`（方法论）+ `149.2【实现目标】Combat Graph的能力.md`（验收矩阵）
> 协议遵循：`07-single-track-migration`（运行时单轨）、`09-refactor-delivery-protocol`（设施+握手分 N 次落位、禁兜底修 bug）、`12-no-unrequested-scaffolding`（不默认加菜单/测试）
> 现状基线：147.1 已落地（`CombatGraphAsset` + `CombatGraphRunner` + 编译管线 + Condition 资产）

## 0. 一句话目标

把 CombatFlow 从「147.1 的**输入兜底**（Entry 解析失败才查图）」改造为 149.1 定义的
**「上下文优先的 Move Graph（Contextual Entry Resolution）」**：

```
SkillRoute = How（动作内部怎么执行）
CombatFlow = Where Next（当前动作 + 当前输入 → 下一步去哪）
Entry      = 输入意图入口（永远存在，不被替代）
```

**解析优先级（终态契约）**：

```
[Graph 启用 + 命中边]  CombatGraph Edge
        >  Derived Route（暂留，后续比较去留）
        >  Default Entry Route（Graph 未启用 / 无命中边时）
```

> 这是相对 147.1 的**方向反转**：147.1 是 `Entry 优先，Graph 兜底`；终态是 `Graph 优先，Entry 兜底`。本计划全部围绕这次反转安全落地。

## 1. 统一认知（写入实现前必须对齐）

### 1.1 CombatFlow 是什么 / 不是什么

| 是 | 不是 |
|---|---|
| Move Graph（招式树）：动作之间的**关系** | 打断系统（Interrupt 仍由 ActionWindow 单点判定） |
| 上下文敏感输入：同键不同 Context 不同结果 | ComboRoute 的可视化换皮（必须能做 Branch / Cross-Route 才算脱皮） |
| 可选增强（Graph 为空=禁用，Interrupt 仍工作） | Entry 的替代品（Entry 永远存在） |
| 二级路由（Context Route） | 一级路由（Entry→Default Route 仍保留） |

### 1.2 只允许进 Graph 的 6 类能力（149.1 第十节）

1. **Context Override**（Idle RM ≠ Combo RM）— Graph 存在的根基
2. **Branch Combo**（A2 ├LM→A3 └RM→B1）
3. **Cross Route Transition**（A2 → B2，未来吸收 ExtendedRoute）
4. **Air Context**（Ground→Air→Ground）
5. **Recovery Context**（Late Window 后摇容错）
6. **Dodge / Jump Cancel**（跨系统流转）

### 1.3 禁止进 Graph（仍归各自系统）

- **蓄力**（Tap/Hold）→ Input 解析 → ChargeRoute（**不要碰**）
- **命中派生 / 处决**（Hit→Execute）→ Route 内部窗口
- **方向输入**（Forward/Back+LM）→ SkillGroup / Intent

### 1.4 双闸门模型（149.1 第七节）

```
第一层 Interrupt Gate  = 是否允许尝试打断（ActionWindow.InterruptibleByCategories）
第二层 CombatFlow Gate = 允许流向哪里（Graph 边 + Condition + TargetRoute）
特别规则：Graph 禁用 → 退化为单闸门（仅 Interrupt + Entry 解析）
```

### 1.5 窗口归属（149.1「Early/Late Window 数据源」终稿）

| 窗口 | 数据源 | 语义 | 时间制 |
|---|---|---|---|
| **Early Window** | **Action**（`ActionWindow`，权威） | 动作未播完时「何时允许离开」= 打断/衔接窗 | 归一化 `OpenNormalized~CloseNormalized` |
| **Late Window** | **FlowEdge**（`LateWindowSeconds`，权威） | 动作**已结束后**的容错缓冲 | 绝对秒 |
| FlowEdge.EarlyWindow | **只读投影**（来自 Action） | Graph 编辑器显示用，**不存储** | 显示 `65%~100%` + `(1-0.65)*duration` 绝对值 |

**运行时分流（149.1 line 3012）**：

```
当前动作未播完  → 询问当前 Action 的 Interrupt/Early Window
当前动作已结束  → 询问 Graph（结合 Context + Late Window）按定义节点结算
```

### 1.6 资产组织（149.1 第十节）

```
一个角色 → 多个 Stance → 每 Stance 一张 CombatGraph
每张 Graph 只有 1 个 Start；Start 语义 = Idle Context（当前无 Action）
```

> 本次仅做 `NormalStance / CombatGraph_Normal` 单图；Stance 多图为后续扩展，**本计划不实现 Stance 切换**。

## 3. 终态数据模型（落地前定稿）

### 3.1 `CombatFlowEdgeAuthoring` / `CombatFlowCompiledEdge` 新增字段

```csharp
// 新增（编译期同步进 CompiledEdge）
public float LateWindowSeconds;     // G5：动作结束后容错（绝对秒，0 表示无 late）
// EarlyWindow 不新增字段：编辑器从 FromNode.Action 的 ActionWindow 只读投影
```

> `Priority`、`Conditions`、`TargetRoute`、`InputSlot`、`InputSemantic` 复用现有字段。
> 终态 `FlowEdge` 形态对齐 149.1 line 3480：`{ Trigger(InputSlot+Semantic), LateWindowSeconds, Conditions[], Priority, Target }`。

### 3.2 `CombatGraphAsset` 新增

```csharp
public CombatFlowGraphMissPolicy MissPolicy;   // G9：FallbackToEntry | Block
// 「启用」= (combatFlow != null && HasValidCompile)；不新增运行时 bool 开关（避免双轨语义）
public enum CombatFlowGraphMissPolicy : byte { FallbackToEntry = 0, Block = 1 }
```

### 3.3 节点语义补充

- **Start**：Idle Context。出边 = 「空闲时按某键解析到 Route」（G2）。
- **FlowAction**：当前动作节点。`BindEntryAction` 按 Action 对齐游标（现状已有）。
- Air 节点用 `Conditions` 含 `OnAirborne()` 表达 Context，不新增节点种类（G7）。

### 3.4 运行时解析入口（终态唯一真相）

```
SkillEntryService.TryResolveForIntent(intent, ctx):
  1. if GraphEnabled:
        if CombatGraphRunner.TryResolveContextual(intent, ctx, out route):   // G1/G3
             return route   // 命中 Graph 边
        else if MissPolicy == Block: return null（discard 由调用方决定）       // G9
        // FallbackToEntry: 落到 2
  2. （现状 Entry 解析：Charge/Combo/Directional/MultiStage/Normal）            // 不动
```

> 单轨保证：解析权**只有一处**（`TryResolveForIntent`）。Graph 命中即返回，未命中才进 Entry。**不保留** 147.1 的「resolve 失败后 `TryAdvanceCombatFlowOnInput` 二次查图」旁路——该旁路在 Landing 1 删除，避免两套查图路径（违 07）。

## 4. 契约表（唯一真相 — 禁止兜底分散写）

| 语义 | 唯一写入点 | 读取方 | 禁止 |

## 10. 风险与回滚

| 风险 | 规避 |
|---|---|
| 解析反转影响所有连段（LM 连击回归） | L1 先只接 OnInput 边，Charge/Directional/Combo 仍 Entry；逐 Landing 扩面 |

| Air/Cancel 与 Interrupt 双写状态 | 双闸门**有序**：先 Interrupt 判许可，再 Graph 选 target；状态仍由各自单点写 |
| Late Window 与 Combo link window 打架 | Late 仅作用于「动作已自然结束」；Combo link window 由 ComboRouteRuntime 管，互不覆盖；同节点二选一并加 Log |
| 游标在环/跨状态漂移 | L7 专测 Loop + 地空地；游标推进只在 Runner 单点 |
| 回滚 | 每 Landing git tag；出问题回退提交，不在代码堆开关 |
