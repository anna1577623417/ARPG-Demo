## 一、核心诉求与运行时契约

**目标**：从 `AnimationClip` 离线得到 `MotionProfileSO.AxisCurves`（X/Y/Z 曲线 + Scale，米），供 `MotionExecutor` 在 Action 逻辑时长内驱动位移。

**运行时语义**（`MotionAxisCurves`）：

- `Evaluate(t) × Scale` = 米；t ∈ [0,1] 对齐 **Action.LogicDuration**
- **X** = 角色 Right，**Y** = World Up，**Z** = 角色 Forward（执行时再经 `MotionSpace` 映射到世界）

提取失败的表现：`scale=(0,0,0)`、`keys=(2,2,2)` → 等于「三轴平线」，运行时该轴位移为 0。

---

## 二、无法提取的根因（机制层）

### 2.1 当前管线在做什么

```text
选中 Hierarchy 节点（多为 Armature）
  → clip.SampleAnimation(gameObject, t)
  → 读 sampleRoot.localPosition（47 帧）
  → 减首帧、算 max、归一化、拟合 → 写入 AxisCurves
```

### 2.2 为什么和「动画正常、有 RM」矛盾

| 现象                      | 原因                                                                |
| ------------------------- | ------------------------------------------------------------------- |
| Scene/Animator 里冲刺正常 | 骨骼在动 + 可能有 **Root Motion 曲线**；或旧 MotionProfile 仍在驱动 |
| `scale=0`                 | **采样的 Transform 在 47 帧内几乎不动**                             |
| 多个 `_RM` Clip 一起挂    | 同一 Rig + 同一错误采样点 → **系统性失败**                          |

**三层叠加**：

1. **`SampleAnimation` 不应用 Humanoid Root Motion**  
   Unity 设计：根运动主要由 **`RootT.*` / `RootQ.*` 曲线** 表达，运行时靠 `Animator` + `applyRootMotion` 消费。  
   `SampleAnimation` 只推进骨骼绑定，**不会**把 Root Motion 写到随便一个父节点 `transform.localPosition` 上。

2. **采样点错误**  
   蓝图 131 要求采 **`Hips` / RootMotion 节点`**；实现里用 **`Selection.activeTransform`（Armature）** 的 `localPosition`。  
   UAL/Mixamo 常见：`Armature` 不动，**Hips/骨盆** 相对父级在动 → 父节点读数恒为 0。

3. **后处理掩盖问题**  
   max≈0 → 归一化全 0 → Scale=0 → 拟合压成 2 个 key → 日志像「提取跑完了」，实际是**空曲线**。

**旁证**：项目里 `RefSpeedExtractor` 读的是 Clip 上的 **`RootT.z`**，说明位移数据可以在**曲线里**，而不在当前 `localPosition` 路径里。

```text
┌─────────────────────────────────────────────────────────┐
│ AnimationClip                                           │
│  ├─ RootT.x/y/z  (Humanoid RM)     ← 有数据，当前未读    │
│  └─ 骨骼 localRotation/Position   ← SampleAnimation 会动 │
│                                                         │
│ Armature.localPosition            ← 当前在读，常为 0     │
└─────────────────────────────────────────────────────────┘
```

## 三、方案空间（解决「三轴曲线提不出来」）

下面方案都围绕：**在 t∈[0,1] 上得到有意义的 (x,y,z) 米制位移序列**，再接入现有 `MotionCurveFitPipeline`（滤波 + 抽 key + Scale）。

---

### 方案 A：直接读 Clip 的 Humanoid Root 曲线（推荐主路径）

**做法**  
`AnimationUtility.GetCurveBindings` → 取 `RootT.x` / `RootT.y` / `RootT.z`（及必要时 `RootQ` 仅用于诊断），按 `samplingFps` 在 [0, clip.length] 上 `Evaluate`，减首帧归零，写入 X/Y/Z。

**优点**

- 与 Humanoid + `_RM` 资源一致；和 `RefSpeedExtractor` 同源，**批量 Clip 可恢复**
- 不依赖 Hierarchy 选中、不需 Play Mode
- 速度快、确定性高

**难点 / 必须设计**

| 点         | 说明                                                                                                                           |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------ |
| **坐标系** | `RootT` 多在 **模型根空间**；Motion 要 **角色 Right / World Up / Forward**                                                     |
| **映射**   | 提取时用 **Bind Pose 或 t=0 的根朝向** 把 `(RootT.x, RootT.y, RootT.z)` 旋转到「角色前/右/上」；或约定 UAL 资源 Z=前、再文档化 |
| **缺曲线** | Import 勾了 Bake Into Pose、或 Generic 无 `RootT` → 走方案 B 或 C                                                              |
| **仅单轴** | 很多 Dash 只有 `RootT.z`，X/Y Scale 可为 0，属正常                                                                             |

**适用**：`UAL2_Standard` 类人形、命名带 RM、Inspector 里能看到 `RootT` 的 Clip。

---

### 方案 B：骨骼路径采样（Transform Hierarchy）

**做法**  
`SampleAnimation` 后读 **`rigRoot` 下指定骨骼**（默认 `Hips`，可配 `RootBonePath`）的 **`localPosition`（相对 Armature）** 或相对采样根。

**优点**

- RM 被 **Bake Into Pose**、位移在骨盆上的 Clip 仍可能采到
- 与蓝图 131 原意一致；`ResolveSampleRoot` 已有雏形，只需接入 UI

**缺点**

- 仍依赖 Hierarchy 与 Avatar 一致；路径错则仍全 0
- 骨骼位移 ≠ 根运动曲线，和 Runtime「逻辑位移」可能差一截
- 仍需处理 **不应用 RM 的 SampleAnimation**（骨骼曲线要真的在动）

**适用**：无 `RootT`、但 Hips `localPosition` 随时间变化的 Generic / 烘焙型 Clip。

---

### 方案 C：Animator + AnimationMode 采 `rootPosition`

**做法**  
预览 Rig 带 `Animator`，`AnimationMode` + `SampleAnimationClip` 或逐帧 `Update`，`applyRootMotion=true`，累计 **`Animator.rootPosition` 增量**（或每帧 world delta 再投到角色平面）。

**优点**

- 最接近 Play Mode 根运动表现
- 可覆盖部分 Import/曲线边界情况

**缺点**

- 必须正确 Rig、Controller 可空、Avatar 匹配
- 编辑器更重、多窗口/多 Clip 要注意 `AnimationMode` 生命周期
- 坐标仍要映射到 Motion 三轴

**适用**：A/B 都失败时的 **兜底**；或需与 Animator 状态机一致时。

---

### 方案 D：世界空间骨骼轨迹再投影（Camera/Character Forward）

**做法**  
对 Hips（或 Root）采 **世界坐标** 轨迹，用 **提取时刻角色 Forward/Right** 投影成 X/Z，Y 取世界高度差。

**优点**

- 与 `MotionSpace.CameraForward` 等运行时策略更易对齐（尤其四向闪避）

**缺点**

- 依赖采样时「参考朝向」选取规则（应用 t=0 还是 Bind Pose）
- 实现比 A 复杂；与「局部曲线 × 运行时 MotionSpace」要文档写清

**适用**：四向 Dodge、位移语义跟镜头/输入强绑定；可作为 A 之后的 **增强档**，不必第一刀。

---

### 方案 E：多源自动选择（推荐落地形态）

**不做双轨运行时**，只在 **Editor 提取器内** 按优先级选唯一数据源：

```text
1) Clip 存在有效 RootT.x/y/z 且幅度 > ε  → 方案 A
2) 否则 配置骨骼路径 local 位移有效      → 方案 B
3) 否则 Animator rootPosition 有效         → 方案 C
4) 全失败 → 明确报错（列 bindings / 骨骼名 / 建议 Import 设置）
```

**日志契约**（避免再出现「假成功」）：

```text
[MotionXYZ][Extract] source=RootT clip=... max=(x,y,z)m scale=(...) keys=(...)
[MotionXYZ][Extract] FAIL no displacement source=... bindings=12 RootT=missing
```

**禁止**：`scale` 全 0 仍打 Info 当成功。

## 四、推荐方案（针对「必须提出三轴曲线」）

### 4.1 总览

| 阶段     | 内容                                        | 解决什么                          |
| -------- | ------------------------------------------- | --------------------------------- |
| **P0**   | **方案 A（RootT 曲线）** + 失败显式报错     | 批量修好 Humanoid `_RM` Dash/Roll |
| **P1**   | **方案 B（可配骨骼路径）** + Inspector 预览 | Bake Into Pose / 无 RootT 的 Clip |
| **P2**   | 方案 C 兜底 + 方案 D（按需）                | 边角 Rig、四向语义                |
| **P0.5** | 坐标映射表 + 验收工具                       | Scale/方向与 Runtime 一致         |

### 4.2 P0：RootT 提取（核心）

**输入**：`AnimationClip` + 可选「仅用于 B/C 的 Rig」  
**输出**：与现有一致的 `AxisCurves` + `ExtractReport` + **source=RootT**

**步骤**：

1. 解析 `RootT.x/y/z`（缺轴则该轴 max=0，不伪造）  
2. 在 `N` 个采样点构建 `positions[i]`（秒 → 归一化 t 仍按 `clip.length` 或 `Action.LogicDuration` 对齐策略，与现逻辑一致）  
3. **坐标旋转**：用 t=0 根朝向或固定「模型 Z=前」矩阵，映射到 Motion 的 X/Y/Z  
4. `ZeroOrigin` → `max` → `Normalize` → 现有 `MotionCurveFitPipeline`  
5. 若 `maxX+maxY+maxZ < ε` → **Warning/Fail**，不写「假 Scale=0 成功」

**与 `RefSpeedExtractor` 关系**：共用 `RootT` 读取工具函数，避免两套解析。

### 4.3 P1：骨骼路径（补洞）

- Inspector：`Sample Bone Path`（默认 `Hips` 或空=仅 A）  
- `SampleAnimation` 后读 `bone.localPosition`（相对 `Armature`）  
- 仍要求 **幅度 > ε**，否则失败并提示检查路径

### 4.4 坐标系（必写进设计，否则「提出来了但方向反了」）

| Motion 轴 | 建议提取定义                          |
| --------- | ------------------------------------- |
| Z         | 沿 **角色 Forward（t=0）** 的位移分量 |
| X         | 沿 **角色 Right（t=0）**              |
| Y         | **世界 Up** 分量（跳跃/浮空）         |

Humanoid `RootT` 常在模型空间：  
`motionLocal = inverse(rotation(t=0)) * (rootT(t) - rootT(0))`，再拆 X/Y/Z。

四向闪避：提取仍用 **Clip 自身位移**；**CameraForward** 在 **Runtime `MotionSpace`** 旋转，不在提取阶段硬绑镜头（与 136.3 一致）。

### 4.5 Import / 资产侧（非代码但常是「假无 RM」）

策划/ TA 检查清单：

- Rig：**Humanoid**  
- Root Motion：**Bake Into Pose 关闭**（若要用 RootT）  
- 动画类型：位移在 **Root Transform** 而非仅网格形变  
- Clip 名 `_RM` 只作提示，**以 Animation 窗口是否见 `RootT` 为准**
