# MotionProfile 时间与速率系统收敛计划书

---

# 一、问题分析（37%）

经过这一轮设计讨论，目前已经暴露出 MotionProfile 与 ActionData 的职责边界开始混乱的问题。

当前存在的问题不是某个字段是否保留，而是：

```text
谁拥有时间？
谁拥有速率？
谁决定动作结束？
```

没有统一答案。

---

## 问题1：AnimSpeed 与 Duration 双真值

当前 ActionData：

```text
AnimSpeed
Duration
```

同时存在。

例如：

```text
AnimSpeed = 2

Duration = 0.6
```

此时：

```text
到底按0.6秒结束？

还是按动画2倍速结束？
```

无法确定。

属于：

```text
双真值问题
```

---

### 风险

后续加入：

```text
AttackSpeed
CastSpeed
Slow
Haste
```

以后：

```text
Duration
AnimSpeed
Buff
```

会产生冲突。

最终出现：

```text
HitBox结束了
动画还没结束

动画结束了
Motion还没结束
```

的问题。

---

## 问题2：MotionProfile开始侵入逻辑层

当前 MotionProfile 中出现：

```text
Stat Scaling

Reference Speed
```

这意味着：

```text
Motion开始知道角色属性
```

例如：

```text
AttackSpeed

MoveSpeed

CastSpeed
```

这些实际上属于：

```text
Gameplay层
```

而不是：

```text
Animation层
```

---

### 风险

未来 MotionProfile 会依赖：

```text
CharacterStats

Buff

Equipment
```

导致：

```text
表现层
↕
逻辑层
```

双向耦合。

---

## 问题3：位移结束与动画结束可能不同步

未来：

```text
AttackSpeed ×2
```

时：

Action耗时缩短。

如果：

```text
Motion曲线仍按原时间执行
```

则会出现：

```text
动画结束

Motion还在跑
```

或者：

```text
Motion结束

动画还没结束
```

---

### 风险

直接影响：

```text
翻滚

冲锋

位移技

突刺技
```

等所有 Motion 技能。

---

## 问题4：Reference Speed 价值极低

当前设计：

```text
Reference Speed = 10
```

然后：

```text
Current Attack Speed = 20
```

得到：

```text
Multiplier = 20 / 10
```

实际上：

完全可以直接：

```text
AttackSpeedMultiplier
```

得到同样结果。

---

### 问题本质

Reference Speed 是：

```text
中间状态
```

不是最终需求。

属于典型的：

```text
设计过度
```

---

## 问题5：Motion Speed Curve 的职责不清晰

当前：

```text
Speed Curve
```

可能被用于：

```text
控制动画总时长

控制局部节奏

控制攻速缩放
```

三种用途。

但实际上：

它应该只负责：

```text
局部时间流速
```

例如：

```text
前摇慢

攻击快

收招慢
```

而不负责：

```text
动作总时长
```

# 二、设计目标（10%）

构建统一时间系统：

```text
Action
拥有时间

Motion
消费时间

Timeline
消费时间

Animation
消费时间
```

保证：

```text
动画结束
=
Motion结束
=
HitBox结束
=
Action结束
```

永远同步。

# 三、落地方案（53%）

---

# 方案一：建立唯一时间权威

新增原则：

```text
Action Duration
是唯一真值
```

---

ActionData：

```csharp
public class ActionData
{
    float BaseDuration;
}
```

例如：

```text
翻滚

BaseDuration = 0.6
```

---

运行时：

```csharp
FinalDuration =
BaseDuration
/
SpeedMultiplier;
```

得到：

```text
最终耗时
```

---

# 方案二：删除 Action.AnimSpeed

删除：

```text
AnimSpeed
```

---

原因：

```text
Duration
已经决定播放速度
```

例如：

```text
ClipLength = 1.2

Duration = 0.6
```

自动得到：

```csharp
AnimatorSpeed =
1.2f / 0.6f;
```

---

因此：

```text
AnimSpeed
无需人工维护
```

避免双真值。

---

# 方案三：Stat Scaling迁移到Action

从：

```text
MotionProfile
```

迁移至：

```text
ActionData
```

---

结构：

```csharp
public enum StatScalingType
{
    None,

    MoveSpeed,

    AttackSpeed,

    CastSpeed,

    Custom
}
```

---

Action：

```csharp
public class ActionData
{
    StatScalingType ScalingType;
}
```

---

作用：

决定：

```text
Duration如何缩放
```

---

例如：

普攻：

```text
AttackSpeed
```

---

吟唱：

```text
CastSpeed
```

---

翻滚：

```text
None
```

---

# 方案四：彻底删除Reference Speed

删除：

```text
Reference Speed
```

---

改为：

```csharp
SpeedMultiplier =
Stats.GetMultiplier(ScalingType);
```

直接获得：

```text
1.0

1.2

1.5

2.0
```

即可。

---

# 方案五：Motion只保留表现职责

MotionProfile：

```csharp
MotionProfile
{
    AnimationClip Clip;

    MotionCurveX;
    MotionCurveY;
    MotionCurveZ;

    RotationCurve;

    SpeedCurve;
}
```

---

禁止出现：

```text
AttackSpeed

CastSpeed

ReferenceSpeed

Duration
```

相关字段。

---

Motion只负责：

```text
在0~1时间内

如何运动
```

---

# 方案六：统一NormalizedTime驱动

运行时：

```csharp
NormalizedTime =
ElapsedTime
/
FinalDuration;
```

---

所有系统：

```text
Animator

Motion

HitTrack

InvincibleTrack

FXTrack

AudioTrack

CameraTrack
```

统一读取：

```text
NormalizedTime
```

---

例如：

```csharp
MotionCurve.Evaluate(NormalizedTime);

HitTrack.Evaluate(NormalizedTime);

Animator.Play(..., NormalizedTime);
```

---

保证：

```text
任何攻速变化

任何时间缩放

任何Buff
```

全部自动同步。

---

# 方案七：新增【自动匹配基础速率】按钮

这是最值得保留的功能。

---

MotionProfile Inspector：

```text
[ Auto Match Base Speed ]
```

---

点击后：

自动计算：

```csharp
ClipLength
/
ActionDuration
```

---

例如：

```text
ClipLength = 1.2

ActionDuration = 0.6
```

自动得到：

```text
BaseSpeed = 2.0
```

---

写入：

```text
Speed Curve 默认值
```

或者：

```text
Preview Speed
```

---

作用：

解决：

```text
动画导入长度

动作设计长度
```

不一致的问题。

---

本质是：

```text
编辑器辅助功能
```

而不是运行时逻辑。

# 四、最终架构

```text
ActionData
│
├─ BaseDuration
├─ StatScalingType
├─ TimelineTracks
└─ MotionProfile

                ↓

FinalDuration

                ↓

NormalizedTime

                ↓

┌──────────────┐
│ Animator     │
│ Motion       │
│ HitTrack     │
│ FXTrack      │
│ AudioTrack   │
│ CameraTrack  │
│ Invincible   │
└──────────────┘
```

最终原则收敛为：

```text
Action决定动作多久结束

Motion决定动作如何运动

SpeedCurve决定局部节奏

StatScaling决定总时长缩放

NormalizedTime驱动整个Timeline
```

这是后续扩展攻速、施法速度、时间减速、狂暴状态、连招缩短后摇以及 RootMotion 曲线系统时最稳定的一套架构。
