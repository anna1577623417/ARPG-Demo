```text
Level1：选择逻辑错误（Bug）
```

# 一、当前BUG分析

从截图来看：

```text
点击Edge
↓
弹出属性
↓
再次重绘
↓
Selection丢失
↓
面板消失
```

很像：

```csharp
OnSelectionChanged()
```

与

```csharp
GraphViewSelection
```

不同步。

---

通常发生于：

```csharp
MouseDown
↓
Edge被选中

Inspector刷新

GraphView重新Focus

Selection变空
```

---

最终：

```csharp
CurrentEdge = null
```

导致Inspector关闭。

---

## 应修复为

采用：

```text
Persistent Selection
```

模式。

---

即：

```csharp
CurrentSelection
{
    Node
    Edge
}
```

作为唯一数据源。

---

不要：

```csharp
Inspector直接读取GraphView.selection
```

---

而应该：

```csharp
GraphView.selection
↓
SelectionController
↓
CurrentSelection
↓
Inspector
```

---

这样Inspector永远不会因为重绘消失。

---

# 二、框选不应触发Edge Inspector

这是一个非常典型的专业编辑器需求

目前：

```text
框选
↓
Edge被选中
↓
Inspector打开
```

体验很差。

---

正确逻辑：

## 单选

```text
Node
→ Node Inspector

Edge
→ Edge Inspector
```

---

## 多选

```text
Node+Node
Node+Edge
Edge+Edge
```

统一：

```text
Multi Selection
```

---

Inspector显示：

```text
2 Objects Selected
```

而不是：

```text
Edge Inspector
```

---

即：

```csharp
if(selection.Count == 1)
{
    ShowInspector();
}
else
{
    ShowMultiSelection();
}
```

---

这是Unity官方Animator的行为。

# 五、Inspector宽度自适应

你提的问题很关键。

目前：

```text
Transition
──────────────────────────────
```

拉满一整行。

---

非常浪费。

---

推荐：

## Label固定宽度

例如：

```text
120px
```

---

## Value区域自适应

例如：

```text
Transition    [Dropdown      ▼]

Priority      [0             ]

TargetRoute   [RouteA        ○]
```

---

而不是：

```text
Transition
[————————————————————————]
```

---

这样视觉密度会高很多。

# 八、下一阶段建议

我认为优先级应该是：

```text

```

---

## P1（本周）


---

## P2（后续）

```text
✓ 折叠分组

✓ 搜索框

✓ 条件资产拖拽

✓ LateWindow编辑

✓ Context Input编辑
```

---

如果按专业工具标准来看，你现在最值得投入的并不是继续扩展 Combat Graph 功能，而是先把 **Selection + Inspector 工作流** 做稳定。

因为一个编辑器如果存在：

```text
点击选不中
点击就消失
框选乱弹窗
```

这类问题，后面无论加多少功能，使用体验都会迅速恶化。当前阶段最合理的目标是把它做成接近 Animator、ShaderGraph、Blueprint 那种“选中对象 → Inspector稳定编辑”的工作流，然后再继续扩展 Combat Flow 本身。
