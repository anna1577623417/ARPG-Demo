# Action 时间权威系统 V2 计划书

## 一、问题分析（37%）

### 问题1：逻辑时长与动画完成度被混为一谈

当前系统：

```text
Duration
↓
AnimSpeed
```

默认认为：

```text
逻辑结束
=
动画100%完成
```

即：

```text
0.5秒逻辑时长

动画必须在0.5秒播完
```

这种方案对于：

```text
翻滚
跳跃
短动作
```

没有问题。

但是对于：

```text
普攻
重击
施法
收刀
```

问题很大。

---

例如：

动画：

```text
ClipLength = 1.0s
```

内容：

```text
0.0~0.6 攻击动作

0.6~1.0 收招后摇
```

---

设计师希望：

```text
技能结束
=
0.8s
```

即：

```text
只播放到80%
```

截断后摇。

---

如果使用：

```text
AnimSpeed = ClipLength / Duration
```

则会变成：

```text
0.8秒播放完整动画
```

后摇反而被保留。

完全违背设计目标。

---

### 问题2：攻速变化会破坏后摇裁剪


---

问题本质：

系统保存的是：

```text

```

而不是：

```text
动作完成度
```

## 方案三：动态速率算法

定义：

```text
C = ClipLength

D = Duration

R = AnimationEndRatio
```

---

最终动画速度：

```csharp
AnimSpeed =
(C * R) / D;
```

---

示例：

```text
ClipLength = 1

Duration = 0.5

Ratio = 0.8
```

得到：

```text
AnimSpeed = 1.6
```

---

效果：

```text
0.5秒结束

动画播放到80%
```

---

攻速变化：

```text
Duration = 0.25
```

---

得到：

```text
AnimSpeed = 3.2
```

---

效果：

```text
0.25秒结束

依然播放80%
```

---

后摇裁剪永远有效。

```text
ActionData
│

└─ MotionProfile

                ↓
```

最终收敛原则：

```text

决定结束时动画播放到哪里

决定Duration如何缩放

Motion

```

这套设计已经非常接近 ACT（动作游戏）编辑器的思路：设计师编辑的是“动作节奏”和“动作完成度”，而不是手工维护一堆容易冲突的播放速度参数。

==【2】双思维角度按钮（快速填入数字）==

这个补充非常合理，而且实际上会让编辑体验提升一个档次。

因为：

```text
Duration
AnimationEndRatio
```

本质上描述的是同一件事的两个观察角度。

---

例如：

```text
ClipLength = 1.0s

Duration = 0.8s

Ratio = 0.8
```

实际上表达的是：

```text
用0.8秒时间
播放1秒动画的前80%
```

---

对于策划来说：

有时思考方式是：

```text
我要砍掉20%后摇
```

于是直接编辑：

```text
Ratio = 0.8
```

---

有时思考方式是：

```text
我希望这个技能总共0.8秒结束
```

于是直接编辑：

```text
Duration = 0.8
```

---

因此这两个参数虽然职责不同：

```text
Duration
=
逻辑时间

Ratio
=
动作完成度
```

但在静态编辑阶段其实存在天然换算关系。

# 运行时原则（保持不变）

运行时永远采用：

```csharp
FinalDuration
```

和：

```csharp
AnimationEndRatio
```

双参数驱动。

---

计算：

```csharp
AnimSpeed =
(ClipLength * Ratio)
/
FinalDuration;
```

---

Motion：

```csharp
Progress =
NormalizedTime
*
Ratio;
```

---

因此：

```text
攻速变化
施法速度变化
时间缩放
Buff
```

只影响：

```text
FinalDuration
```

---

而：

```text
Ratio
```

保持不变。

---

保证：

```text

永远裁掉20%后摇
```

不会因为：

```text
攻速变快
攻速变慢
```

而失效。

# 最终Time Authority V2.1

```text
ActionData
│
├─ Duration
├─ AnimationEndRatio
├─ StatScalingType
├─ MotionProfile
└─ Timeline

Editor Helper
│
├─ Ratio → Duration
├─ Duration → Ratio
├─ Convert From AnimSpeed
├─ Suggested Ratio
└─ Suggested Duration

Runtime
│
├─ FinalDuration
├─ AnimSpeed
├─ Progress
└─ NormalizedTime
```

最终形成三层结构：

```text
编辑层
    ↓
(Duration ↔ Ratio 快速换算)

配置层
    ↓
(Duration + Ratio)

运行层
    ↓
(FinalDuration + Progress)
```

这样设计师编辑的是最符合直觉的“时间”和“完成度”，而系统内部负责推导 AnimSpeed、MotionProgress 和最终同步关系。这样既保留了你现在的 Time Authority 面板价值，又彻底摆脱了 AnimSpeed 作为配置项带来的混乱。
