# 138.1 落地计划书：AbilitySystem（按状态施法闸门）

## 切片目标
- 引入 `AbilitySystem`，定义“当前可以释放什么技能/动作”。
- 支持按状态精确施法：
  - 地面可释放（Grounded-only）
  - 滞空可释放（Airborne-only）
  - 滞空上升可释放（Ascending-only）
  - 滞空下落可释放（Falling-only）
- 与现有 `SkillRoute / CombatFlow / ActionInterruptResolver` 单轨协同，不再写死 Jump/Dash/Roll。

---

## 一、现状基线（当前代码）
- 已有 `EntityCapabilityTag` 与 `EntityAbilitySystem.Update(Player)`，但能力粒度较粗（`CanCastAbility1` 等），不区分上升/下落。
- `PlayerAirborneState` 已能通过 `VerticalSpeed > 0` 区分上升/下落相位（仅用于打断类别）。
- `CombatContextSnapshot` 当前只提供 `IsAirborne`，没有“空中相位（上升/下落）”字段。
- `SkillEntryService` 尚未统一通过 Ability 规则判定“该 Entry/Group/Route 能否释放”。

---

## 二、终态定义（单轨）

### 1) AbilitySystem 职责
- 唯一回答：**“现在能不能放这个能力语义”**。
- 不做选路（选路仍归 `SkillEntryService/CombatFlow`）。
- 不做窗口时序（窗口仍归 `ActionWindow`）。

### 2) 施法条件分层
- **能力层（AbilityGate）**：Grounded/Airborne/Ascending/Falling 等状态闸门。
- **流转层（CombatFlow）**：允许从当前节点流向哪个后继节点。
- **窗口层（ActionWindow）**：当前动作是否允许被打断。

三者必须同时成立，任一失败即拒绝。

---

## 三、契约表（唯一真相）

| 语义 | 唯一写入点 | 读取方 | 禁止 |
|---|---|---|---|
| 当前空中相位（Ascending/Falling） | `Player.BuildCombatContext` | `AbilityGateService` | 在 SkillRouteRuntime 内重复判定相位 |
| 能力可施放规则 | `AbilityMapSO/AbilityRuleSO` | `SkillEntryService` | 在 Entry/Route 里散写 `if (IsGrounded)` |
| 施法最终准入 | `AbilityGateService.CanActivate` | `SkillEntryService` | 绕过 AbilityGate 直接进 Route |

## 四、设施表（先建）

| 设施 | 层级 | 说明 |
|---|---|---|
| `AirbornePhase` 枚举 | 2_Framework 或 3_Gameplay 公共 | `None/Ascending/Falling` |
| `CombatContextSnapshot` 扩展字段 | 2_Framework | 增加 `AirbornePhase` |
| `AbilityRuleSO` | 4_Data | 定义能力规则（状态/标签/可选资源） |
| `AbilityMapSO` | 4_Data | Ability -> 可触发组/入口映射 |
| `AbilityGateService` | 2_Framework | 单点判定能力准入 |
| Loadout 装配 AbilityMap | 4_Data + Player/SkillEntryService | 从 Loadout 注入能力表 |

## 五、核心数据模型（建议）

```csharp
public enum AirbornePhase : byte
{
    None = 0,       // 非空中
    Ascending = 1,  // VerticalSpeed > +epsilon
    Falling = 2,    // VerticalSpeed < -epsilon
}
```

```csharp
public enum AbilitySemantic : ushort
{
    Attack = 1,
    Mobility = 2,
    Defense = 3,
    Counter = 4,
    Special = 5,
    Interaction = 6,
}
```

```csharp
// 规则资产（每条能力语义一条或多条）
AbilityRuleSO
- AbilitySemantic ability
- bool requireGrounded
- bool requireAirborne
- bool allowAscending
- bool allowFalling
- ulong requiredStateTags
- ulong forbiddenStateTags
- ulong requiredMechanicTags
- ulong forbiddenMechanicTags
```

```csharp
// 装配资产
AbilityMapSO
- AbilityBinding[]
  - AbilitySemantic ability
  - SkillEntrySlot slot
  - ISkillUnit targetUnit (Group/Route)
  - AbilityRuleSO rule
```

## 六、运行时闸门流程

```text
InputSemanticResolver
  -> GameplayIntent (semantic + slot + axis)
  -> SkillEntryService.TryResolveForIntent
      -> ResolveAbilitySemantic(intent, entry/group/route)
      -> AbilityGateService.CanActivate(ability, rule, combatCtx, tags, resources)
      -> pass ? 继续 CombatFlow/Group选路 : 拒绝并日志
```

判定顺序建议：
1. Ground/Airborne 基础闸门
2. AirbornePhase（上升/下落）
3. required/forbidden tags
4. （可选）资源与CD

## 九、验收案例（你指定的场景）

### Case A：地面施放限定
- 规则：`requireGrounded=true`
- 预期：
  - 地面按键：通过
  - 空中（上升/下落）按键：拒绝
- 日志：
  - pass: `[Ability] gate pass ability=... grounded=true`
  - deny: `[Ability] gate deny reason=require grounded`

### Case B：滞空上升限定
- 规则：`requireAirborne=true, allowAscending=true, allowFalling=false`
- 预期：
  - 上升可放
  - 下落拒绝
  - 地面拒绝

### Case C：滞空下落限定
- 规则：`requireAirborne=true, allowAscending=false, allowFalling=true`
- 预期：
  - 下落可放
  - 上升拒绝
  - 地面拒绝

## 十、最小日志规范
- `[Ability] ctx grounded={bool} airborne={bool} phase={None|Ascending|Falling}`
- `[Ability] gate ability={x} pass={bool} reason={...}`
- `[Resolve] ability pass -> route={...}` / `[Resolve] ability deny -> no route`

---

## 十一、风险与规避
- 风险：AbilityGate 与 CombatFlow 条件重复配置导致互相打架
  - 规避：Ability 只做“能不能开始”，Flow 只做“能不能从A到B”。
- 风险：空中相位抖动（顶点附近上下切换）
  - 规避：使用 `verticalEpsilon` 与最短保持帧（可选）。
- 风险：旧硬编码分支残留
  - 规避：grep 守卫（`IsGrounded` 直读施法分支清零）。
