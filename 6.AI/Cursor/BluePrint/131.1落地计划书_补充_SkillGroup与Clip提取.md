# 《XYZ Motion + SkillGroup 四向翻滚兼容》补充蓝图

## 0. 为何需要这份补充

主蓝图（XYZ Motion Runtime）只回答了 **"角色怎么动"**。
四向翻滚跑通后暴露三件主蓝图没解决的事：

1. **技能单位错位** — 四向翻滚是 4 条 Route，但玩家认知只有 1 个"翻滚"；当前 SkillEntryDefinition 把 Route 当作直接挂载点，导致：
   - CD / Icon / Cost 重复配 4 份；
   - HUD widget 不知道该读哪条 Route；
   - Combat Flow Graph 越过 SkillEntry 直接驱动 Route，主导权倒挂（见 127.1 §一）。
2. **HUD 没有 Group-aware 数据源** — 当前 HUD 只能订阅单 Route Runtime，看不到"翻滚集合体的总 CD / 当前激活变体 / 方向预览"。
3. **Motion 曲线无法工业化生产** — 主蓝图 L1~L5 全是 Runtime 改造，**没有"Clip → XYZ 0-1 位移曲线"的真实提取链路**，设计师只能手 K 曲线，四向翻滚等"动画固定但需 Motion 复刻"的场景无法落地。

本补充作为主蓝图的**第二条切片轨**，与主蓝图 5 个 Landing **并行而非替代**；冲突点统一在 §10 "与主蓝图冲突清单"集中说明。

## 1. 目标与诚实边界

### 架构目标（3 条）

1. **引入 `SkillUnit` 抽象层** —— `SkillRouteDefinition` 与新 `SkillGroupDefinition` 同时实现 `ISkillUnit`，让 `SkillEntryDefinition` 改持 `ISkillUnit` 而非具体 Route；普通技能（火球、升龙）继续直接挂 Route，**不强制 Group 化**（127.1 §一明确否决）。
2. **HUD Runtime ViewModel 层** —— 新增 `ISkillUnitHandle`（Route Handle / Group Handle 两实现），HUD widget 只订阅 Handle，不直接读 SO；CD / Icon / 当前激活变体 / Charge 进度 / Combo Index 全部从 Handle 拉。
3. **Clip → XYZ Curve 离线提取工具** —— 在 ActionData / MotionProfile Inspector 增加按钮"从 AnimationClip 采样根骨/Root Motion → 写入 MotionProfile.XCurve/YCurve/ZCurve"，0-1 归一化，作为设计师手调的参考底。

### 本补充不解决什么

- ❌ **不做 Group 的 RouteResolver 重写** —— 复用现有 `RouteResolver`，Group 只是"挂多个 Route + 共享 CD/Icon"的容器；Group 内部走哪条 Route 仍由原有 Directional / Combo / Charge Resolver 决定。
- ❌ **不做 Combat Flow Graph 重新挂载** —— 127.1 §一 1 提到的"Graph 不该挂 Player 而该挂 SkillEntry"留下一 Slice；本补充只把 Group 引入数据层，Graph 仍按当前位置使用。
- ❌ **不做 Rotation Curve / Gravity Weight Curve 提取** —— 仅 X/Y/Z 三轴位置；旋转和重力曲线提取留 L-Ex-3。
- ❌ **不做 Clip 反向写回（XYZ → Clip）** —— 单向：Clip 是参考源，Motion 曲线是产物。
- ❌ **不做 SkillGroup 嵌套**（Composite Pattern 完整版）—— 127.1 §三虽提及"Group 可包含 Group"，本切片仅一层 Group。
- ❌ **不做 Loadout 编辑器升级** —— Loadout 字段类型由 `Route` 改为 `ISkillUnit`，Inspector 用 Unity 默认 ObjectField，不做自定义 Drawer。

### 与 127.1 资料的对照

| 127.1 提出 | 本补充对应 | 备注 |
|---|---|---|
| Group 与 Route 都作为 Skill Unit | §3 数据层抽象 | 完全采纳 |
| Route 设置可跟随 Group（继承/覆盖）| §3.2 OverrideFlags | 采纳 |
| HUD 动态获取 Group 或 Route | §4 ISkillUnitHandle | 采纳 |
| Loadout 持有 SkillUnit | §3.4 SkillEntryDefinition 字段改造 | 采纳 |
| Combat Flow Graph 挂载位置矫正 | **延后** | 见 §10 冲突 #3 |
| Group 内 Directional+Combo+Charge 共存 | **延后** | MVP 仅 Directional Group |
| Route Container 多嵌套 | **延后** | MVP 一层 |

## 3. 数据层：SkillUnit 抽象与 SkillGroup

### 3.1 ISkillUnit 接口

```csharp
public interface ISkillUnit
{
    string DisplayName { get; }
    Sprite Icon { get; }
    float Cooldown { get; }
    SkillResourceCost[] Costs { get; }      // 现有 cost 结构沿用
    ulong RequiredAbilityTags { get; }      // 闸门位，沿用 EntityCapabilityTag
}
```

### 3.2 SkillGroupDefinition（新 SO）

```csharp
[CreateAssetMenu(menuName="GameMain/SkillRoute/Group/Skill Group", fileName="Group_")]
public class SkillGroupDefinition : ScriptableObject, ISkillUnit
{
    [SerializeField] string displayName;
    [SerializeField] Sprite icon;
    [SerializeField] float cooldown;
    [SerializeField] SkillResourceCost[] costs;
    [SerializeField] ulong requiredAbilityTags;

    [Header("Group Composition")]
    [SerializeField] SkillRouteDefinition[] routes;     // 组内成员（顺序无意义）
    [SerializeField] SkillRouteDefinition fallbackRoute; // 无方向/Resolver miss 时用

    public ISkillUnit AsUnit => this;
    public IReadOnlyList<SkillRouteDefinition> Routes => routes;
    public SkillRouteDefinition FallbackRoute => fallbackRoute;
}
```

### 3.3 SkillRouteDefinition 加 Group 隶属与覆盖位

```csharp
public abstract class SkillRouteDefinition : ScriptableObject, ISkillUnit
{
    // 既有字段不变...

    [Header("Group Membership")]
    [SerializeField] SkillGroupDefinition ownerGroup;     // 可空；空=独立技能单位

    [Header("Group Override Flags (仅在 ownerGroup != null 时生效)")]
    [SerializeField] bool overrideCooldown;
    [SerializeField] bool overrideIcon;
    [SerializeField] bool overrideCost;

    // ISkillUnit 实现：未 override 时回退到 Group
    public float Cooldown =>
        (ownerGroup != null && !overrideCooldown) ? ownerGroup.Cooldown : routeCooldown;
    // ... Icon / Costs 同理
}
```

### 3.4 SkillEntryDefinition 字段改造（向后兼容）

```csharp
public class SkillEntryDefinition : ScriptableObject
{
    // 既有字段保留（chargeRoute / comboRoute / ... / normalRoute / derivativeRoutes）

    [Header("Primary Skill Unit (Ver4.3.7+)")]
    [SerializeField, Tooltip("【主单位】优先于旧 Route 字段；可为 SkillGroupDefinition 或 SkillRouteDefinition。")]
    UnityEngine.Object primaryUnit;  // 由 PropertyDrawer 限制为 ISkillUnit 实现者

    public ISkillUnit PrimaryUnit => primaryUnit as ISkillUnit;
}
```

> **冲突点**：SkillEntryDefinition 当前持有 6 个 Route 字段（Charge/Combo/AirCombo/Directional/MultiStage/Normal），属于"用字段穷举语义"。本补充引入 `primaryUnit` 作为统一入口，**L-Ex-5 删除旧 6 字段**。过渡期通过编辑器迁移工具一键转换：`{NormalRoute, ComboRoute, ChargeRoute, ...}` → 自动构造一个隐式 Group 或直接 Promote 为单 Route Unit。

### 3.5 Resolver 接入

- `SkillEntryService.TryResolveForIntent`：先看 `PrimaryUnit`。
  - Unit 是 `SkillRouteDefinition` —— 直走现有路径。
  - Unit 是 `SkillGroupDefinition` —— 把 `group.Routes` 喂给原 Resolver；Resolver 不变，只是输入候选集换源。
- **Group 没有自己的 Resolver**（与 127.1 §九一致）—— Group 仅 "容器 + 共享元数据"。

## 4. HUD Runtime ViewModel：ISkillUnitHandle

### 4.1 接口

```csharp
public interface ISkillUnitHandle
{
    ISkillUnit Definition { get; }
    float Cooldown01 { get; }              // 0=ready, 1=full cd
    float CooldownRemainingSeconds { get; }
    bool CanCast { get; }                  // Ability 闸门 + 资源 + CD 综合
    bool IsActive { get; }                 // 正在执行
    SkillRouteDefinition ActiveRoute { get; }   // Group 时为当前激活变体；Route 时即自己
    int ComboIndex { get; }                // 不适用时 -1
    float ChargeProgress01 { get; }        // 不适用时 0
}
```

### 4.2 两种实现

- `SkillRouteRuntimeHandle` — 对接现有 `SkillRouteRuntime`，1:1 映射。
- `SkillGroupRuntimeHandle` — 聚合视图：
  - `Cooldown01` = `group.Routes` 中**最长**剩余 CD 还是**共享 CD**？→ 本补充采用 **Group 自带 CD 字段**：`group.Cooldown` 由 SkillEntryService 在任一组员触发后统一启动；Route 各自的 routeCooldown 仅 override 时启用。
  - `ActiveRoute` = 最近一次触发的成员 Route，未触发时 = `fallbackRoute`。

### 4.3 Player 暴露

```csharp
public class Player
{
    public SkillEntryService SkillEntries { get; }       // 既有
    public ISkillUnitHandle GetUnitHandle(SkillEntrySlot slot);  // 新
}
```

HUD widget 改为只调 `GetUnitHandle(slot)`，按 `IsActive / ComboIndex / ChargeProgress01` 渲染。不再触及 SO / Resolver / Runtime。

### 4.4 事件层

- 现有 EventBus 已发 `SkillRouteStarted / SkillRouteEnded`；本补充新加：
  - `SkillUnitCdStarted(slot, totalSeconds)`
  - `SkillUnitActiveRouteChanged(slot, route)` — Group 内 Route 切换时
- HUD widget 监听这两个，配合 Handle 拉数据，0 主动轮询。

## 5. Clip → XYZ Curve 离线提取工具

### 5.1 设计目标

设计师在 ActionData Inspector 看到一个 AnimationClip 引用（既有的 `clip` 字段）和"Extract Motion Curve"按钮。点击：

1. 工具检查 `ActionData.boundMotionProfile`：
   - 已绑定 → 直接写入；
   - 未绑定 → 弹"请先在【MotionProfile Override】槽填一个目标 MotionProfile"提示，并把当前选中的 MotionProfile（如 Project window 选中）作为候选填入。
2. 采样 Clip 根节点（默认 `Armature/Hips` 或 RootMotion 节点，可配 BoneFilter）在 Local Space 的 (x, y, z) 位置，按 `samplingFps=30`（可调）逐帧抽样。
3. 把每帧 `(t, position - position[0])` 写入 `XCurve / YCurve / ZCurve`：
   - **t 归一化**到 [0,1]：`t = i / (frameCount - 1)`；
   - **位置归零**：减去 frame[0] 让曲线从 0 起。
4. **不**写 Duration —— 主蓝图 MotionDefinition 已有 Duration 字段，由 ActionData 的 Clip Length 同步。

### 5.2 静态工具类骨架

```csharp
public static class ClipMotionExtractor
{
    public struct Options
    {
        public int SamplingFps;            // 默认 30
        public string RootBonePath;        // 默认 "" → 用 Animator root
        public bool UseLocalSpace;         // 默认 true（与主蓝图轴语义一致）
        public bool ZeroOrigin;            // 默认 true
        public AxisMask Axes;              // X/Y/Z 任意组合
    }

    public static void ExtractInto(
        AnimationClip clip,
        GameObject previewRig,             // 临时实例化用的 Armature 模型
        MotionProfileSO target,
        Options opt);
}
```

### 5.3 编辑器入口

两个挂载位：

- **ActionData Inspector** → 按钮"Extract Motion → Bound MotionProfile"。
  - 若 ActionData 没有 boundMotionProfile，且 Selection 含 MotionProfile，弹"将选中 MotionProfile 填入 ActionData.boundMotionProfile 并提取？[确认/取消]"。
- **MotionProfileSO Inspector** → 按钮"Extract from AnimationClip..."。
  - 弹简易窗口选 Clip + 预览 Rig + Options。

### 5.4 工具不做的事

- 不做 RootMotion 烘焙到 Clip 自身的反向操作（Unity 自带）。
- 不做曲线降采样 / 关键点优化（先全帧写入，未来 Slice 再做）。
- 不做多 Clip 平均（每次只处理一个 Clip）。

### 5.5 与四向翻滚的关系

四向翻滚的 4 段 Clip → 4 个 MotionProfile → 用本工具一键提取 XZ 位移（Y 通常无）；过去手 K 4 条曲线的环节直接消除。
