
Unity `GameMain Log Settings` 只需开启独立开关：`Reaction Direction (220.6)`。本专项不依赖旧的 `Combat Hit`；该开关现在也会输出 Player 冲量与速度诊断。若需同时观察仲裁细节，再额外开启 `Intent Arbitration` 或 `Interrupt Flow`。每个方向单独记录一个 `eventId`，不要把四次命中合并成一条无法对应的日志。

## 二、方向判定约定

方向是“攻击者位于受击者本地空间的哪一侧”，不是世界坐标方向，也不是冲量最终移动方向：

| 攻击者相对受击者的位置 | 期望 `direction` | 期望 Route | 期望 Action |
|---|---|---|---|
| 目标本地 `+Z` 前方 | `Front` | `Hit_F` | `Hit_F` |
| 目标本地 `-Z` 后方 | `Back` | `Hit_B` | `Hit_B` |
| 目标本地 `-X` 左方 | `Left` | `Hit_L` | `Hit_L` |
| 目标本地 `+X` 右方 | `Right` | `Hit_R` | `Hit_R` |
| `LaunchUpSpeed > 0` | `Up` | `Hit_Up` | `Hit_Up` |

## 三、四向 Reaction 验收

### F：前方受击

将攻击者放在目标本地 `+Z`，保持 `LaunchUpSpeed=0`。期望同一 `eventId` 出现：

```text
[Feedback] Reaction resolve result=Resolved eventId=<id> target=<target> route=Hit_F direction=Front ...
[Feedback] channel=Reaction result=Intent eventId=<id> target=<target> enqueueResult=Accepted
[Enemy] HitReact phase=Commit kind=HitReact result=Consumed route=Hit_F sourceEventId=<id> ...
[EnemyAnim] PLAY action=Hit_F ... kind=HitReact ...
```

判定：`direction=Front`、`route=Hit_F`、Commit route 和实际动作必须一致。

### 四向旋转复测

将目标 Enemy 旋转 90°，保持攻击者相对目标的本地位置不变，重复 F/B/L/R 中至少两项。若目标旋转后仍按世界坐标路线不变，判定为方向解析错误；若 `direction` 与 `route` 随目标本地方向一致，方向坐标契约通过。

## 四、Player 冲量与速度专项诊断

本节用于分析“Player 当前速度与击退方向相反时，冲量是否被抵消”，以及动作/移动写入是否覆盖 Hit Reaction 期间的击退。开启 `Reaction Direction (220.6)` 后，命中 Player 时收集以下 Log：

```text
[Feedback] channel=Impulse result=Applied ... target=Player ... log=220.6
[Reaction2206] channel=PlayerImpulse phase=BeforeApply ... currentPlanar=... requestedPlanar=... alignment=Opposed dot=...
[Reaction2206] channel=PlayerImpulse phase=AfterApply ... result=Applied postPlanar=...
[Reaction2206] channel=PlayerMotor phase=SetPlanarVelocity ... previous=... next=...
[Reaction2206] channel=PlayerMotor phase=ApplyMotor ... velocityBefore=... planarAfter=... solvedDelta=... actualDelta=...
```

判读规则：

| Log 事实 | 初步判断 |
|---|---|
| `BeforeApply alignment=Opposed` | 仅说明命中前速度与击退方向相反，不等于冲量已经被抵消 |
| `AfterApply result=Applied` 且 `postPlanar` 等于请求方向 | 冲量已写入 Player Motor，问题不在 `TryApplyImpulse` 的申请结果 |
| `AfterApply=Applied` 后紧接 `SetPlanarVelocity next` 改成移动方向 | 移动/动作逻辑覆盖了冲量，属于控制权未统一的设计缺口 |
| `solvedDelta` 明显大于 `actualDelta` | KCC 障碍求解、墙体或地形阻挡缩短了实际位移 |
| `AfterApply=Applied`、无覆盖写入但只移动一帧 | 需要继续检查冲量持续时间、Motor 生命周期和状态切换 |

静态上，当前 `Player.TryApplyImpulse` 使用 `SetPlanarVelocity` 替换平面速度，而不是把冲量叠加到当前速度；因此“反向速度直接在这一行把冲量抵消”不是已证实事实。更可能的路径是：冲量写入成功后，Player Locomotion/Action 在后续帧再次写入速度，或者 KCC 求解受到碰撞约束。后续应以 `BeforeApply → AfterApply → SetPlanarVelocity → ApplyMotor` 的同帧/相邻帧链条定责。

同时，当前 Player 没有与 Enemy 对等的 ReactionProfile/HitReact 消费路径，Player 命中更多走无 Profile 的兼容冲量分支；因此动作打断、移动打断、HitReact 状态和冲量持续通道尚未统一，这正是“万向受击位移”后续需要补齐的架构问题，不在本轮修复。

## 五、Up 专向验收

使用 `LaunchUpSpeed > 0` 的命中，分别从目标前方和侧方各测试一次。两次均应优先识别为 `Up`：

```text
[Feedback] Reaction resolve result=Resolved eventId=<id> target=<target> route=Hit_Up direction=Up ...
[Enemy] HitReact phase=Commit kind=HitReact result=Consumed route=Hit_Up sourceEventId=<id> ...
[EnemyAnim] PLAY action=Hit_Up ... kind=HitReact ...
```

同时检查：`ActionMotion` 为位移权威时，不能为同一次受击额外出现重复的平面 Motor Impulse；Up 动作本身的垂直表现问题另行记录，不与方向解析混为一项。

## 六、其它 220.6 专向验收

| 专项 | 操作 | Log 事实 | 通过条件 |
|---|---|---|---|
| Payload | 填入非空 VFX/SFX 键后命中 | `[Feedback] Present ... vfx=... sfx=...` | Payload 被消费并发布事件 |
| CancelAction | Enemy 出招中受击 | `ActionLease ... reason=HitReact` | 旧动作取消后进入对应 HitReact |
| KeepImpulseOnly | 加 `SuperArmor` 命中 | `enqueue=False superArmor=True` | 不进入 HitReact |
| QueueAfterAction | 霸体期间配置排队 | `HitReact ... Retain` 或过期 Discard | 等待消费或明确过期 |
| Structure/Ward | 命中 Structure/Ward | `Reaction ignore kind=...` | 无 HitReact 入队 |
| Death | 用致死伤害命中 | `reason=target-dead` | 死亡目标不补播 |
| Queue pressure | 快速连续命中 | `enqueueResult=Accepted/RejectedFull` | 无悬挂 Lease、eventId 可追溯 |

## 七、AI Log 判定规则

### 单次四向通过

同一个 `eventId` 必须能够串起：

```text
Reaction resolve(direction + route)
→ Reaction Intent enqueue
→ HitReact Commit(route + sourceEventId)
→ EnemyAnim PLAY(action)
```

缺少其中任一环，只能判定为“部分通路”，不能判定该方向受击反馈通过。

### 方向错误分类

```text
direction 错误：Resolver 坐标判定错误或目标旋转未纳入本地空间
route 错误：ReactionProfile 的 HitDirection → RouteId 配置错误
action 错误：ReactionSet RouteId → Action/Motion 资产装配错误
只有 resolve 无 PLAY：Intent/FSM/Lease 消费链断裂
有 PLAY 无正确 direction：日志或 Plan 快照缺失，不能仅凭动画猜测
```
