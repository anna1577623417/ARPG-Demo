## 1. 顶层分层架构

项目采用**五层螺旋**结构——从核心基础设施向外逐层扩展到表现层。每层只依赖内层，形成单向依赖：

```
                    ┌──────────────────────────────────────┐
                    │     5_Presentation (表现层)          │
                    │  Animation / Visual / Turn / Shaders │
                    │          PlayerAnimController        │
                    ├──────────────────────────────────────┤
                    │     4_Data (数据资产层)              │
                    │  SkillDataSO / ActionDataSO /        │
                    │  MotionProfileSO / BuffDefinitionSO  │
                    ├──────────────────────────────────────┤
                    │     3_Gameplay (玩法逻辑层)          │
                    │  Player / Entities / Combat / Motion │
                    │  ActionSystem / Buff / Damage        │
                    ├──────────────────────────────────────┤
                    │     2_Framework (框架层)             │
                    │  SkillSystem / UI / FSM / Input      │
                    │  GameplayTags / DI / Camera / Combat │
                    ├──────────────────────────────────────┤
                    │     1_Core (核心层)                  │
                    │  EventBus (Global/Local) /           │
                    │  Singleton / MonoSingleton           │
                    └──────────────────────────────────────┘
```

| 层 | 目录 | 典型类型 | 职责 |
|----|------|---------|------|
| 1_Core | `EventBus/` `Utilities/` | `GlobalEventBus`, `LocalEventBus`, `MonoSingleton<T>` | 跨系统解耦通信 + 单例基类 |
| 2_Framework | `DI/` `FSM/` `Skill/` `UI/` `Input/` `GameplayTags/` `Camera/` `Combat/` | `ServiceRegistry`, `State<T>/StateMachine<T>`, `SkillSystem`, `InputReader`, `GameplayTagContainer` | 可复用框架——不绑定具体游戏 |
| 3_Gameplay | `Characters/` `Combat/` `Motion/` `Entities/` | `Player`, `PlayerStateManager`, `Entity<T>`, `ActionInterruptResolver`, `MotionExecutor` | 游戏专用逻辑 |
| 4_Data | `1.Skills/` `2.Actions/` `3.Motion/` `Buff/` `Stats/` `Catalogs/` | `SkillDataSO`, `ActionDataSO`, `MotionProfileSO`, `PlayerIntentCatalog` | ScriptableObject 资产——策划可配 |
| 5_Presentation | `Animation/` `Visual/` `Turn/` `UI/` | `PlayerAnimController`, `DamageTextSystem` | 纯表现——不反写逻辑 |

**关键分层约束（由内向外）**：

- `1_Core` **不依赖** 任何具体游戏类型
- `2_Framework` **不引用** `3_Gameplay` 或 `4_Data`
- `3_Gameplay` **不引用** `5_Presentation`（通过 `LocalEventBus` 单向推送表现事件）
- `4_Data` 只放 `ScriptableObject` / `enum` / `struct` —— 零运行时依赖

## 2. 技能核心数据流（7 层管线）

任一帧内「按下 Q → 释放一个 Ability_06 技能 → 播动作 → 出伤害」始终穿过 7 层。以下以 `SlotAbility_06` (Q 键) 为例展开完整调用链。

### 2.1 层 1 — 设备

```
Keyboard "Q" → Unity Input System → InputAction "SlotAbility_06" (performed 回调)
```

### 2.2 层 2 — 翻译层 (InputReader)

```
InputReader.OnSlotAbility_06(ctx)
  ├─ _ability06PressedPulse = true             // 兼容旧 API
  └─ WriteSlotEdge(SkillSlotType.Ability_06, pressed:true)
       ├─ _slotPressedPulses[Ability_06] = true
       ├─ _slotHeld[Ability_06] = true
       └─ _slotHeldStartTime[Ability_06] = Time.time
```

**设计准则**：InputReader 只翻译物理信号为结构字段，不决策，不走 EventBus。

### 2.3 层 3 — 采样层 (PlayerController.Update → ConsumeDiscreteIntents)

```
PlayerController.Update()
  └─ ConsumeDiscreteIntents()
       └─ TryDispatchSlot(SkillSlotType.Ability_06)
            ├─ PlayerIntentCatalog.HasFactoryFor(Ability_06) → true
            ├─ inputReader.ConsumeSkillEntryPressed(SkillEntrySlot.Skill_06_Q, out holdSeconds)
            │    // Route 模式下走 Entry API；否则走 ConsumeSkillSlotPressed
            ├─ intent = PlayerIntentCatalog.ForSkillEntry(Skill_06_Q, Time.time, primaryHold:holdSeconds)
            │    // 内部: Kind=Skill_Entry_06, HasSkillSlot=true, SkillSlot=Ability_06
            │    // ExpireTime = Time.time + 0.18s (DefaultBufferSeconds)
            │    // RequiredAllAbility = CanCastAbility1, Forbidden = Dead|Stunned
            └─ player.EnqueueGameplayIntent(intent)
                 └─ GameplayIntentBuffer.Enqueue(in intent)
```

### 2.4 层 4 — 缓冲层 (GameplayIntentBuffer)

```
GameplayIntentBuffer
  ├─ 环形数组, cap=16, 零 GC (struct 队列)
  ├─ FlushExpired(Time.time) → 丢弃 ExpireTime < now 的意图
  ├─ TryPeek → 返回队首
  ├─ ReplaceFront → 原地覆盖 (SkillSystem 注入 intent.Action)
  └─ Pop → 消费确认后出队
```

### 2.5 层 5 — 仲裁层 (PlayerStateManager.OnPreLogicUpdate)

仲裁层是**整个技能管线的核心正确性边界**，采用「延迟规划三段提交」避免资源回滚混乱：

```
每帧固定顺序 (exec order = -20, maxIntentConsumptionsPerFrame = 1):

1. Entity.TickSkillRuntimes(dt)         // 推进所有 SkillRuntime: CD/回充/二段窗过期/Combo 超时
2. Entity.IntentBuffer.FlushExpired(now) // 丢弃过期

3. TryPeek 队首意图

4. [5.1 全局闸门] SkillSystem.TryPrepareIntentForSkills(player, ref intent)
   ├─ TryMapIntentToSlot → 解析 slot (优先 intent.SkillSlot / IntentSkillSlotMapSO / 代码默认表)
   ├─ player.TryGetResolvedSkill(slot) → SkillLoadoutSO.Resolve(slot) 取 SkillDataSO
   ├─ player.TryGetSkillRuntime(slot) → 取 SkillRuntime
   ├─ Combo 过期判断 → runtime.ResetCombo()
   ├─ 取 hold 时长: PrimaryHoldDurationSeconds (LightAttack/Ability) vs SecondaryHoldDurationSeconds (Heavy/Ultimate)
   ├─ segment 选择: Charge 恒用根资产; 非 Charge 走 SkillSegmentResolver.ResolveSegment(comboChain)
   ├─ runtime.CanCast(stats, resources, ref tags, self) → 校验 CD/资源/Stun/二段窗
   ├─ SkillGcd.IsGlobalCooldownActive() → GCD 检查 (跳过 ignoreGlobalCooldown)
   ├─ 二段窗 Bump: SecondStageAvailable && stages.Length>1 && CurrentStageIndex==0
   ├─ stage = SkillSegmentResolver.ResolveActiveStage(segment, effectiveIdx)
   ├─ actionOut = stage.action
   ├─ SkillChargeCommit.TryApplyChargeOverride(...) → Charge 蓄力分档替身 (替换 stage / action / damage)
   ├─ intent.Action = actionOut
   ├─ ctx = player.BorrowSkillContext() → 填充 Runtime/Stage/ResolvedSheet/Target/Modifiers
   ├─ ctx.CastHandler = SkillCastHandlerFactory.Create(segment) → 装配处理句柄 (Instant/Charge/CastTime/Channel/HoldRelease)
   ├─ BootstrapCastHandshake → handler.OnInputPressed(ctx)
   └─ player.BeginDeferredSkillPlanning(ctx, slot, runtime, secondBumpDeferred)
      // ※ 注意: 此时仅「准备」，未真正提交

5. IntentBuffer.ReplaceFront(in intent) // 写回 intent.Action

6. [5.2 过渡闸门] TransitionResolver.CanOfferIntent(in ctx, in intent, out reason)
   ├─ 过期检查
   ├─ StateTag 禁止位 / 必需位
   ├─ AbilityTag 禁止位 / 必需位
   └─ 失败 → player.CancelDeferredSkillPlanning(); break

7. player.FinalizeDeferredSkillPlanning() → m_activeSkillContext 提交

8. [5.3 状态本地闸门] Current.TryConsumeGameplayIntent(player, in ctx, in intent)
   ├─ Locomotion: 按 ActionCategory 掩码 → Change<PlayerActionState>
   ├─ Airborne: 上升/下降两套掩码
   ├─ Action: ActionInterruptResolver.CanInterrupt() → 窗口内同/异类别硬打断
   └─ Dead: 拒绝一切
   └─ 失败 → player.RevertCommittedSkillPlanningAfterFailedConsume(); break

9. player.AcknowledgeCommittedSkillConsumed(); IntentBuffer.Pop()
```

### 2.6 层 6 — 路由 (IntentRouter)

```
IntentRouter.Route(player, in intent, forceActionReentry)
  ├─ Jump → player.RequestJumpFromIntent() + States.Change<PlayerAirborneState>
  └─ (其余所有) → player.ArmPendingAction(kind, actionData)
                   + States.Change<PlayerActionState>() (或 ForceChange 同状态重入)
```

### 2.7 层 7 — 执行 (PlayerActionState)

```
PlayerActionState.OnEnter:
  ├─ 读取 player.PendingAction / ActiveSkillContext
  ├─ MotionExecutor.Begin(action.MotionProfile, duration, motionDir, ...)
  ├─ TaskExecutor.StartAll(stage.tasks, ctx)
  └─ 资源扣除: player.TryBeginSkillCostsIfNeeded(ctx)

PlayerActionState.OnUpdate (每帧):
  ├─ ctx.CastHandler.OnUpdate(ctx, dt)       // 推进 CastHandler 状态机
  ├─ SkillCastGating.ShouldDispatchTasksAndWindows(handler, sheet)
  │    // Charge: 蓄力中 false, 松手 true
  │    // CastTime: 读条完成才 true
  │    // Channel: 引导中 true
  ├─ ActionWindow 事件派发 (HitFrame / ChargeHoldEnter|Exit / Sound / VFX)
  ├─ MotionExecutor.Tick(dt, timeScale, pos) → 程序化位移
  ├─ PlayerKCCMotor → 物理步进 (CapsuleSweep + Collide&Slide)
  └─ 蓄力松手: Player.TryNotifySkillCastInputReleasedForSlot → handler.OnInputReleased

PlayerActionState.OnExit:
  ├─ MotionExecutor.End() → 动画速率复位
  ├─ CD 结算: runtime.StartCooldown(stats) (按 CooldownPolicy)
  ├─ 中间段抑制: SuppressLastCastCooldownThisExit
  └─ TaskExecutor.CancelAll / Complete
```

## 3. 数据资产层 — ScriptableObject 驱动设计

整个技能/动作/运动系统由 5 类 ScriptableObject 资产组成层级数据管道：

```
SkillLoadoutSO (角色技能装配)
  └─ SkillEntryRow[] entries
       └─ SkillRouteUnit[] units
            └─ skillData → SkillDataSO (技能模板)

SkillDataSO (技能模板)
  ├─ Cast Model: CastType / castTime / channelDuration
  ├─ Charge Config: ChargeConfig (tapThreshold / chargeFullTime / maxHoldTime / levels)
  ├─ Stages: SkillStageSO[]
  │    └─ action → ActionDataSO
  │    └─ tasks → AbilityTaskSO[]
  ├─ Cooldown: CooldownPolicy / baseCooldown / maxCharges / comboChain[]
  ├─ Costs: SkillCost[] (ResourceType + baseAmount)
  ├─ Progression: damageByLevel / cooldownByLevel / costByLevel (AnimationCurve)
  └─ Traits: SkillTrait (Flags: IgnoreDefense / Unstoppable / RefundCostOnMiss / …)

ActionDataSO (动作资产)
  ├─ Animation: MainClip / CrossfadeTime / AnimSpeed / Duration
  ├─ Interrupt: Category (Movement|Offense|Defensive|Utility) / Priority / Stability / AllowSelfInterrupt
  ├─ Motion: MotionProfileSO (null = 纯表现，非 null = 程序化位移)
  ├─ Windows: ActionWindow[] (归一化时间切片 + InterruptibleByCategories + MinIncomingPriority)
  └─ Teleport: TeleportTrigger[] (离散瞬移事件)

MotionProfileSO (运动曲线)
  ├─ AnimSpeedMode: Constant / Curve(SpeedOverTime) / StrideMatch
  └─ GravityBehavior / MotionScale / DisplacementCurves

AbilityTaskSO (技能子任务模板)
  ├─ 控制类: ShowIndicator / WaitConfirm / WaitWindowSignal
  ├─ 运动类: Dash / MoveToTarget
  ├─ 生成类: SpawnProjectile / SpawnSummon
  └─ 结果类: ApplyDamage / ApplyEffect / ModifyCooldown
```

**数据流向的唯一性（SSOT）**：

| 关注点 | 唯一数据源 | 禁止 |
|--------|-----------|------|
| 技能装配 | `SkillLoadoutSO.Resolve(slot)` | 代码内硬编码 slot → skill 映射 |
| 释放模型 | `SkillDataSO.castType` | 状态机内分支判断 CastType |
| 动作窗口 | `ActionDataSO.Windows[]` | 代码内手写时间窗判断 |
| 运动曲线 | `MotionProfileSO` | 代码内 `Mathf.Lerp` 写死位移 |
| 打断语义 | `ActionDataSO.Category` + `ActionWindow.InterruptibleByCategories` | 按 IntentKind 名字判断 |

## 4. 运行时状态 — SkillRuntime 与 SkillContext

### 4.1 SkillRuntime — 单槽运行态

每个 `SkillSlotType` 对应一个 `SkillRuntime` 实例，托管于 `Player.m_skillRuntimes` Dictionary。

```
SkillRuntime
├── Data: SkillDataSO                    // 静态模板 (只读引用)
├── Level: int                           // 技能等级
├── CurrentStageIndex: int               // 当前段位指针 (同一 SkillData 内 stages[])
├── IsActive: bool                       // HoldRelease 等持续技能的状态标记
├── CD 系统
│   ├── CdRemaining: float               // 剩余 CD 时间
│   ├── CdScaledCooldown: float          // 本次 CD 总长 (供 UI: 1 - CdRemaining / CdScaledCooldown)
│   ├── CurrentCharges: int              // 多充能技能的当前可用层数
│   ├── RechargeTimer / RechargeTimerMax  // 回充计时
│   └── CooldownPolicy: OnFirstCast / OnLastCast / OnSkillEnd
├── Combo 系统
│   ├── ComboIndex: int                  // comboChain[] 内的连段索引
│   ├── LastInputTime: float             // 上次输入时间 (用于 comboResetTime 超时)
│   └── IsComboExpired()                 // Time.time - LastInputTime > comboResetTime
├── 二段窗
│   ├── SecondStageAvailable: bool       // 是否在二段输入窗口内
│   ├── SecondStageExpireTime: float     // 窗口截止时间
│   └── OpenSecondStageWindow(float)     // 任务侧打开窗口
├── 蓄力状态
│   ├── IsCharging: bool
│   └── ChargeStartTime: float
└── 中间段 CD 抑制
    └── SuppressLastCastCooldownThisExit: bool
```

**关键方法链**：

```
CanCast(stats, resources, ref tags, self)
  → IsDead? → Stun? → IsCooldownReady? → HasEnoughResource? → SecondStageAvailable?

StartCooldown(stats)
  → GetScaledCooldown() → ApplyCooldownReduction(stats) → 设置 CdRemaining/CdScaledCooldown
  │  // 多充能: CurrentCharges--, 启动 RechargeTimer

StartCancelCooldown(stats, mode, value)   // 蓄力取消专用
  → SkipCooldown / ReturnPercent(cd * (1-value)) / ReturnFixed(max(0, cd - value)) / None

ModifyCooldown(op, value)
  → Reset / ReduceFlat / ReducePercent / Set
```

### 4.2 SkillContext — 单次释放上下文

每次技能释放时从 `Player.BorrowSkillContext()` 获取或新建，**非池化**（struct 语义，赋值即拷贝）：

```
SkillContext
├── Self: Entity (施法者)
├── SelfTransform: Transform
├── Stats: IStatSet
├── Resources: IResourcePool
├── Tags: GameplayTagContainer
├── Runtime: SkillRuntime (装配根 — CD/Combo 载体)
├── ResolvedSkillSheet: SkillDataSO (连招段或根技能)
├── CurrentStage: SkillStageSO
├── StageElapsedTime / StageNormalizedTime: float
├── Target: TargetData (Entity + Position + Direction + IsValid)
├── MarkedTarget / MarkedPosition
├── FinalModifiers: SkillModifiers (RadiusScale/DamageScale/DurationScale/...)
├── ActiveRouteUnit: SkillRouteUnit? (Phase 6+)
└── CastHandler: ICastHandler (Phase 5 装配)
```

## 5. 释放五态 — CastType 与 CastHandler 工厂

技能释放模型 (CastType) 决定**玩家输入如何映射到技能推进**。工厂 `SkillCastHandlerFactory.Create(sheet)` 按 `SkillDataSO.castType` 装配对应处理器。

| CastType | Handler | OnInputPressed | OnUpdate | OnInputReleased | ShouldTrigger | IsComplete |
|----------|---------|----------------|----------|-----------------|---------------|------------|
| **Instant** | `InstantCastHandler` | 空 | 空 | 空 | 恒 true | 恒 true |
| **CastTime** | `CastTimeCastHandler` | reset elapsed | 累计计时 | 早松 → cancelled | 读条完成才 true | cancelled 或到时 |
| **Channel** | `ChannelCastHandler` | reset | 累计计时 | releasedEarly | 引导中持续 true | 松手或到时 |
| **Charge** | `ChargeCastHandler` | IsHolding=true, 开始计时 | 推进 HoldSeconds；达 maxHoldTime 触发超时策略 | 决出 Tap/Charge/FullCharge/Cancel | 松手后 true | 松手或超时后 true |
| **HoldRelease** | `HoldReleaseCastHandler` | IsActive=true | 空 | _released=true | 按住中持续 true | 松手后 true |

**核心设计意图**：

- `ShouldTrigger` 控制 ActionWindow 派发闸门——读条中不触发 HitFrame
- `IsComplete` 控制 Action 退出时机——Instant 立即退，Charge 等松手
- 五态之间无继承层级——每态是一个独立 sealed class，通过 `ICastHandler` 接口统一签名

### 5.1 InstantCastHandler

```
public sealed class InstantCastHandler : ICastHandler
{
    public bool IsComplete => true;       // 立即结束
    public bool ShouldTrigger => true;    // 恒可触发
    // OnInputPressed/Released/Update 均为空
}
```

适用：瞬发普攻、瞬发技能——按钮按下即完成。

### 5.2 CastTimeCastHandler

```
public sealed class CastTimeCastHandler : ICastHandler
{
    readonly float _seconds;             // 读条总时长
    float _elapsed;
    bool _cancelled;
    // ShouldTrigger: !cancelled && elapsed >= seconds
}
```

适用：需要读条的技能——读条中不可移动（由 ActionDataSO 控制），早松取消。

### 5.3 ChannelCastHandler

```
public sealed class ChannelCastHandler : ICastHandler
{
    readonly float _duration;
    float _elapsed;
    bool _releasedEarly;
    // ShouldTrigger: !IsComplete (引导中持续为 true)
}
```

适用：持续引导技能——按住期间持续触发效果，松手或到时结束。

### 5.4 HoldReleaseCastHandler

```
public sealed class HoldReleaseCastHandler : ICastHandler
{
    bool _released;
    // ShouldTrigger: !_released (按住中持续 true)
}
```

适用：按住持续生效、松手收尾——类似防御/格挡姿态。

## 6. 蓄力系统 — ChargeConfig × ChargeCastHandler × ChargeCommit

蓄力系统是**最复杂的单一子模块**，跨越 SkillDataSO（数据定义）、ChargeCastHandler（运行时状态机）、SkillChargeCommit（装配替身）三个层次。

### 6.1 ChargeConfig 数据模型

```
ChargeConfig (挂 SkillDataSO.charge)
├── [时间]
│   ├── tapThreshold: float          // Tap 阈值 (秒) — 低于此值视为轻点
│   ├── chargeFullTime: float        // 蓄满时长 — 到达后动画压到 holdAnimSpeedAtFull
│   └── maxHoldTime: float           // 极限保持 — 到达后按 expiryStrategy 处理
├── [动画挂起]
│   ├── holdAnimSpeedAtFull: float   // 蓄满后 Animator 速率 (0 = 完全冻结, 0.05 = 抖动循环)
│   ├── holdAnchorMode: ByChargeFullTime | ByActionWindow
│   ├── holdAnchorBehavior: Freeze | LoopWindow
│   ├── holdLoopWindowStart/End: float
├── [伤害曲线]
│   └── damageMultiplierByProgress: AnimationCurve  // X=充电进度(0..1), Y=倍率
├── [超时/取消]
│   ├── expiryStrategy: Cancel | ForceRelease
│   ├── cancelCdMode: SkipCooldown | ReturnPercent | ReturnFixed | None
│   ├── cancelCdValue: float
│   └── refundResourceOnCancel: bool
└── [Tap 回退]
    ├── enableTapFallback: bool
    └── tapFallbackSlot: SkillSlotType  // Tap 时路由到哪个槽位
```

### 6.2 ChargeCastHandler 状态机

```
内部状态:
├── HoldSeconds: float               // 累计按住时长
├── ChargeProgress01: float          // HoldSeconds / chargeFullTime [0,1]
├── IsHolding: bool                  // 是否正在按住
├── HasReachedThreshold: bool        // HoldSeconds >= tapThreshold
├── HasReachedFull: bool             // HoldSeconds >= chargeFullTime
├── HasExpired: bool                 // HoldSeconds >= maxHoldTime (超时)
├── WasTap: bool                     // 松手时 HoldSeconds < tapThreshold
├── WasCancelled: bool               // 超时且 expiryStrategy=Cancel
├── IsComplete: bool                 // 松手或超时后 = true
├── ShouldTrigger: bool              // 松手后或超时ForceRelease = true
└── DesiredAnimSpeed: float          // 蓄满且按住 → holdAnimSpeedAtFull; 否则 1

状态转换:
  OnInputPressed → IsHolding=true, HoldSeconds=0
  OnUpdate → HoldSeconds += dt
    ├─ HoldSeconds >= chargeFullTime → HasReachedFull=true
    └─ HoldSeconds >= maxHoldTime → HasExpired=true
         ├─ ForceRelease → ShouldTrigger=true, IsComplete=true
         └─ Cancel → WasCancelled=true, IsComplete=true
  OnInputReleased → IsHolding=false
    ├─ HoldSeconds < tapThreshold → WasTap=true
    ├─ ShouldTrigger=true
    └─ IsComplete=true
```

### 6.3 SkillChargeCommit — 蓄力分档替身

在仲裁阶段（5.1 末端），`SkillChargeCommit.TryApplyChargeOverride` 按当前 `chargeHoldSeconds` 决定是否替换 `stage/action/damage`：

```
TryApplyChargeOverride(segment, slot, kind, chargeHoldSeconds, ref stage, ref action, out dmgMul):
  ├─ 非 Charge 类型 → 直接返回 false
  ├─ 不匹配槽位 → 返回 false
  ├─ chargeHoldSeconds < tapThreshold → 返回 false
  ├─ 命中 chargeLevels[] 中 max(minHoldTime ≤ hold) 的档位:
  │   └─ 替换 stage / action / damageMultiplier
  └─ 未配分档但有 stages[1]:
      └─ stage = stages[1], action = stages[1].action (作为长按段)
```

## 7. 槽位体系 — SkillSlotType / SkillEntrySlot / SkillLoadout

### 7.1 双枚举对齐设计

系统定义两个 byte 值强制一致的枚举：

```
SkillSlotType (玩法语义):
  Skill_Primary_01=0  Skill_Primary_02=1  Skill_Primary_03=2
  Secondary_04=3      Ultimate_05=4
  Ability_06=5        Ability_07=6  Ability_08=7
  Ability_09=8  …  Ability_17=16

SkillEntrySlot (入口语义 — Ver 4.6+ C1 规范):
  Skill_01_LM=0       Skill_02_LM_b=1   Skill_03_LM_c=2
  Skill_04_RM=3       Skill_05_R=4
  Skill_06_Q=5        Skill_07_Shift=6  Skill_08_Space=7
  Skill_09_Key1=8  …  Skill_17_Key9=16

无损转换: SkillEntrySlots.FromSkillSlot / ToSkillSlot (直接 (byte) 强转)
```

**设计动机**：

- `SkillSlotType`：历史命名，携带"Primary/Secondary/Ultimate/Ability"玩法语义
- `SkillEntrySlot`：蓝图 C1 新规范，**只表达物理入口**，不带任何玩法语义
- 两枚举 byte 值强制一致，双轨迁移时无需任何数据转换

### 7.2 SkillLoadoutSO — 角色技能装配

```
SkillLoadoutSO
├── bindings[]: SlotBinding[]            // 迁移期: 槽位 → 技能直接映射
│   └── { slot, skill, hudKeyLabel }
├── entries[]: SkillEntryRow[]           // Ver 4.6+: 入口行，每行含 1+ SkillRouteUnit
│   └── { entrySlot, hudKeyLabel, units: SkillRouteUnit[] }
│        └── SkillRouteUnit { routeId, icon, showOnHud, skillData, conditions[] }
└── Resolve(slot) → SkillDataSO
    ├─ entries 优先: 走 TryGetPrimaryRouteUnit → unit.skillData
    └─ bindings 回退: 遍历 bindings[] 找同 slot
```

**迁移期兼容**：`TryEnsureEntriesFromBindings()` 在运行时/编辑器自动从旧 `bindings` 合成 `entries`（每槽一行、每行一个 RouteUnit）。

## 9. 双层闸门 — TransitionResolver + ActionInterruptResolver

### 9.1 全局闸门 — TransitionResolver

```
TransitionResolver.CanOfferIntent(in FrameContext, in GameplayIntent) → bool:
  ├─ 过期检查: ctx.Time >= intent.ExpireTime → "expired"
  ├─ StateTag 禁止位: (currentTags & intent.ForbiddenTags) != 0 → "hit forbidden tags"
  ├─ AbilityTag 禁止位: (abilityTags & intent.ForbiddenAbilityTags) != 0 → "hit forbidden ability tags"
  ├─ StateTag 全必需: (currentTags & intent.RequiredAllTags) != intent.RequiredAllTags → "missing required-all tags"
  ├─ AbilityTag 全必需: (abilityTags & intent.RequiredAllAbilityTags) != intent.RequiredAllAbilityTags
  └─ StateTag 任一必需: intent.RequiredAnyTags != 0 && (currentTags & intent.RequiredAnyTags) == 0
```

**输入**：`FrameContext`——每帧快照（Time/DeltaTime/IsGrounded/Velocity/CurrentTags/CurrentAbilityTags/Stamina/IsPrimaryAttackHeld）。

### 9.2 局部闸门 — ActionInterruptResolver

```
ActionInterruptResolver.CanInterrupt(action, normalizedTime, intent, incomingAction):
  ├─ 硬打断: incomingPriority > action.InterruptStability → 直接 true (跳窗口)
  └─ 窗口匹配: 遍历 action.Windows[]
       ├─ 时间命中: t ∈ [w.NormalizedStart, w.NormalizedEnd]
       ├─ 类别匹配: (w.InterruptibleByCategories & incomingCategory) != 0
       ├─ 优先级满足: incomingPriority >= w.MinIncomingPriority
       └─ 自打断: isSelf && !w.AllowSelfInterrupt && !action.AllowSelfInterrupt → 拒绝
```

**类别优先级默认表**：

| ActionCategory | 默认 Priority | 典型槽位 |
|----------------|-------------|---------|
| Defensive | 40 | (预留) |
| Movement | 30 | Dodge (Ability_08), SwordDash (Ability_07) |
| Offense | 20 | Primary_01…03, Secondary_04, Ultimate_05, Ability_06, Ability_09…17 |
| Utility | 10 | (预留) |

## 10. 执行层 — PlayerActionState + TaskExecutor + MotionExecutor

### 10.1 PlayerActionState — 万能动作状态

作为 4 支柱 FSM 中的"动作入口"，所有攻击/技能/闪避/剑冲最终都通过此状态执行：

```
OnEnter:
  ├─ 读取 PendingAction / ActiveSkillContext
  ├─ 标签标记: gameplayTags.Add(StateTag.PhaseStartup|PhaseActive)
  ├─ MotionExecutor.Begin(motionProfile, resolvedDuration, motionDir, startPos, animSpeed)
  ├─ TaskExecutor.StartAll(stage.tasks, ctx)
  └─ 资源扣除: Skills.TryBeginSkillCostsIfNeeded(ctx)

OnUpdate:
  ├─ ActionTimeline: normalizedTime += dt / resolvedDuration
  ├─ ctx.CastHandler.OnUpdate(ctx, dt)
  ├─ ActionWindow 派发:
  │   ├─ HitFrame → TaskExecutor.BroadcastWindowSignal(HitFrame)
  │   ├─ ChargeHoldEnter/Exit → 动画锚点
  │   ├─ Sound / VFX
  │   └─ EvaluatePhaseTags → mask 中叠加标记位
  ├─ MotionExecutor.Tick(dt, timeScale, position)
  │   └─ 内部三层动画速率: baseSpeed × profileFactor × Charge.DesiredAnimSpeed
  ├─ 离散瞬移: TeleportTriggers 单帧触发
  ├─ PlayerKCCMotor → 物理步进
  └─ 归一化时间 >= 1f → 退出判断:
      ├─ CastHandler.IsComplete → End()
      └─ 否则等待 (Charge 松手 / CastTime 读条)

OnExit:
  ├─ MotionExecutor.End()
  ├─ 标签清理: Remove(PhaseStartup|PhaseActive|PhaseRecovery)
  ├─ CD 结算: runtime.StartCooldown(stats) (按 CooldownPolicy)
  ├─ Stage 推进: runtime.AdvanceStage() / OpenSecondStageWindow()
  ├─ Combo 推进: runtime.AdvanceCombo() / ResetCombo()
  ├─ TaskExecutor.ExitAll(ctx)
  └─ 技能上下文回收: player.ReturnSkillContext()
```

### 10.2 TaskExecutor — 并行任务执行器

```
TaskExecutor
├── _activeTasks: List<AbilityTask>(8)
├── StartAll(taskDefs[], ctx) → 每个 def.CreateInstance() → OnEnter(ctx)
├── UpdateAll(ctx, dt) → 倒序遍历, Running 的 task.OnUpdate
├── BroadcastWindowSignal(ctx, kind) → 全部 Running task.OnWindowSignal
├── ExitAll(ctx) → task.OnExit × 全部
├── AllCompleted() / AnyFailed()
└── 任务类型:
    ├─ ShowIndicatorTask    — 显示技能指示器
    ├─ WaitConfirmTask      — 等待玩家确认
    ├─ WaitWindowSignalTask — 等待 ActionWindow 事件触发
    ├─ DashTask             — 冲刺位移
    ├─ MoveToTargetTask     — 移动到目标
    ├─ SpawnProjectileTask  — 生成弹道
    ├─ SpawnSummonTask      — 生成召唤物
    ├─ ApplyDamageTask      — 造成伤害
    ├─ ApplyEffectTask      — 施加效果
    └─ ModifyCooldownTask   — 修改冷却
```

### 10.3 MotionExecutor — 程序化位移

```
MotionExecutor
├── Begin(profile, duration, direction, startPos, animSpeed)
├── Tick(dt, timeScale, currentPos) → 期望速度向量
│   └─ 三层动画速率组合:
│       finalAnimSpeed = ActionDataSO.AnimSpeed
│           × profileFactor (AnimSpeedMode: Constant=1 / Curve(t) / StrideMatch(v/ref))
```

## 12. 设计哲学总结

### 12.1 已落地的最佳实践

| 原则 | 实现 | 评注 |
|------|------|------|
| **零 GC 战斗** | `GameplayIntent` (struct), `GameplayIntentBuffer` (struct 数组), `GlobalEventBus` (泛型静态缓存) | 环形缓冲 + 值类型杜绝堆分配 |
| **数据驱动** | 全部技能/动作/运动/Buff 配置为 ScriptableObject | 策划可在 Inspector 手调 |
| **单一事实来源** | `SkillLoadoutSO` = 槽位装配唯一入口; `ActionDataSO` = 动作参数唯一入口 | 杜绝隐式多源 |
| **标签驱动状态** | `GameplayTagContainer` 5 轨 (State/Status/Ability/Mechanic/Faction), 位掩码 O(1) 查询 | 比字符串状态名快且不被 typo 坑 |
| **策略模式** | `ICastHandler` 5 态, `IDamageStage` 链路, `IAnimSpeedControl` | 开放扩展/封闭修改 |
| **构造注入** | `SystemRoot` + `PlayerFactory` 通过 `InjectMovementContext` 传递, 避免 `FindObjectOfType` | 显式依赖优于隐式查找 |
| **泛型 CRTP** | `Entity<T>`, `EntityState<T>`, `EntityStateManager<T>` | 编译期类型安全 |
| **三层动画速率** | `ActionDataSO.AnimSpeed × profileFactor × Charge.DesiredAnimSpeed` | 职责分明，覆写优先 |

### 12.2 设计决策与取舍

| 决策 | 为什么 |
|------|--------|
| **主管线不走 EventBus** | 技能管线需要严格帧序保证（5.1→5.2→5.3 不可逆序）；EventBus 用于旁路（UI/Camera/音效）解耦 |
| **延迟规划三段提交** | 避免「SkillSystem 已扣资源、TransitionResolver 失败」的回滚地狱——先准备，确认通过才提交 |
| **static class 技能管线** | 性能优先：`SkillSystem.TryPrepareIntentForSkills` 每帧只调 1 次，static 无虚调用开销。代价：不可单元测试 |
| **SkillSlotType 保留玩法语义** | 与 `SkillEntrySlot` (纯入口) 双轨共存迁移，不破坏序列化兼容 |
| **Player.cs 集中所有字段** | 快速迭代期单文件 > 过早拆分；已规划 Phase 2 拆出 SkillComponent |

## 13. 当前架构风险与演进路线

### 13.1 已知风险 (2026-05-13)

| 风险 | 严重度 | 现状 | 缓解 |
